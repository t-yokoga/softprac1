    第14回　演習：再帰¶

    解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

    講義を読んでから取り組んでください．

    準備と進め方¶

    作業場所はPL1\week14です．第1回と同じ設定（Cとしてコンパイル，C17，警告レベル4）を使います．演習では，課題ごとに別の空のプロジェクトを作り，次のファイルを1つだけ追加します．

    課題・小問 プロジェクト名 ソースファイル
    課題1-1〜1-2：階乗 Factorial factorial.c
    課題2-1〜2-2：再帰の復帰順 Trace trace.c
    課題3-1〜3-2：互除法の反復版 GcdLoop gcd_loop.c
    課題4：安全な入口 CheckedFactorial checked_factorial.c
    発展1-1〜1-2：フィボナッチ数の呼び出し Fibonacci fibonacci.c
    発展2-1〜2-3：二分木の走査 TreeTraversal tree_traversal.c
    発展3：帰りがけ順の解放 FreeTree free_tree.c

    各プロジェクトはPL1\week14の下へ保存します．1つのプロジェクトにmainを持つファイルを複数追加しないでください．

    同じソリューションへ複数のプロジェクトを追加した場合は，実行したいプロジェクトを右クリックして「スタートアッププロジェクトに設定」を選びます．

    保存後にCtrl+Shift+Bでビルドし，成功を確認してCtrl+F5で実行します．

    提出するのは，上の表の7つのソースファイルです．成績はソースファイルで評価します．提出先や締切は，授業時に案内します．

    今回の課題¶

    課題 内容 確認すること
    1 階乗の再帰版と反復版 基底条件，復帰時に完成する計算
    2 再帰の復帰順 呼び出しと復帰の表示順，再帰の前の入力検査
    3 互除法の反復版 再帰から反復への変換，更新の順序
    4 再帰の安全な入口 入力検査と内部関数の分離
    発展1 フィボナッチ数の呼び出し 呼び出し回数と最大深さ
    発展2 二分木の走査 3つの走査順，ノード数と高さ，木の形
    発展3 動的な木の解放 帰りがけ順による後始末

    ソースの書き方¶

    • 課題に示した場合は，すべてmainから呼び出して表示します．値を書き換えて実行し直すのではなく，1回の実行ですべての結果が表示されるようにします．
    • 小問のある課題は，同じファイルへ小問の順に書き足します．前の小問で作った関数や表示は消さずに残します．
    • 関数の名前，引数，戻り値の型は，課題の指定どおりにします．
    • 表示は，課題に示した出力と同じにします．

    今回のプログラムはどれも入力を待ちません．実行するとすぐに結果を表示して終了します．

    再帰関数には基底条件を置き，呼び出すたびに基底条件へ近づく引数を渡します．関数が前提とする範囲の外の値は，再帰へ入る前に呼び出し側で拒否します．止まらない再帰や，結果があふれる大きな入力はソースに書きません．

    課題1　階乗を再帰と反復で求める¶

    Factorialプロジェクトにfactorial.cを作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

    1. 課題1-1：階乗を再帰と反復の両方で求め，結果を比べる．
    2. 課題1-2：再帰の各段が返す値を，復帰するときに表示する．

    課題1-1　再帰版と反復版を比べる¶

    階乗を再帰と反復の両方で求めるプログラムを作成し，0!，1!，5!，20!で2つの結果が一致することを確認してください．

    プログラムが満たすこと（仕様）は次のとおりです．

    • 講義のunsigned long long factorial(unsigned int n)（再帰版）とunsigned long long factorial_loop(unsigned int n)（反復版）をmainの前に定義する．どちらもnは0〜20とする．
    • 関数void show_factorial(unsigned int n)を作る．show_factorialは2つの関数でnの階乗を求め，printf("%u! = %llu loop=%llu equal=%d\n", n, 再帰版の結果, 反復版の結果, 2つが等しいかの比較);で表示する．比較は，等しければ1，そうでなければ0になる式とする．
    • mainでは，0，1，5，20の順にshow_factorialを呼ぶ．

    表示は次のようになります．

    0! = 1 loop=1 equal=1
1! = 1 loop=1 equal=1
5! = 120 loop=120 equal=1
20! = 2432902008176640000 loop=2432902008176640000 equal=1

    0!では，再帰版は基底条件ですぐに1を返し，反復版はループ本体を1回も実行せずに1を返します．再帰版は子から戻った後に積を作り，反復版はループの各回で積を更新します．

    20!は64ビットのunsigned long longに収まりますが，21!は収まりません．そのため，21以上はこの関数へ渡しません．範囲外の値を拒否する入口は課題4で作ります．

    課題1-2　各段の戻り値を表示する¶

    再帰の各段が子から受け取った値と自分が返す値を，復帰するときに表示するプログラムを作成し，3!の計算で戻り値が基底条件の側から順に決まることを確認してください．

    • 関数unsigned long long factorial_trace(unsigned int n)を作る．計算はfactorialと同じで，nは0〜20とする．
    • nが0なら，printf("n=0 return=1\n");で表示して1を返す．
    • nが正なら，factorial_trace(n - 1)の戻り値を変数に受け取り，それにnを掛けた値を求めてから，printf("n=%u child=%llu return=%llu\n", n, 子の戻り値, 自分の戻り値);で表示して返す．
    • mainでは，課題1-1の表示の後にprintf("3! = %llu\n", factorial_trace(3));を実行する．

    課題1-1の表示に続けて，次の5行が出ます．

    n=0 return=1
n=1 child=1 return=1
n=2 child=1 return=2
n=3 child=2 return=6
3! = 6

    課題1全体の表示は次のようになります．

    0! = 1 loop=1 equal=1
1! = 1 loop=1 equal=1
5! = 120 loop=120 equal=1
20! = 2432902008176640000 loop=2432902008176640000 equal=1
n=0 return=1
n=1 child=1 return=1
n=2 child=1 return=2
n=3 child=2 return=6
3! = 6

    呼び出しはnが3，2，1，0の順に進みますが，表示は0から始まります．各段の表示は子から戻った後に実行されるからです．n=3の段が待っている間も，その段のnは3のままです．深い呼び出しでnが0になっても，待っている段のnまで0になるわけではありません．

    課題2　再帰の復帰順¶

    Traceプロジェクトにtrace.cを作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

    1. 課題2-1：講義のsum_toを，入力を検査する関数から呼ぶ．
    2. 課題2-2：enterの表示位置を変えた版を加える．

    課題2-1　呼び出しと復帰の順を表示する¶

    講義のsum_toを入力の検査付きで呼び出すプログラムを作成し，呼び出しと復帰の表示順と，範囲外のnではsum_toに入らないことを確認してください．

    プログラムが満たすこと（仕様）は次のとおりです．

    • 講義のtrace.cにあるint sum_to(int n)を，enterとleaveの表示を含めてそのままmainの前に定義する．nは0〜100とする．
    • 関数void show_sum(int n)を作る．show_sumは，まずprintf("n=%d\n", n);で表示する．nが0〜100でなければ，sum_toを呼ばずにprintf("rejected\n");で表示して戻る．範囲内ならprintf("sum=%d\n", sum_to(n));で表示する．
    • mainでは，3，0，−1，101の順にshow_sumを呼ぶ．

    表示は次のようになります．

    n=3
enter 3
enter 2
enter 1
enter 0
leave 0: 0
leave 1: 1
leave 2: 3
leave 3: 6
sum=6
n=0
enter 0
leave 0: 0
sum=0
n=-1
rejected
n=101
rejected

    enterは再帰呼び出しより前にあるので3，2，1，0の順に，leaveは子から戻った後にあるので0，1，2，3の順に表示されます．sum_to(0)がreturnした直後に戻る先はmainではなく，待っているsum_to(1)です．

    −1と101ではenterが1行も表示されません．範囲外の値をsum_toへ渡す前に拒否しているからです．負数を渡すとnは0から遠ざかり，基底条件へ到達しません．

    課題2-2　表示位置を変える¶

    enterの表示位置だけを基底条件の判定の後へ移した関数で合計を求めるプログラムを作成し，n=0の段ではenterが表示されないことを確認してください．

    • 関数int sum_to_late(int n)を作る．計算とleaveの表示はsum_toと同じで，再帰呼び出しはsum_to_late自身を呼ぶ．
    • printf("enter %d\n", n);は，if (n == 0)のブロックの後，再帰呼び出しの前に置く．
    • mainでは，課題2-1の表示の後にprintf("late\n");とprintf("sum=%d\n", sum_to_late(2));を実行する．

    課題2-1の表示に続けて，次の7行が出ます．

    late
enter 2
enter 1
leave 0: 0
leave 1: 1
leave 2: 3
sum=3

    課題2全体の表示は次のようになります．

    n=3
enter 3
enter 2
enter 1
enter 0
leave 0: 0
leave 1: 1
leave 2: 3
leave 3: 6
sum=6
n=0
enter 0
leave 0: 0
sum=0
n=-1
rejected
n=101
rejected
late
enter 2
enter 1
leave 0: 0
leave 1: 1
leave 2: 3
sum=3

    sum_to_late(0)も呼ばれていることは，leave 0: 0の表示から分かります．n=0の段は表示位置へ到達する前にreturnするので，enter 0だけが出ません．表示がないことと，関数が呼ばれていないことは違います．どの文が実行されるかを基準に流れを追いましょう．

    課題3　互除法を反復へ書き換える¶

    GcdLoopプロジェクトにgcd_loop.cを作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

    1. 課題3-1：最大公約数を再帰版と反復版で求め，結果を比べる．
    2. 課題3-2：反復版のループの各回の値を表示する．

    課題3-1　再帰版と反復版を比べる¶

    最大公約数を再帰とwhileによる反復の両方で求めるプログラムを作成し，7組の入力で2つの結果が一致することと，(0, 0)を呼び出し側で拒否することを確認してください．

    プログラムが満たすこと（仕様）は次のとおりです．

    • 講義のunsigned int gcd(unsigned int a, unsigned int b)（再帰版）をmainの前に定義する．
    • 同じ計算をwhileで行うunsigned int gcd_loop(unsigned int a, unsigned int b)（反復版）を定義する．gcd_loopは再帰を使わない．
    • どちらの関数も，aとbがともに0である入力は受け付けないものとする．
    • 関数void show_gcd(unsigned int a, unsigned int b)を作る．show_gcdは，aとbがともに0なら，どちらの関数も呼ばずにprintf("gcd(0, 0): rejected\n");で表示して戻る．それ以外ならprintf("gcd(%u, %u) = %u loop=%u\n", a, b, 再帰版の結果, 反復版の結果);で表示する．
    • mainでは，次の8組について，表の順にshow_gcdを呼ぶ．
    a b 確かめる性質
    48 18 通常の値
    18 48 引数の大小が逆
    7 0 最初から基底条件
    0 7 最初の余りが0
    7 7 同じ数
    13 8 互いに素
    100 25 一方が他方の倍数
    0 0 呼び出し側で拒否する

    表示は次のようになります．

    gcd(48, 18) = 6 loop=6
gcd(18, 48) = 6 loop=6
gcd(7, 0) = 7 loop=7
gcd(0, 7) = 7 loop=7
gcd(7, 7) = 7 loop=7
gcd(13, 8) = 1 loop=1
gcd(100, 25) = 25 loop=25
gcd(0, 0): rejected
    ヒント

    ループはbが0でない間だけ続けます．余りを一時変数へ保存してからaとbを更新します．

    どちらの関数も，bが0かを調べてから剰余を求めるので，0による剰余を計算しません．(0, 0)では関数の本体が0を返せますが，この授業では最大公約数の入力として扱いません．関数が受け付ける入力の条件と，呼び出し側で検査する条件をそろえています．

    課題3-2　ループの各回を表示する¶

    反復版のループの各回でa，b，余りを表示する関数で最大公約数を求めるプログラムを作成し，(48, 18)ではループが3回，(7, 0)では0回実行されることを確認してください．

    • 関数unsigned int gcd_loop_trace(unsigned int a, unsigned int b)を作る．計算はgcd_loopと同じとする．
    • ループ本体では，余りを求めた直後，aとbを更新する前にprintf("a=%u b=%u remainder=%u\n", a, b, 余り);で表示する．
    • mainでは，課題3-1の表示の後にprintf("result=%u\n", gcd_loop_trace(48, 18));とprintf("result=%u\n", gcd_loop_trace(7, 0));を実行する．

    課題3-1の表示に続けて，次の5行が出ます．

    a=48 b=18 remainder=12
a=18 b=12 remainder=6
a=12 b=6 remainder=0
result=6
result=7

    課題3全体の表示は次のようになります．

    gcd(48, 18) = 6 loop=6
gcd(18, 48) = 6 loop=6
gcd(7, 0) = 7 loop=7
gcd(0, 7) = 7 loop=7
gcd(7, 7) = 7 loop=7
gcd(13, 8) = 1 loop=1
gcd(100, 25) = 25 loop=25
gcd(0, 0): rejected
a=48 b=18 remainder=12
a=18 b=12 remainder=6
a=12 b=6 remainder=0
result=6
result=7

    余りを保存する前にaをbで上書きすると，元のaを失って正しい余りを求められません．再帰版では最後のgcd(6, 0)も1回の呼び出しなので，(48, 18)の呼び出しは4回です．反復版はbが0の状態ではループ本体を実行しないので，3回です．

    課題4　再帰の入口を安全にする¶

    範囲を検査する入口の関数と，再帰を行う内部の関数に分けて階乗を求めるプログラムを作成し，範囲内のnでは結果が保存され，範囲外のnやNULLでは保存先が変わらないことを確認してください．

    CheckedFactorialプロジェクトにchecked_factorial.cを作ります．第8回の出力用の引数と，第12回のstatic関数を組み合わせます．プログラムが満たすこと（仕様）は次のとおりです．

    • NULLを使うのでstddef.hをインクルードする．
    • 再帰を行う内部の関数をstatic unsigned long long factorial_impl(unsigned int n)とする．nは0〜20とし，計算は講義のfactorialと同じにする．
    • 入口の関数をint factorial_checked(int n, unsigned long long *out)とする．nが0〜20でoutがNULLでなければ，nの階乗を*outへ保存して1を返す．nが範囲外かoutがNULLなら，*outを変更せずに0を返す．
    • 再帰はfactorial_implだけで行う．factorial_checkedは，intのまま範囲を検査してからunsigned intへ変換し，範囲外の値でfactorial_implを呼ばない．
    • 関数void show_checked(int n)を作る．show_checkedはunsigned long long result = 99;を宣言してok = factorial_checked(n, &result)を求め，printf("n=%d ok=%d result=%llu\n", n, ok, result);で表示する．
    • mainでは，0，1，5，20，−1，21の順にshow_checkedを呼び，最後にprintf("null ok=%d\n", factorial_checked(5, NULL));を実行する．

    表示は次のようになります．

    n=0 ok=1 result=1
n=1 ok=1 result=1
n=5 ok=1 result=120
n=20 ok=1 result=2432902008176640000
n=-1 ok=0 result=99
n=21 ok=0 result=99
null ok=0
    ヒント

    負数を先にunsigned intへ変換すると大きな正の値になります．n < 0の検査は，intのままで行います．

    失敗したときの99は計算結果ではありません．この関数を使う側は，okを確かめてから結果を使います．検査を通った後は，nが0〜20で，1ずつ減らせば0に到達することが分かっています．内部の関数はその前提を使えるので，再帰の中で検査を繰り返す必要はありません．

    NULLを検査しても，無効なアドレスまで見分けられるわけではありません．NULL以外のoutが有効なunsigned long longを指すことは，呼び出し側が保証します．

    発展1　再帰の呼び出し回数と深さ¶

    Fibonacciプロジェクトにfibonacci.cを作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

    1. 発展1-1：フィボナッチ数を素朴な再帰で求め，呼び出し回数と最大深さを数える．
    2. 発展1-2：fib(4)の呼び出しを，字下げした木の形で表示する．

    フィボナッチ数は，fib(0) = 0，fib(1) = 1，fib(n) = fib(n - 1) + fib(n - 2)とします．

    発展1-1　回数と深さを数える¶

    フィボナッチ数を再帰で求めながら呼び出し回数と最大深さを数えるプログラムを作成し，8つのnで反復版と同じ値になることと，呼び出し回数と最大深さの違いを確認してください．

    プログラムが満たすこと（仕様）は次のとおりです．

    • 回数と深さを記録する構造体を，次のように宣言する．

      typedef struct {
    unsigned long long calls;
    unsigned int max_depth;
} Stats;

    • 関数unsigned long long fib(unsigned int n, unsigned int depth, Stats *stats)を作る．入口でstats->callsを1増やし，depthがstats->max_depthより大きければstats->max_depthをdepthにする．nが2未満ならnを返す．それ以外は，fib(n - 1, depth + 1, stats)とfib(n - 2, depth + 1, stats)を別々の文でこの順に呼び，2つの和を返す．

    • 前の2項を保持して反復で求めるunsigned long long fib_loop(unsigned int n)を作る．
    • fibとfib_loopのnは0〜20とする．
    • 関数void show_fib(int input)を作る．inputが0〜20でなければ，fibを呼ばずにprintf("n=%d rejected\n", input);で表示して戻る．範囲内なら，Stats stats = {0, 0};を宣言してfib(n, 1, &stats)を呼び，printf("n=%u fib=%llu calls=%llu depth=%u loop=%llu\n", n, 結果, stats.calls, stats.max_depth, fib_loop(n));で表示する．nはinputをunsigned intへ変換した値とする．
    • mainでは，0，1，2，3，4，5，10，20，−1，21の順にshow_fibを呼ぶ．

    表示は次のようになります．

    n=0 fib=0 calls=1 depth=1 loop=0
n=1 fib=1 calls=1 depth=1 loop=1
n=2 fib=1 calls=3 depth=2 loop=1
n=3 fib=2 calls=5 depth=3 loop=2
n=4 fib=3 calls=9 depth=4 loop=3
n=5 fib=5 calls=15 depth=5 loop=5
n=10 fib=55 calls=177 depth=10 loop=55
n=20 fib=6765 calls=21891 depth=20 loop=6765
n=-1 rejected
n=21 rejected

    最初の呼び出しも数えるので，n=0でもcallsは1です．depthは呼び出しごとの通常の引数なので段ごとに違いますが，statsの参照先はすべての段で共通です．Statsをshow_fibの中で毎回{0, 0}に初期化しているので，前の場合の回数は加算されません．

    左右を順に処理するので，呼び出しの木の全ノードを同時に待たせるわけではありません．そのため，n=20で呼び出し回数は21891回でも，最大深さは20です．depthは対象の関数の論理的な深さで，実際に使ったスタックのバイト数ではありません．

    改善の方向

    fib(2)を一度計算して保存できれば，再計算を省けます．これがメモ化の考え方です．fib_loopは前の2項だけを保持し，nに比例する回数の反復で求めます．メモ化と反復への書き換えは，異なる方法です．

    発展1-2　呼び出しの木を表示する¶

    発展2　二分木の3つの走査¶

    TreeTraversalプロジェクトにtree_traversal.cを作ります．この課題では，次の3つの小問を順に行い，同じファイルへ書き足します．

    1. 発展2-1：講義の木と部分木を，3つの順序で走査する．
    2. 発展2-2：部分木のノード数と高さを求める．
    3. 発展2-3：右へ一直線につないだ木を作り，同じ処理を行う．

    発展2-1　3つの順序で走査する¶

    発展2-2　ノード数と高さを求める¶

    部分木のノード数と高さを再帰で求めるプログラムを作成し，木全体，NULL，葉，2つの部分木で値を確認してください．

    • 関数size_t node_count(const Node *p)を作る．空の木（NULL）は0，それ以外は1＋左の部分木のノード数＋右の部分木のノード数を返す．
    • 関数size_t tree_height(const Node *p)を作る．高さは「根から葉までの最長の経路に含まれるノードの個数」とし，空の木は0，葉は1とする．
    • 関数void show_size(const char *name, const Node *root)を作り，printf("%s count=%zu height=%zu\n", name, ノード数, 高さ);で表示する．
    • mainでは，発展2-1の表示の後に，次の表の順にshow_sizeを呼ぶ．
    name root
    "whole" &nodes[0]
    "NULL" NULL
    "nodes[3]" &nodes[3]

    "nodes[6]" &nodes[6]

    発展3　帰りがけ順で木を解放する¶

    各ノードを個別にmallocして講義と同じ形の木を作り，帰りがけ順ですべて解放するプログラムを作成し，子を先に解放する順序と，解放後に残るノードが0個になることを確認してください．

    FreeTreeプロジェクトにfree_tree.cを作ります．プログラムが満たすこと（仕様）は次のとおりです．

    • Nodeの宣言は講義のtree.cと同じにする．mallocとfreeを使うのでstdlib.hをインクルードする．
    • 確保中のノードの個数を数えるファイルスコープの変数static int live_count = 0;を置く．
    • 関数Node *make_node(int value)を作る．mallocでノードを1つ確保し，失敗したらNULLを返す．成功したら値をvalue，左右の子をNULLにし，live_countを1増やしてから返す．
    • 関数void destroy_tree(Node *p)を作る．pがNULLなら何もしない．それ以外は，左の部分木，右の部分木の順にdestroy_treeで解放した後，printf(" %d", p->value);で値を表示し，pをfreeしてlive_countを1減らす．
    • mainでは，Node *nodes[10]の各要素へmake_node(i + 1)の結果を入れる．途中でNULLが返ったら，それまでに確保したノードをすべてfreeし，fputs("out of memory\n", stderr);で表示して1を返す．
    • すべて確保できたら，講義のtree.cと同じ親子関係にノードをつなぎ，Node *root = nodes[0];とする．
    • 次の順に実行する．
      1. printf("live=%d\n", live_count);
      2. printf("freed:");の後，destroy_tree(root);を呼び，root = NULL;とする．
      3. printf("\nlive=%d\n", live_count);
      4. もう一度printf("freed:");の後にdestroy_tree(root);を呼び，printf("\nlive=%d\n", live_count);で表示する．

    表示は次のようになります．

    live=10
freed: 4 5 3 6 2 9 8 10 7 1
live=0
freed:
live=0

    解放の順序は，発展2の帰りがけ順と同じです．子を解放する前に親をfreeすると，その後に親のleftやrightを読めません．free(p)を関数の最初へ移すと，p->leftとp->rightが解放後の使用になります．

    destroy_treeはrootのコピーを受け取るので，呼び出し元のrootは自動ではNULLになりません．所有者がroot = NULL;としておけば，2回目のdestroy_tree(root)は何もせずに戻ります．2つの親が同じ子を指す木では同じノードを2回解放してしまうので，この関数は共有も循環もない木だけに使います．木が一直線に長いと，解放する関数の再帰も深くなります．

    確認問題¶

    この節は自習用で，成績には含めません．

    1. 基底条件を書けば，入力の範囲を確認しなくても必ず止まるか．
    2. sum_to(3)でsum_to(0)がreturnした直後，mainへ戻るか．
    3. fibの呼び出しが9回なら，最大深さも9か．
    4. gcdは末尾再帰なので，C17では必ずスタックを使わないか．
    5. 木の走査でNULLを判定する前にp->valueを読んでよいか．
    6. returnすると，その呼び出しでmallocした領域も自動解放されるか．

    チェックリスト¶

    • 各課題のソースが1つのファイルにまとまり，警告なしでビルドできる．
    • 1回の実行で，課題に示したすべての場合の結果が表示される．
    • 表示が，課題に示した出力と一致する．
    • 関数の名前，引数，戻り値の型が課題の指定どおりである．
    • 小問のある課題で，前の小問の関数や表示を残している．
    • 再帰関数に基底条件があり，再帰呼び出しの引数が基底条件へ近づく．
    • 不正な入力を呼び出し側で拒否し，範囲外の値で再帰を始めていない．
    • 木の走査で，NULLを判定してからノードのメンバを読んでいる．
    • mallocしたノードをすべて解放し，局所配列のノードはfreeしていない．
