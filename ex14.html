    第14回　演習：再帰¶

    解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

    講義を読んでから取り組んでください．出力と処理の流れを予測しましょう．

    準備と進め方¶

    作業場所は PL1\week14 です．第1回と同じ設定（Cとしてコンパイル，C17，警告レベル4）で，課題ごとに別の空のプロジェクトを作ります．特に指定がなければ，mainを持つソースは1プロジェクトに1つです．保存後にCtrl+Shift+Bでビルドし，Ctrl+F5で実行します．

    各課題で，ソース，試した値，予測，実行結果，結果の説明を残してください．提出先や締切は，授業時に案内します．

    基本課題1〜4では，基底条件，復帰順，反復との対応，入力検査を確認します．発展課題では，フィボナッチ数の重複計算と木の走査を扱います．すべての課題で「何が小さくなるから止まるのか」を文章で説明してください．

    プロジェクト 使用する例 主な観察

    Trace trace.c 呼び出しと復帰，各段の局所変数

    大きな入力を使ってPCを止めたり，スタックの限界を探したりする必要はありません．誤った再帰の断片は読解だけで扱い，実行用プロジェクトへそのまま入れないでください．

    0〜20のすべてで比較してもかまいません．ただし，範囲を広げて型の限界を探す課題にはしません．再帰版は復帰時に積を作り，反復版はループの各回で積を更新する，という違いを説明してください．

    課題2　再帰の復帰順¶

    Trace プロジェクトでtrace.cを実行します．sum_to(3)とsum_to(0)の呼び出し図を書きます．表示順を予測してから実行してください．

    表示順を完全に書き出す¶

    n=2の場合の出力を，空欄を残さず紙に書きます．enterは関数に入ったとき，leaveはその関数が返る直前です．

    mainのnを0，1，2，3へ変更し，手書きの予測と比べます．100では合計5050です．−1と101はmainで拒否され，enterの表示が出ないことを確認します．sum_toへ直接負数を渡す呼び出しへ書き換えないでください．

    呼び出し履歴を見る¶

    講義5.2の手順に従い，Debug構成でsum_to内のifの行にブレークポイントを置きます．n=3から開始し，n=0まで進んだときに次を記録してください．

    履歴にある待機中のsum_toを選ぶと，その呼び出しの変数を調べられます．実行を巻き戻したり，その関数をもう一度呼んだりする操作ではありません．初期化文を完了していないresultの表示を正しい値として記録しないでください．

    出力位置を変える¶

    sum_toの最初にあるenterの表示だけを，n==0の判定の後へ移した場合を予測します．元の版は保存し，別コピーで試してください．

    次に，leaveの表示を再帰呼び出しより前へ移す案を考えます．その位置ではresultはまだ計算されていません．完成前のresultを出力するのではなく，nだけを表示する形にする必要があります．戻り値を観察する目的なら，元の位置が適切です．

    スタックの図を描く¶

    sum_to(3)がsum_to(0)を実行中の状態を4段の箱で描き，各段へnと「何を待っているか」を書きます．次に0が戻った後の3段の状態を描きます．各段のnが独立していることと，後入れ先出しで復帰することを図から説明してください．

    (0,0)を呼び出し側で拒否する¶

    mainでaとbを変数として用意する版では，次の条件を呼び出しより前へ置きます．

    gcd_loopの本体が(0,0)に対して0を返せることは，今回の入力仕様として受け入れる理由にはなりません．関数の契約と呼び出し側の検査をそろえます．

    課題4　再帰の入口を安全にする¶

    再帰本体は前提を守って使う内部関数にし，外部から使う入口で入力を検査します．第8回の出力引数と，第12回のstatic内部関数を組み合わせます．

    仕様¶

    • int factorial_checked(int n, unsigned long long *out)を用意する．
    • nが0〜20で，outが有効な書き込み先なら結果を保存し1を返す．
    • nが範囲外，またはoutがNULLなら0を返し，保存先を変更しない．
    • 再帰は内部のfactorial_implだけで行う．
    • 不正な値で再帰へ入らない．
    入口で検査する利点

    入力検査を通過した後は，0まで1ずつ減らすことが分かっています．内部関数ではその前提を利用できます．入口のintで負数を拒否してからunsigned intへ変換します．NULLを検査しても，無効なアドレスまで検査できるわけではありません．NULL以外のoutは有効なunsigned long longを指すことを呼び出し側で保証します．

    実装にはNULLを宣言するstddef.hを取り込みます．factorial_implはstatic unsigned long long factorial_impl(unsigned int n)とし，講義の階乗を参考に作成してください．

    呼び出す断片¶

    main内に次を置き，nを変更して確認してください．

unsigned long long result = 99;
int ok = factorial_checked(n, &result);
printf("ok=%d result=%llu\n", ok, result);

    実行しないレビュー問題¶

    次の各変更をしたら何が問題になるか，停止条件・進行・数値範囲の観点で説明してください．誤った版は実行しません．

    1. 基底条件のifを削除する．
    2. 再帰呼び出しの引数をnにする．
    3. 再帰呼び出しの引数をn+1にする．
    4. 再帰呼び出しの引数をn--にする．
    5. 負数の検査をせず，先にunsigned intへ変換する．
    6. checkedの範囲検査を外し，21以上の階乗を計算する．

    発展1　再帰の呼び出し数¶

    fib(0)=0，fib(1)=1，fib(n)=fib(n−1)+fib(n−2)として，fib(4)の呼び出しの木を紙に書きます．同じ引数で複数回呼ばれる箇所を探してください．

    #include <stdio.h>

typedef struct {
    unsigned long long calls;
    unsigned int max_depth;
} Stats;

unsigned long long fib(unsigned int n, unsigned int depth, Stats *stats)
{
    ++stats->calls;
    if (depth > stats->max_depth) {
        stats->max_depth = depth;
    }
    if (n < 2) {
        return n;
    }
    unsigned long long left = fib(n - 1, depth + 1, stats);
    unsigned long long right = fib(n - 2, depth + 1, stats);
    return left + right;
}

unsigned long long fib_loop(unsigned int n)
{
    unsigned long long a = 0;
    unsigned long long b = 1;
    for (unsigned int i = 0; i < n; ++i) {
        unsigned long long next = a + b;
        a = b;
        b = next;
    }
    return a;
}

int main(void)
{
    int input = 4;
    if (input < 0 || input > 20) {
        fputs("n must be 0..20\n", stderr);
        return 1;
    }
    unsigned int n = (unsigned int)input;
    Stats stats = {0, 0};
    unsigned long long result = fib(n, 1, &stats);
    printf("fib=%llu calls=%llu depth=%u loop=%llu\n",
           result, stats.calls, stats.max_depth, fib_loop(n));
    return 0;
}

    このプログラムのfibとfib_loopは，検査済みの0〜20のnを前提とします．fibのstatsは有効なStatsを指し，depthは1から始めます．入力検査を外した大きなnには適用しません．

    計測結果の読み方¶

    1. 最初の呼び出しも数えるので，n=0でcallsは0にならない．
    2. statsを初期化せずに再びfibを呼べば，callsは加算され続ける．別の測定には新しく{0,0}で初期化する．
    3. 左右は順番に処理するため，呼び出しの木にある全ノードを同時にスタックへ積むわけではない．
    4. depthは対象関数の論理的な深さであり，実際に何バイトのスタックを使ったかを測っているわけではない．
    改善案を考える

    fib(2)を一度計算して保存できれば，再計算を省けます．これがメモ化の考え方です．一方，fib_loopは前の2項だけを保持し，入力の大きさに比例する回数の反復で求めます．メモ化と反復への変更は，異なる方法だと整理してください．

    発展2　二分木の3つの走査¶

    TreeTraversalへ講義のtree.cを保存します．実行前に，講義8の木の各ノードへpreorder，inorder，postorderの訪問番号を書き込みます．ノードの値と訪問番号は別です．

    出力を予測する¶

    1. 1を根とする木全体を，行きがけ順でたどる．
    2. 同じ木を，通りがけ順でたどる．
    3. 同じ木を，帰りがけ順でたどる．
    4. 実行して，予測の列と比較する．

    小さい木で基底条件を確認する¶

    走査の開始位置 行きがけ順の値 確認すること

    mainにある呼び出しの引数だけを変えます．pre:などの見出しは表示されるので，「何も表示しない」は走査関数がノードの値を出さないという意味です．NULLの判定をprintfやp->leftへのアクセスより後へ動かさないでください．

    ノード数を返す関数¶

    表示の代わりに，部分木に含まれるノード数を返す関数を追加します．空の木は0，自分がいるなら1＋左の個数＋右の個数です．今回の10ノード以下の木ではsize_tの範囲に十分収まります．

    stddef.hを取り込み，size_t node_count(const Node *p)を自分で実装してください．全体・葉・NULLで検証し，結果を記録します．

    高さを返す関数¶

    ここでは高さを「根から葉までの最長経路に含まれる実ノードの個数」と定義します．空の木は0，葉は1です．文献によって辺の数で数える場合もあるため，最初に定義をそろえます．

    size_t tree_height(const Node *p)を自分で実装してください．左右の高さをどのように組み合わせるか考えます．

    木の形を変える¶

    正常版を保存し，ノードをつなぐ代入文をすべて外してから，0〜8の各iについてnodes[i].right = &nodes[i + 1];だけを設定します．これは右へ一直線の10ノードの木です．

    • ノード数と高さを予測する．
    • 行きがけ順，通りがけ順，帰りがけ順の表示を予測する．
    • 元の木と一直線の木で，各実ノードの表示回数と最大深さを比較する．

    最後のノードを先頭へつなぐような循環は作りません．木の前提を外したデータへ単純な再帰走査を使うと，停止条件へ到達しない可能性があります．確認後は元の接続に戻します．

    発展3　帰りがけ順と解放の順序¶

    第13回と結び付けて，「各ノードを個別にmallocした木」を考えます．子を解放する前に親をfreeすると，その後に親のleftやrightを読むことができません．子を処理してから自分を処理する帰りがけ順が，後始末にも使えます．

    次のコードは個別に動的確保したノードだけに使う説明用の断片です．講義のnodes配列には使いません．

    /* 前提：共有・循環がなく，各ノードが個別にmallocされている */
void destroy_tree(Node *p)
{
    if (p == NULL) {
        return;
    }
    destroy_tree(p->left);
    destroy_tree(p->right);
    free(p);
}

    Nodeの宣言とstdlib.hが必要です．実際に動的な木を作る場合には，構築途中の確保失敗でも作成済みの部分を解放する経路が必要です．この課題ではまず順序の説明に集中し，完成した動的な木の構築プログラムは要求しません．

    読解の問い¶

    1. free(p)を最初へ移すと，どの式が解放後の使用になるか．
    2. 2つの親が同じ子を指していた場合，何が起こるか．
    3. 呼び出し元のrootは自動でNULLになるか．
    4. 木が一直線に長い場合，解放処理にも深さの問題があるか．

    確認問題¶

    1. 基底条件を書けば，入力の範囲を確認しなくても必ず止まるか．
    2. sum_to(3)でsum_to(0)がreturnした直後，mainへ戻るか．
    3. fibの呼び出しが9回なら，最大深さも9か．
    4. gcdは末尾再帰なので，C17では必ずスタックを使わないか．
    5. 木の走査でNULLを判定する前にp->valueを読んでよいか．
    6. returnすると，その呼び出しでmallocした領域も自動解放されるか．

    チェックリスト¶

    • 正常な値だけでなく，課題に示された境界の値でも確認した．
    • 警告を確認し，原因を説明・修正した．
    • 自分の言葉で，処理の流れと使った型を説明できる．
    • 基底条件と，呼び出すたびに小さくなる量を説明できる．
    • 呼び出し時と復帰時を分け，待機中の局所変数を追跡した．
    • 数値の範囲，総呼び出し回数，最大深さを区別した．
    • 不正な入力は再帰に入る前に拒否し，無限再帰を実行しなかった．
    • 木のノードの寿命と所有権を確認し，局所配列のノードをfreeしていない．
