    第1回　プログラミングの基礎¶

    今回は，WindowsのVisual Studioを使ってC言語のプログラムを作成し，ビルドして実行するまでの流れを学びます． 最初のプログラムは，画面に Hello, world! と表示する短いものです． ファイルの場所，ビルドの意味，プログラムの構造を理解することが，これからの学習の土台になります．

    到達目標

    • ソースファイルと実行ファイルを区別できる．
    • Visual StudioでCのプロジェクトを作成し，ビルド・実行できる．
    • 短いCプログラムの構造を説明できる．
    • エラーの場所を調べ，修正して再実行できる．

    1．プログラミングとは¶

    プログラムは，コンピュータに実行させたい処理を記述したものです． 例えば，測定データの平均を計算する，文字列を検索する，画面に図形を表示する，といった処理をプログラムとして表せます．

    プログラミングでは，おおまかに次の作業を行います．

    1. 何をしたいかを決める：入力と，得たい結果を整理する．
    2. 手順を考える：必要な処理を，小さな処理の組み合わせとして表す．
    3. コードを書く：プログラミング言語の規則に従って記述する．
    4. 実行して確かめる：期待した結果になるかを調べ，必要なら修正する．

    この講義では C言語 を使います．C言語では，値の型やメモリの扱いを意識しながらプログラムを組み立てます． 今回はその入口として，コードを書いて実行する流れを身に付けましょう．

    2．作業を始める前に¶

    Visual Studioの役割¶

    Visual Studio は，エディタ，コンパイラ，デバッガなどをまとめて利用できる 統合開発環境（IDE） です． この講義では，Windows版のVisual Studioと，そのC/C++コンパイラである MSVC を使います．

    道具・機能 役割 今回行うこと
    Visual Studioのエディタ ソースコードを編集・保存する hello.c を作成する
    コンパイラなどのビルドツール ソースコードから実行ファイルを作る プロジェクトをビルドする
    コンソール画面 プログラムの文字入出力を表示する Hello, world! を確認する

    必要な機能の確認

    演習室PC以外で作業する場合，Visual Studioに 「C++によるデスクトップ開発」 が導入されていることを確認してください．C言語もこの機能で扱います． 「空のプロジェクト」が見つからない場合は，Visual Studio Installerで導入状況を確認します．

    この資料の言語設定はC17です．C17を選べるMSVCを使います（Visual Studio 2019ではバージョン16.8以降）．メニューの表記はバージョンによって多少異なります．

    Visual StudioとVisual Studio Codeは別のアプリケーション

    この講義で使うのは Visual Studio です．Visual Studio Code（VS Code）の画面とは操作が異なります．

    GUIとCLI：操作を伝える方法¶

    GUI（Graphical User Interface） は，ボタンやメニューなどを画面上で選んで操作する方法です．エクスプローラーでフォルダを開くことや，Visual Studioのメニューからビルドすることが該当します．

    CLI（Command Line Interface） は，文字で書いた命令（コマンド）を入力して操作する方法です．コマンドには，行いたい処理の名前に加えて，対象のファイルや動作を指定する情報を渡します．同じ操作を繰り返したり，一連の処理を自動化したりするときに役立ちます．

    GUIとCLIは，コンピュータへ指示を伝える方法の違いです．どちらでもファイルの操作やビルドを行えます．この授業ではVisual StudioのGUIで操作し，コマンド入力の実習は行いません． また，自作プログラムの文字が表示されるコンソール画面と，操作用のコマンドを入力する画面は，役割を区別してください．

    作業用フォルダ¶

    エクスプローラーで，自分が保存できる場所に PL1 フォルダを作成し，その中に week01 フォルダを作成してください． この week01 を，第1回の作業場所にします．例えば，ドキュメントフォルダの中に作成してかまいません．

    PL1/
└── week01/

    エクスプローラーのアドレスバーから，week01 の 実際のフルパス を確認しておきましょう． ユーザ名や，OneDriveを利用しているかどうかによって，パスは異なります．

    ファイル・フォルダとパス¶

    ファイルは，ソースコードなどのデータを保存する単位です．フォルダ（ディレクトリ） は，ファイルや別のフォルダをまとめる入れ物です．hello.cの.cは拡張子で，ファイルの種類を見分ける手掛かりになります．ソースファイル.cと，ビルドで作られる実行ファイル.exeは別のファイルです．

    ファイルやフォルダの場所を表す文字列をパスと呼びます．次は説明用の配置です．実際のプロジェクトの配置とは異なる場合があります．

    C:\Users\student\Documents\PL1\
├── week01\
│   └── hello.c
└── week02\
    └── area.c
    種類 例 読み方
    絶対パス（フルパス） C:\Users\student\Documents\PL1\week01\hello.c ドライブからたどって場所を指定する
    相対パス week01\hello.c 基準がPL1フォルダなら，その下のweek01にあるhello.c
    相対パス .\hello.c 基準フォルダ自身（.）にあるhello.c
    相対パス ..\week02\area.c 基準がweek01なら，親フォルダ（..）に戻り，week02のarea.cへ進む

    相対パスは，どのフォルダを基準にするかで指す場所が変わります．プログラム実行時の基準を作業ディレクトリと呼び，ソースファイルの保存先と常に同じとは限りません．ファイルをプログラムから開く際の設定は第10回で扱います．ここでは，ファイル名だけでなく保存場所も確認する習慣を付けましょう．

    パスの表記

    Windowsのパスの区切りにはバックスラッシュを使います．表示環境によっては円記号に見えることがあります．上の例は場所を説明する表記であり，Cの文字列リテラルではありません．Cの文字列に書く場合のエスケープは，後の節で扱います．

    3．最初のCプログラム¶

    プロジェクトを作成する¶

    Visual Studioでは，プログラムのファイルとビルド設定を プロジェクト としてまとめます． プロジェクトをまとめて管理する単位を ソリューション と呼びます．まずは，1つのソリューションに1つのプロジェクトを作ります．

    1. Visual Studioを起動し，「新しいプロジェクトの作成」 を選ぶ．既に起動している場合は，「ファイル → 新規作成 → プロジェクト」を選ぶ．
    2. 検索欄で 「空のプロジェクト」 を探す．C++／Windowsの空のプロジェクト を選ぶ．
    3. プロジェクト名を HelloC とし，「場所」に先ほどの week01 を指定する．
    4. 「ソリューションとプロジェクトを同じディレクトリに配置する」 にチェックを入れ，作成する．

    この設定では，week01 の下に HelloC フォルダが作られ，その中でプロジェクトを管理します．

    テンプレートはC++でも，作成するソースはC

    Visual Studioでは，C言語のプログラムもC++のプロジェクト機能で管理します．次の手順で拡張子を .c にし，Cとしてコンパイルする設定を確認します． C++用の .cpp のままにしないでください．

    hello.cを追加する¶

    1. ソリューション エクスプローラー の「ソース ファイル」を右クリックする．表示されていなければ「表示 → ソリューション エクスプローラー」を開く．
    2. 「追加 → 新しい項目」 を選ぶ．
    3. 「C++ファイル（.cpp）」を選び，名前を hello.c に変更して追加する．簡易入力欄が出る場合も，ファイル名を hello.c にする．
    4. 次のコードを入力し，Ctrl+S で保存する．
    hello.c

    #include <stdio.h>

int main(void)
{
    printf("Hello, world!\n");
    return 0;

    サンプルファイルをダウンロード

    人が読める形で書かれたプログラムを ソースコード，保存したファイルを ソースファイル と呼びます． ファイル名が hello.c であることを確認してください．hello.cpp や hello.c.txt とは異なります．

    Cとしてビルドする設定¶

    ソリューションではなく，プロジェクト HelloC を右クリックして「プロパティ」を開きます．上部の「構成」を「すべての構成」，「プラットフォーム」を「すべてのプラットフォーム」にして，次の項目を確認・設定します．

    設定場所 項目 設定値
    C/C++ → 詳細設定 コンパイル言語 Cコードとしてコンパイル（/TC）
    C/C++ → 言語 C言語標準 ISO C17標準（/std:c17）
    C/C++ → 全般 警告レベル レベル4（/W4）

    「適用」または「OK」で保存します．C言語標準の項目がなければ，使用しているVisual Studioやツールセットを確認してください． /TC はこのプロジェクトをC専用にする設定です．新しい課題のプロジェクトでも同様に設定します．

    ビルドする¶

    「ビルド → ソリューションのビルド」 を選びます（通常のショートカットは Ctrl+Shift+B）．

    ソースコードをコンピュータが実行できる形へ翻訳することを コンパイル と呼びます． ビルド は，コンパイルや必要なコードを結び付けるリンクなどを行い，実行ファイルを作る作業です．詳しい処理段階は第12回で学びます．

    「出力」ウィンドウの表示対象を「ビルド」にすると，処理結果を確認できます．見つからない場合は「表示 → 出力」を開いてください． 成功し，失敗したプロジェクトがないことを確認します．警告が出ていれば，その内容も読んでください．

    実行ファイルはどこにできるか

    作成されるファイルは，通常 HelloC.exe です．出力先はビルド構成により異なり，例えば x64\Debug などのフォルダになります． ビルドの出力に表示される .exe のフルパスを確認してください．ソースと同じ場所にできるとは限りません．

    実行する¶

    「デバッグ → デバッグなしで開始」 を選びます（Ctrl+F5）． コンソール画面に，次の内容が表示されます．

    Hello, world!

    Visual Studioが，終了コードや「何かキーを押してください」といった案内を追加で表示する場合があります．それらは，今回の printf が表示した文字列とは別です．確認後，コンソールを閉じます．

    hello.cソースファイル
    ビルド→
    HelloC.exe実行ファイル
    実行→
    Hello, world!プログラムの出力

    ソースを保存する操作，実行ファイルを作る操作，作ったプログラムを動かす操作は，それぞれ別です． Visual Studioが実行前にビルドを自動で行う場合もありますが，最初は各段階の結果を確認しましょう．

    4．Cプログラムの構造¶

    #include：必要な宣言を読み込む¶

    #include <stdio.h>

    stdio.h は標準入出力に関する ヘッダ です．この例では，後で使う printf の宣言を利用できるようにします． #include は，コンパイルに先立つ前処理の指示です．末尾にセミコロンは付けません．

    main：プログラムの入口¶

    int main(void)

    今回のような通常のCプログラムは，main 関数から処理を始めます． int は整数を返すこと，void はここでは引数を受け取らないことを表します． 関数を自分で定義する方法は第5回で学びます．まずはこの形を使ってください．

    { と } で囲まれた部分に，実行する処理を書きます．今回の例では，表示を行ってから終了します．

    printf：文字列を表示する¶

    printf("Hello, world!\n");

    printf は，指定した内容を標準出力へ書き出す関数です．この実行例では，標準出力はコンソール画面につながっています． "..." で囲んだものを 文字列リテラル と呼びます．最後の \n は改行を表します．

    関数を呼び出す式などの末尾に ; を置くと，1つの文になります． すべての行末に ; を付けるわけではありません．#include や，ここでの main の宣言部分，開き波括弧の行には付けません．

    return：処理を終える¶

    return 0;

    return は関数の処理を終え，値を返します． main から 0 を返すと，プログラムが正常に終了したことを実行環境へ伝えます．画面に数字の 0 を表示する命令ではありません．

    インデントとコメント¶

    波括弧の内側を字下げすると，処理のまとまりが読み取りやすくなります．この資料では，基本的に半角空白4つ分の インデント を使います． また，コードの意味を説明する文章を コメント として書けます．

    // これは行末までのコメントです．
/* この書き方では，囲まれた部分がコメントです． */

    コメントの文章自体が，画面に表示されることはありません． コード中の記号は，半角の "，;，(，)，{，} を使ってください．

    5．表示を変えてみる¶

    編集してからもう一度ビルドする¶

    hello.c の表示する文字列を，次のように変更します．

    printf("Hello, C!\n");

    変更後は，保存 → ビルド → 実行をもう一度行ってください． ソースを編集・保存しただけでは，既に作成した実行ファイルは変わりません．

    改行や特殊な文字¶

    特殊な文字を表す記法を エスケープシーケンス と呼びます．

    ソースコード中の記法 表すもの
    \n 改行
    \t 水平タブ
    \" 二重引用符 "
    \\ バックスラッシュ \

    printf で % そのものを表示する場合は，書式文字列内に %% と書きます．これはバックスラッシュによるエスケープとは別の，printf の書式の規則です．

    次の例では，現在の hello.c の内容を一時的に置き換えて動作を確認してください．別の main を持つファイルを，同じプロジェクトに追加しないようにします．

    表示を確かめるコード
     1
 2

    #include <stdio.h>

int main(void)
{
    printf("First line\nSecond line\n");
    printf("She said, \"Hello!\"\n");
    printf("Backslash: \\\n");
    printf("Progress: 100%%\n");
    return 0;
}

    ビルドして実行すると，次の内容を表示します．

    First line
Second line
She said, "Hello!"
Backslash: \

    ソースの改行と，表示の改行は別

    ソースコードを読みやすく改行することと，文字列に \n を入れることは別です． 表示中に改行したい場合は，文字列の中に \n を書きます．2回続けると，間に空行を入れられます．

    Windowsでのバックスラッシュの表示

    フォントやキーボードの設定によっては，バックスラッシュが円記号のように見える場合があります． エスケープに使うのは半角のバックスラッシュです．全角の円記号を入力しないでください．

    6．エラーメッセージを読む¶

    エラーと警告¶

    コンパイラは，コードに問題を見つけると診断メッセージを表示します．

    種類 基本的な扱い
    エラー ビルドに失敗する．原因を直してからやり直す．
    警告 ビルドできる場合でも，問題の可能性がある．内容を読み，原因を確認する．

    例えば，printf の行末のセミコロンを忘れたとします．

    間違いを含むコードの一部
    printf("Hello, world!\n")

    MSVCでは，例えば C2143 という番号と，; がないことを示す構文エラーの説明が表示されます．文面や行番号は環境により異なります． 「エラー一覧」の ファイル・行・説明 を確認し，該当項目をダブルクリックしてコードへ移動します．必要なら「出力」のビルドログも確認してください．

    最初の診断から調べることが大切です．1か所の間違いが，多数の診断につながる場合があります． また，コンパイラが問題に気付いた場所と，実際に直すべき場所が同じとは限りません．示された行の前の行も確認しましょう．

    ビルドに失敗したら，古いプログラムを起動しない

    Visual Studioが「最後に成功したビルドを実行するか」と尋ねる場合は，実行せず，まずエラーを修正してください． 古い .exe が動いても，今編集しているコードが正しくビルドされたとはいえません．

    うまくいかないときの確認順序¶

    状況 確認すること
    空のプロジェクトが見つからない C++によるデスクトップ開発が導入されているか．C++／Windowsで検索しているか．
    Cとして扱われない 拡張子が .c か．コンパイル言語が /TC か．
    main が重複しているというエラー 同じプロジェクトに，別々のmainを持つファイルを追加していないか．
    pch.h などが必要といわれる 空のプロジェクトを選んだか．課題と異なるテンプレートを使っていないか．
    編集した内容が表示されない 保存・ビルドに成功したか．正しいプロジェクト／exeを実行しているか．
    ファイルが見つからない ソリューション エクスプローラーで，対象のプロジェクトにファイルが追加されているか．保存先は正しいか．
    エラーはないが結果が違う 文字列の内容や \n を見直す．ビルド成功だけでは，目的どおりの動作は保証されない．

    7．まとめ¶

    プログラムを作る基本の流れは，編集 → 保存 → ビルド → 実行 → 結果の確認です．

    確認問題¶

    次の問いに，自分の言葉で答えてみましょう．

    • ソースファイルと実行ファイルは，何が違うか．
    • Visual StudioでC言語のファイルを追加するとき，何に注意するか．
    • printf("Hello, world!\n"); の \n と ; は，それぞれ何を表すか．
    • 保存しただけで，既にある実行ファイルの内容は変わるか．
