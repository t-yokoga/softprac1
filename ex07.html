    第7回　演習：入出力¶

    解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

    講義を読んでから取り組んでください．出力と処理の流れを予測しましょう．

    準備と進め方¶

    作業場所はPL1\week07です．第1回と同じ設定（Cとしてコンパイル，C17，警告レベル4）を使います．演習では，プログラムごとに別の空のプロジェクトを作り，次のファイルを1つだけ追加します．設定は「Cとしてコンパイル」「C17」「警告レベル4」です．

    課題・小問 プロジェクト名 ソースファイル
    課題1-1・1-2：複写・改行表示・スラッシュ追加 Echo echo.c
    課題1-3：小文字化フィルタ LowerInput lower_input.c
    課題2-1：英字数 LetterCount letter_count.c
    課題2-2：全入力のバイト数 ByteCount byte_count.c
    課題3-1〜3-3：行の容量 LineInput line.c
    課題4-3：書式の表示 Formats formats.c
    発展：タイピングの採点 Typing typing.c

    各プロジェクトはPL1\week07の下へ保存します．複写プログラムの一時的な変更と，行入力の容量変更は，それぞれ元のプロジェクト内のファイルを編集して試します．別のプログラムへ進むときは新しいプロジェクトを作るので，前のソースを上書きする必要はありません．1つのプロジェクトにmainを持つファイルを複数追加しないでください．

    同じソリューションへ複数のプロジェクトを追加した場合は，実行したいプロジェクトを右クリックして「スタートアッププロジェクトに設定」を選びます．

    保存後にCtrl+Shift+Bでビルドし，成功を確認してCtrl+F5で実行します．

    各課題で，ソース，試した値，予測，実行結果，結果の説明を残してください．提出先や締切は，授業時に案内します．

    今回の課題と入力方法¶

    課題 内容 終了条件
    1 複写・小文字化フィルタ 入力終了（EOF）
    2 1行の英字数と，全入力のバイト数 改行またはEOF／EOF
    3 1行を配列へ読み込む 1行または入力終了
    4 ストリームの接続・書式 読解と固定値の表示
    発展 タイピングの採点 改行またはEOF

    起動したコンソールに英数字を入力してEnterを押します．EOFまで読むプログラムでは，Enterだけでは終了しません．通常のWindowsコンソールで新しい行の先頭からCtrl+Z，続けてEnterを押して入力終了を知らせてください．強制停止すると，最後の集計や表示まで実行されない場合があります．

    記録には，キーボードから入力した文字とプログラムが表示した文字を分けて書きます．コンソールに入力文字が映ることは，printfやputcharで表示したこととは別です．ソースを変更するたびに保存・ビルドしてから再実行しましょう．

    この回の対話入力はASCIIの英数字・空白・記号と改行を対象にします．NULバイトや日本語を含む入力は扱いません．大量の入力を試す必要はなく，各課題の上限を守ります．

    課題1　入力をそのまま出力する¶

    Echoプロジェクトを作り，講義のサンプルecho.cを追加して実行します．この課題では，次の3つの小問を順に行います．

    1. 課題1-1：複写プログラムをそのまま実行し，入力と出力の関係を確かめる．
    2. 課題1-2：複写プログラムを一時的に書き換え，改行やスラッシュを見える形で表示する．
    3. 課題1-3：複写プログラムをもとに，小文字化フィルタを作る．
    ヒント

    入力待ちの間はプログラムは終わっていません．通常のWindowsコンソールでは，新しい行でCtrl+Z，Enterです．

    課題1-1　複写と読み取り順を確かめる¶

    getcharで読む値 EOFとの比較 プログラムの処理
    'a' 等しくない aを出力
    'b' 等しくない bを出力
    'c' 等しくない cを出力
    '\n' 等しくない 改行を出力
    次の入力 到着するまで待つ 終了ではない
    EOF 等しい 本体へ入らず終了

    次の3通りを，それぞれプログラムを起動し直して試します．

    試すこと 操作 予想される出力
    ① 空の入力 起動直後に，何も入力せずCtrl+Z，Enter 何も出力されない
    ② 空行1個 Enterだけを押し，次の行でCtrl+Z，Enter 改行が1個出力される
    ③ 2行の入力 abcとEnter，XYZとEnterを押し，次の行でCtrl+Z，Enter 2行がそのまま出力される

    「空の入力」と「空行1個の入力」は同じではありません．①と②の違いを記録に書いてください．

    課題1-2　改行表示とスラッシュ追加を試す¶

    echo.cにある複写プログラムのうち，whileの中にある次の部分（putcharとその失敗処理）を，一時的に置き換えます．

    if (putchar(ch) == EOF) {
    fprintf(stderr, "output error\n");
    return 1;
}

    置き換えた後のwhileの中身は，次のようになります．

    if (ch == '\n') {
    printf("new line\n");
} else {
    printf("character=%c\n", ch);
}

    abとEnterを入力すると，character=a，character=b，new lineの3行が表示されます．Enterを1回押しただけで3つの文字がまとめて届き，getcharがそれを3回に分けて読んでいることを確かめてください．確かめたら，元のputcharの部分に戻します．

    次に，元のif (putchar(ch) == EOF) { ... }の直前に，putchar('/')を呼ぶ処理を加えます．putchar('/')の戻り値も，putchar(ch)と同じ形でEOFかどうかを確かめてください．実行する前に，abとEnterを入力したときの出力を予測して記録し，その後で実行して比べます．スラッシュは入力の各文字の前に入るので，改行の前にも付く点に注意します．確かめたら，加えた処理を消して元に戻します．

    課題1-3　小文字化フィルタを作る¶

    LowerInputプロジェクトを作り，複写プログラムをlower_input.cへコピーして書き換え，入力をすべて出力し，そのうち英大文字（'A'〜'Z'）だけを小文字に変えて出力するプログラムを作ります．第6回では文字列を配列に入れてから変換しましたが，今回は配列を使わず，getcharで読んだ1文字ずつを変換してputcharで出力します．入力はEOFまで読みます．

    入力 出力
    Hello C17! hello c17!
    AZaz09 azaz09

    英大文字以外（小文字・数字・空白・記号・改行）は変えずにそのまま出力します．EOFは文字ではないので，変換も出力もしません．2行以上入力しても正しく動くことを確かめてください．

    説明すること：次の2点を記録に書いてください．

    • 変換の処理を，EOFかどうかを調べた後に行う理由．
    • 入力全体を配列に保存しなくても変換できる理由．

    課題2　英字の数を数える¶

    この課題は2つの小問からなります．課題2-1は英字の数を数えるプログラムを自分で作り，課題2-2は全入力のバイト数を数えるプログラム（下に掲載）を実行して比べます．

    課題2-1　1行の英字数を数える¶

    課題2-1では，LetterCountプロジェクトにletter_count.cを作り，1行（Enterを押すまで）に含まれる英字（'A'〜'Z'と'a'〜'z'）の個数を数えるプログラムを作ります．改行を読むかEOFになったら読むのをやめ，数えた個数をprintf("%d\n", count);のように1行で表示します．例えばabc 12!なら3，空行なら0，AZazなら4です．この課題の入力は1000バイト以内とします．

    ヒント

    EOFだけでなく改行でもループを止めます．大文字と小文字の2つの範囲を論理演算でつなぎます．

    英字の範囲と停止条件を確かめる¶

    次の表の「期待する数」は，実行する前に自分で予測して記録に書き，その後で実行結果と比べてください．入力ごとにプログラムを起動し直します．

    1行の入力 期待する数 注目点
    abc 12! 記入してください 数字・空白・記号は除く
    空行 記入してください 本体を実行せず改行で終了
    AZaz 記入してください 大文字・小文字の両方を数える
    @AZ[ 記入してください Aの前，Zの後は英字ではない
    123!? 記入してください 英字なし

    このプログラムは，EOFを知らせなくてもEnterを押した時点で個数を表示します．課題1との違いは，ループを続ける条件にch != '\n'が加わることです．条件を&&でつなぐときは，左側が偽なら右側は評価されない（短絡評価）ことを踏まえて，getcharで読む部分とch != '\n'のどちらを左に書くべきかを考えましょう．

    課題2-2　改行も含めた全入力のバイト数¶

    課題2-2では，ByteCountプロジェクトを作り，次のプログラム全体をbyte_count.cへ保存して実行します．このプログラムは改行では止まらず，EOFまで読んで，読み取ったバイト数（改行を含む）を表示します．入力は改行を含めて合計1000バイト以内とします．

    #include <stdio.h>
int main(void)
{
    int count = 0;
    while (getchar() != EOF) {
        ++count;
    }
    if (ferror(stdin)) {
        fprintf(stderr, "input error\n");
        return 1;
    }
    printf("%d\n", count);
    return 0;
}

    課題2-1と同じように，「期待する数」を予測して記録に書いてから実行します．どの入力でも，最後に新しい行の先頭でCtrl+Z，Enterを押して入力を終わりにします．

    入力してからEOF 期待する数
    何も入力しない 記入してください
    Enterだけ 記入してください
    abcdとEnter 記入してください
    abとEnter，CとEnter 記入してください

    ここで数えているのはプログラムが読み取ったバイトで，単語数ではありません．改行も数えます．日本語の見た目の文字数や，改行変換前のファイルサイズを求めるプログラムでもありません．

    説明すること：課題2-1の英字数を数えるプログラムと，課題2-2のバイト数を数えるプログラムのそれぞれについて，「何を数えるか」と「いつ結果を表示するか」を記録に書いてください．

    課題3　行の容量¶

    LineInputプロジェクトを作り，講義のサンプルline.cを追加して実行します．このプログラムは1回の実行で1行だけ読むので，入力ごとに起動し直します．次の5つを入力し，それぞれの結果を記録してください．

    • 空行（Enterだけ）
    • Hello
    • 30個のA
    • 31個のA
    • 32個のA

    課題3-1　3つの長さを区別する¶

    HelloとEnterでは，入力として読むのは本文5文字と改行の6文字です．fgetsはさらに終端を付けて保存するので7要素を使います．例題は改行を終端に置き換えてから，本文の長さ5を表示します．

    本文 最初のfgetsの保存内容 例題の最終結果
    空行 改行＋終端 length=0 text=
    Hello Hello＋改行＋終端 length=5 text=Hello
    Aが30個 A30個＋改行＋終端 length=30 text=の後にAが30個
    Aが31個 A31個＋終端 残った改行をgetcharで読み，length=31 text=の後にAが31個
    Aが32個 A31個＋終端 残ったAをgetcharで見つけ，Line too long.

    31個と32個を用意するときは，エディタなどで個数を確認してからコンソールへ貼り付けてかまいません．個数があいまいなまま結果だけを比較しないでください．初期のText:は入力案内で，length=...はプログラムが読み取り後に出す結果です．

    課題3-2　入力終了だけを知らせた場合¶

    起動後，何も入力せず新しい行でCtrl+Z，Enterを押してください．No line read.と表示されることを確かめ，記録します．Enterだけの空行は正常に読めます．「長さ0の文字列を読み取れた」と「行を読み取れなかった」を区別しましょう．

    課題3-3　容量を小さくして仕組みを見る¶

    LineInputのline.cで，char line[32];をchar line[8];に変えます．それ以外の部分は変更しません．このとき保存できる本文は最大7文字です．ABCDEF（6文字），ABCDEFG（7文字），ABCDEFGH（8文字）をそれぞれ起動し直して入力し，length=6，length=7，Line too long.と表示されることを確かめてください．

    fgetsにはsizeof lineで容量を渡しているので，配列の宣言を変えるだけで，読み込む上限も自動的に変わります．ただし，関数の引数として受け取った配列にsizeofを使っても，元の配列の大きさは得られません（第5回の復習）．

    説明すること：次の3点を記録に書いてください．

    • fgetsで改行まで読めなかったとき，続くgetcharで何を調べているか．
    • 変数extraは何を表すか．行が長すぎなかった場合，extraはどの値のままか．
    • 改行かEOFになるまで，残りを読み捨てるループが必要な理由．

    課題4　接続関係を説明する¶

    この課題は，課題4-1・4-2が接続関係を考える問題，課題4-3がprintfの書式を確かめる実行課題です．課題4-1・4-2はプログラムを実行せず，文章か接続図で答えて記録に書きます．コマンドの操作やファイルの上書きは行いません．

    課題4-1　ストリームの分け方を考える¶

    次の2つのプログラムを考えます．

    • プログラムA：課題1-3で作った小文字化フィルタに，処理の状況を知らせるメッセージをstderrへ出す処理を加えたもの．小文字にしたテキストはstdoutへ出す．

    • プログラムB：課題2-2のように，stdinから読んだバイト数を改行も含めて数え，表示するプログラム．

    • AのstdoutをBのstdinにつなぐと，BはAがstderrへ出したメッセージも数えるか．理由も答えよ．

    • Aがstdoutへ入力案内を出すと，Bの結果にどのような影響があるか．

    課題4-2　リダイレクトの結果を予測する¶

    入力ファイルの内容はABと改行で，プログラムが読み取るのは3バイトとします．AとBは上と同じプログラムです．

    1. 入力ファイルをAのstdinにつなぎ，Aのstdoutを画面につなぐと，何が表示されるか．
    2. 1と同じAのstdoutを，画面ではなく出力ファイルにつなぐと，ファイルには何が書かれるか．
    3. 2の実行を2回行うとき，「2回とも上書き（>）」の場合と，「1回目は上書き（>），2回目は書き足し（>>）」の場合とで，出力ファイルの中身はどう違うか．
    4. AのstdoutをBのstdinにつなぐと，Bは何と表示するか．
    5. Aが処理結果の前に，stdoutへReadyと改行を出すように変えると，4のBの表示はどう変わるか．

    課題4-3　printfの幅と書式を確かめる¶

    Formatsプロジェクトを作り，次のプログラム全体をformats.cへ保存して実行します．このプログラムは入力を待ちません．縦棒で囲むことで，追加された空白を見やすくしています．

    #include <stdio.h>
int main(void)
{
    int n = 3;
    double value = 154.423;
    unsigned int base = 500u;
    long long big = 5000000000LL;
    printf("|%d|%5d|\n", n, n);
    printf("|%f|%.2f|%8.2f|\n", value, value, value);
    printf("|%e|%g|\n", 1.3e10, 1.3e10);
    printf("%u %o %x\n", base, base, base);
    printf("%lld\n", big);
    return 0;
}

    |3|    3|
|154.423000|154.42|  154.42|
|1.300000e+10|1.3e+10|
500 764 1f4
5000000000

    実行して上の出力と同じになることを確かめたら，次の2つを1つずつ試します．それぞれ，実行する前に出力を予測して記録し，実行結果と比べてください．

    1. nの初期値を123456に変える．
    2. baseの初期値を0764uに変え，次に0x1f4uに変える．

    1では，%5dでも6桁すべてが表示されます．表示幅は最小の幅で，上限ではないからです．2では，0764uも0x1f4uも十進数の500と同じ値なので，出力は変わりません．なお，bigの書式を%dに変える実験は行わず，型に合った%lldのままにします．

    説明すること：次の3点を記録に書いてください．

    • %.2fと%8.2fの違い．
    • %fの精度（.2など）と%gの精度の意味の違い．
    • long longの値を表示するとき，%lldのll（長さ修飾子）が必要な理由．

    発展　タイピングの採点¶

    Typingプロジェクトを作り，タイピングの採点プログラムをtyping.cに作ります．お手本の文字列This is a penと，キーボードから入力した1行とを，同じ位置の文字どうしで比べ，一致した文字の数を得点として表示します．

    プログラムが満たすこと（仕様）は次のとおりです．

    • お手本This is a penは，プログラムの中に文字列の配列として用意する．お手本は空白も含めて13文字である．
    • 入力の前に，お手本を示す入力案内をstdoutへ表示する（文言は自由）．
    • 入力をgetcharで1文字ずつ読み，改行を読むかEOFになったら採点を終えて得点を表示する．
    • 入力の1文字目とお手本の1文字目，2文字目と2文字目，…のように同じ位置どうしを比べる．空白も1文字として比べる．
    • 大文字と小文字は区別しない（tとTは一致とみなす）．
    • 14文字目以降の入力は比べず，得点にも加えない．お手本の配列の範囲外を読まないように，位置が13未満かどうかを先に調べてから，お手本の文字を読む．
    • 入力は1行1000バイト以内とする．

    完成したら，次の入力で確かめます．入力ごとにプログラムを起動し直してください．

    確認すること 入力 得点
    空行 Enterだけ 0
    完全に一致 This is a pen 13
    途中まで入力 This 4
    同じ位置だけを比べる Txxxxxxxxxp 2
    大文字・小文字を区別しない thiS is a Pen 13
    14文字目以降は加点しない This is a pen! 13
    一致なし xxxxxxxxxxxxx 0

    文字が抜けたり余分に入ったりしても，位置を合わせ直す処理はしません．例えばThi is a penはsが1文字抜けているので，4文字目以降が1つずつずれ，最初のThiだけが一致して3点になります．

    ヒント

    入力の位置positionと得点scoreを別々の変数で管理します．1文字読むたびにpositionは1進みますが，scoreは一致したときだけ1増えます．大文字・小文字を区別せずに比べるには，入力の文字とお手本の文字の両方を，課題1-3と同じ方法で小文字に変えてから比べます．入力の文字はgetcharの値をintで受け取り，EOFでないことを確かめてから小文字に変えます．

    大文字・小文字を区別する版を試したいときは，比較をch == target[position]に変えます（chは入力の文字，targetはお手本の配列）．

    考えること：このプログラムは，人が画面を見ながら使うことを想定しているので，入力案内をstdoutに表示しています．得点だけを別のプログラムにパイプで渡したい場合，どこを変える必要があるかを，課題4と関連付けて考え，記録に書いてください．

    確認問題¶

    1. getcharの戻り値をcharへ先に保存しないのはなぜか．
    2. '0'，'\0'，'\n'，EOFの役割はそれぞれ何か．
    3. abcdとEnterは，getcharで何回の読み取りに対応するか．
    4. getcharを1回呼ぶと，入力した112は整数112になるか．
    5. fgetsの戻り値を確認する前にstrlenを使ってはいけないのはなぜか．
    6. char line[32]に保存できる本文の最大長は，この例題では何バイトか．
    7. printfでdoubleを表示するときと，scanfでdoubleへ読み込むときの書式は何か．
    8. パイプへ接続されるのは通常どの出力か．stderrはどう扱われるか．

    チェックリスト¶

    • 正常な値だけでなく，課題に示された境界の値でも確認した．
    • 警告を確認し，原因を説明・修正した．
    • 自分の言葉で，処理の流れと使った型を説明できる．
    • Enterによる改行，EOFによる終了，強制停止を区別できる．
    • 入力文字の表示と，プログラム自身の出力を区別して記録した．
    • 本文の長さ，改行，終端のための容量を別々に数えた．
