    第10回　演習：ファイル¶

    解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

    講義を読んでから取り組んでください．出力と処理の流れを予測しましょう．

    準備と進め方¶

    作業場所は PL1\week10 です．第1回と同じ設定（Cとしてコンパイル，C17，警告レベル4）で，課題ごとに別の空のプロジェクトを作ります．特に指定がなければ，mainを持つソースは1プロジェクトに1つです．保存後にCtrl+Shift+Bでビルドし，Ctrl+F5で実行します．

    各課題で，ソース，試した値，予測，実行結果，結果の説明を残してください．提出先や締切は，授業時に案内します．

    作業フォルダを分ける¶

    すべてのプロジェクトで作業ディレクトリを$(ProjectDir)にします．ファイルへ書く課題は，そのプロジェクトの練習用フォルダだけで実行してください．別の資料や元のデータを出力先に指定しません．ソースに書いたファイル名と，エクスプローラーで確認するファイル名を照合します．

    課題 主な内容 作成・使用するファイル
    1 文字・行単位で読む input.txt
    2 数値引数と文字列引数 ファイルは不要
    3 バイト列を保存する bytes.binを上書き
    4 テキストを書く・追記する scores.txtを上書き，追記
    発展1 同じ数値を2形式で往復 numbers.txt，numbers.binを上書き
    発展2 二乗の一覧を書いて検索 新しいsquares.txtを作成

    ファイルの上書きはプログラムを実行した時点で起きます．ビルドしただけでは起きません．既にある出力ファイルが前回の結果なのか，今回の結果なのか，更新日時や内容を確認してください．失敗時にできた途中までのファイルを，完成した結果として扱わないようにします．

    課題1　ファイルを読む¶

    ReadText プロジェクトでread_text.cを使います．講義の設定でinput.txtを引数にし，次の2行を入れたファイルを読んでください．

    Hello
File

    空ファイル，最後に改行のないファイル，存在しない名前，引数なしでも試します．

    保存場所を確認する¶

    input.txtはASCII文字だけを使い，UTF-8のBOMなしで保存します．エディタで作成したら，.vcxprojのあるフォルダへ保存してください．拡張子を非表示にしている場合はinput.txt.txtとなっていないか，ファイルのプロパティでも確認します．

    入力を表示するプログラムの実行には「コマンド引数」欄へinput.txtだけを書きます．ReadText.exeという名前は付けません．引数を変えてもソースは変更しません．

    試す条件 期待する結果 理由
    HelloとFileの2行 記入してください 1文字ずつ最後まで読む
    空ファイル 記入してください EOFは必ずしもエラーではない
    最後のFileの後に改行なし 記入してください 改行を前提にしていない
    missing.txt 記入してください 存在しないファイルはrで作られない
    引数欄を空にする 記入してください ファイル名を受け取れない
    引数欄を""にする 記入してください 空のファイル名を拒否する

    空白を含むファイル名¶

    input.txtをコピーしてmy input.txtという練習ファイルを作ります．引数欄を"my input.txt"とすると1個のファイル名として渡せます．引用符なしのmy input.txtは2個の追加引数なので，このプログラムは引数の個数が違うと判断します．

    うまくいかない場合は，まず短いinput.txtに戻して動作を確認します．同時に内容・名前・作業ディレクトリのすべてを変えると，どれが原因だったか分からなくなります．

    行の長さを表示する¶

    別のLineLengthsプロジェクトで講義のline_lengths.cを使います．引数欄へinput.txtを指定し，同じ入力を読ませてください．HelloとFileなら5，4と表示されます．

    入力の1行 改行の有無 期待する長さ
    ABC あり 記入してください
    ABC なし 記入してください
    空行 あり 記入してください
    Aを31個 あり・なし 記入してください
    Aを32個 あり・なし 記入してください

    空ファイルは長さ0の行があるのではなく，行がないため出力しません．31文字で改行がない場合も，1文字を追加で調べてEOFを確認できます．32文字の行を2行として数えないことを確認してください．入力の上限を超えた後は処理を続けず，閉じて終了する仕様です．

    説明すること：strlen(line)から常に1を引くと，改行のないABCの長さが2になってしまいます．改行を実際に読み取ったかどうかを調べる必要があります．

    課題2　数値引数の検査¶

    ParseNumber プロジェクトでparse_number.cを使います．「コマンド引数」を42，0，100，101，-1，12x，非常に長い整数に順に変更してください．

    ヒント

    起動ごとに引数を変えます．文字列は必ず数値として正しいとは限りません．

    境界と文字列の形を確かめる¶

    引数欄 期待する結果 注目点
    0 記入してください 下限を含む
    100 記入してください 上限を含む
    +42 記入してください 先頭の符号は許す
    " 42" 記入してください 先頭の空白はstrtolが読み飛ばす
    "42 " 記入してください 末尾の空白はこのコードでは拒否
    12x 記入してください 途中までの12だけで成功にしない
    abc 記入してください 数字を読めない
    42 50 記入してください 引数が多すぎる

    極端に長い整数は999999999999999999999999999999などを使います．Windowsと他の環境でlongのサイズが同じとは限らないので，「10桁なら必ず範囲外」のようには判断しません．

    複数の数値を合計するなら¶

    parse_number.cを基に，追加引数を最大10個，各数値を0〜100とする合計を考えてください．合計は最大1000なので，この条件では範囲内です．配列を作らず，1つ変換するたびにlongの合計へ加えられます．mainの検査・変換部分を次の断片へ置き換えます．必要なヘッダは元のままです．

    if (argc < 2 || argc > 11) {
    fprintf(stderr, "expected 1 to 10 integers\n");
    return 1;
}
long total = 0;
for (int i = 1; i < argc; ++i) {
    char *end;
    errno = 0;
    long value = strtol(argv[i], &end, 10);
    if (end == argv[i] || *end != '\0' || errno == ERANGE ||
        value < 0 || value > 100) {
        fprintf(stderr, "invalid integer\n");
        return 1;
    }
    total += value;
}
printf("%ld\n", total);

    12 23 34なら69，0 100なら100です．12 x 34なら合計を表示せず失敗します．元の最後のprintfでvalueを表示する部分は残さず，この断片の後はreturn 0;で終了します．

    引数を表示して文字列を探す¶

    Argumentsプロジェクトでは数値変換をせず，受け取った文字列を表示します．toyama，ishikawa，fukuiのどれかがあれば，最後にhokuriku!を1回だけ表示します．

    引数欄をnagano ishikawaにするとarg1=nagano，arg2=ishikawa，hokuriku!の3行です．fukui ishikawaでもhokuriku!は1回だけです．引数なしなら何も表示しません．大文字を含むToyamaはtoyamaと一致しません．文字列の比較で==を使わない理由も説明してください．

    課題3　バイト列を保存する¶

    Binary プロジェクトでbinary.cを使います．専用のプロジェクトフォルダを作業ディレクトリにし，bytes.binが4バイトになることをエクスプローラーのプロパティで確認してください．繰り返し実行すると同名ファイルを上書きします．

    読み取った個数だけを使う¶

    bufferは16要素ですが，4バイトの入力を読んだ後に使用できるデータは最初の4個です．残り12個を表示してはいけません．nの値が4であることをprintfで追加表示して確かめても構いません．size=1なので，この例では戻り値がバイト数と一致します．

    ファイルが16バイトより大きければ，1回のfreadでは全部読めません．このサンプルのdataをむやみに増やさず，今回は4〜5バイトに限定します．同じ関数名でも「ファイル全体を読み終えた」とは限りません．

    UTF-8をバイトとして観察する¶

    dataを次の4バイトに置き換えます．この例はソースに日本語を直接書かずに，UTF-8の「あ」とLFを表します．

    const unsigned char data[] = {0xE3, 0x81, 0x82, 0x0A};

    表示はE3 81 82 0A，保存されたファイルは4バイトです．画面上で「あ」と表示できるかどうかではなく，読み書きしたバイトが一致することを確認します．UTF-8のBOMを付けるなら先頭にEF BB BFが増えますが，この課題の形式には付けません．

    バイト順を調べる¶

    講義のunsigned shortの観察用断片を別のmainで実行します．まずsizeof valueを%zuで表示し，次に1バイトずつの16進数を見ます．通常のVisual Studio x64ではサイズ2，値1は01 00です．値を0x1234へ変更すると34 12になります．

    先のバイトが0x34だからといって，数値が0x3412に変わったわけではありません．メモリへ保存する順序の違いです．1バイトを2進数表示する場合は，次の断片で00000001を確認できます．

    unsigned char byte = 1;
for (int bit = 7; bit >= 0; --bit) {
    putchar((byte & (1u << bit)) != 0 ? '1' : '0');
}
putchar('\n');

    課題4　テキストを書き出す¶

    WriteText プロジェクトで，scores.txtへ72，85，60を1行ずつ書きます．出力先は練習用フォルダです．

    作成したファイルを課題1で読み返してください．Windowsの改行変換があるため，バイナリで保存した場合とバイト数が異なることがあります．

    上書きと追記を比較する¶

    最初はwで実行します．3行のscores.txtを確認したら，同じ条件でもう1回実行します．再び同じ3行になり，6行にはなりません．開く時点で以前の内容を消すためです．

    次に，fopenのモードだけをaへ変えます．既に3行ある状態で1回実行すると，その後ろに72，85，60の3行が加わり，6行になります．もう1回実行すれば9行です．ファイルがない場合，aは新しく作ります．この実験はscores.txtだけを対象にしてください．

    モード 実行前に3行ある場合 注意
    w 今回の3行だけになる 以前の内容を消す
    a 以前の3行と今回の3行で6行 繰り返すたびに増える
    wx 開くのに失敗 既存ファイルを保護する

    wxは「新しいファイルだけを作る」指定です．発展課題では，指定された出力名を誤って上書きしないために使います．失敗しても自動でwへ変更せず，別の未使用ファイル名を指定します．

    説明すること：fprintfが成功していても，なぜfcloseの戻り値を調べるのでしょうか．メモリ上に保留していた出力が，閉じる際に書き込まれて失敗する可能性があるためです．

    発展1　数値をテキスト・バイナリで往復する¶

    NumberFormatsプロジェクトでは，3つのdoubleを両方の形式で保存して読み戻します．numbers.txtとnumbers.binだけを作る練習用フォルダで実行してください．毎回上書きするので，入力として別のファイルを指定する課題ではありません．

    テキストは最初の行に3，次の3行に数値を書きます．バイナリは1バイトの個数3に続けて，doubleを3個保存します．バイナリ側は同じ処理系での読み戻し専用です．

    text=0.50 1.25 -2.00
binary=0.50 1.25 -2.00

    サイズと精度の見方¶

    numbers.binは1 + 3 * sizeof(double)バイトです．通常のVisual Studioでdoubleが8バイトなら25バイトです．numbers.txtは文字数と改行方式で変わります．この例のWindowsの通常のCRLFでは22バイト，LFでは18バイトとなり，小さな例ではテキストの方が小さくなります．

    data[0]を0.125にし，最後の2行の表示書式だけ%.3fへ変えてください．保存の書式は%.2fのままにします．テキスト側は小数点以下2桁へ丸められるので0.125とは一致せず，バイナリ側は0.125を保ちます．丸めの境界でどちら側になるかより，保存時に桁が失われた点に注目します．

    ここでのfscanfは，この実行で自分が生成した小さな数値を読むためのものです．任意の外部ファイルに対する厳密な検査器ではありません．入力を自動作成する部分を外して利用するなら，数値の範囲，余分なデータ，バイト表現の妥当性なども検証する必要があります．外部テキストの検査例は次の課題を参照してください．

    大量データで時間を測る場合，画面への出力，ディスクのキャッシュ，測定回数が結果へ影響します．この小さな課題の実行時間だけで一般的な速度差を結論付けません．

    発展2　二乗の一覧を書き出して検索する¶

    2つのプログラムを別プロジェクトで作ります．第1のプログラムは個数Nと新しいファイル名，第2はそのファイル名と検索する整数を引数にします．Nは0〜100，検索値と保存する値は0〜9801に限定します．99の二乗が9801なので，この条件では計算のオーバーフローを避けられます．

    書く側：WriteSquares¶

    引数欄を4 squares.txtにします．出力先が既にあれば失敗するwxを使います．再実行するときはsquares2.txtなど未使用の名前を指定してください．

    正常終了したらファイルを開き，4，0，1，4，9の5行になっていることを確認します．N=0なら最初の0の行だけです．N=100ならヘッダを含めて101行で，最後は9801になります．

    読む側：CheckValue¶

    作業ディレクトリはこのプロジェクト自身のフォルダです．WriteSquaresで作ったsquares.txtをここへコピーしてから，引数欄へsquares.txt 9と入力します．同じ相対パスでも，プロジェクトが違えば探す場所が変わることに注意してください．

    ファイルの形式はASCII・NULなし・1行1整数・各行30バイト以内とします．値の前後の空白は許しますが，空行，個数不足，余分な行，範囲外の値は拒否します．最後の行に改行がなくても受け付けます．

    9ならfound，12ならnot foundです．個数を先に読んでも，その個数の行が本当にあるかは別に確認します．見つかった直後にreturnせず，後続の行も検証してから結果を表示しています．

    このプログラムは保存された数列から値を検索するものです．各値が本当に0，1，4，9という順の二乗になっているかまでは検査しません．例えばN=2で5，6を持つ正しい形式のファイルも受け付けます．「ファイル形式の検査」と「値が特定の計算結果かの検査」を区別します．

    異常なデータも別ファイルで確認する¶

    正常なsquares.txtは残し，コピーへ変更を加えてbad.txtなどの名前で試してください．

    変更 期待する結果
    ヘッダを4のまま最後の9を削除 記入してください
    値の1行をabcへ変更 記入してください
    値の1行を99999へ変更 記入してください
    最後に余分な数値や空行を追加 記入してください
    ヘッダを101へ変更 記入してください
    正常な最終行の改行だけ削除 記入してください
    ファイル全体を空にする 記入してください

    read_valueが失敗したときは，その呼び出しで得られなかった値を読みません．数値を集めるだけなら固定長配列に保存する方法もありますが，検索だけなら1個ずつ比較できるため，本課題では全体を配列に保存していません．

    確認問題¶

    1. ファイルを開くことに失敗した後，fclose(NULL)で後始末してよいか．
    2. 最後に改行がない行の長さを，strlenから必ず1を引いて求めてよいか．
    3. argcが正しくても引数の内容を調べる理由は何か．
    4. freadの戻り値3は，必ず3バイト読んだという意味か．
    5. ファイルの拡張子を変えるとテキストとバイナリが変換されるか．
    6. UTF-8の「あ」のバイト数と見た目の文字数は同じか．
    7. 読んだ個数をそのまま配列の長さとして信用してよいか．
    8. 値を見つけても，CheckValueが最後まで読むのはなぜか．

    チェックリスト¶

    • 正常な値だけでなく，課題に示された境界の値でも確認した．
    • 警告を確認し，原因を説明・修正した．
    • 自分の言葉で，処理の流れと使った型を説明できる．
