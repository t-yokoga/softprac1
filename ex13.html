    第13回　演習：メモリ管理¶

    解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

    講義を読んでから取り組んでください．出力と処理の流れを予測しましょう．

    準備と進め方¶

    作業場所は PL1\week13 です．第1回と同じ設定（Cとしてコンパイル，C17，警告レベル4）で，課題ごとに別の空のプロジェクトを作ります．特に指定がなければ，mainを持つソースは1プロジェクトに1つです．保存後にCtrl+Shift+Bでビルドし，Ctrl+F5で実行します．

    各課題で，ソース，試した値，予測，実行結果，結果の説明を残してください．提出先や締切は，授業時に案内します．

    基本課題1〜4では，確保・初期化・利用・解放を追跡します．発展課題ではcallocとrealloc，静的記憶期間，第12回から続く不透明な構造体を扱います．

    プロジェクト 使用するソース 主な確認
    Dynamic 講義のdynamic.c 入力検査，必要量の確保，逆順
    NewPoint 課題3の1ファイル 所有権の移動，複合リテラル，失敗時の分岐
    GrowArray 発展1の1ファイル callocとrealloc，保持部分と追加部分
    StorageCount 発展2の1ファイル 自動変数とstatic変数
    DynamicVector 講義のvector_main.c，vector.c，vector.h 分割，途中失敗，解放API

    課題4の誤ったコードは実行しません．課題3以降の失敗試験も，巨大な領域を要求するのではなく，確保関数の戻り値を試験用に変えて行います．

    課題1　動的配列¶

    Dynamic プロジェクトでdynamic.cを実行します．起動引数1，5，1000で確認し，0，-1，1001，abc，引数なしを拒否することを確かめます．

    準備と予測¶

    Visual Studioの「プロパティ → 構成プロパティ → デバッグ → コマンド引数」で個数を設定します．引数には実行ファイル名を含めず，まず5だけを入力します．設定対象の構成が，実行するDebug/x64等の構成と一致していることを確かめてください．

    実行前に，ソース内へ次の6つの役割を示すコメントを付けます．コメントによって処理の順番が読み取れるようにしてください．

    1. 引数の個数と数値を調べる．
    2. 有効な要素数へ変換する．
    3. 必要バイト数を表せるかを調べる．
    4. 領域を確保し，失敗なら要素を使わず終了する．
    5. 値を書き込んでから合計を計算する．
    6. 使い終わった領域を解放する．

    検証表¶

    引数 結果の予測 確認する点
    1 記入してください 最小個数
    5 記入してください 通常値
    1000 記入してください 上限
    0，-1，1001 記入してください 確保前に終了
    abc，3x，空引数"" 記入してください 未変換・余計な文字
    999999999999999999999999 記入してください strtolのERANGE
    指定なし，5 6 記入してください 引数の不足・過剰

    エラー時には正常時の合計が表示されないことも確認します．「何も表示されずに落ちた」と「診断を出して意図的に終了した」は別です．

    確保量を説明する¶

    n=5のとき，sizeof *valuesが4であると仮定すると必要量は20バイトです．実際のsizeof *valuesを%zuで表示して確認してもかまいません．sizeof valuesが同じ値になるとは限らないことを説明してください．

    ポインタと配列を混同しない

    valuesの型はint *です．ポインタ自身のsizeofを何で割っても，mallocへ渡した個数は復元できません．nを保持すること自体が配列を安全に使うための情報管理です．診断の追加ではアドレスは%pと(void *)values，サイズは%zuを使い，環境依存の数値を固定の正解にしません．

    追跡表を作る¶

    n=3で，各反復のi，代入後のvalues[i]，加算後のsumを書き出します．最後の要素の添字は3ではなく2です．なぜi <= nではなくi < nなのかを，確保した領域の図で説明してください．

    課題2　配列を逆順にする¶

    課題1の配列の初期化後，freeより前に逆順に並べ替える処理を追加します．n=5なら5 4 3 2 1です．1，2，5で確認してください．

    ヒント

    先頭と末尾から組にし，半分まで交換します．

    sumやmeanは順序を変えても変わりません．奇数個の中央要素を交換しなくてよい理由を説明します．

    変更する場所¶

    初期化と集計のループを終え，sumとmeanを表示した後，free(values)より前に自分で作成した逆順処理を追加します．mallocする回数は増やさず，確保した同じ領域を使って並べ替えます．

    n 交換する添字の組 表示される逆順
    1 記入してください 記入してください
    2 記入してください 記入してください
    5 記入してください 記入してください

    考察¶

    • n/2が整数の除算であることは，反復回数にどう影響するか．
    • 全要素について交換すると，なぜ元の順序へ戻るか．
    • 作業用のtempにfreeが不要なのはなぜか．
    • 逆順後もvaluesが確保領域の先頭を指していることは，解放にどう役立つか．

    追加：独立したコピー¶

    元の配列を残したい場合は，別の領域を確保してコピーする必要があります．int *copy = values;ではポインタをコピーするだけなので，copyを通して逆順にすると元の配列も変わります．

    初期化後に別のint配列copyを動的確保し，要素をコピーする処理を自分で作成してください．copyだけを逆順にし，両方を表示します．確保失敗時には先に確保していたvaluesを解放して終了し，成功時は最後に両方の領域を解放します．この課題ではnのサイズ検査はすでに済んでいます．

    課題3　構造体を確保する関数¶

    NewPoint プロジェクトでPointを動的確保して返す関数を作ります．成功時の所有者は呼び出し元です．

    Pointはdouble型のxとyを持つ構造体とします．Point *new_point(double x, double y)を実装し，mainで(3.0, 4.0)を生成してください．確保失敗を検査し，成功時だけ両メンバを表示して解放します．stdio.hとstdlib.hを取り込みます．

    実行前に結果を予測し，実行後に結果とその理由を記録してください．

    関数の契約を書く¶

    new_pointの前へ，「成功なら初期化済みのPointを返し，呼び出し元がfreeする．失敗ならNULLを返す」というコメントを追加してください．関数名だけから解放責任を推測させないことが大切です．

    場面 new_point内のp 動的なPoint本体
    確保成功直後 本体を指す 初期化前
    メンバへの代入後 本体を指す x，yが有効
    return後 局所変数としての寿命は終了 呼び出し元のpから使える
    mainのfree後 関数はすでに終了 寿命が終了し，再参照しない

    複合リテラルで初期化する¶

    p->x = x; p->y = y;の2文を，*p = (Point){.x = x, .y = y};へ置き換えても同じ出力になることを確認してください．NULL判定は削除しません．左辺をpにしてしまうと，ポインタに構造体を代入する型の誤りになります．

    値を(0,0)，(−2,5)へ変更して，すべてのメンバが初期化されることを確認します．この例では構造体内にさらに動的なメンバがないため，Point本体へのfreeだけで後始末が終わります．

    失敗を模擬する¶

    実際のメモリ不足を起こす代わりに，試験用の小さな関数をnew_pointより前へ追加します．正常版を残した別プロジェクトかコピーで行い，完了したら試験設定を戻してください．

    static void *point_allocate(size_t bytes)
{
    const int simulate_failure = 0;
    if (simulate_failure) {
        return NULL;
    }
    return malloc(bytes);
}

    new_pointのmalloc呼び出しだけをpoint_allocate(sizeof *p)へ変更します．simulate_failure=0なら正常出力，1ならallocation failedという診断で終了するはずです．エラーを出した後でp->xへアクセスしないことを，ソースとステップ実行の両方で確認します．

    この関数はerrnoを設定しません．NULLを見て失敗を判定できることが重要です．本物のmallocの資源管理やOSの診断まで模擬したわけではありません．

    戻り方を比較する¶

    Pointを値として返す，呼び出し元のPoint *へ書き込む，mallocしたPoint *を返す，という3つの方法を比較してください．1個の小さなPointを作るだけなら動的確保が必須ではありません．必要な寿命，失敗の可能性，解放責任が違います．

    課題4　コードレビュー¶

    次は実行せず，問題を指摘してください．aはmallocで確保に成功したポインタとします．

    int *b = a;
free(a);
a = NULL;
printf("%d\n", b[0]);
free(b);

    追加のレビュー¶

    以下も実行せずに，「問題が起きる理由」と「安全な順序」を説明してください．各例は独立しており，必要な宣言はあるものとします．

    断片 調べる観点
    int *p; free(p); pにどの値が入っているか
    int a[3]; free(a); 誰が確保した領域か
    free(values + 1); 確保した領域の先頭か
    p = malloc(3 * sizeof *p); p = NULL; 確保成功後の解放手段が残るか
    p = realloc(p, bytes); 失敗時に元の領域を指せるか
    free(buffer); free(buffer->data); 後のメンバ参照は有効か
    malloc(n * sizeof p) p自身と要素のどちらの大きさか

    所有者を図にする¶

    「mainが配列を確保し，表示関数が借りて表示し，mainが解放する」場合を矢印で描きます．次に「生成関数が確保し，mainへ所有権を渡す」場合を描きます．関数に渡しただけで自動的に解放責任が移るわけではないことを説明してください．

    レビューで確認する順序

    まず各malloc/calloc/reallocの成功で生きている領域を数えます．次にすべてのreturnや失敗分岐をたどり，誰が解放するかを確認します．最後に別名ポインタが残る場所と，解放・再確保後の参照を探します．正常入力で1回動いただけでは，これらの不具合をすべて見つけることはできません．

    発展1　callocとreallocで配列を拡張する¶

    GrowArrayプロジェクトを作ります．最初の3要素をcallocし，0であることを確認してから1，2，3を代入します．その後5要素へ拡張し，増えた要素を4，5で初期化します．

    仕様¶

    • calloc・reallocの両方で失敗を検査する．
    • reallocの前に新しい個数とバイト数を検査する．
    • 失敗時は元の領域を解放して終了する．
    • 成功時は返されたポインタだけを以後使用する．
    • 新しい部分は読む前に代入する．
    • 今回の個数は1〜1000に制限する．
    実装前に考える

    old_nは元の個数，new_nは変更後の個数です．reallocが成功するまでは，元の領域を管理しているpを上書きしません．初期化が必要なのはold_nからnew_n−1までです．縮小した場合には増分がないので，そのループは実行されません．

    境界を調べる¶

    old_n new_n 確認すること
    3 5 先頭3要素を保持し，2要素を初期化
    3 3 同じ個数でも成功後は返されたポインタを使用
    3 1 先頭の1だけが有効
    1 4 1を保持し，2，3，4を追加
    3 0 確保済み領域を解放してエラー終了
    0 5 最初の確保前にエラー終了
    3 1001 上限違反で，元の領域を解放して終了

    realloc後のp[3]が，拡張時と縮小時でどう違うかを説明してください．new_n=1でp[3]を読んで確かめてはいけません．

    reallocの失敗を模擬する¶

    次の関数をmainより前へ追加し，reallocの呼び出しをtry_resizeへ置き換えます．課題3の失敗模擬と同じ考え方ですが，失敗したとき元の領域が残る点が違います．

    static void *try_resize(void *old, size_t bytes)
{
    const int simulate_failure = 1;
    if (simulate_failure) {
        return NULL;
    }
    return realloc(old, bytes);
}

    NULL分岐でfreeする直前に，p[0]を表示すれば1のままであることを確認できます．この参照は再確保が失敗した経路だけで行います．試験後は元の関数呼び出しへ戻してください．

    発展3　不透明なVectorの生成と解放¶

    講義8の3ファイルをDynamicVectorへ保存します．この課題ではvector_main.cとvector.cの両方を同じプロジェクトへ追加します．第12回の同名ファイルとは内容が異なるため，コピー先のフォルダを分けてください．

    正常時の流れ¶

    1. headerには構造体のメンバがないことを確認する．
    2. 2x+yを手計算し，出力result=5.0 8.0を予測する．
    3. x，y，resultについて，生成した関数と解放した場所を対応させる．
    4. vector_destroyに渡すのがxではなく&xである理由を説明する．
    5. 解放後のx，y，resultがNULLになることを，変数ウォッチで確認する．メンバの参照はしない．

    途中で失敗した場合¶

    vector.cのvector_createで使用するmallocを，次の試験用関数へ置き換えます．関数はvector_createより前に追加します．番号を0，1，2，3に変え，それぞれ新しく実行します．

    static void *vector_allocate(size_t bytes)
{
    static int calls = 0;
    const int fail_on_call = 2;
    ++calls;
    if (calls == fail_on_call) {
        return NULL;
    }
    return malloc(bytes);
}
    fail_on_call 確保できる領域 後始末の予測
    0 記入してください 記入してください
    1 記入してください 記入してください
    2 記入してください 記入してください
    3 記入してください 記入してください

    fail_on_call=0はこの3回の呼び出しで失敗させない設定です．OSの空きメモリが十分な通常の実行を前提とします．試験関数のstatic変数は実行中の呼び出し回数を保持しますが，プログラムを起動し直せば初期状態から始まります．

    デバッガで見る場所

    cleanupの行とvector_destroyにブレークポイントを置きます．Vector **pを受けた関数の*pがNULLか，有効な所有対象かを確認します．解放した本体へウォッチからアクセスし続けないでください．最後まで進んだ後，正常版の呼び出しへ戻してビルドします．

    添字と保存先の検査¶

    正常版で，resultが有効な間に次の断片を追加します．0と1は有効な添字，2は範囲外です．outの初期値99が失敗時に保たれることを確認します．

    double out = 99.0;
int ok = vector_get(result, 2, &out);
printf("ok=%d out=%.1f\n", ok, out);

    実行前に結果を予測し，実行後に結果とその理由を記録してください．

    二重ポインタの意味¶

    すべての後始末の後，さらにvector_destroy(&x);を呼んでも，xはNULLなので何もしません．ただし，解放前に別のポインタへxをコピーしていた場合，そのコピーは自動ではNULLになりません．このAPIはすべての二重解放を防ぐ魔法ではないことを説明してください．

    さらに考える：動的なメンバ¶

    Vectorの配列メンバは本体に含まれるので，この例は本体へのfreeで完了します．もしdouble *v;へ変え，vの配列も別に確保したなら，生成の途中失敗と解放順に何を追加する必要があるでしょうか．

    確認問題¶

    1. ポインタ変数が局所変数なら，指す領域も必ずスタックにあるか．
    2. callocした整数配列とmallocした整数配列を，代入前に同じように表示してよいか．
    3. freeの後にp=NULLとしたら，q=pで以前に作った別名もNULLになるか．
    4. realloc失敗後の元の配列と，成功後の古い要素ポインタは同じ扱いか．
    5. 動的な配列を含む構造体の本体だけをfreeすれば，配列も自動で解放されるか．
    6. エラー処理があることを確認するのに，実際にメモリを使い切る必要があるか．

    チェックリスト¶

    • 正常な値だけでなく，課題に示された境界の値でも確認した．
    • 警告を確認し，原因を説明・修正した．
    • 自分の言葉で，処理の流れと使った型を説明できる．
    • 確保した各領域の所有者を1つに決め，途中失敗の経路でも解放した．
    • ポインタのsizeofと要素のsizeofを区別し，積を計算する前に検査した．
    • realloc成功後には古い参照を使わず，追加部分を初期化した．
    • 未初期化領域の読み取り，解放後の使用，巨大な確保実験を行っていない．
    • 試験用の失敗設定を戻し，最後に正常版のビルド・実行を確認した．
