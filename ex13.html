    第13回　演習：メモリ管理¶

    解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

    講義を読んでから取り組んでください．

    準備と進め方¶

    作業場所はPL1\week13です．第1回と同じ設定（Cとしてコンパイル，C17，警告レベル4）を使います．演習では，課題ごとに別の空のプロジェクトを作り，次のファイルを追加します．

    課題・小問 プロジェクト名 ソースファイル
    課題1-1〜1-3：動的配列 DynamicArray dynamic_array.c
    課題2：構造体を確保する関数 NewPoint new_point.c
    発展1：callocとrealloc GrowArray grow_array.c
    発展2：static変数の寿命 StorageCount storage_count.c
    発展3：不透明なVector DynamicVector vector_check.c（講義のvector.hとvector.cも追加する）

    各プロジェクトはPL1\week13の下へ保存します．1つのプロジェクトにmainを持つファイルを複数追加しないでください．発展3では，講義のvector.hとvector.cを変更せずにプロジェクトへ追加し，mainを持つファイルは自分で作るvector_check.cだけにします．講義のvector_main.cは追加しません．第12回の同名ファイルとは内容が異なるため，コピー先のフォルダを分けてください．

    同じソリューションへ複数のプロジェクトを追加した場合は，実行したいプロジェクトを右クリックして「スタートアッププロジェクトに設定」を選びます．

    保存後にCtrl+Shift+Bでビルドし，成功を確認してCtrl+F5で実行します．

    提出するのは，上の表の5つのソースファイルです．発展3で提出するのはvector_check.cだけです．成績はソースファイルで評価します．提出先や締切は，授業時に案内します．

    今回の課題¶

    課題 内容 確認すること
    1 動的配列，逆順，独立したコピー 個数の検査，mallocとfree，所有権
    2 構造体を確保する関数 呼び出し元への所有権の移動，失敗時の分岐

    ソースの書き方¶

    • 課題に示した場合は，すべてmainから呼び出して表示します．値を書き換えて実行し直すのではなく，1回の実行ですべての結果が表示されるようにします．
    • 小問のある課題は，同じファイルへ小問の順に書き足します．前の小問で作った関数や表示は消さずに残します．
    • 関数の名前，引数，戻り値の型は，課題の指定どおりにします．
    • 表示は，課題に示した出力と同じにします．確保の失敗を表すallocation failedなども，標準出力へ表示します．

    今回のプログラムはどれも入力を待たず，起動引数も使いません．実行するとすぐに結果を表示して終了します．

    確保関数の戻り値は必ずNULLと比べてから使います．確保に成功した領域は，どの経路でもちょうど1回freeします．解放後の領域へのアクセス，二重解放，確保していない領域のfree，未初期化の要素の読み取りは，ソースに書きません．確保の失敗を試すために巨大な領域を要求することもしません．失敗の経路は，課題で指定する引数を使って通します．

    課題1　動的配列¶

    DynamicArrayプロジェクトにdynamic_array.cを作ります．この課題では，次の3つの小問を順に行い，同じファイルへ書き足します．

    1. 課題1-1：実行時に決めた個数の配列を確保し，合計と平均を表示する．
    2. 課題1-2：確保した配列を逆順に並べ替える．
    3. 課題1-3：配列の独立したコピーを作る．

    課題1-1　1からnまでの配列を作る¶

    1からnまでの整数を入れた配列をmallocで確保して返す関数を使うプログラムを作成し，5通りの個数で，合計と平均，範囲外の個数を確保前に拒否することを確認してください．

    プログラムが満たすこと（仕様）は次のとおりです．

    • 必要な標準ヘッダ（stdio.h，stdlib.h，stdint.h）をインクルードする．
    • 関数int *make_sequence(size_t n)を作る．nは1以上とする．n要素のint配列をmallocで確保し，a[i]にi + 1を入れて返す．成功時の所有者は呼び出し元で，呼び出し元がfreeする．
    • make_sequenceは，mallocの前に，要素数と要素の大きさの積n * sizeof *aがSIZE_MAXを超えないことを調べる．超える場合と確保に失敗した場合はNULLを返す．この約束を関数の前にコメントで書く．
    • 関数void show_sequence(size_t n)を作る．show_sequenceは次の処理を行う．
      • nが1〜1000の範囲外なら，printf("n=%zu rejected\n", n);で表示し，確保せずに戻る．
      • make_sequence(n)を呼ぶ．戻り値がNULLならprintf("allocation failed\n");で表示して戻る．
      • 要素の合計をlong longで求め，printf("n=%zu sum=%lld mean=%.1f\n", n, sum, (double)sum / (double)n);で表示してから，配列をfreeする．
    • mainでは，nが1，5，1000，0，1001の順にshow_sequenceを呼ぶ．

    表示は次のようになります．

    n=1 sum=1 mean=1.0
n=5 sum=15 mean=3.0
n=1000 sum=500500 mean=500.5
n=0 rejected
n=1001 rejected
    ヒント

    要素の大きさはsizeof *aで求めます．sizeof aはポインタ自身の大きさで，要素の大きさではありません．n > SIZE_MAX / sizeof *aなら，積n * sizeof *aはsize_tで表せません．

    valuesのようなポインタのsizeofから，mallocへ渡した個数を復元することはできません．個数nを別に持ち続けることが，動的配列を安全に使うための情報管理です．n要素の最後の添字はn - 1なので，ループの条件はi <= nではなくi < nです．

    課題1-2　配列を逆順にする¶

    確保した配列を同じ領域の中で逆順に並べ替える関数を加えたプログラムを作成し，要素数が1，2，5の配列で並べ替えの結果を確認してください．

    プログラムが満たすこと（仕様）は次のとおりです．

    • 関数void print_array(const char *label, const int *a, size_t n)を作る．printf("%s:", label);の後，各要素をprintf(" %d", a[i]);で表示し，最後に改行する．
    • 関数void reverse(int *a, size_t n)を作る．先頭と末尾から組にして，半分まで交換する．新しい領域は確保しない．
    • 関数void show_reverse(size_t n)を作る．make_sequence(n)で配列を作り，NULLならprintf("allocation failed\n");で表示して戻る．成功したらreverseで逆順にし，print_array("reversed", 配列, n)で表示してからfreeする．
    • mainで，課題1-1の表示の後に，nが1，2，5の順にshow_reverseを呼ぶ．

    表示は，課題1-1の5行に続けて次の3行が出ます．

    reversed: 1
reversed: 2 1
reversed: 5 4 3 2 1

    交換する組はn / 2組です．整数の除算なので，奇数個のときの中央の要素は交換しません．中央の要素は自分自身と組になるので，交換しなくても結果は同じです．すべての添字について交換すると，各組を2回交換することになり元の順序に戻ります．

    作業用の変数tempは通常の局所変数なので，freeは不要です．reverseはポインタを進めずに添字で操作するので，呼び出し元のvaluesは確保した領域の先頭を指したままで，そのままfreeへ渡せます．

    課題1-3　独立したコピーを作る¶

    配列の要素を新しく確保した別の領域へコピーする関数を加えたプログラムを作成し，コピーだけを逆順にしても元の配列が変わらないことを確認してください．

    プログラムが満たすこと（仕様）は次のとおりです．

    • 関数int *copy_array(const int *a, size_t n)を作る．n要素の新しい配列をmallocで確保し，aの要素をコピーして返す．成功時は呼び出し元がfreeし，確保に失敗したらNULLを返す．この約束を関数の前にコメントで書く．nは課題1-1で範囲を調べた個数とする．
    • 関数void show_copy(size_t n)を作る．show_copyは次の処理を行う．
      • make_sequence(n)で元の配列valuesを作る．NULLならprintf("allocation failed\n");で表示して戻る．
      • copy_array(values, n)でコピーcopyを作る．NULLならprintf("allocation failed\n");で表示し，先に確保したvaluesをfreeしてから戻る．
      • copyだけをreverseで逆順にし，print_array("values", values, n)とprint_array("copy", copy, n)の順に表示する．
      • copyとvaluesをそれぞれ1回ずつfreeする．
    • mainで，課題1-2の表示の後に，nが2，5の順にshow_copyを呼ぶ．

    表示は，課題1-2までの8行に続けて次の4行が出ます．

    values: 1 2
copy: 2 1
values: 1 2 3 4 5
copy: 5 4 3 2 1

    int *copy = values;ではポインタの値をコピーするだけで，領域は1つのままです．そのcopyを通して逆順にすると，valuesから見ても逆順になります．元の配列を残すには，別の領域を確保して要素をコピーします．このとき領域は2つになるので，それぞれを解放します．

    課題1全体の表示は次のようになります．

    n=1 sum=1 mean=1.0
n=5 sum=15 mean=3.0
n=1000 sum=500500 mean=500.5
n=0 rejected
n=1001 rejected
reversed: 1
reversed: 2 1
reversed: 5 4 3 2 1
values: 1 2
copy: 2 1
values: 1 2 3 4 5
copy: 5 4 3 2 1

    課題2　構造体を確保する関数¶

    Pointを動的に確保して返す関数を使うプログラムを作成し，3通りの座標で生成したメンバの値と，失敗を模擬した場合に確保した領域を使わずallocation failedを表示することを確認してください．

    NewPointプロジェクトにnew_point.cを作ります．プログラムが満たすこと（仕様）は次のとおりです．

    • stdio.hとstdlib.hをインクルードする．
    • double型のメンバxとyを持つ構造体を，typedefでPointという名前にする．
    • 関数Point *new_point(double x, double y, int fail)を作る．
      • failが0以外なら，確保せずにNULLを返す．これは確保の失敗を試験するための引数である．
      • failが0ならmalloc(sizeof *p)でPointを1個確保する．失敗したらNULLを返す．
      • 成功したら，複合リテラル*p = (Point){.x = x, .y = y};で両メンバを初期化して返す．
      • 「成功なら初期化済みのPointを返し，呼び出し元がfreeする．失敗ならNULLを返す」という約束を関数の前にコメントで書く．
    • 関数void show_point(double x, double y, int fail)を作る．new_point(x, y, fail)を呼び，NULLならprintf("allocation failed\n");で表示して戻る．成功したらprintf("point=(%.1f, %.1f)\n", p->x, p->y);で表示してからfreeする．
    • mainでは，次の4通りを表の順にshow_pointへ渡す．
    x y fail
    3.0 4.0 0
    0.0 0.0 0
    −2.0 5.0 0
    3.0 4.0 1

    表示は次のようになります．

    point=(3.0, 4.0)
point=(0.0, 0.0)
point=(-2.0, 5.0)
allocation failed
    ヒント

    複合リテラルの代入の左辺はpではなく*pです．pはアドレス，*pは確保した構造体本体を表します．NULLを確かめる前に*pへ代入してはいけません．

    new_pointの局所変数pの寿命はreturnで終わりますが，mallocした本体はfreeされるまで生きています．そのため，呼び出し元のpから本体を使えます．関数内の通常の局所変数Pointのアドレスを返すと，戻った時点でその変数の寿命が終わっているので，そのようには書きません．

    failを使うと，本当にメモリを使い切らなくても，NULLが返った後の経路を毎回確実に通せます．失敗の経路でp->xを読まないことが大切です．この関数はerrnoを設定しないので，失敗はNULLかどうかで判定します．

    1個の小さなPointを作るだけなら，値として返す方法や，呼び出し元のPoint *へ書き込む方法でも足ります．動的確保を選ぶと，寿命を呼び出し元が決められる代わりに，失敗の可能性と解放責任が増えます．

    発展1　callocとreallocで配列を拡張する¶

    callocで確保した配列をreallocで拡張・縮小する関数を使うプログラムを作成し，7通りの個数と失敗の指定で，0で初期化されること，保持される要素と追加される要素，失敗したときに元の領域が残ることを確認してください．

    GrowArrayプロジェクトにgrow_array.cを作ります．プログラムが満たすこと（仕様）は次のとおりです．

    • 必要な標準ヘッダ（stdio.h，stdlib.h，stdint.h）をインクルードする．
    • 課題1-2と同じvoid print_array(const char *label, const int *a, size_t n)を作る．
    • 関数int *resize_array(int *p, size_t old_n, size_t new_n, int fail)を作る．pはold_n要素の確保済みの配列とする．
      • new_nが1〜1000の範囲外，または積new_n * sizeof *pがSIZE_MAXを超える場合は，reallocを呼ばずにNULLを返す．
      • failが0以外なら，reallocを呼ばずにNULLを返す．これは再確保の失敗を試験するための引数である．
      • reallocの戻り値を別の変数nextで受け，NULLならNULLを返す．
      • 成功したら，増えた要素（添字old_n〜new_n - 1）に添字+1を代入し，nextを返す．
      • NULLを返したときは，pの領域は解放されずに残り，その解放は呼び出し元が行う．
    • 関数void try_grow(size_t old_n, size_t new_n, int fail)を作る．try_growは次の処理を行う．
      • printf("%zu -> %zu\n", old_n, new_n);で表示する．
      • old_nが1〜1000の範囲外なら，printf("invalid size\n");で表示し，確保せずに戻る．
      • calloc(old_n, sizeof *p)で配列pを確保する．NULLならprintf("allocation failed\n");で表示して戻る．
      • print_array("zero", p, old_n)で確保直後の値を表示し，その後にp[i]へi + 1を代入する．
      • resize_array(p, old_n, new_n, fail)を呼ぶ．NULLならprintf("resize failed\n");とprint_array("kept", p, old_n)で表示し，pをfreeして戻る．
      • 成功したら，以後は返されたポインタだけを使い，print_array("values", 配列, new_n)で表示してからfreeする．
    • mainでは，次の7通りを表の順にtry_growへ渡す．
    old_n new_n fail 確認すること
    3 5 0 先頭3要素を保持し，2要素を追加
    3 1 0 縮小すると先頭の1要素だけが残る
    1 4 0 1を保持し，2，3，4を追加
    3 0 0 新しい個数が0なら失敗し，元の領域が残る
    3 1001 0 上限を超えると失敗し，元の領域が残る
    3 5 1 再確保の失敗でも，元の領域が残る
    0 5 0 最初の確保の前に拒否する

    表示は次のようになります．

    3 -> 5
zero: 0 0 0
values: 1 2 3 4 5
3 -> 1
zero: 0 0 0
values: 1
1 -> 4
zero: 0
values: 1 2 3 4
3 -> 0
zero: 0 0 0
resize failed
kept: 1 2 3
3 -> 1001
zero: 0 0 0
resize failed
kept: 1 2 3
3 -> 5
zero: 0 0 0
resize failed
kept: 1 2 3
0 -> 5
invalid size
    ヒント

    reallocの戻り値をp = realloc(p, ...)と直接pへ代入すると，失敗したときに元の領域への唯一の手がかりを失います．nextで受け，成功してから持ち替えます．初期化が必要なのは添字old_nからnew_n - 1までです．縮小した場合は増分がないので，そのループは1回も実行されません．

    callocは全ビットを0にして確保するので，int配列なら代入前に読んでも0です．mallocやreallocで増えた部分は初期化されないので，値を代入してから読みます．

    縮小した後に有効なのは先頭のnew_n要素だけです．new_nが1のときp[3]を読んで確かめることはできません．拡張した後のp[3]は，代入してから読める要素です．reallocが成功したら，古いポインタや古い要素へのポインタは使わず，返されたポインタから参照を作り直します．サイズ0のreallocは扱いが複雑なので，この課題では呼ばずに失敗として扱います．

    発展2　static変数の寿命を確かめる¶

    局所変数の書き方だけを変えた，呼ばれた回数を返す3つの関数を使うプログラムを作成し，それぞれを3回呼んだ結果で，静的記憶期間と自動記憶期間，初期化と代入の違いを確認してください．

    StorageCountプロジェクトにstorage_count.cを作ります．プログラムが満たすこと（仕様）は次のとおりです．

    • 3つの関数は，どれもstatic int 関数名(void)の形とし，局所変数countを1増やしてその値を返す．
    • 3つの関数のcountの書き方は次のとおりとする．
    関数 countの書き方
    next_static static int count = 0;
    next_auto int count = 0;
    next_reset static int count;の後に，文としてcount = 0;
    • mainでは，next_static，next_auto，next_resetの順に，それぞれを3回呼ぶ．関数ごとに，printf("static:");のように関数名からnext_を除いた名前とコロンを表示し，各戻り値をprintf(" %d", 値);で続けて表示して改行する．

    表示は次のようになります．

    static: 1 2 3
auto: 1 1 1
reset: 1 1 1

    static int count = 0;のcountは静的記憶期間を持ち，初期化はプログラムの開始前に一度だけ行われます．そのため，呼ぶたびに値が増えます．int count = 0;は呼ぶたびに新しいcountが作られて0で初期化されます．next_resetのcountは静的記憶期間を持ちますが，文として書いたcount = 0;は呼ぶたびに実行されるので，値は保たれません．

    関数の前のstaticは，その関数名を同じファイルの中だけで使えるようにする内部リンケージを表します．関数内のcountに付けたstaticは，名前の見える範囲を関数内に保ったまま，静的記憶期間を与えます．countはmallocで確保した領域ではないので，freeしません．

    発展3　不透明なVectorの生成と解放¶

    講義のVectorを使って2x+yを計算する関数を使うプログラムを作成し，途中の生成を失敗させない場合と1〜3番目の生成を失敗させた場合で，結果と後始末の後の状態を確認してください．

    DynamicVectorプロジェクトに，講義のvector.hとvector.cを変更せずに追加し，vector_check.cを作ります．vector.hには構造体のメンバがないので，vector_check.cからはメンバを直接使わず，vector.hの関数だけを使います．プログラムが満たすこと（仕様）は次のとおりです．

    • "vector.h"とstdio.hをインクルードする．
    • 関数int run_axpy(int fail_on)を作る．講義のvector_main.cと同じく，所有する3つのポインタx，y，resultを最初にNULLで初期化し，int status = 1;とする．gotoで初期化を飛び越えないように，double first, second;，double out = 99.0;，int ok = 0;も最初に宣言する．
    • printf("fail_on=%d\n", fail_on);で表示した後，次の3つの生成を順に行う．fail_onが1，2，3のときは，それぞれ1番目，2番目，3番目の生成の関数を呼ばず，ポインタをNULLのままにして確保の失敗を模擬する．fail_onが0なら失敗させない．
      1. x = vector_create(1.0, 2.0);
      2. y = vector_create(3.0, 4.0);
      3. result = vector_axpy(2.0, x, y);
    • 各生成の後でポインタがNULLなら，printf("allocation failed\n");で表示してgoto cleanup;で後始末へ進む．
    • 3つとも成功したら，vector_getでresultの添字0と1の値を取り出し，printf("result=%.1f %.1f\n", first, second);で表示する．続けて，範囲外の添字2でok = vector_get(result, 2, &out);とし，printf("ok=%d out=%.1f\n", ok, out);で戻り値とoutを表示する．最後にstatusを0にする．
    • cleanup:では，vector_destroy(&result);，vector_destroy(&y);，vector_destroy(&x);の順に解放する．その後，printf("cleared=%d\n", x == NULL && y == NULL && result == NULL);で表示し，さらにvector_destroy(&x);をもう一度呼んでから，statusを返す．
    • mainでは，fail_onを0から3まで変えながらrun_axpyを呼び，戻り値をprintf("status=%d\n", run_axpy(fail_on));の形で表示する．

    表示は次のようになります．

    fail_on=0
result=5.0 8.0
ok=0 out=99.0
cleared=1
status=0
fail_on=1
allocation failed
cleared=1
status=1
fail_on=2
allocation failed
cleared=1
status=1
fail_on=3
allocation failed
cleared=1
status=1
    ヒント

    fail_onによる模擬は，if (fail_on != 1) { x = vector_create(1.0, 2.0); }のように，生成の呼び出しをifで囲むと書けます．その直後のNULLの検査は，本当に確保に失敗した場合と共通にします．

    確保できる領域は，fail_onが0ならx，y，resultの3つ，1ならなし，2ならxだけ，3ならxとyです．どの場合も同じcleanup:へ進み，生成に成功した領域だけが解放されます．まだ生成していないポインタはNULLなので，vector_destroyへ渡しても何もしません．

    vector_destroyへ渡すのはxではなく&xです．関数がxそのものを書き換えられるので，解放後にxがNULLになり，cleared=1と表示されます．そのため，2回目のvector_destroy(&x);も何もしません．ただし，解放前にxを別のポインタへコピーしていた場合，そのコピーは自動ではNULLになりません．このAPIで，すべての二重解放を防げるわけではありません．

    範囲外の添字2では，vector_getが添字を検査して0を返し，outを変更しません．そのためoutは99.0のままです．

    Vectorの配列メンバは本体に含まれるので，この例は本体へのfreeで後始末が終わります．メンバをdouble *v;に変えて配列を別に確保するなら，配列の確保に失敗したときに本体を解放する処理と，配列，本体の順に解放する処理が必要になります．

    確認問題¶

    この節は自習用で，成績には含めません．

    1. ポインタ変数が局所変数なら，指す領域も必ずスタックにあるか．
    2. callocした整数配列とmallocした整数配列を，代入前に同じように表示してよいか．
    3. freeの後にp=NULLとしたら，q=pで以前に作った別名もNULLになるか．
    4. realloc失敗後の元の配列と，成功後の古い要素ポインタは同じ扱いか．
    5. 動的な配列を含む構造体の本体だけをfreeすれば，配列も自動で解放されるか．
    6. エラー処理があることを確認するのに，実際にメモリを使い切る必要があるか．

    チェックリスト¶

    • 各課題のソースが1つのファイルにまとまり，警告なしでビルドできる．
    • 1回の実行で，課題に示したすべての場合の結果が表示される．
    • 表示が，課題に示した出力と一致する．
    • 関数の名前，引数，戻り値の型が課題の指定どおりである．
    • 小問のある課題で，前の小問の関数や表示を残している．
    • malloc，calloc，reallocの戻り値をNULLと比べてから使っている．
    • 確保に成功した領域を，失敗の経路も含めてすべて1回ずつ解放している．
    • 解放後の使用，二重解放，確保していない領域のfree，未初期化の要素の読み取りを書いていない．
    • reallocの戻り値を別の変数で受け，成功してから持ち替えている．
