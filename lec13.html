    第13回　メモリ管理¶

    到達目標¶

    • 自動・静的・動的な記憶域の寿命を説明できる．
    • 必要な個数を検査してmallocし，初期化・使用・freeできる．
    • リーク・二重解放・解放後の使用を避けられる．
    • callocとreallocを使い分け，失敗時にも元の領域を失わずに処理できる．
    • 構造体の生成・利用・解放を関数に分け，所有者を説明できる．

    今回の見通し¶

    配列の要素数を実行前に固定できない場合や，関数の終了後もデータを残したい場合には，領域の寿命を自分で管理する方法が必要になります．第8・9回のポインタ，第11回の構造体，第12回のモジュール分割を組み合わせ，動的なデータを安全に扱いましょう．

    今回は「確保できたら使う」だけでなく，誰が初期化し，誰が解放し，失敗したら何を残すかまでを1つの処理として考えます．前半は1本の動的配列，後半は構造体を返す関数と，内部を隠したVectorの例です．WindowsのVisual StudioでC17の.cファイルとして実行します．

    1　どこまで有効な領域か¶

    変数の名前が使える範囲と，領域の寿命は別の概念です．

    種類 例 寿命の目安
    自動記憶域 通常の局所変数・固定長配列 ブロックの実行中
    静的記憶域 ファイルスコープの変数・static局所変数 プログラム全体の実行中
    動的に確保した記憶域 mallocで得た領域 確保成功からfree等で解放するまで

    通常の実装では関数呼び出しにスタック，動的確保にヒープが使われます．ただし，Cの言語仕様がすべての変数の物理的な置き場所を固定しているわけではありません．最適化の影響もあるため，まず寿命の規則を理解します．

    static int count = 0; を関数内に置くと，名前はその関数のブロック内ですが値は呼び出しの間も保持されます．巨大な局所配列を作れば常に安全，というわけでもありません．

    1.1　ポインタ自身と，指す領域を分ける¶

    関数の実行中
  局所変数p [アドレス] ──→ 動的領域 [要素0][要素1][要素2]

return pで呼び出し元へアドレスを返した後
  関数内のpの寿命は終了
  呼び出し元q [同じアドレス] ──→ 動的領域はまだ有効

free(q)の後
  動的領域の寿命は終了．qや別名から読み書きしない

    pというポインタ変数が局所変数であることと，pが指す領域が局所変数であることは同じではありません．mallocで確保した領域は，ポインタを持つ関数が戻っても自動では解放されません．逆に，通常の局所配列の先頭アドレスを返しても，その配列の寿命は延びません．

    次は誤りを読むための断片です．実行して結果を確かめる課題にはしません．

    /* 誤った設計：この関数は使用しない */
int *bad_array(void)
{
    int values[3] = {1, 2, 3};
    return values;
}

    valuesは関数から戻ると寿命が終わります．たまたま以前の値が見えたとしても，有効な配列として使える根拠にはなりません．配列を作る関数が必要なら，呼び出し元に領域を用意してもらう方法と，動的確保した領域を返す方法を選びます．前者でも，呼び出し元の配列が生きている間なら別の関数へ渡して使えます．「局所配列は複数の関数で使えない」という意味ではありません．

    1.2　スタックとヒープの使い分け¶

    観点 通常の局所配列 動的に確保した配列
    領域を得る 配列を定義する mallocやcallocを呼ぶ
    寿命の終わり 宣言したブロックの実行終了 freeまたはreallocによる解放
    要素数 この授業では固定長を使う 実行時の入力から決められる
    サイズの変更 同じ配列オブジェクトの長さは変えられない reallocで別の大きさの領域に更新できる
    管理の負担 スコープに沿って自動で管理 失敗・初期化・解放を設計する

    一般にスタックにはヒープとは別の容量制限があります．巨大な局所配列は危険ですが，ヒープなら必ず確保できるわけでもありません．容量はOS，実行形式，設定，残り資源に左右されます．授業では100MBの配列や最大サイズの確保で故意に資源を消費する実験は行いません．小さなデータで管理手順を確かめます．

    アドレスを表示するならprintf("%p", (void *)p);のように型を合わせます．通常のWindowsアプリで見えるのは仮想アドレスで，物理メモリの番地そのものではありません．マイコンなどOSのない環境ではリンカの設定で配置を指定する場合もあります．アドレスの大小だけからスタック・ヒープの位置関係を一般化しないでください．

    2　実行時に個数を決める¶

    mallocは指定したバイト数を確保し，成功なら領域へのポインタ，失敗ならNULLを返します．宣言は <stdlib.h> にあります．

    int *values = malloc(n * sizeof *values);

    Cではmallocの戻り値をint へ明示的にキャストする必要はありません．sizeof *values と書けば，要素の型を変更したときにサイズ指定も追従します．sizeof(int )だとポインタ自体のサイズなので間違いです．

    必ず次の順序で扱います．

    1. 個数が目的に合う範囲か調べる．
    2. バイト数の掛け算がsize_tの範囲を超えないか調べる．
    3. mallocの戻り値を確認する．
    4. 各要素を初期化してから読む．
    5. 必要なくなったらfreeする．

    n > SIZE_MAX / sizeof *values を先に調べると，掛け算であふれる前に拒否できます．符号付きの負数をsize_tへ変換する前にも検査が必要です．この講義では個数0を拒否し，ゼロサイズ確保の扱いを避けます．

    2.1　個数とバイト数¶

    mallocの引数は要素数ではなくバイト数で，型はsize_tです．仮にsizeof(int)が4の環境なら，intを5個確保するには20バイトが必要です．ただし4を直接書くのではなくsizeofを使います．

    n = 5，sizeof *values = 4 の場合の概念図
values ─→ [ int ][ int ][ int ][ int ][ int ]
添字          0      1      2      3      4
総バイト数 = 5 × 4 = 20

    values + 1は次のint要素を指します．1バイト先とは限りません．mallocは通常のintや構造体を置くのに適した境界へ整列した領域を返すので，この授業の型では追加の位置調整は不要です．

    sizeof valuesはポインタ変数のサイズです．確保したバイト数は分かりません．sizeof values / sizeof values[0]でも個数を求められません．sizeofによる配列全体の大きさの取得は，式の型が本当に配列である場合の話であり，「同じ関数内にあるか」だけでは決まりません．配列を引数で受け取った関数でも，個数を別に受け取ります．

    2.2　掛け算の前に調べる理由¶

    size_tは符号なし整数型です．積が表現範囲を超えると，小さな値へ回り込む可能性があります．必要量より小さい領域を確保し，大きな配列だと思って使うと範囲外アクセスになります．n * sizeof *valuesを計算した後ではなく，除算を使って先に上限を判定します．

    (size_t)-1はsize_tの最大値になります．これは負の個数を正しい個数へ直す方法ではありません．負数を先に拒否しないと，極端に大きな要求へ変わってしまうことを示しています．最大値はstdint.hのSIZE_MAXで表せます．

    アプリケーション上の上限（ここでは1000）と，型が表せるバイト数の上限は別です．前者は過剰な資源使用を避けるため，後者は計算の正しさを守るために調べます．両方を満たしても，実際の確保が成功するとは限りません．

    #include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <errno.h>
int main(int argc, char *argv[])
{
    if (argc != 2) {
        fprintf(stderr, "usage: Dynamic count (1..1000)\n");
        return 1;
    }
    char *end;
    errno = 0;
    long count = strtol(argv[1], &end, 10);
    if (argv[1] == end || *end != '\0' || errno == ERANGE ||
        count < 1 || count > 1000) {
        fprintf(stderr, "count must be 1..1000\n");
        return 1;
    }
    size_t n = (size_t)count;
    int *values = NULL;
    if (n > SIZE_MAX / sizeof *values) {
        fprintf(stderr, "size overflow\n");
        return 1;
    }
    values = malloc(n * sizeof *values);
    if (values == NULL) {
        fprintf(stderr, "allocation failed\n");
        return 1;
    }
    long long sum = 0;
    for (size_t i = 0; i < n; ++i) {
        values[i] = (int)i + 1;
        sum += values[i];
    }
    printf("n=%zu sum=%lld mean=%.1f\n", n, sum, (double)sum / n);
    free(values);
    values = NULL;
    return 0;
}

    dynamic.c

    第10回と同じVisual Studioの「コマンド引数」に5を指定すると，n=5 sum=15 mean=3.0 と表示します．nは1〜1000に限定し，合計にはlong longを使います．配列の容量はポインタだけでは分からないため，nを一緒に管理します．

    malloc直後の領域は初期化されていません．前の内容を表示して調べるのではなく，自分で値を設定します．

    3.1　処理を順番に読む¶

    手順 確認していること 失敗した場合
    argcの検査 個数を表す引数が1つあるか 確保前に終了
    strtol 数字があり，末尾まで変換でき，longの範囲内か 確保前に終了
    countの検査 1〜1000か 確保前に終了
    SIZE_MAXによる検査 バイト数の積を表せるか 確保前に終了
    mallocとNULL判定 実際に領域を得られたか 要素へ触れずに終了
    初期化と集計 各要素へ書いてから読む 有効添字は0〜n−1
    free 所有している領域の利用を終える 解放後は参照しない

    初期化のループでは，values[i] = ...;の後にsum += values[i];を実行しています．この順序が重要です．最大値n=1000でも要素は1〜1000，合計は500500なので，今回の合計用のlong longの範囲に収まります．

    strtolは先頭の空白や+符号を受け付けます．この例では末尾の余計な文字は拒否します．数値の仕様とメモリの仕様をそれぞれ確認し，たまたま小さい値になったから受け付ける，という処理にしません．

    3.2　確保した後の終了経路¶

    この例では確保後に失敗する処理がありません．ファイル読み込みなどを追加すると，途中で終了する経路が増えます．その場合には，正常終了の直前だけでなく，確保後のすべての終了経路で解放する必要があります．確保前のエラーには解放対象がない，という違いも整理しましょう．

    4　freeと所有権¶

    freeには，動的確保で得てまだ解放していない先頭のポインタ，またはNULLを渡します．局所配列，文字列リテラル，途中の要素のアドレスは渡せません．

    問題 原因
    メモリリーク 解放する前に確保した領域へ到達する手段を失う
    二重解放 同じ領域を2回解放する
    解放後の使用 寿命の終わった領域へアクセスする
    範囲外アクセス 確保した個数を超えて読み書きする

    所有者を「最後に解放する責任を持つ側」として決めると整理できます．関数が動的領域を返すなら，呼び出し側が解放するのかを仕様に書きます．

    free(p); p = NULL; はpを誤って再使用しにくくしますが，別のポインタqにも同じアドレスをコピーしていたなら，qは自動ではNULLになりません．別名参照も含めて使わないことが必要です．

    4.1　所有と借用¶

    確保後                     解放後
所有者p ─┐                 p = NULL
         ├→ [動的な配列]    [領域の寿命は終了]
借用者q ─┘                 qを評価・参照・freeしない

    例えばmainが配列を確保し，表示関数に渡す場合，表示関数は一時的に借りて読むだけです．表示関数が勝手にfreeすると，mainがその後使えなくなります．反対に，生成関数が新しい配列を返す場合は，呼び出し元へ解放責任を移す仕様にできます．これはCの型だけで自動的に検査される規則ではないので，コメントや関数名でも明示します．

    操作 意味 その後の責任
    q = p; ポインタ値のコピー 領域は1つ．所有者を増やしたことにしない
    新しい領域を確保して要素をコピー データの複製 2つの領域をそれぞれ解放する
    ポインタを関数の引数へ渡す 呼び出し先にも参照を渡す 借用か所有権移動かを仕様で決める
    free(p); 領域の寿命を終える どの別名からも使わない

    freeはポインタ変数を書き換える関数ではありません．解放前のポインタ値は解放後には有効な参照として使えず，比較や表示による確認もしません．p = NULL;は以前の値を読み出さずに上書きする操作です．

    4.2　リークは代入でも起きる¶

    動的領域を指す唯一のポインタに別のアドレスを代入すると，元の領域へ到達できなくなります．p = NULL;も解放の代わりにはなりません．「ポインタを消す」と「指す領域を解放する」を区別してください．

    mallocが成功した回数だけfreeを書く，という数合わせも不十分です．どの成功した確保に対する解放かを追跡します．free(NULL)は何もしないので安全ですが，未初期化のポインタを渡してよいわけではありません．管理用のポインタは初めにNULLにしておくと，途中失敗時の後始末をまとめやすくなります．

    freeは使用中の領域を再利用可能にする操作であり，その内容を必ず0で消したり，OSへ直ちに返したりする保証ではありません．タスクマネージャーの表示がすぐ減らないことだけで，解放に失敗したとは判断できません．

    5　callocとrealloc¶

    callocは個数と要素サイズを受け，領域の全ビットを0にして確保します．int配列なら0で初期化できます．ただし全ビット0があらゆる型の意味上の0やNULLを表すとは限りません．戻り値と個数の検査は必要です．

    reallocは確保済みの領域のサイズを変更します．場所が移る場合があります．新しいサイズが正の場合，失敗するとNULLを返し，元の領域は残ります．

    int *next = realloc(values, new_n * sizeof *values);
if (next != NULL) {
    values = next;
    /* 増えた要素は別途初期化する */
} else {
    /* 元のvaluesはまだ有効．必要に応じて解放して終了する */
}

    この断片の前にnew_n > 0とサイズの積を検査します．成功時は古い別名ポインタや要素へのポインタを使い続けてはいけません．values = realloc(values, ...) と直接代入すると，失敗時に元の領域への唯一の手がかりを失う場合があります．

    5.1　3つの確保関数の比較¶

    関数 主な用途 内容の初期化 失敗時
    malloc(bytes) 新しく必要量を確保 行わない NULL
    calloc(n, size) 新しく配列を確保 全ビットを0にする NULL
    realloc(p, bytes) 既存領域の大きさを更新 元と新しいサイズの小さい方まで保持．増分は未初期化 正のサイズならNULL，元の領域は有効

    callocでも個数を検査し，戻り値を確認します．ポインタのメンバは必要なら明示的にNULLを代入し，浮動小数点数も型に合う値で初期化すれば，表現への依存を避けられます．

    5.2　reallocは成功してから持ち替える¶

    失敗： next = NULL       values ─→ 元の領域（まだ有効）
成功： next ─→ 新しい領域（移動する場合がある）
       values = next    古いポインタや古い要素への参照は使わない

    成功時は，たとえ見かけ上同じ場所だったとしても，返されたポインタを使って参照を作り直します．元のポインタと返されたポインタの値を比較して「移動したか」を判定する必要はありません．

    縮小した場合は，残る先頭部分だけが有効です．拡張した場合は，増えた部分に値を代入してから読みます．realloc(NULL, 正のサイズ)はmallocに相当しますが，この授業では確保と変更の役割を分けて書きます．サイズ0のreallocはC17でも扱いが複雑なので使用せず，全要素を捨てる場合はfreeしてNULLを代入します．

    6　確保失敗を扱う¶

    6.1　戻り値が第一の判断材料¶

    メモリ不足は起こりにくいから省略してよい，とは考えません．NULLかどうかを確認する前にp[0]やp->xを使うと，失敗時に不正なアクセスになります．サイズ検査とNULL検査は異なる問題を防ぎます．

    errnoは関数が失敗の理由を知らせるために使う仕組みです．errno.hで利用できますが，成功時に自動で0へ戻るとは限りません．errnoだけを見てmallocの成功・失敗を判定しません． ISO Cではmallocが失敗理由をerrnoへ設定することまで一律には要求されません．MSVCのmallocでは失敗時にENOMEMを設定することが説明されています．Microsoft：malloc

    perrorは現在のerrnoに対応する説明を標準エラー出力へ出し，strerrorは指定したエラー番号の説明文字列を返します．メッセージは環境・言語設定に依存するので，文面の完全一致を正解にしません．失敗直後のerrnoを保存しておけば，別の処理で変わってしまうのを避けられます．

    /* MSVCでの診断の断片．pはmallocの戻り値 */
if (p == NULL) {
    int saved_errno = errno;
    fprintf(stderr, "%s: allocation failed (%d)\n", __func__, saved_errno);
    /* errnoの設定が保証される環境ならperrorなども利用できる */
}

    この断片にはstdio.hとerrno.hが必要です．__func__は現在の関数名を表す，C99以降の定義済み識別子です．通常の#defineによるマクロではありません．どの関数で失敗したかを示す診断に使えます．

    6.2　資源を消費せずに失敗経路を試す¶

    本当に空きメモリがなくなるまで確保を繰り返す方法は，授業用PCや他の作業へ影響します．代わりに，演習では確保を担当する小さな関数に「試験時だけNULLを返す」分岐を入れます．確認したいのはOSがメモリ不足になる様子ではなく，失敗した後でプログラムが安全に終了し，確保済みの領域を残さないことです．

    関数の内部でreturnすると，その関数から呼び出し元へ戻ります．exitはプログラム全体を終了します．mainからのreturnもプログラム終了につながりますが，普通の生成関数ではNULLなどで失敗を返すと，利用側が回復・表示・後始末を選べます．exitを呼んでも，呼び出し元に書いた後始末の文が順に実行されるわけではありません．

    7　構造体の生成と解放¶

    Pointのような構造体もmalloc(sizeof *p)で1個分を確保できます．成功を確認してから，メンバへ代入します．第11回の複合リテラルを使えば，構造体全体を初期化するように代入できます．

    /* Point *pの確保に成功した後の例 */
*p = (Point){.x = x, .y = y};

    左辺はpではなく*pです．pはアドレス，*pは確保した構造体本体を表します．局所変数Pointのアドレスを返すのとは異なり，mallocした本体は関数から戻った後も生きています．複合リテラルの値を本体へコピーしているので，一時的な値のアドレスを返しているわけでもありません．

    7.1　動的なメンバを持つ場合¶

    typedef struct {
    size_t length;
    int *data;
} IntBuffer;

    この構造体の本体を確保しても，dataの指す配列は自動で作られません．本体と配列を別に確保したなら，解放も別です．配列の確保に失敗した場合には，先に成功した本体の確保を解放する必要があります．

    buffer ─→ [ length | data ] ─→ [int][int][int]
              本体の確保           配列の確保
解放順：dataの指す配列 → bufferの指す本体

    本体を先にfreeしてからbuffer->dataを読むのは解放後の使用です．また，構造体を代入してもポインタメンバの参照先まではコピーされません．2つの構造体が同じ配列を指す場合，両方が所有者のつもりで解放すると二重解放になります．所有権移動，借用，独立したコピーのどれかを決めます．

typedef struct vector Vector;

/* Successful creation transfers ownership to the caller. */
Vector *vector_create(double x, double y);

    操作 成功時 失敗・注意

    #include "vector.h"
#include <stdlib.h>

struct vector {
    double v[2];
};

Vector *vector_create(double x, double y)
{
    Vector *p = malloc(sizeof *p);
    if (p == NULL) {
        return NULL;
    }
    *p = (Vector){.v = {x, y}};
    return p;
}

Vector *vector_axpy(double alpha, const Vector *a, const Vector *b)
{
    if (a == NULL || b == NULL) {
        return NULL;
    }
    return vector_create(alpha * a->v[0] + b->v[0],
                         alpha * a->v[1] + b->v[1]);
}

int vector_get(const Vector *p, size_t index, double *out)
{
    if (p == NULL || index >= 2 || out == NULL) {
        return 0;
    }
    *out = p->v[index];
    return 1;
}

void vector_destroy(Vector **p)
{
    if (p != NULL) {
        free(*p);
        *p = NULL;
    }
}

    struct vectorの定義はvector.cだけにあります．そのため，sizeof *pやp->vを使えるのは中身を知る実装側です．利用側ではVector *を宣言できますが，Vectorの実体をローカルに作ることや，そのサイズの取得はできません．

    vector_destroyへは&xのようにポインタ変数のアドレスを渡します．Vector pからpを変更すると，呼び出し元のxもNULLになります．単にVector を引数に取り，その局所的なコピーへNULLを代入するだけでは，呼び出し元は変わりません．

    Vector *x = NULL;
    Vector *y = NULL;
    Vector *result = NULL;
    int status = 1;
    double first, second;

    x = vector_create(1.0, 2.0);
    if (x == NULL) {
        fputs("allocation failed\n", stderr);
        goto cleanup;
    }
    y = vector_create(3.0, 4.0);
    if (y == NULL) {
        fputs("allocation failed\n", stderr);
        goto cleanup;
    }
    result = vector_axpy(2.0, x, y);
    if (result == NULL) {
        fputs("allocation failed\n", stderr);
        goto cleanup;
    }
    if (!vector_get(result, 0, &first) ||
        !vector_get(result, 1, &second)) {
        fputs("invalid access\n", stderr);
        goto cleanup;
    }
    printf("result=%.1f %.1f\n", first, second);
    status = 0;

cleanup:
    vector_destroy(&result);
    vector_destroy(&y);
    vector_destroy(&x);
    return status;
}

    vector.h ／ vector.c ／ vector_main.c

    2x+y=(5,8)なので，出力はresult=5.0 8.0です．x，y，resultはそれぞれ別の領域を所有します．3回目の確保に失敗したら，resultはNULLですがxとyはすでに確保済みです．まとめて後始末する経路が必要になります．

    cleanup:はラベル，goto cleanup;はそのラベルへ制御を移す文です．ここでは複数の失敗箇所から最後の後始末へ進む用途に限定しています．すべての所有ポインタを最初にNULLで初期化し，必要な変数も先に宣言しています．初期化を飛び越えて未定義の変数を使うような飛び方はしません．

    statusの初期値は失敗を表す1です．すべて成功した場合だけ0へ変え，後始末の後に返します．free(NULL)が安全なので，まだ作られていないオブジェクトも同じ後始末へ渡せます．解放責任をまとめることで，returnの追加による解放漏れを防ぎやすくなります．

    9　スコープ・記憶期間・リンケージ¶

    同じstaticやexternでも，「いつまで値があるか」と「どこから名前を使えるか」を混同しないようにします．

    宣言の例 名前の見える範囲・結び付き 記憶期間
    関数内のint n = 0; 宣言したブロック内，リンケージなし 自動
    関数内のstatic int n = 0; 宣言したブロック内，リンケージなし 静的
    ファイルスコープのint total = 0; 通常は外部リンケージ．他の.cからは適切な宣言が必要 静的
    ファイルスコープのstatic int total = 0; 内部リンケージ．同じ翻訳単位内 静的
    extern int total; 既存の定義を参照する宣言 参照するオブジェクトに従う

    9.1　staticの初期化と代入は別¶

    関数内のstatic int count = 0;は，関数を呼ぶたびに0を代入する処理ではありません．Cでは静的記憶期間のオブジェクトはプログラム開始前に一度初期化されます．「関数が初めて呼ばれたときに初期化する」というC++の一部の規則と混同しないでください．Microsoft：Cの寿命

    一方，static int count;とした後，普通の文としてcount = 0;を書けば，その代入は呼ぶたびに実行されます．staticを外した通常の局所変数の初期化とも比較すると違いが分かります．静的記憶期間の整数は明示的な初期化子がなければ0になりますが，通常の局所変数には同じ規則を期待できません．

    9.2　externと定義の確認¶

    第12回と同じく，ヘッダにextern int total;，1つの.cにint total = 0;を置きます．他の.cに定義があっても，宣言なしに使えるわけではありません．逆に全ファイルがextern宣言だけなら，実体を定義していないため，使用箇所のリンクで解決できません．

    externと初期化子を組み合わせたファイルスコープの宣言は，宣言だけではなく定義になります．本講義ではヘッダを宣言のみに保つため，その書き方を使いません．また，ファイルスコープのint total;は仮定義であり，単なるextern宣言の代用にはしません．同じ翻訳単位でint total = 1024;の後にint total;があっても，初期値は1024です．異なる翻訳単位に仮定義をばらまく設計にはしないでください．

    9.3　他の言語との比較¶

    Cでは，動的領域の所有者と解放のタイミングを自分で管理します．Pythonなどでは参照の管理やガベージコレクションによって自動管理され，Rustでは所有権を型や言語の規則として扱います．どの方式にも利点と制約があります．自動管理ならファイルなどすべての資源管理を考えなくてよい，という意味ではありません．第15回で言語ごとの考え方を比較します．

    確認問題¶

    1. malloc直後に要素を読んでよいか．
    2. sizeofポインタとsizeof要素のどちらで確保量を計算するか．
    3. free後に1つの変数をNULLへ変えるだけで，すべての別名が安全になるか．
    4. 局所的なポインタ変数の寿命と，mallocした領域の寿命は同じか．
    5. reallocが正のサイズへの変更に失敗したとき，元の領域はどうなるか．
    6. 3つ目のオブジェクトの確保に失敗した場合，先に確保した2つを誰が解放するか．
    7. static int count = 0;と，static宣言後のcount = 0;の違いは何か．
    8. callocでポインタを含む構造体を確保しただけで，すべての意味上の初期値を保証できるか．
    確認の要点

    mallocした領域は初期化してから読みます．確保量は個数×要素サイズであり，ポインタサイズから個数を復元できません．別名参照は解放後に使わず，正のサイズへのrealloc失敗時は元の領域を保持します．各終了経路の所有者が解放し，局所的なポインタ変数が消えることを自動解放だと思わないようにします．staticの初期化と通常の代入も別です．callocは全ビット0であり，型の意味に合わせた初期化とは区別します．
