    第11回　演習：構造体¶

    解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

    講義を読んでから取り組んでください．出力と処理の流れを予測しましょう．

    準備と進め方¶

    作業場所は PL1\week11 です．第1回と同じ設定（Cとしてコンパイル，C17，警告レベル4）で，課題ごとに別の空のプロジェクトを作ります．特に指定がなければ，mainを持つソースは1プロジェクトに1つです．保存後にCtrl+Shift+Bでビルドし，Ctrl+F5で実行します．

    各課題で，ソース，試した値，予測，実行結果，結果の説明を残してください．提出先や締切は，授業時に案内します．

    今回の進め方¶

    課題 作る・確認するもの 学ぶこと
    1 Pointの移動 値渡しとポインタ経由の変更
    2 Student配列の平均 配列と構造体メンバの組合せ
    3 Rectの面積 入れ子の構造体とメンバ参照
    4 2種類の文字列のコピー 内部配列と外部データの共有
    発展1 点の加算と初期化 指定初期化子・複合リテラル・戻り値
    発展2 長方形の正規化と包含判定 境界条件と構造体のコピー
    発展3 配置の観察 sizeofとoffsetof

    今回の座標には有限な−1000〜1000の値を使います．点数は0〜100です．入力の範囲を決め，出力を予測してから実行します．大きな構造体のコピー速度を競う課題ではありません．まず，何がコピーされ，どの変数が変更されるかを説明できるようにします．

    構造体の定義はmainより前に置きます．同じプロジェクトに複数のmainを置かず，別課題の型定義を重複して貼り付けないでください．指定初期化子の書き方で診断が出た場合は，.cppではなく.cで，C17としてコンパイルしているかも確認します．

    課題1　値とポインタの違い¶

    PointMove プロジェクトでstructs.cを実行し，movedを呼んだ直後とmove_in_placeを呼んだ直後のaを比較します．移動量を0，0にした場合も確認してください．

    変更される対象を追跡する¶

    ダウンロードしたstructs.cの最初の出力は，aが(1.0, 2.0)，bが(4.0, 1.0)です．movedの中にもpというPointがありますが，それはmainのaとは別のコピーです．呼び出し前後で次の表を埋めてください．

    時点 a.x a.y b.x b.y
    aの初期化直後 1 2 まだない まだない
    movedの戻り値でbを初期化した後 1 2 4 1
    move_in_placeでaを変更した後 4 1 4 1

    最後にaとbが同じ座標になっても，同じ保存場所になったわけではありません．その後にb.x = 100.0;を追加すれば，変わるのはbだけです．aも変わると予想した場合は，構造体のコピーをポインタのコピーと混同していないか，図で確かめましょう．

    3つの呼び出し方を比較する¶

    次の例は，aを(1, 2)で初期化した状態から，それぞれ独立に試します．bの宣言や表示も，試す形に合わせて整理してください．

    呼び出し方 実行後のa 理由
    moved(a, 3.0, -1.0); (1, 2) 結果を受け取っていない
    a = moved(a, 3.0, -1.0); (4, 1) 計算結果をaへ代入した
    move_in_place(&a, 3.0, -1.0); (4, 1) aのアドレスを渡して変更した

    値渡しの関数でも，戻り値を元の変数へ代入すれば，結果としてその変数を更新できます．「値渡しなら呼び出した後も絶対に元の変数が変わらない」と覚えるのではなく，関数内での変更と呼び出し側の代入を分けて考えます．

    移動量を変える¶

    dx，dy 初期値(1, 2)からの移動結果
    0，0 (1, 2)
    −1，−2 (0, 0)
    2，3 (3, 5)

    元のサンプルではmovedとmove_in_placeの2か所に移動量があります．両方を同じ条件へ変更して比較してください．片方だけ変えた場合，aとbの結果が違うのは自然です．

    説明すること：move_in_placeのpはポインタのコピーです．なぜそのコピーからaを書き換えられるのでしょうか．p自体とpが指すPointを別の箱として描いてください．NULLや初期化していないポインタは渡しません．

    課題2　点数の平均¶

    Students プロジェクトで名前と点数を持つStudentを定義し，Aki=80，Ren=70，Mio=90の平均を表示してください．点数は0〜100，人数は1〜3とします．

    ヒント

    配列の各要素から.scoreを取り出します．計算の関数は読み取り専用です．

    実行前に結果を予測し，実行後に結果とその理由を記録してください．

    配列要素とメンバを順に読む¶

    a[1]は2人目のStudent，a[1].scoreはその点数70，a[1].nameは名前を保存した配列です．a[1].name[0]は'R'になります．添字とドットのどちらを使っているかを順に確認してください．

    関数の仮引数aはStudent配列の先頭へのポインタです．Studentを1個渡すのとは違い，3人分の構造体が自動でコピーされているわけではありません．平均関数では変更しないことを示すためにconstを付けています．

    変更条件 期待する出力
    元の点数，n=1 記入してください
    元の点数，n=2 記入してください
    全員0，n=3 記入してください
    全員100，n=3 記入してください
    80，70，91，n=3 記入してください

    平均関数には1<=n<=3で，実際にn人分のデータがあることを約束して渡します．n=4なら存在しない要素へ進み，n=0なら0で割るので，どちらも実行する実験にはしません．

    名前と点数を一緒に交換する¶

    mainでa[0]とa[2]を交換する場合は，次のように構造体全体をコピーできます．

    Student temp = a[0];
a[0] = a[2];
a[2] = temp;
for (int i = 0; i < 3; ++i) {
    printf("%s %d\n", a[i].name, a[i].score);
}

    表示順はMio 90，Ren 70，Aki 80です．平均は80.0のままです．scoreだけを交換すると，名前と点数の対応が壊れます．構造体へまとめたことで「1人分」という単位で操作できる点を確認してください．

    名前を比較する¶

    同じ学生のデータかを「名前と点数が一致すること」と定義する場合，string.hを追加して次の条件を使えます．ここでleftとrightはStudent型の変数です．

    int same = strcmp(left.name, right.name) == 0 &&
           left.score == right.score;

    left == rightという比較はCの構造体には使えません．また，nameのアドレスの一致を調べるのではなく，文字列の内容を比較します．同名の学生を区別する必要があるなら，学生番号など別のメンバを設計する必要があります．

    課題3　長方形を表す¶

    Pointを2つ持つRectを定義してください．左下(1, 2)，右上(5, 5)から面積12.0を求めます．右上のx・yはそれぞれ左下以上とします．

    幅0，高さ0でも面積0になることを確認します．

    メンバ参照を分解する¶

    mainのr.lower.xと，areaの引数rに対するr->lower.xは同じ書き方ではありません．前者のrはRect本体，後者のrはRectへのポインタです．関数をまたいで同じ変数名を使っているため，宣言を確認してください．

    mainでRect *q = &r;とすると，次の4つは同じ値1.0を表します．

    printf("%.1f %.1f %.1f %.1f\n",
       r.lower.x, (r.lower).x, q->lower.x, (q->lower).x);

    lowerはPoint本体であってPointへのポインタではありません．そのためq->lower->xとは書けません．また，*q.lower.xという書き方では必要な間接参照の順序になりません．

    面積の境界を確認する¶

    lower upper 幅 高さ 面積
    (1, 2) (5, 5) 4 3 12
    (1, 2) (1, 5) 0 3 0
    (1, 2) (5, 2) 4 0 0
    (−2, −1) (1, 3) 3 4 12

    この課題のareaは，upperの各座標がlower以上であることを前提にしています．逆向きの座標を渡したら必ず適切な面積になる，という仕様ではありません．両方の差が負なら積が正になってしまうので，面積が正だっただけでは前提を守った証拠にもなりません．座標の順序をそろえる処理は発展2で扱います．

    名前もメンバにする¶

    Rectの型にchar name[21];を追加すると，座標と名前をまとめられます．その場合は初期化も，例えば次の形へ変更します．

    Rect r = {
    .lower = {1.0, 2.0},
    .upper = {5.0, 5.0},
    .name = "sample"
};

    この断片はnameを追加した型でのみ使えます．21要素なので，ASCIIなら20文字と終端を保存できます．r.nameを別の文字列で更新する場合，宣言後にr.name = "other";とは書けません．配列の容量を確かめて文字をコピーする必要があります．構造体全体の代入ができることと，配列メンバ単独への代入ができることは別です．

    課題4　配列メンバとポインタメンバを比較する¶

    Studentのnameがchar配列ではなくchar *なら，構造体をコピーした後の2つのnameは何を指すでしょうか．図で説明してください．

    CopyMembersプロジェクト¶

    配列を内部に持つ場合と，別の配列を指す場合を同じプログラムで比較します．どの出力が同じになり，どの出力が違うか，先に矢印の図を描いてください．

    array=Hoge hoge
pointer=Hoge Hoge same=1
redirect=fuga Hoge same=0

    変更を分類する¶

    処理 直接変更するもの 他方にも見えるか
    a1.text[0] = 'H'; a1の内部配列 a2には見えない
    p1.text[0] = 'H'; 共有しているbuffer p2からも見える
    p1.text = other; p1に入っているアドレス p2のアドレスは変わらない

    ポインタをコピーした直後は同じ場所を指すため，==で1になります．最後は別々の配列を指すので0です．これはアドレスの比較を意図したものです．文字列の内容を比較したい場面のstrcmpとは目的が違います．

    実際のアドレスを表示するならprintf("%p", (void *)p1.text);とします．具体的な数値より，同じか違うかを確認してください．構造体自体のアドレス&p1と，メンバに保存されたp1.textも別物です．

    全体を別の文字列へ変える場合¶

    長さ4のhogeを長さ4のfugaへ置き換えるなら，終端を含む5個をコピーします．次の断片を，先頭1文字だけを書き換えていた行の代わりに使えます．a1.textには7要素があり，この固定の文字列は収まります．

    const char replacement[] = "fuga";
for (size_t i = 0; i < sizeof replacement; ++i) {
    a1.text[i] = replacement[i];
}

    配列版ではa1がfuga，a2がhogeです．同様のコピーをbufferへ行えば，p1とp2の両方からfugaが見えます．任意の長さの文字列を受け付けるなら，第8回の容量検査を行う関数が必要です．この固定入力に十分な容量があることを，一般の文字列にもそのまま当てはめないでください．

    危険な例は実行せず説明する¶

    次の状況について，何が問題かを説明してください．

    1. ポインタメンバへ文字列リテラル"hoge"を入れ，その先へ書き込む．
    2. 関数内のchar buffer[8]を指す構造体を返し，関数終了後に表示する．
    3. 未初期化のTextPointerへ，いきなりtext[0]を書き込む．

    発展1　初期化と構造体を返す関数¶

    PointInitプロジェクトで，メンバ名を指定した初期化，省略したメンバ，複合リテラル，構造体の戻り値を確認します．

    a=10.0 2.0 result=13.0 7.0
partial=3.0 0.0 zero=0.0 0.0
assigned=-1.0 4.0

    宣言順と指定順を比較する¶

    aは.yを先に書いていますが，yへ2.0，xへ10.0が入ります．Point a = {2.0, 10.0};へ変えるとx=2.0，y=10.0となり，同じ意味にはなりません．名前を指定しない初期化は宣言順に対応します．

    partial.yとzeroの両メンバは0.0です．これを「初期化しなくても構造体は0になる」と説明してはいけません．Point partial;とだけ宣言したローカル変数のメンバを表示する実験はしません．

    最後の代入で(Point)を省略した形は正しい代入式ではありません．複合リテラルはPoint型の値として扱えるため，構造体全体の代入に利用できます．個別にa.x，a.yへ代入する方法と使い分けます．

    typedefの意味を説明する¶

    typedef int JPY;とJPY price = 100;は別の役割です．前者は別名を付け，後者は変数を作ります．Pointも同じで，typedefの定義だけで座標データが1個作られるわけではありません．

    発展として，Pointをタグ付きのtypedefへ書き換え，変数宣言の1つだけをstruct pointに変えても，同じ型として扱えることを確認してください．型の定義を追加するのではなく，既存の定義を書き換えます．

    発展2　長方形を正規化して点を判定する¶

    RectContainsプロジェクトを作ります．2点が逆順でも，xとyそれぞれの下限・上限へそろえた長方形を作る関数normalizedと，点が範囲内かを判定するcontainsを使います．この課題の範囲は下限を含み，上限を含みません．

    sample lower=1.0 1.0 upper=3.0 4.0
inside=1 original=1.0 4.0

    座標の順序を独立にそろえる¶

    入力の2点 正規化後のlower 正規化後のupper
    (1, 1)，(3, 4) (1, 1) (3, 4)
    (3, 4)，(1, 1) (1, 1) (3, 4)
    (1, 4)，(3, 1) (1, 1) (3, 4)
    (3, 1)，(1, 4) (1, 1) (3, 4)

    それぞれを別々に試します．2点を一括で交換するだけでは，3行目や4行目を正規化できません．また，xを交換した後の値を使ってyを判定する必要はなく，各軸を独立に処理できます．

    関数の最初のRect result = r;は，座標だけでなく名前もコピーします．座標だけを新しい未初期化のRectへ書き込むと，nameが未設定のままになってしまいます．戻す構造体のすべてのメンバが，どこで値を得たのかを説明してください．

    内側・外側・境界を調べる¶

    lower=(1, 1)，upper=(3, 4)へ正規化した長方形について確認します．

    点 結果 理由
    (2, 2) 記入してください 内側
    (1, 1) 記入してください 下限を含む
    (1, 3) 記入してください xが下限でもyが範囲内
    (3, 2) 記入してください xの上限を含まない
    (2, 4) 記入してください yの上限を含まない
    (0, 2) 記入してください xが下限より小さい
    (2, 5) 記入してください yが上限より大きい

    幅0や高さ0の長方形では，この条件を満たす点はありません．例えばlower=(1, 1)，upper=(1, 4)でp=(1, 2)でも0です．閉じた図形なら境界も含めるという直感だけで，<を<=へ変えないでください．まず仕様を決めます．

    元のデータと計算結果¶

    normalizedはrの値を変更して返すのではなく，rのコピーから結果を作ります．呼び出し元のrは入力の順序のままです．元も正規化したい場合はr = normalized(r);と代入します．

    名前の保持を確かめるには，.nameを"test_rect"などへ変えて実行します．名前が長すぎて21要素に収まらない例は使いません．名前を保存することと座標を並べ替えることは別の処理ですが，1つの構造体の戻り値にまとめられます．

    発展3　構造体のサイズを観察する¶

    StructLayoutプロジェクトではstdio.hとstddef.hを読み込み，講義のRecordを定義します．次の断片をmainへ置きます．

    printf("size=%zu tag=%zu count=%zu flag=%zu\n",
       sizeof(Record), offsetof(Record, tag),
       offsetof(Record, count), offsetof(Record, flag));

    通常のVisual Studio x64の既定設定ではsize=12 tag=0 count=4 flag=8となります．ただし環境や配置設定によって結果が違っても，直ちに誤りとは限りません．sizeofが3個のメンバのサイズの単純な合計と違う場合，どこに隙間があるかを図にしてください．

    この実験は隙間の中身を表示するものではありません．パディングの値が一定だと仮定せず，メンバの位置と全体サイズだけを調べます．memcmpで構造体全体を比較して，同じデータか判定する課題にも使いません．

    第10回と結び付けて考えましょう．構造体全体をfwriteした場合，どのような情報まで保存されるでしょうか．メンバの表現だけでなく，処理系依存の配置も含まれます．ポインタメンバのアドレスを保存しても，次の実行で同じ文字列を指せるとは限りません．保存形式はメンバごとに意味を決めて設計する必要があります．
