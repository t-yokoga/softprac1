    第9回　演習：ポインタ2¶

    解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

    講義を読んでから取り組んでください．出力と処理の流れを予測しましょう．

    準備と進め方¶

    作業場所は PL1\week09 です．第1回と同じ設定（Cとしてコンパイル，C17，警告レベル4）で，課題ごとに別の空のプロジェクトを作ります．特に指定がなければ，mainを持つソースは1プロジェクトに1つです．保存後にCtrl+Shift+Bでビルドし，Ctrl+F5で実行します．

    各課題で，ソース，試した値，予測，実行結果，結果の説明を残してください．提出先や締切は，授業時に案内します．

    今回の進め方¶

    段階 取り組むこと 確認する違い
    課題1 最大要素の検索と変更 値の出力と，場所の出力
    課題2 文字列の表示順を交換 ポインタの交換と，文字の書き換え
    課題3 二次元配列の平均 行数と列数，配列本体と仮引数
    課題4 二次元配列の行交換 アドレスの交換と，要素の交換
    発展 長さの違う行と型の整理 int **とint (*)[3]

    今回の入力はソース中の初期値です．数値や添字を変更するたびに再ビルドします．範囲外アクセスや文字列リテラルへの書き込みを試して，異常終了することを確認する課題ではありません．危険な例は型と図を使って説明してください．

    最初は「矢印を何段たどるか」と「どの変数が変わるか」を紙に書きます．アドレスの数値を記録する代わりに，p == &a[1]のような比較で，意図した要素を指しているかを調べることもできます．この方法なら実行ごとにアドレスが変わっても確認できます．

    課題1　見つからない場合¶

    FindMax プロジェクトでdouble_pointer.cを実行します．find_maxへ渡すnを0にしたとき，answerと戻り値はどうなるでしょうか．空の配列は宣言せず，元の配列とn=0を渡します．

    ヒント

    *answerを読むのは成功したときだけです．

    検索範囲と同点の扱い¶

    元の配列は{7, 12, 4}です．nを変えたら，検索に使われる要素を先に囲んでください．プログラム末尾のa[1]の表示は，検索結果の表示とは別です．

    n 成功・失敗 検索結果 *answer = 99;の影響
    3 成功 a[1]の12 a[1]が99
    1 成功 a[0]の7 a[0]が99，a[1]は12
    0 失敗 answerはNULL 代入を実行しない
    −1 失敗 answerはNULL 代入を実行しない

    n=4は実際の要素数を超えるので試しません．find_maxはnが実際の配列長以下かどうかを自動では判定できません．負のnを失敗として扱えることと，大きすぎるnが安全であることは別です．

    次にn=3へ戻し，配列を{12, 12, 4}へ変更します．選ばれるのはa[0]です．if本体でprintf("first=%d\n", answer == &a[0]);を追加し，1になることを確認してください．条件を>=へ変更するとa[1]になり，この比較は0です．変更後は条件を>へ戻します．

    説明すること：*out = best;を*out = &a[0];に変えたら何が起こるでしょうか．探索で求めたbestを使わず，常に先頭要素を返すことになります．コンパイルが通るだけでは，仕様どおりとは限りません．

    失敗時に古い結果を残さない¶

    mainでanswerを最初に&a[1]として，n=0で呼んでください．この関数は先に*out = NULL;を実行するので，以前のアドレスが残らずNULLになります．これはこの関数が採用した仕様です．一般に，失敗した関数が出力先をどう扱うかは，関数ごとに確認する必要があります．

    out自体へNULLを渡す実験はしません．有効なポインタ変数のアドレスを渡す契約と，出力結果としてNULLを受け取ることは違います．&answerはポインタ変数の場所，answerは検索結果の場所です．

    値を返す版と，場所を返す版¶

    ReturnMaximumという別プロジェクトで比較します．max_valueはn>=1だけに対応し，max_pointerはn<=0ならNULLを返します．値を返す版にも無条件にn=0を渡さないでください．

    before=12 12
after=12 99

    savedが12のままである理由を説明してください．savedは最大値を求めた時点のコピーです．一方foundは元の配列の要素を指しているので，*foundの変更はaへ反映されます．関数内のbestという変数自体のアドレスを返しているわけではありません．

    配列を{-7, -12, -4}へ変更するとbeforeは−4と−4，afterは−4と99です．最大候補を0から始めない理由も説明しましょう．場所を返す版だけのnを0に変更した場合は何も表示されません．値を返す版のn=3はそのままにして，比較する条件を混同しないようにします．

    二重ポインタの代入を追う¶

    次の断片をmain内で使い，実行前に各行の結果を予測してください．必要なヘッダはstdio.hです．

    int x = 10, y = 30;
int *p = &x;
int **pp = &p;
**pp = 20;
printf("%d %d %d\n", x, y, p == &x);
*pp = &y;
**pp = 40;
printf("%d %d %d\n", x, y, p == &y);

    課題2　表示順を変更する¶

    Names プロジェクトでconst char *配列にTokyo，Osaka，Nagoyaを入れ，最初と最後のポインタを交換して表示してください．文字列の内容はコピーしません．

    表示順を予測し，各文字列の長さが異なっていてもポインタを交換できる理由を説明してください．

    関数へ分ける¶

    交換部分をvoid swap_names(const char *names[], int i, int j)という関数へ移し，mainからswap_names(names, 0, 2);と呼びます．関数はmainより前に自分で定義してください．iとjは0〜2という条件です．mainに元の交換処理を残さないようにします．関数の仮引数をconst char **namesと書いた場合との関係も説明してください．

    呼び出し 表示の順番
    swap_names(names, 0, 2); 記入してください
    swap_names(names, 1, 1); 記入してください
    swap_names(names, 0, 2);を2回 記入してください

    各ケースは初期状態から別々に試します．文字列の長さを求める処理が不要なのは，文字を移動せず，固定サイズのポインタ値を交換しているからです．

    表示と書き換えを区別する¶

    printf("%s-city\n", names[i]);へ変更するとNagoya-cityなどと表示できます．これは文字列本体へ-cityを追加したのではありません．別のprintf("%s\n", names[i]);では元の文字列が表示されます．strlen(names[i])にも-cityの長さは加わりません．

    文字を変更したい場合は，次のように変更可能な配列を用意します．同じmainへ追加する場合は，既存の変数名との重複に注意してください．

    char city0[] = "Tokyo";
char city1[] = "Osaka";
char *editable[] = {city0, city1};
editable[0][0] = 't';
printf("%s %s\n", city0, editable[0]);

    実行前に結果を予測し，実行後に結果とその理由を記録してください．

    禁止する実験：names[0][0]を変更するためにconstを外す，キャストして文字列リテラルへ書き込む，文字列の長さより先を%sで表示する，といった操作は実行しません．

    課題3　行ごとの平均¶

    MatrixMean プロジェクトでmatrix.cをもとに，2行3列の行ごとの平均を計算する関数を作ります．行の値は0〜100とし，列数は3に固定します．

    実行前に結果を予測し，実行後に結果とその理由を記録してください．

    入力を変えて確かめる¶

    配列の2行 rows 出力
    {1, 2, 3}，{4, 5, 6} 1 記入してください
    {0, 0, 0}，{100, 100, 100} 2 記入してください
    {1, 1, 2}，{2, 2, 3} 2 記入してください
    元の配列 0 記入してください

    この課題ではrowsは0〜2とします．rows=3を渡すと存在しない3行目へ進むので，試しません．(double)totalをtotalに変えると整数除算になり，小数部分が失われます．表示桁数を増やしても，除算で失った情報は戻りません．

    配列へのポインタで表す¶

    関数の宣言をvoid print_means(int (*a)[COLS], int rows)に変え，出力が変わらないことを確認します．括弧を落としてint *a[COLS]とすると，仮引数はint **となり，別の型です．この形へ変えたまま警告を無視して実行してはいけません．

    mainで次の式を確認します．sizeofの結果を表示するなら%zuを使います．数値は処理系に依存するため，まずsizeof(int)を使う式で説明してください．

    式 意味
    sizeof a 2 * COLS * sizeof(int)
    sizeof a[0] COLS * sizeof(int)
    sizeof a / sizeof a[0] 行数2
    sizeof a[0] / sizeof a[0][0] 列数3

    これらはmainの実際の配列に対する結果です．関数内の仮引数aにsizeof a / sizeof a[0]を適用して，行数を調べてはいけません．関数に渡ったaはポインタだからです．

    行平均と全体平均¶

    この例の全体平均は3.5です．行平均2.0と5.0の平均でも一致しますが，それは行の要素数が同じだからです．行の長さが異なる場合に行平均を単純に平均すると，全要素の平均にはなりません．発展課題では，長さの違う行を使ってこの点も考えます．

    全体平均を返す関数を追加する場合は，rows>=1を条件にし，doubleで合計してsum / ((double)rows * COLS)を返せます．rows=0のときに0で割らないよう，仕様を決めてから書きます．行平均を表示する関数がrows=0で何もしないことと，平均値を返す関数の空入力の扱いは同じではありません．

    課題4　二次元配列の行を交換する¶

    SwapRowsプロジェクトを作り，3行9列の文字配列でtoyama，ishikawa，fukuiを保存します．2行目と3行目を交換してください．この課題では行のアドレスを入れ替えるのではなく，9個のcharを交換します．

    ヒント

    行は配列なので，names[i] = names[j];とは書けません．列cを0〜WIDTH−1まで進め，各文字を一時変数で交換します．終端や初期化で0になった残りの要素も含めて交換します．

    実行前に結果を予測し，実行後に結果とその理由を記録してください．

    交換前後の内容を描く¶

    行 交換前の9要素 交換後の9要素
    0 t o y a m a 0 0 0 t o y a m a 0 0 0
    1 i s h i k a w a 0 f u k u i 0 0 0 0
    2 f u k u i 0 0 0 0 i s h i k a w a 0

    表の0は文字'0'ではなく，値0のcharです．行の開始位置は変わっていません．その位置に保存されている内容が変わっています．課題2では文字列本体を動かさず，配列中のポインタを変えました．図でこの違いを説明してください．

    終端も交換する理由¶

    短いfukuiの5文字だけをishikawaの先頭へ上書きしても，直後に終端を書かなければ余分な文字が表示されます．また片方の文字列の終端までしか交換しないと，長い方の残りを正しく移せません．本課題では固定幅全体を交換することで，長さが違う場合も扱います．

    swap_rows(names, 1, 1);なら内容は変わりません．swap_rows(names, 1, 2);を2回実行すると元へ戻ります．初期値のfukuiを空文字列""へ変更しても，1回の交換後は2行目が空行，3行目がishikawaになります．各ケースを別々に確認してください．

    比較すること：ポインタ版は文字列の長さに関係なく一定個数のポインタ代入で交換できます．行交換版はWIDTH回の反復が必要です．一方，二次元配列は本体を連続した固定幅の領域として確保できます．どちらも同じ目的に使えますが，データ構造と操作の費用が異なります．

    発展1　長さが異なる行を扱う¶

    RaggedRowsプロジェクトでは，3要素の行と2要素の行をポインタ配列へまとめます．配列本体と，先頭を集めた配列と，長さを保存した配列の3種類を区別してください．

    row0 sum=6
row1 sum=9
original=40

    ここではポインタ配列をint **で指せます．二次元配列int a[2][3]をint **で指すのとは違います．p[1]の場所には実際にint *が保存されています．ポインタ配列を用意しただけではrow0やrow1の内容はコピーされません．そのためp[1][0]の変更はrow1[0]にも反映されます．

    長さも一緒に交換する¶

    rows[0]とrows[1]を交換する場合は，lengths[0]とlengths[1]も交換します．ポインタだけを交換すると，2要素の行を長さ3として読んでしまいます．不一致のまま実行するのではなく，どの添字が範囲外になるかを図で確認してください．

    反復処理の前に次の断片を追加します．両方の交換を一組として扱います．

    int *temp_row = rows[0];
rows[0] = rows[1];
rows[1] = temp_row;
int temp_length = lengths[0];
lengths[0] = lengths[1];
lengths[1] = temp_length;

    実行前に結果を予測し，実行後に結果とその理由を記録してください．

    交換前の全要素の平均は15 / 5 = 3.0です．行平均2.0と4.5を単純に平均した3.25とは一致しません．要素数が異なる場合は，各行の合計と個数を集計してから割ります．

    二重ポインタの別の使い方¶

    次の例では，pが指すのはポインタ変数1個です．pを進めて別のポインタがあるかのように使いません．

    const char *animal = "dog";
const char **p = &animal;
printf("%s\n", *p);
*p = "cat";
printf("%s\n", animal);

    dog，catと表示します．変更したのはanimalが指す場所であり，dogという文字列そのものではありません．次の例は，各ポインタが1文字だけを指します．

    char first = 'a', second = 'b';
char *letters[] = {&first, &second};
char **p = letters;
for (int i = 0; i < 2; ++i) {
    printf("%c\n", *p[i]);
}

    実行前に結果を予測し，実行後に結果とその理由を記録してください．

    発展2　型の説明¶

    int a[2][3]; と int *rows[2]; のsizeofは何を数えるでしょうか．実際の数値だけでなく式で答えてください．

    アドレスが似ていても型は違う¶

    int a[2][3] = {{1, 2, 3}, {4, 5, 6}};を宣言したとして，次の型を書いてください．sizeofや&で配列が変換されない場合と，通常の式で変換される場合を区別します．

    式 解答欄で説明すること
    a + 0 何を1単位とするポインタか
    a[0] + 0 何を1単位とするポインタか
    &a 配列全体を指す型
    &a[0] 1行を指す型
    &a[0][0] 整数1個を指す型

    さらにint (*q)[3] = a;に対する&qはint (**)[3]です．配列のアドレス&aとは別物で，qというポインタ変数自身を指しています．分からなくなったら，変数の宣言を先に読み，「その変数の型へのポインタ」を考えてください．

    連続性と範囲¶

    int *p = &a[0][0];としてp[0]〜p[5]を走査する方法は使いません．最初の行の範囲を越えてしまうためです．二次元配列ではa[r][c]を使います．一次元として扱う課題ならint flat[6] = {1, 2, 3, 4, 5, 6};を最初から宣言します．幅3の行列として読むならflat[r * 3 + c]を使えます．

    「メモリ上で隣にある」「同じアドレスのように表示される」「正しい型で範囲内にアクセスできる」は同じ意味ではありません．実行して期待値になったことだけで，型や境界の誤りを正当化しないようにしましょう．

    確認問題¶

    1. int *pを関数内から変更するには，何を渡すか．
    2. **pp = 10;と*pp = &x;では何が変わるか．
    3. find_maxで最大値が2個あると，どちらを選ぶか．
    4. ポインタ配列を交換すると，文字列本体は移動するか．
    5. char *names[]とchar names[][9]は何を保存するか．
    6. 二次元配列の関数引数で列数が必要なのはなぜか．
    7. ポインタ配列の行を交換する際，長さも交換する理由は何か．
    8. int **へキャストすれば二次元配列を渡せるか．
