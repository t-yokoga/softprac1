    第11回　構造体¶

    到達目標¶

    • 異なる型の値を構造体へまとめられる．
    • typedef，メンバ参照，構造体のコピーを使える．
    • 値渡しとポインタ渡しを目的に応じて選べる．

    1　関連するデータをまとめる¶

    前回までとのつながり¶

    第10回では，ファイルへ保存するデータの個数・順序・意味を決めました．今回は，プログラムの中でも関連するデータをひとまとめにします．例えば学生の名前と点数を別々の配列で管理すると，並べ替えるときに対応を崩すおそれがあります．1人分を構造体として表せば，名前と点数を一緒に扱えます．

    実習はWindowsのVisual Studio，C17，.cファイルを使います．同じPointやStudentの定義を，1つのファイルへ何度も貼り付けないでください．各例は独立したものとして読み，実際のプログラムでは必要な型をmainより前に1回ずつ定義します．入力はソース中の初期値を使い，動的メモリ確保はまだ使いません．

    配列は同じ型の値を並べます．構造体は，座標のxとy，学生の名前と点数のように，意味のあるまとまりを表します．メンバは異なる型でもかまいません．

    struct point {
    double x;
    double y;
};
struct point p = {1.0, 2.0};

    型の定義の末尾にはセミコロンが必要です．変数pのメンバへは p.x，p.y でアクセスします．p.x = 3.0; はxだけを変更します．構造体の中に配列や別の構造体も置けます．ただし，自分自身を直接メンバにして無限の大きさにすることはできません．自分と同じ型へのポインタを置く方法は可能です．

    型の定義と，変数の作成¶

    struct pointは型の名前で，pointの部分を構造体タグと呼びます．上の型定義だけでは，座標を保存する変数pは作られません．struct point p;と書くことで，その型の変数を定義します．この変数を構造体の実体，あるいはインスタンスと呼ぶことがあります．

    型の定義：struct point          その型の変数
  xというdoubleを持つ           p [ x:1.0 | y:2.0 ]
  yというdoubleを持つ           q [ x:5.0 | y:8.0 ]
  （データの形を決める）          （それぞれ別の保存場所）

    実際の配置には隙間が入る場合がありますが，まずは各メンバに名前が付いた箱として考えます．構造体のメンバxは，単独の変数名xではありません．どの構造体のxかをp.xやq.xで指定します．

    型の定義と変数の定義を同時に書くこともできます．ただし学習中は，型と変数を分けて書くと読みやすくなります．

    struct position {
    double x;
    double y;
} origin;

    これはstruct positionという型を定義し，originという変数も作っています．最後のセミコロンを忘れると，次の行付近に診断が出ることがあります．型名なのか，変数名なのかを確認してください．

    初期化しないまま使わない¶

    関数の中でstruct point p;とだけ書いた場合，メンバは自動的に0にはなりません．p.xだけに代入してp.yを表示するような使い方は避けます．次のように両方を初期化します．

    struct point p = {1.0, 2.0};
struct point zero = {0};

    最初の例は宣言順にx=1.0，y=2.0です．zeroはメンバが0.0で初期化されます．初期化リストで省略したメンバは0に相当する値で初期化されますが，「初期化を何も書かなかったローカル変数」とは違います．パディングを含む全バイトが必ず0になる，という意味でもありません．

    2　typedefで別名を付ける¶

    typedef struct {
    double x;
    double y;
} Point;

    これで Point p; と書けます．typedefは型に別名を付ける仕組みです．オブジェクトを作る操作や，メモリを動的に確保する操作ではありません．

    タグ付きとタグなしの書き方¶

    上の例はタグを省略しています．タグも付けたい場合は，次のように書けます．

    typedef struct point {
    double x;
    double y;
} Point;

    この定義ではstruct pointとPointが同じ型を表します．先にstruct pointを定義してから，別の行でtypedef struct point Point;と書くこともできます．どちらか1つの方法を選び，同じ場所で重複して定義しないようにします．

    名前・表記 役割
    struct point タグpointを使った構造体型の名前
    Point typedefで付けた型の別名
    Point p;のp その型で作った変数
    p.xのx メンバ名

    typedefは構造体以外にも使えます．typedef int JPY;ならJPY price = 100;と書けますが，JPYはintの別名です．通貨を区別する新しい検査規則が自動的に生まれるわけではなく，printfの書式もintと同じ%dです．

    指定初期化子でメンバ名を明示する¶

    Point a = {.x = 1.0, .y = 2.0};
Point b = {.y = 2.0, .x = 1.0};
Point c = {.x = 3.0};

    ドットでメンバ名を指定する初期化を，指定初期化子と呼びます．aとbは同じメンバ値を持ちます．指定しているので，初期化リストを宣言順に並べる必要はありません．c.yは省略されているため0.0になります．C17で利用できます．C++の初期化規則と混同しないよう，この講義では.cファイルを使います．

    メンバが増えたり似た型のメンバが並んだりする場合，名前付きの初期化は取り違えを減らせます．一方，初期化する内容が短く明確なら{1.0, 2.0}という書き方も有効です．

    後からまとめて代入する：複合リテラル¶

    変数を宣言した後にp = {1.0, 2.0};とは書けません．波括弧だけの初期化リストは，そのまま代入式の右辺にはならないためです．型名を付けた複合リテラルを使えば，構造体の値として代入できます．

    Point p = {0};
p = (Point){.x = 1.0, .y = 2.0};

    (Point){...}はPoint型の名前のないオブジェクトを表します．上の例はそこからメンバの値をpへ代入します．単に型名を付けずに波括弧を書くのとは違います．本回では代入や値渡しに使い，ブロック内で作った複合リテラルのアドレスを外へ持ち出す使い方はしません．対象の寿命を越えてポインタを使えないことは，第8回と同じです．

    3　コピーできるもの・できないもの¶

    同じ構造体型なら Point b = a; や b = a; でメンバの値をコピーできます．配列メンバもその一部としてコピーされます．構造体同士の a == b は使えないので，必要なメンバを比較します．

    ポインタメンバの場合はポインタ値だけがコピーされます．指す先のデータは増えません．これを浅いコピーと呼びます．先のデータも複製するには別途領域を用意してコピーする必要があります．第13回では解放の責任とも結び付けます．

    メンバ 構造体代入の結果
    int score 整数値がコピーされる
    char name[16] 16個の配列要素がコピーされる
    char *name ポインタがコピーされ，同じ先を指す

    配列そのものと，配列を持つ構造体¶

    通常の配列では，int b[3] = a;や，宣言後のb = a;で配列全体をコピーすることはできません．一方，次の型は構造体なので代入できます．

    typedef struct {
    int values[3];
} Triple;
Triple a = {{1, 2, 3}};
Triple b = a;
b.values[0] = 100;

    代入直後                      b.values[0]を変更した後
a [1][2][3]                   a [  1][2][3]
b [1][2][3]                   b [100][2][3]

    aとbはそれぞれ自分の配列を持ちます．構造体の代入という規則により配列メンバの値もコピーされるのであって，配列変数に対する代入が一般に可能になったわけではありません．b.values自体を別の配列で置き換えることはできません．要素を代入するか，構造体全体を代入します．

    配列の文字列とポインタの文字列¶

    typedef struct { char text[7]; } TextArray;
typedef struct { char *text; } TextPointer;

    TextArrayは最大6バイトの文字列と終端を内部に持てます．TextPointerは文字列本体を持たず，別の場所にあるcharを指します．この2つでは，構造体の外にあるものが違います．

    配列メンバをコピー
a1 [ h o g e \0 0 0 ]       a2 [ h o g e \0 0 0 ]
    自分の文字配列               自分の文字配列

ポインタメンバをコピー
p1 [アドレス] ----+
                 +----> buffer [ h o g e \0 ]
p2 [アドレス] ----+

    配列版でa1だけを書き換えるとa2は変わりません．ポインタ版で共有するbufferを書き換えると，p1.textからもp2.textからも変更が見えます．ただしp1.textそのものを別の配列へ向けても，p2.textの値は変わりません．「ポインタの先の変更」と「ポインタ値の変更」を区別してください．

    リテラルを指す場合と寿命¶

    変更しない文字列リテラルを参照するなら，メンバをconst char *textにします．その構造体をコピーしても，文字列リテラルは書き換え可能にはなりません．constを外したりキャストしたりして書き込む実験は行いません．

    関数内のchar配列を指すポインタを構造体に入れ，その構造体を返した場合，返す構造体自体は値としてコピーできます．しかし，指していたローカル配列は関数終了時に寿命が終わるため，返されたポインタを使えません．配列を構造体の内部に持たせて値として返す場合とは違います．

    本回のポインタメンバは，mainなど呼び出し元で用意した配列を借りて使います．構造体が配列を自動で確保・複製・解放するわけではありません．第13回では，動的に確保したデータを誰が解放するかも明示します．

    等しさは，意味のあるメンバで判定する¶

    Pointのaとbが同じ座標か調べるなら，必要な条件はa.x == b.x && a.y == b.yです．構造体同士の==や!=は使えません．数値演算で得たdoubleを比較する場合には，第3回で扱った丸め誤差と許容誤差の考え方も必要です．

    Studentなら，名前と点数の両方を等しさの条件にするのか，名前だけで検索したいのかによって処理が変わります．文字列はstrcmpで内容を比較します．構造体を定義しても，「どのメンバが同じなら同じ学生か」という仕様までは決まりません．

    4　関数に渡す・関数から返す¶

    構造体は値として引数に渡し，戻り値として返せます．Point moved(Point p, ...) のpはコピーなので，関数内でpを変更しても呼び出し元は変わりません．戻り値を受け取って使います．

    呼び出し元を直接変更するなら void move_in_place(Point *p, ...) とします．p->x は (*p).x と同じ意味です．読み取りだけなら const Point *p として，関数の意図を示せます．

    値渡しで2つの点を足す¶

    Point add_point(Point a, Point b)
{
    a.x += b.x;
    a.y += b.y;
    return a;
}

    呼び出し元でa=(10, 2)，b=(3, 5)なら，結果は(13, 7)です．関数内のaはコピーなので，元のaは(10, 2)のままです．戻り値は構造体の値なので，Point result = add_point(a, b);と受け取れます．本回の座標は有限な−1000〜1000程度の値を使い，計算結果も十分に範囲内に収めます．

    関数内のローカルなPointを値としてreturnすること自体は問題ありません．呼び出し元が受け取る値があるからです．そのローカル変数のアドレスを返すこととは区別します．また，add_point(a, b);と呼ぶだけで戻り値を保存しなければ，呼び出し元の座標は変わりません．

    ポインタでメンバを操作する¶

    Point point = {3.0, 10.0};
Point *q = &point;
q->x = 5.0;

    point.xは5.0になります．qはPointへのポインタで，q->xはその先のPointのxです．*q.xは*(q.x)として解釈されるため，Pointへのポインタqには使えません．間接参照してからドットを使うなら，(*q).xという括弧が必要です．

    対象 正しい表記 意味
    Point point point.x 変数のメンバ
    Point *q q->x ポインタの先のメンバ
    Point *q (*q).x 上と同じ
    Point points[3] points[i].x 配列のi番目のメンバ
    Point *q = points q[i].x 同じ配列要素のメンバ

    ポインタは有効なPointを指している必要があります．NULLや寿命の終わった対象へ->を使うことはできません．->という表記が対象の存在を保証するわけではありません．

    値渡しとポインタ渡しを選ぶ¶

    目的 関数の形の例 呼び出し元への影響
    小さな構造体から計算結果を作る Point moved(Point p, ...) 元の構造体は変更しない
    構造体を直接更新する void move_in_place(Point *p, ...) メンバを書き換えられる
    構造体を読み取る void print_point(const Point *p) この経路では直接のメンバを書き換えない

    ポインタを渡す場合も，ポインタの値そのものはコピーされます．そのコピーが同じ構造体を指しているので，先のメンバを変更できます．Cに特別な「参照渡し」の構文があるということではありません．

    例えばdouble values[1000]を内部に持つ大きな構造体は，値として渡すと意味としては配列を含む構造体のコピーになります．実際のコピー命令や費用は最適化や呼び出し規則にも左右されるので，必ず遅いとは断定できません．読み取りだけならconst付きのポインタを使う選択肢があります．一方，小さなPointの値渡しは処理の意図を表しやすい書き方です．

    const付きポインタも，構造体の外のデータまで一律に読み取り専用にするものではありません．char *をメンバに持つ構造体では，そのメンバが指す変更可能な文字配列は別の対象です．文字まで変更させない設計なら，メンバ側の型もconst char *とすることを考えます．

    #include <stdio.h>
typedef struct {
    double x;
    double y;
} Point;
typedef struct {
    char name[16];
    int score;
} Student;
Point moved(Point p, double dx, double dy)
{
    p.x += dx;
    p.y += dy;
    return p;
}
void move_in_place(Point *p, double dx, double dy)
{
    p->x += dx;
    p->y += dy;
}
int main(void)
{
    Point a = {1.0, 2.0};
    Point b = moved(a, 3.0, -1.0);
    printf("a=(%.1f, %.1f) b=(%.1f, %.1f)\n", a.x, a.y, b.x, b.y);
    move_in_place(&a, 3.0, -1.0);
    printf("a=(%.1f, %.1f)\n", a.x, a.y);
    Student s = {"Aki", 80};
    Student t = s;
    t.name[0] = 'M';
    printf("%s %s\n", s.name, t.name);
    return 0;
}

    structs.c

    a=(1.0, 2.0) b=(4.0, 1.0)
a=(4.0, 1.0)
Aki Mki

    名前の例ではtの配列だけを変更しているため，sの名前は変わりません．

    実行前後を表で追う¶

    処理 a b 注目すること
    aの初期化 (1, 2) まだない 2つのメンバを初期化
    b = moved(a, 3, −1)に相当する初期化 (1, 2) (4, 1) aのコピーを変更して返す
    move_in_place(&a, 3, −1) (4, 1) (4, 1) aそのものを変更

    最後にはaとbのメンバ値が一致しますが，同じ変数になったわけではありません．その後にb.xだけ変更してもa.xは変わりません．値が同じであることと，保存場所が同じであることは別です．

    名前の例でも同様です．tはsからコピーした別のStudentで，t.name[0]だけを'A'から'M'へ変更しています．これは学生名を置換する一般的な関数ではなく，内部配列の独立性を観察する例です．

    6　構造体配列とサイズ¶

    Student class_list[3] = {{"Aki", 80}, {"Ren", 70}, {"Mio", 90}}; とすれば，class_list[i].score で各点数を扱えます．配列の境界と文字列の容量，両方に注意が必要です．

    構造体にはアラインメントを満たすためのパディング（隙間）が入ることがあります．sizeofがメンバのサイズの合計と等しいとは限りません．memcmpで構造体を丸ごと比べる方法は，意味のあるメンバ比較の代わりにはなりません．また，メモリ全体をfwriteするだけでは環境に依存しない保存形式になりません．

    「構造体の配列」と「配列メンバ」¶

    Student class_list[3]
  [0] [ name[16] | score ]
  [1] [ name[16] | score ]
  [2] [ name[16] | score ]

    class_listはStudentが3個の配列です．1個のStudentの中にnameという16個のcharの配列があります．class_list[1].name[0]は，2人目の名前の先頭文字です．外側の人数の範囲と，内側の名前の容量の両方を確認します．

    構造体配列も，関数へ渡すと先頭要素へのポインタとして扱われます．仮引数const Student a[]はconst Student *aと同じ意味です．Studentを1個値渡しするとコピーされる一方，Student配列を引数へ渡しても配列全体は自動ではコピーされません．

    固定長ならenum { COUNT = 3 };を用いてStudent a[COUNT]と書けます．Student a[] = {...};の要素数を初期化リストから決める書き方も固定長です．実行時の変数nによる可変長配列は，このVisual Studio向けの資料では使いません．

    配置をoffsetofで観察する¶

    例えばchar，int，charを持つ構造体では，整数を適切な境界へ置くために隙間が生じることがあります．メンバが何バイト目から始まるかは，stddef.hのoffsetofで調べられます．戻り値はsize_tなので%zuで表示します．

    typedef struct {
    char tag;
    int count;
    char flag;
} Record;

    通常のVisual Studio x64の既定設定で，intが4バイトなら，tagが0，countが4，flagが8バイト目，全体が12バイトという配置になります．これは環境依存の観察例で，すべてのC処理系での固定仕様ではありません．パディングを削る設定をこの課題のために変更する必要はありません．

    一例：Record 1個
[tag][隙間3バイト][count 4バイト][flag][隙間3バイト]
  0                4             8                  合計12

    offsetofはメンバの位置を調べるためのマクロです．異なるメンバのアドレスを適当なポインタ型へ変換して引き算するのではなく，標準の仕組みを使います．offsetofの仕様とMicrosoftのx64配置規則も参照できます．

    7　入れ子の構造体と長方形¶

    Pointを2個と名前を持つ構造体を定義します．この節では座標の下限をlower，上限をupperと呼びます．名前は最大20バイトと終端です．

    enum { MAX_NAME = 20 };
typedef struct {
    Point lower;
    Point upper;
    char name[MAX_NAME + 1];
} Rect;

Rect r = {
    .lower = {.x = 1.0, .y = 1.0},
    .upper = {.x = 3.0, .y = 4.0},
    .name = "sample"
};

    r.lower.xはrのlowerというPointのxです．Rect *q = &r;ならq->lower.xで同じ値を参照します．最初に->でRectの先へ進み，lowerはポインタではなくPoint本体なので，次はドットを使います．

    式 この例での値
    r.lower.x 1.0
    (r.lower).x 1.0
    q->lower.x 1.0
    (q->lower).x 1.0

    本回の配列メンバは幅を明示した固定長です．名前を普通の文字配列として保持したいのに，幅を省略してよいとは考えません．Cには末尾の配列について特別な使い方もありますが，それは別のメモリ管理を必要とするため本回では扱いません．

    点が範囲に入るか判定する¶

    長方形の下限を含み，上限を含まない範囲として，次の条件を採用します．

    int contains(Point p, Rect r)
{
    return p.x >= r.lower.x && p.x < r.upper.x &&
           p.y >= r.lower.y && p.y < r.upper.y;
}

    lower=(1, 1)，upper=(3, 4)なら，(2, 2)は含み，(1, 1)も含みます．(3, 2)や(2, 4)は含みません．このように一方だけを含む区間を半開区間と呼びます．隣り合う領域の境界を両方に数えない設計に使えます．すべての図形判定で必ずこの規則を使うわけではなく，課題の仕様として明示しています．

    幅または高さが0なら，この条件では含まれる点はありません．面積0の線や点まで含めたいなら別の仕様が必要です．また，画面座標ではyが下へ増える場合もありますが，ここでは見た目の上下ではなく，数値の下限・上限で考えます．

    2点の順番をそろえる¶

    lowerとupperに逆向きの2点が入っていても扱いたい場合は，xとyそれぞれの小さい方をlowerへ，大きい方をupperへ置きます．2点を丸ごと交換するだけでは，(1, 4)と(3, 1)のような交差した組合せを直せません．

    Rect normalized(Rect r)
{
    Rect result = r;
    if (r.lower.x > r.upper.x) {
        result.lower.x = r.upper.x;
        result.upper.x = r.lower.x;
    }
    if (r.lower.y > r.upper.y) {
        result.lower.y = r.upper.y;
        result.upper.y = r.lower.y;
    }
    return result;
}

    最初にresult=rとしているので，名前も含めて全メンバが引き継がれます．未初期化のRectを用意して座標だけ埋め，名前を未設定のまま返すことはしません．rを値渡ししているので，元の長方形は変わりません．Rect standard = normalized(r);と受け取り，contains(p, standard)で判定します．

    この例はすべての座標が有限値であることを前提とします．NaNの比較などを含む汎用的な図形ライブラリではありません．構造体によって関数の引数と結果を1つの意味のあるまとまりにできる点を学びましょう．
