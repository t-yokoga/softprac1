    第7回　入出力¶

    到達目標¶

    • 標準入力・標準出力・標準エラー出力を区別できる．
    • EOFを正しく見分けながら文字を読み，容量を指定して行を読める．
    • リダイレクトとパイプによる接続を説明できる．

    1　プログラムと外部をつなぐストリーム¶

    前回とのつながりと準備¶

    第6回では，プログラムの中に配列として用意した文字列を扱いました．今回は，プログラムを実行している間に外から受け取るデータ（キーボードから打ち込んだ文字など）を扱います．外から来るデータは，どれくらいの量があるのか，どこで終わるのかが，プログラムに前もって分かるとは限りません．そこで，データを読み取る，入力が終わったかを判断する，読んだ結果を保存するという3つの仕事に分けて考えましょう．

    作業場所はPL1\week07です．第1回の手順でプロジェクトを作り，「C17」「Cとしてコンパイル」「警告レベル4」を設定します．講義例の確認には空のプロジェクトWeek07を1つ作り，ソースファイルmain.cを1つだけ追加します．講義に出てくるプログラムは，このmain.cに書いて実行します．演習課題では，演習ページの一覧に従ってプログラムごとに別のプロジェクトとファイルを作成します．完全なプログラムを試すときは内容全体を置き換え，短い断片を試すときはmain関数内の対応する処理を置き換えます．置き換える前のソースは，PL1\week07\recordsなどプロジェクト外のフォルダへ保存してください．

    一部のプログラムはファイルとしてダウンロードできますが，ダウンロードしたファイルはプロジェクトに追加しないでください．1つのプロジェクトにmain関数が2つ以上あると，ビルドでエラーになるからです．ほかの.cファイルをすでに追加してしまった場合は，ソリューションエクスプローラーでそのファイルを右クリックし，「削除 → プロジェクトから除外」を選んで，main.cだけを残してください．

    保存したらCtrl+Shift+Bでビルドし，成功したことを確かめてからCtrl+F5で実行します．

    キーボードからの入力は，Visual Studioのエディタではなく，実行すると開くウィンドウ（コンソール）に打ち込みます．

    入出力を使うプログラムには#include <stdio.h>が必要です（strlenを使う例では#include <string.h>も必要です）．この回は，コマンドを打ち込む実習は行いません．後半で学ぶリダイレクトとパイプは，つながり方を表す図で理解します．

    ストリームは，データを先頭から順番に読んだり書いたりするための仕組みです．データが1列に並んで流れてくる「流れ」だと考えてください．<stdio.h>には，最初から使える3つのストリームが用意されています．

    名前 役割 ふだん実行したときのつながる先
    stdin 標準入力 キーボード
    stdout 標準出力 画面
    stderr 標準エラー出力 画面

    printfは標準出力に書きます．エラーのメッセージは，fprintf(stderr, "input error\n");のように書くと，標準エラー出力という別の出力先に書けます．どちらも同じ画面に表示されますが，別々のストリームです．

    ストリームを流れてくるデータは，「改行で区切られた行がいくつか並んだもの」になっているとは限りません．最後の行に改行が付いていない入力や，何も入っていない空の入力もあります．また，第6回で学んだ文字列の終わりの印'\0'が，入力の最後に自動で付いてくるわけでもありません．読んだデータを配列に保存して文字列として使うときは，プログラムで'\0'を付ける必要があります．

    データがキーボードから来ても，ファイルから来ても，プログラムから見れば「順番に読めるストリーム」として同じように扱えます．このため，同じプログラムのまま，入力元を別のものに付け替えることができます．後の回でファイルを直接開くときも，同じストリームの考え方を使います．

    2　1文字ずつ読む¶

    getcharとputcharの役割¶

    getchar()は，読み取った1バイトの値，または EOF をint型で返します．EOF（End Of File の略）は，「入力が終わった」または「読み取りに失敗した」ことを知らせる特別な値で，文字ではありません．

    getcharが返す値は，文字なら0〜255のどれか，入力の終わりや失敗ならEOFです．つまり全部で257通りの値があります．intの変数なら257通りをすべて区別して保存できますが，charの変数は1バイトなので256通りしか入りません．1つ足りないので，どこかで2つの値が同じになってしまいます．

    例えばMSVCでは，値255の文字をcharの変数に入れると，EOFと同じ負の値になります．すると，その文字を読んだところで「入力が終わった」と誤って判断し，ループが途中で止まります．別の環境では逆に，EOFをcharの変数に入れると255に変わり，EOFと比べても等しくならないので，ループがいつまでも終わりません．

    どちらもcharの変数に入れた時点で起きる問題です．getcharの戻り値は必ずintの変数で受け取りましょう．

    関数 読む・書く先 単位 戻り値
    getchar() stdin 1バイト 読んだ文字の値（0〜255），またはEOF
    putchar(ch) stdout 1バイト 書いた文字の値，失敗したときはEOF

    getcharのcharは，英語のcharacter（文字）の略です．「単語」を読む関数ではなく，1回呼ぶたびに1文字（正確には1バイト）だけを読みます．

    例えば112と入力してEnterを押した場合，最初のgetcharが返すのは整数の112ではなく，文字'1'を表す値です．もう一度呼ぶと次の'1'，その次は'2'，最後に改行'\n'を読みます．つまり112は，「1」「1」「2」「改行」の4文字としてプログラムに届きます．

    なお，日本語の「あ」のような文字は，コンピュータの中では複数のバイトで表されることがあります．その場合，画面で見える1文字を読み終えるまでに，getcharを何回か呼ぶことになります．

    putcharも1回呼ぶたびに1文字だけを書きます．putchar('a');はaを書くだけで，改行は自動では付きません．行を変えたいときは，putchar('\n');も呼びます．

    EOFはstdio.hの中で決められている負の整数です．プログラムでは−1のような数を直接書かず，必ずEOFという名前を使って比べます．printf("EOF=%d\n", EOF);を実行すれば値を確かめられますが，表示された数をキーボードから打ち込んでも，入力の終わりにはなりません．打ち込んだものは，112のときと同じように，'-'や数字の文字としてgetcharに届くだけです．

    実行例：112を1文字ずつ読む¶

    次のプログラムでmain.cの中身をすべて置き換えて実行し，112と打ってEnterを押します．出力に出てくる数値は，それぞれの文字に割り当てられた番号（ASCIIコード）です．

    #include <stdio.h>
int main(void)
{
    int ch;
    while ((ch = getchar()) != EOF) {
        if (ch == '\n') {
            printf("new line: %d\n", ch);
            break;
        }
        printf("character=%c value=%d\n", ch, ch);
    }
    if (ferror(stdin)) {
        fprintf(stderr, "input error\n");
        return 1;
    }
    return 0;
}

    入力は次の1行です．

    112

    プログラムの出力は次のとおりです．

    character=1 value=49
character=1 value=49
character=2 value=50
new line: 10

    '1'は49，'2'は50，改行は10という番号で表されています．プログラムは112を整数の112に直しているわけではありません．改行を含めて4回読み取り，改行を読んだところでbreakによってループを抜けて終わります．

    #include <stdio.h>
int main(void)
{
    int ch;
    while ((ch = getchar()) != EOF) {
        if (putchar(ch) == EOF) {
            fprintf(stderr, "output error\n");
            return 1;
        }
    }
    if (ferror(stdin)) {
        fprintf(stderr, "input error\n");
        return 1;
    }
    return 0;
}

    echo.c

    while ((ch = getchar()) != EOF)は，次の順に動きます．①getcharで1文字読む，②読んだ値をchに代入する，③chがEOFでないかを調べる．EOFでなければループの中に入り，その文字をputcharで出力します．EOFのときはループを抜けるので，EOFそのものをputcharに渡すことはありません．

    条件の中で(ch = getchar())を括弧で囲んでいる点に注意してください．括弧を外してch = getchar() != EOFと書くと，!=の方が=より先に計算されます．そのためchには読んだ文字ではなく，比較の結果である0か1が入ってしまいます．第3回で学んだ演算子の優先順位と代入式の値に関わる部分なので，括弧は省かないでください．

    ループが終わる理由には，入力の終わりと読み取りエラーの2つがあり，どちらも同じEOFで知らされます．そこで，ループを抜けた後にferror(stdin)で，エラーだったかどうかを確かめています．また，putcharも書き込みに失敗するとEOFを返すので，その場合はエラーメッセージを出して終わります．

    読み込みと条件を分けて，次のように書くこともできます．流れは上と同じです．ここでは流れだけを示すため，出力エラーの処理は省いています．実行するときは，上の複写プログラム全体をmain.cへコピーして使ってください．

    int ch = getchar();
while (ch != EOF) {
    putchar(ch);
    ch = getchar();
}

    この書き方では，ループの前とループの最後の2か所にgetcharを書く必要があります．最後のgetcharを書き忘れると，chが変わらないので，同じ文字をいつまでも出力し続けます．条件の中で読み込む書き方なら，getcharは1か所で済みます．

    Visual Studioで入力する¶

    Ctrl+F5で実行すると開くコンソールに文字を打ち込み，Enterを押します．画面には，自分が打ち込んだ文字と，プログラムが出力した文字の両方が表示されることがあります．入力を終わりにしたいときは，Windowsのコンソールでは新しい行の先頭でCtrl+Zを押し，続けてEnterを押します．なお，Ctrl+Zを押しても，文字列の終わりの印'\0'が入力されるわけではありません．

    実行例：複写の入力と出力を見分ける¶

    複写プログラムをmain.cにコピーして実行し，abと打ってEnterを押します．ふつうのコンソールでは，次のように2行表示されます．

    ab
ab

    1行目は自分が打ち込んだ文字をコンソールが表示したもの，2行目はputcharが出力したものです．Enterの後も，プログラムは次の入力を待ち続けています．続けて新しい行の先頭でCtrl+Zを押し，Enterを押すと，ループが終わります．上の表示例には，^Zのようなキー操作の表示や，終了後にVisual Studioが出す案内文は含めていません．

    EnterとEOFを区別する¶

    ふつうのコンソールでは，打ち込んだ文字はEnterを押すまでいったんためておかれ，Enterを押した時点で改行も含めてまとめてプログラムに渡されます．ただし，これはコンソールの仕組みによるもので，「getcharは必ずEnterを待つ」というC言語の決まりではありません．まだ読んでいない文字が残っていれば，getcharは待たずにその文字を読みます．

    コンソールで ab と入力してEnter
              ↓
読む順序：    'a' → 'b' → '\n' → 次の入力を待つ
              ↓      ↓       ↓
複写の出力：   a      b      改行
    状況 意味 EOFまで読むループ
    Enterだけ押す 改行1文字が届く（空行） まだ続く
    abの後にEnter a，b，改行が届く まだ続く
    新しい行の先頭でCtrl+Z，Enterを押す これ以上の入力がない 終わる
    強制停止する 実行そのものを途中で止める ループの後の処理（集計の表示など）が行われるとは限らない

    EOFは「入力が終わった」という状態を表す値，'\n'は改行という文字，'\0'は配列の中で文字列の終わりを示す文字です．この3つを混同しないでください．また，入力の終わり（EOF）で集計結果を出すプログラムを強制停止で終わらせても，正しく終わったときと同じ動きにはなりません．デバッグ中は「デバッグの停止」で実行を止められますが，これも入力の終わりとは別のものです．

    #include <stdio.h>
int main(void)
{
    for (int i = 0; i < 3; ++i) {
        printf("before read %d\n", i + 1);
        fflush(stdout);
        int ch = getchar();
        if (ch == EOF) {
            if (ferror(stdin)) {
                fprintf(stderr, "input error\n");
                return 1;
            }
            printf("end of input\n");
            return 0;
        }
        if (ch == '\n') {
            printf("after read: new line\n");
        } else {
            printf("after read: %c\n", ch);
        }
    }
    return 0;
}

    自分が打ち込んだ文字も含めた表示例です．abの行だけが入力で，ほかはプログラムの出力です．

after read: a

after read: b
before read 3
after read: new line

    1回目のgetcharは，Enterが押されるまで待ちます．Enterを押すとa，b，改行の3文字がまとめて渡されるので，2回目と3回目のgetcharは，残っているbと改行をすぐに読みます．入力し直す必要はありません．このプログラムは3回読んだところで終わります．

    読んだ文字を数える・変換する¶

    getcharで1文字読めるたびにカウンタ（数を数える変数）を1増やせば，読み取ったバイト数を数えられます．abcdと打ってEnterを押し，入力を終わりにした場合は，a，b，c，d，改行で5になります．単語の数ではないことに注意してください．なお，Windowsでは読み書きのときに改行が変換されるため，この数がディスク上のファイルのバイト数と同じになるとは限りません．

    また，putchar(ch)の直前にputchar('/');を加えると，入力された各文字の前にスラッシュを付けられます．abと改行を入力すると，出力は/a/b/と改行になります．改行も1文字として扱われるので，改行の前にもスラッシュが付きます．

    第6回の小文字への変換も，配列を使わずに書けます．読み取ったchが'A'〜'Z'のどれかなら小文字に変えてから，putcharで出力すればよいのです．このように，入力を少しずつ読んで処理し，結果を次へ渡していくプログラムをフィルタと呼びます．

    3　行を読む¶

    fgetsでの容量の指定¶

    fgets(配列, 容量, stdin)は，標準入力から1行を読んで配列に保存する関数です．読むのは最大で「容量−1」個の文字までで，読み取りに成功すると，最後に文字列の終わりの印'\0'を付けます．改行まで読めた場合は，改行も配列に入ります．以前のCには容量を指定できないgetsという関数がありましたが，配列からあふれる危険があるため削除されており，この授業のC17では使いません．

    この回では，容量が2以上の配列を使います．fgetsの戻り値は，読み取りに成功すれば配列の先頭を指す値，1文字も読めないまま入力が終わったときや読み取りエラーのときはNULLです．戻り値がNULLでないことを確かめる前に，配列をstrlenや%sに渡してはいけません．NULLが何なのかはポインタの回で詳しく学びます．今は「読み込みに失敗した印」として使ってください．

    例えばHelloと打ってEnterを押すと，配列には'H'，'e'，'l'，'l'，'o'，'\n'，'\0'が入ります．このときstrlenの結果は，改行も数えて6です．最後の改行を'\0'に置き換えると，Helloの長さである5になります．Enterだけを押した空行でも，'\n'と'\0'が入るので，読み込みは成功です．

}

    4　書式付き入出力¶

    出力する型と書式を対応させる¶

    printfでは，%d，%f，%sなどの書式を，渡す値の型に合わせて選びます．一方，scanfは書式に従って入力を読み，値に変換する関数です．例えばscanf("%d", &n)は，変換に成功した項目の数を返すので，その数を確かめる必要があります．変数の前に&を付けて渡す理由は第8回で学びます．

    scanfには，intに入りきらない数が入力された場合や，読み残した改行の扱いなど，注意する点があります．そのため，この回の必須演習はgetcharとfgetsで行います．数字の並びを確かめてから数値に変換する方法は第10回で扱います．

    printfに渡す値 書式 例
    int %d 123
    unsigned int %u，%o，%x 十進，八進，十六進
    long / unsigned long %ld / %lu 値が小さくても型に合わせる
    long long / unsigned long long %lld / %llu 大きな整数
    double（floatは渡すときにdoubleに変換される） %f，%e，%g 小数・指数の形
    size_t %zu sizeofやstrlenの結果
    intとして渡される文字 %c 'A'など
    '\0'で終わる文字列 %s "abc"など
    void * %p (void *)&nなど

    long型の値は，値が小さくても%dで表示してよいわけではありません．書式は実際の型に合わせてください．書式の型・順番・個数を間違えると，未定義動作（何が起きるか決まっていない状態）になることがあり，おかしな表示が出るだけで済むとは限りません．コンパイラが警告を出したら型を確かめてください．間違った書式でどうなるかを試す実験はしないでください．

    MSVCでは，char・short・unsigned char・unsigned shortの値は，printfに渡すときに自動的にintに変換されます（整数拡張）．例えばunsigned char c = 200;は，printf("%d\n", c);で200と表示できます．unsigned intとして表示したいときは，printf("%u\n", (unsigned int)c);のように型をそろえます．floatがdoubleに変換されることと合わせて，宣言した型だけでなく，実際に渡される型を確かめましょう．

    scanfの書式はprintfと同じではない¶

    scanf("ID:%d", &n)は，「ID:という文字の後に続く整数を読み取り，nに保存する」という意味です．ID:13なら成功しますが，ID :13のように決まった部分（ID:）と違う入力では失敗します．戻り値が1であることを確かめてからnを使います．&nのように変数の場所（アドレス）を渡すのは，scanfが呼び出し元の変数に値を書き込めるようにするためです．

    対象 printfで表示 scanfで読み込む
    int n %dにn %dに&n
    float f %fにf（doubleに変換される） %fに&f
    double d %fにd %lfに&d

    scanfの戻り値は，変換して変数に代入できた項目の数です．入力が書式と合わなければ0，1つ目を代入する前に入力が終わった場合などはEOFになることがあります．失敗した入力はそのまま残ることがあるので，同じscanfをただ繰り返すだけでは先に進めない場合もあります．また，%dで数値を読んだ後には改行が残り，次のgetcharやfgetsがその改行を読む点にも注意してください．

    Visual Studioでは，scanfを使うと安全性についての警告が出る場合もあります．この節はコードを読むことと教員による実演で扱い，必須演習はgetcharとfgetsで行います．scanfの書式や型を変えるだけで，どんな範囲外の数値も安全に見つけられるとは考えないでください．

    5　リダイレクトとパイプ¶

    標準入力はいつもキーボード，標準出力はいつも画面，と決まっているわけではありません．リダイレクトは，入力や出力のつながる先をファイルなどに変えることです．パイプは，あるプログラムの標準出力を，別のプログラムの標準入力につなぐことです．

    通常の入力：    キーボード → プログラム → 画面
リダイレクト：  入力ファイル → プログラム → 出力ファイル
パイプ：        プログラムAのstdout → プログラムBのstdin

    パイプを使うために，Cのプログラムに特別な文を書く必要はありません．ストリームのつなぎ替えは，プログラムを実行する側（実行環境）が行います．例えば「文字を小文字にする処理」と「文字数を数える処理」をパイプでつなげば，2つを部品のように組み合わせて使えます．

    この回の演習範囲

    演習ではVisual Studioのコンソールから入力します．リダイレクトとパイプは，つながり方を考える課題で確かめ，コマンドを打ち込む操作は行いません．ファイルを直接開くプログラムは第10回で作ります．

    結果はstdoutに，エラーなどのメッセージはstderrに分けて出しておくと，次のプログラムに渡すデータにエラーメッセージが混ざりにくくなります．データを処理するためのプログラムでは，Text:のような入力案内をstdoutに出してよいかどうかも考える必要があります．

    入力・出力・追記を区別する¶

    コマンドの説明でよく出てくる記号を，操作の手順ではなく意味として整理します．これらはC言語の文法ではなく，プログラムを実行する側で使う，つなぎ方の指定です．

    記号 意味 注意
    < ファイルを標準入力につなぐ getcharを使うプログラムを書き直す必要はない
    > 標準出力をファイルにつなぐ ファイルの元の中身が上書きされることがある
    >> 標準出力をファイルの最後に書き足す 実行するたびに結果が増えていく
    | 左側の標準出力を右側の標準入力につなぐ stderrまで自動で一緒に流れるわけではない

    入力と出力のつなぎ替えを同時に行えば，「入力ファイル → フィルタ → 結果ファイル」という流れを作れます．上書き（>）と書き足し（>>）を間違えると，前の記録を消してしまったり，同じ結果を二重に保存してしまったりします．授業では実際にファイルを上書きする操作は行わず，つなぐ先と結果の違いを考えます．

    小さい処理を組み合わせる¶

    固定の文字列を出力するecho，ファイルの中身を出力するcat，ファイルの一覧を出力するlsのような機能も，文字データを送り出す側として考えることができます．これらの名前は，つなぎ方の例を読むために紹介しているだけで，コマンドを実行する課題ではありません．なお，一覧の表示の形などは，画面に出すときとパイプに渡すときで変わることもあります．

    文字列を出力する処理
  stdout → 小文字化フィルタ → バイト数を数える処理 → 結果ファイル
                 ↓ stderr              ↓ stderr
               診断を画面へ           診断を画面へ

    例えば，上流（送り出す側）がABCと改行を出すなら，小文字にした後はabcと改行です．下流（受け取る側）で改行も数えるなら，結果は4になります．送り出す側を，ファイルの中身を出す処理やファイルの一覧を出す処理に変えても，フィルタの仕組みは変わりません．ただし，上流が改行を付けるかどうかも含めて，実際に流れてくるデータを考える必要があります．

    パイプでつながれた下流のプログラムは，上流がデータを送り終えるまで入力を待つことがあります．プログラムは「画面に見えた順に何でも受け取る」わけではなく，つながっているストリームからデータを読むだけです．また，標準出力と標準エラー出力は，それぞれ別の場所（バッファ）にデータをためてから表示することがあるため，画面に表示された順番が処理した順番と同じとは限りません．画面の並びだけを見て処理の順番を判断しないようにしましょう．

    6　確認の進め方とよくある間違い¶

    症状 確かめること
    Enterを押しても集計が出ない ループの終わる条件が改行なのかEOFなのか
    入力が2回表示される コンソールが表示した入力と，複写の出力を見間違えていないか
    0や1の値しか処理されない getcharへの代入を括弧で囲んだか
    EOFで止まらない 戻り値をcharではなくintの変数に入れているか
    次の行を読むとすぐ空行になる 前の処理が改行を読み残していないか
    長い行の後の入力がずれる 読み残しをどこまで読んだか
    表示が崩れる 書式と引数の型・個数・順番が合っているか
    パイプの下流で数が合わない 入力案内や改行までデータに混ざっていないか

    確かめるときは，まず空の入力，空行，短い1行，複数行の順に試します．次に，配列に入る文字数より少ない場合，ちょうどの場合，超える場合を試します．読み取った1文字，配列に保存した文字列，標準出力に書いたデータを分けて記録しておくと，どこで予想と違う動きになったのかを見つけやすくなります．
