    第7回　入出力¶

    到達目標¶

    • 標準入力・標準出力・標準エラー出力を区別できる．
    • EOFを失わずに文字を読み，容量を指定して行を読める．
    • リダイレクトとパイプによる接続を説明できる．

    1　プログラムと外部をつなぐストリーム¶

    前回とのつながりと準備¶

    第6回では，ソース内に用意した文字列を処理しました．今回は，実行中に外から受け取ったデータを処理します．入力の長さや終了時点をプログラムがあらかじめ知っているとは限りません．データを読む・終了を判断する・結果を書くという役割を分けて考えましょう．

    作業場所はPL1の下のweek07です．第1回の手順で課題ごとに空のプロジェクトを作り，.cファイルを追加します．C17・Cとしてコンパイル・警告レベル4を使います．保存してCtrl+Shift+Bでビルドし，Ctrl+F5で実行します．入力する場所はVisual Studioのエディタではなく，起動したプログラムのコンソールです．

    読み込みの例にはstdio.h，strlenも使う例にはstring.hが必要です．1つのプロジェクトへ複数のmainを入れないでください．この回もコマンド入力の実習は行いません．リダイレクトとパイプは接続図で理解します．

    ストリームは順番にデータを読み書きするための仕組みです．<stdio.h> には標準の3つのストリームが用意されています．

    名前 役割 通常の対話実行での接続先
    stdin 標準入力 キーボード
    stdout 標準出力 画面
    stderr 標準エラー出力 画面

    printfは標準出力へ書きます．エラーは fprintf(stderr, "input error\n"); のように別の出力先へ書けます．どちらも画面に見えていても，同じストリームではありません．

    ストリームは単に「改行で区切られた文字列の集合」とは限りません．最後に改行がない入力や，空の入力もあります．また，第6回の文字列の終端'\0'が，自動的に入力の末尾へ流れてくるわけではありません．配列に保存して文字列として使うなら，終端を付ける必要があります．

    データの出所がキーボードでもファイルでも，プログラムからは順番に読める入口として扱えます．この抽象化により，同じプログラムを異なる入力元へ接続できます．後でファイルを直接開く場合も，ストリームという考え方は共通です．

    2　1文字ずつ読む¶

    getcharとputcharの役割¶

    getchar() は読み取った1バイトの値，またはEOFをintで返します．EOFは入力の終了や読み取り失敗を知らせる特別な値で，文字そのものではありません．charへ先に保存すると，文字とEOFを正しく区別できないことがあります．

    関数 読む・書く先 単位 戻り値
    getchar() stdin 1バイト unsigned charの値をintにしたもの，またはEOF
    putchar(ch) stdout 1バイト 書いた文字の値，失敗時はEOF

    関数名のcharは「単語」ではなく文字を表します．112と入力してEnterを押しても，最初のgetcharが返すのは整数112ではなく文字'1'の値です．続けて呼べば'1'，'2'，改行を順に読みます．日本語の見た目の1文字が，getcharの1回に対応するとは限りません．

    putchar('a');はaだけを書き，改行を自動では追加しません．改行したければputchar('\n');も必要です．EOFはstdio.hで定義される負の整数で，具体的に−1と決め打ちせずEOFという名前で比較します．printf("EOF=%d\n", EOF);で値は確認できますが，その数をキーボードから入力しても入力終了にはなりません．

    複写プログラム¶

    #include <stdio.h>
int main(void)
{
    int ch;
    while ((ch = getchar()) != EOF) {
        if (putchar(ch) == EOF) {
            fprintf(stderr, "output error\n");
            return 1;
        }
    }
    if (ferror(stdin)) {
        fprintf(stderr, "input error\n");
        return 1;
    }
    return 0;
}

    echo.c

    括弧の内側で代入し，その結果をEOFと比較しています．括弧を外すと，演算子の優先順位によって違う意味になるため注意します．入力終了とエラーは同じEOFで知らされるので，ループ後にferrorでエラーを確認します．putcharも失敗時にはEOFを返します．

    while ((ch = getchar()) != EOF)は，①読む，②chへ代入する，③EOFでないか調べる，の順です．条件に成功したときだけ本体へ入り，その文字を出力します．EOF自体はputcharへ渡しません．

    ch = getchar() != EOFとすると，!=の方が先にまとまるため，chへ入るのは読み取った文字でなく比較結果の0か1です．第3回の優先順位と代入式の値を使う例なので，括弧を省かないでください．

    読み込みと条件を分けた次の形も，基本的な流れは同じです．ここでは流れを示すため，出力エラーの処理は省略しています．実行には上の完全なecho.cを使います．

    int ch = getchar();
while (ch != EOF) {
    putchar(ch);
    ch = getchar();
}

    こちらではループ前と本体末尾に読み込みを書きます．末尾のgetcharを忘れると同じ文字を繰り返し出力してしまいます．条件式へ読み込みをまとめる書き方は，その重複を減らしています．

    Visual Studioで入力する¶

    Ctrl+F5で起動したコンソールに文字を入力してEnterを押します．入力した文字の表示と，プログラムによる出力の両方が見えることがあります．Windowsの通常のコンソールでは，新しい行の先頭でCtrl+Z，続けてEnterを押すと入力終了を知らせられます．キー自体が文字列の終端文字'\0'になるわけではありません．

    EnterとEOFを区別する¶

    通常の対話コンソールでは，入力した文字がEnterまでいったん蓄えられ，Enterを押すと改行も含めてプログラムへ渡されます．ただし，この入力方式は実行環境の性質であり，getcharが常にEnterを待つというC言語の規則ではありません．すでに読み取り可能な文字が残っていれば，次の呼び出しはそれを読みます．

    コンソールで ab と入力してEnter
              ↓
読む順序：    'a' → 'b' → '\n' → 次の入力を待つ
              ↓      ↓       ↓
複写の出力：   a      b      改行
    状況 意味 EOFまで読むループ
    Enterだけ押す 改行1文字が届く（空行） まだ続く
    abの後にEnter a，b，改行が届く まだ続く
    新しい行で入力終了を知らせる これ以上の入力がない 終了する
    強制停止する 実行そのものを中断する 終了後の集計処理は保証されない

    EOFは入力の状態，'\n'は改行の文字，'\0'は配列中の文字列の終端です．3つを混同しないでください．通常のEOF終了で集計結果を出すプログラムを，強制停止で終えても同じ動作にはなりません．デバッグ中は「デバッグの停止」で中断できますが，これは入力終了とは別です．

    読んだ文字を数える・変換する¶

    各getchar成功時にカウンタを1増やせば，読み取ったバイト数を数えられます．abcdとEnterを入力して終了した場合は，a，b，c，d，改行で5です．単語数を数えているわけではありません．Windowsのテキストモードでは改行の変換が行われるため，ディスク上のファイルのバイト数と同じとは限りません．

    また，出力の直前にputchar('/');を加えると，各入力文字の前にスラッシュを付けられます．abと改行なら/a/b/と改行になります．改行も1文字として処理するので，行末にもスラッシュが付きます．

    第6回の小文字化も，配列全体を用意せず，読み取ったchが'A'〜'Z'なら変更してからputcharすることで実装できます．入力を少しずつ処理して次へ渡すプログラムをフィルタと呼びます．

    3　行を読む¶

    fgetsは容量を指定する¶

    fgets(配列, 容量, stdin) は，最大で容量-1個のcharを読み，成功すれば末尾に'\0'を付けます．改行まで読めた場合，改行も配列に含まれます．容量のないgetsは使用しません．

    この回では容量2以上の配列を使います．戻り値は成功なら配列の先頭を指す値，1文字も読めずに入力が終了した場合や読み取りエラーではNULLです．成功を確認する前に配列をstrlenや%sへ渡してはいけません．NULLの詳しい型はポインタの回で学び，今は読み込み失敗の判定として使います．

    例えばHelloとEnterなら，配列には'H'，'e'，'l'，'l'，'o'，'\n'，'\0'が入ります．strlenの結果は改行も含めて6です．最後の改行を'\0'に置き換えれば，本文Helloの長さ5になります．空行でも'\n'と'\0'を読めるので，読み込み自体は成功です．

    #include <stdio.h>
#include <string.h>
int main(void)
{
    char line[32];
    printf("Text: ");
    fflush(stdout);
    if (fgets(line, sizeof line, stdin) == NULL) {
        fprintf(stderr, "No line read.\n");
        return 1;
    }
    size_t n = strlen(line);
    if (n > 0 && line[n - 1] == '\n') {
        line[--n] = '\0';
    } else {
        int ch;
        int extra = 0;
        while ((ch = getchar()) != '\n' && ch != EOF) {
            extra = 1;
        }
        if (extra) {
            fprintf(stderr, "Line too long.\n");
            return 1;
        }
    }
    if (ferror(stdin)) {
        fprintf(stderr, "input error\n");
        return 1;
    }
    printf("length=%zu text=%s\n", n, line);
    return 0;
}

    line.c

    ASCIIのHelloなら length=5 text=Hello と表示します．この配列に入る本文は31バイトまでです．改行が入らなかった場合は残りを読んで，ちょうど31バイトなのか，超過したのかを区別します．これは1行のテキストを想定し，途中にNULバイトがある入力は対象にしません．

    fflush(stdout) は，改行のない入力案内を送り出すために使っています．fflush(stdin) で入力を捨てる方法には頼りません．

    容量の直前・ちょうど・超過を区別する¶

    入力本文 最初のfgetsで保存されるもの 追加の読み取り 結果
    30文字＋Enter 本文30文字＋改行＋終端 不要 長さ30
    31文字＋Enter 本文31文字＋終端 改行を1個読む 長さ31
    32文字＋Enter 最初の31文字＋終端 残り1文字と改行を読む 長すぎると診断

    「配列の末尾に改行がない」だけでは，長すぎるとは断定できません．ちょうど31文字で改行が読み残されている場合や，改行なしで入力が終了した場合もあります．例題は残りを読み，改行・EOF以外の文字があればextraを1にして超過を知らせます．長すぎた行の残りを消費することは，次の入力へ読み残しを持ち越さないためにも重要です．

    line[--n] = '\0';は，nを1減らしてからその添字の改行を終端へ変えます．先にn > 0を確認しているので，size_tの0から1を引いてしまうことを防げます．読み取った文字列には埋め込みのNULバイトがない，という今回の入力条件も守ってください．

    読めなかった場合とエラー¶

    1文字も入力せず終了すると，この例はNo line read.をstderrへ表示し，return 1;で終了します．改行だけを入力した場合は長さ0の正常な行です．空行と，行が存在しない入力は異なります．

    getcharでEOFが返る理由には，入力の終了と読み取りエラーがあります．ferror(stdin)はエラーの有無，feof(stdin)は終了状態の有無を調べます．feofを先に調べても次の読み込みの成功は予測できません．読み取り関数の戻り値を判定してから状態を調べる順序にします．

    4　書式付き入出力¶

    出力する型と書式を対応させる¶

    printfでは %d，%f，%s を型に合わせます．scanfは書式に従って入力を変換する関数です．例えば scanf("%d", &n) は変換できた項目数を返すため，成功数の確認が必要です．アドレスを渡す意味は第8回で学びます．

    scanfでは数値の範囲外入力や読み残した改行にも注意が必要です．この回の必須演習はgetcharとfgetsで行います．数値文字列を検査して変換する方法は第10回で扱います．

    printfに渡す値 書式 例
    int %d 123
    unsigned int %u，%o，%x 十進，八進，十六進
    long / unsigned long %ld / %lu 値の大小にかかわらず型を合わせる
    long long / unsigned long long %lld / %llu 大きな整数
    double（floatは渡す際にdoubleへ変換） %f，%e，%g 小数・指数形式
    size_t %zu sizeofやstrlenの結果
    intとして渡される文字 %c 'A'など
    終端を持つ文字列 %s "abc"など
    void * %p (void *)&nなど

    longの値が小さくても%dへ渡してよいという意味ではありません．実際の型に合わせます．書式の型・順序・個数を間違えると未定義動作になることがあり，単に変な表示が出るだけとは限りません．警告が出たら型を確認し，誤った書式で結果を試す実験は行いません．

    MSVCではchar・short・unsigned char・unsigned shortの値は，printfへ渡す際にintへ整数拡張されます．例えばunsigned char c = 200;はprintf("%d\n", c);で200と表示できます．unsigned intとして表示したい場合はprintf("%u\n", (unsigned int)c);のように型をそろえます．floatがdoubleへ変換されることと合わせ，宣言した型だけでなく，実際に渡される型を確認しましょう．

    幅と小数点以下の桁数¶

    int i = 3;
double f = 154.423;
printf("|%d|%5d|\n", i, i);
printf("|%f|%.2f|%8.2f|\n", f, f, f);

    |3|    3|
|154.423000|154.42|  154.42|

    %5dの5は最小の表示幅です．小さい値には左側へ空白を補いますが，123456のように6桁ある値は切り詰めず6桁すべてを表示します．幅には符号や小数点も含みます．%.2fの2は小数点以下の桁数です．表示の丸めを行っても，変数fに保存した値は変わりません．

    指数形式と基数の違い¶

    double value = 1.3e10;
printf("%e\n", value);
printf("%g %g\n", 154.423, value);
unsigned int n = 500u;
printf("%u %o %x\n", n, n, n);

    %eでは1.300000e+10のように指数を使います．1.3e10というリテラルは1.3×10の10乗です．%gは値と指定精度に応じて通常形式か指数形式を選び，この例では154.423 1.3e+10になります．%gの精度は有効桁数で，%fの小数点以下の桁数とは意味が違います．

    最後の行は500 764 1f4です．同じ値を別の基数で表示しているだけで，数値自体は変わりません．八進整数リテラル0764，十六進整数リテラル0x1f4も十進数の500と同じ値です．整数に不用意に先頭の0を付けると八進数になる点に注意してください．

    scanfの書式はprintfと同じではない¶

    scanf("ID:%d", &n)は，ID:という文字列に続く整数を読み取ってnへ保存する指定です．ID:13なら成功しますが，ID :13のように固定部分が異なると一致しません．戻り値が1であることを確認してからnを使います．アドレスを渡すのは，関数が呼び出し元の変数へ書き込むためです．

    対象 printfで表示 scanfで読み込む
    int n %dにn %dに&n
    float f %fにf（doubleへ変換） %fに&f
    double d %fにd %lfに&d

    scanfの戻り値は，変換して代入できた項目数です．一致しなければ0，最初の代入前に入力が終了するなどの入力失敗ならEOFになる場合があります．失敗後に同じ入力が残ることがあり，ただ繰り返すだけでは進まない場合もあります．%dの後に残った改行を，次のgetcharやfgetsが読む点にも注意します．

    Visual Studioではscanfに安全性の診断が出る場合もあります．この節はコードを読むための説明とし，必須演習はgetchar・fgetsで統一します．scanfの書式や型を変えるだけで，任意の範囲外数値を安全に検査できるとは考えないでください．

    5　リダイレクトとパイプ¶

    標準入力は必ずキーボード，標準出力は必ず画面，というわけではありません．リダイレクトは入出力の接続先をファイルなどへ変更することです．パイプは，あるプログラムの標準出力を別のプログラムの標準入力へつなぐことです．

    通常の入力：    キーボード → プログラム → 画面
リダイレクト：  入力ファイル → プログラム → 出力ファイル
パイプ：        プログラムAのstdout → プログラムBのstdin

    Cのソースにパイプ用の文を書く必要はなく，実行環境がストリームを接続します．例えば「文字を小文字にする処理」と「文字数を数える処理」をつなげれば，処理を部品として組み合わせられます．

    この回の演習範囲

    演習ではVisual Studioのコンソール入力を使います．リダイレクトとパイプは接続関係を考える課題で確認し，シェルの操作は行いません．ファイルを直接開くプログラムは第10回で作成します．

    結果だけをstdout，診断をstderrへ出しておくと，次のプログラムへ渡すデータにエラーメッセージが混ざりにくくなります．データ処理用のプログラムでは，入力案内をstdoutに出すかどうかも考える必要があります．

    入力・出力・追記を区別する¶

    一般的なシェルの説明で現れる記号を，操作ではなく意味として整理します．これらはC言語の文法ではなく，実行環境側の接続指定です．

    記号 意味 注意
    < ファイルを標準入力へ接続 getcharのソースを変更する必要はない
    > 標準出力をファイルへ接続 既存ファイルの内容を上書きすることがある
    >> 標準出力をファイルの末尾へ追記 実行のたびに結果が追加される
    | 左側の標準出力を右側の標準入力へ接続 stderrまで自動で混ざるわけではない

    入力と出力の接続変更を同時に行えば，「入力ファイル→フィルタ→結果ファイル」とできます．上書きと追記を間違えると既存の記録を失ったり，同じ結果を重複して保存したりします．授業では実際にファイルを上書きする操作は行わず，接続先と結果の違いを考えます．

    小さい処理を組み合わせる¶

    固定の文字列を出力するechoのような機能，ファイル内容を出すcatのような機能，ファイル一覧を出すlsのような機能も，文字データを供給する側として考えられます．これらの名称は接続例を読むための紹介で，コマンドを実行する課題ではありません．一覧の表示形式などは，画面へ出す場合とパイプへ渡す場合で異なることもあります．

    文字列を出力する処理
  stdout → 小文字化フィルタ → バイト数を数える処理 → 結果ファイル
                 ↓ stderr              ↓ stderr
               診断を画面へ           診断を画面へ

    例えば上流がABCと改行を出すなら，小文字化後はabcと改行です．下流で改行も数えるなら4になります．ファイル内容を読む処理やファイル一覧を出す処理へ供給元を変えても，フィルタの仕組みは変わりません．ただし上流が改行を付けるかどうかまで含めて，実際に流れるデータを考える必要があります．

    パイプの先は，書き手がデータを流し終えるまで入力待ちになることがあります．入出力は「画面で見えた順に何でも受け取る」仕組みではなく，接続されたストリームを読む仕組みです．標準出力と標準エラー出力の表示順も，別々のバッファの影響を受ける場合があるため，画面上の並びだけを処理順の証拠にしないようにします．

    6　確認の進め方とよくある間違い¶

    症状 確認すること
    Enterを押しても集計が出ない 終了条件が改行かEOFか
    入力が2回表示される コンソールの入力表示と複写出力を混同していないか
    0や1の値しか処理されない getcharへの代入を括弧で囲んだか
    EOFで止まらない 戻り値をcharでなくintへ保存しているか
    次の行を読むとすぐ空行になる 前の処理が改行を読み残していないか
    長い行の後の入力がずれる 読み残しをどこまで消費したか
    表示が崩れる 書式と引数の型・個数・順序が合うか
    パイプの下流で数が合わない 案内や改行までデータに混ざっていないか

    まず空の入力，空行，短い1行，複数行の順に確認します．次に容量の手前・ちょうど・超過を試します．読み取った1文字，配列へ保存した文字列，標準出力へ書いたデータを分けて記録すると，どの段階で予想と違ったかを特定できます．

    確認問題¶

    2. fgetsで配列に改行が残るのはどんな場合か．
    3. 標準出力と標準エラー出力を分ける利点は何か．
