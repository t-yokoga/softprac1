## 課題4　再帰の入口を安全にする

再帰本体は前提を守って使う内部関数にし，外部から使う入口で入力を検査します．第8回の出力引数と，第12回のstatic内部関数を組み合わせます．

### 仕様

- `int factorial_checked(int n, unsigned long long *out)`を用意する．
- nが0〜20で，outが有効な書き込み先なら結果を保存し1を返す．
- nが範囲外，またはoutがNULLなら0を返し，保存先を変更しない．
- 再帰は内部のfactorial_implだけで行う．
- 不正な値で再帰へ入らない．

??? tip "入口で検査する利点"

    入力検査を通過した後は，0まで1ずつ減らすことが分かっています．内部関数ではその前提を利用できます．入口のintで負数を拒否してからunsigned intへ変換します．NULLを検査しても，無効なアドレスまで検査できるわけではありません．NULL以外のoutは有効なunsigned long longを指すことを呼び出し側で保証します．

実装にはNULLを宣言するstddef.hを取り込みます．factorial_implは`static unsigned long long factorial_impl(unsigned int n)`とし，講義の階乗を参考に作成してください．

## 発展1　再帰の呼び出し数

fib(0)=0，fib(1)=1，fib(n)=fib(n−1)+fib(n−2)として，fib(4)の呼び出しの木を紙に書きます．同じ引数で複数回呼ばれる箇所を探してください．

### 回数と深さを計測する

次のコードでは，通常の局所引数depthで各呼び出しの深さを表し，Statsへのポインタで全体の回数と最大深さを共有します．最初の深さは1，mainは数えません．

~~~c title="fibonacci.c" linenums="1"
#include <stdio.h>

typedef struct {
    unsigned long long calls;
    unsigned int max_depth;
} Stats;

unsigned long long fib(unsigned int n, unsigned int depth, Stats *stats)
{
    ++stats->calls;
    if (depth > stats->max_depth) {
        stats->max_depth = depth;
    }
    if (n < 2) {
        return n;
    }
    unsigned long long left = fib(n - 1, depth + 1, stats);
    unsigned long long right = fib(n - 2, depth + 1, stats);
    return left + right;
}

unsigned long long fib_loop(unsigned int n)
{
    unsigned long long a = 0;
    unsigned long long b = 1;
    for (unsigned int i = 0; i < n; ++i) {
        unsigned long long next = a + b;
        a = b;
        b = next;
    }
    return a;
}

int main(void)
{
    int input = 4;
    if (input < 0 || input > 20) {
        fputs("n must be 0..20\n", stderr);
        return 1;
    }
    unsigned int n = (unsigned int)input;
    Stats stats = {0, 0};
    unsigned long long result = fib(n, 1, &stats);
    printf("fib=%llu calls=%llu depth=%u loop=%llu\n",
           result, stats.calls, stats.max_depth, fib_loop(n));
    return 0;
}
~~~

このプログラムのfibとfib_loopは，検査済みの0〜20のnを前提とします．fibのstatsは有効なStatsを指し，depthは1から始めます．入力検査を外した大きなnには適用しません．

1. 最初の呼び出しも数えるので，n=0でcallsは0にならない．

## 発展3　帰りがけ順と解放の順序

第13回と結び付けて，「各ノードを個別にmallocした木」を考えます．子を解放する前に親をfreeすると，その後に親のleftやrightを読むことができません．子を処理してから自分を処理する帰りがけ順が，後始末にも使えます．

次のコードは**個別に動的確保したノードだけ**に使う説明用の断片です．講義のnodes配列には使いません．

~~~c
/* 前提：共有・循環がなく，各ノードが個別にmallocされている */
void destroy_tree(Node *p)
{
    if (p == NULL) {
        return;
    }
    destroy_tree(p->left);
    destroy_tree(p->right);
    free(p);
}
~~~

Nodeの宣言とstdlib.hが必要です．実際に動的な木を作る場合には，構築途中の確保失敗でも作成済みの部分を解放する経路が必要です．この課題ではまず順序の説明に集中し，完成した動的な木の構築プログラムは要求しません．

### 読解の問い

1. free(p)を最初へ移すと，どの式が解放後の使用になるか．
2. 2つの親が同じ子を指していた場合，何が起こるか．
3. 呼び出し元のrootは自動でNULLになるか．
4. 木が一直線に長い場合，解放処理にも深さの問題があるか．

## 確認問題

1. 基底条件を書けば，入力の範囲を確認しなくても必ず止まるか．
2. sum_to(3)でsum_to(0)がreturnした直後，mainへ戻るか．
3. fibの呼び出しが9回なら，最大深さも9か．
4. gcdは末尾再帰なので，C17では必ずスタックを使わないか．
5. 木の走査でNULLを判定する前にp->valueを読んでよいか．
6. returnすると，その呼び出しでmallocした領域も自動解放されるか．

## チェックリスト

- 正常な値だけでなく，課題に示された境界の値でも確認した．
- 警告を確認し，原因を説明・修正した．
