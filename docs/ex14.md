## 課題4　再帰の入口を安全にする

再帰本体は前提を守って使う内部関数にし，外部から使う入口で入力を検査します．第8回の出力引数と，第12回の`static`内部関数を組み合わせます．

### 仕様

- `int factorial_checked(int n, unsigned long long *out)`を用意する．
- `n`が0〜20で，`out`が有効な書き込み先なら結果を保存し1を返す．
- `n`が範囲外，または`out`が`NULL`なら0を返し，保存先を変更しない．
- 再帰は内部の`factorial_impl`だけで行う．
- 不正な値で再帰へ入らない．

??? tip "入口で検査する利点"

    入力検査を通過した後は，0まで1ずつ減らすことが分かっています．内部関数ではその前提を利用できます．入口の`int`で負数を拒否してから`unsigned int`へ変換します．`NULL`を検査しても，無効なアドレスまで検査できるわけではありません．`NULL`以外の`out`は有効な`unsigned long long`を指すことを呼び出し側で保証します．

実装には`NULL`を宣言する`stddef.h`を取り込みます．`factorial_impl`は`static unsigned long long factorial_impl(unsigned int n)`とし，講義の階乗を参考に作成してください．

## 発展1　再帰の呼び出し数

`fib(0)=0`，`fib(1)=1`，`fib(n)=fib(n`−`1)+fib(n`−2)として，`fib(4)`の呼び出しの木を紙に書きます．同じ引数で複数回呼ばれる箇所を探してください．

### 回数と深さを計測する

次のコードでは，通常の局所引数`depth`で各呼び出しの深さを表し，`Stats`へのポインタで全体の回数と最大深さを共有します．最初の深さは1，`main`は数えません．

~~~c title="fibonacci.c" linenums="1"
#include <stdio.h>

typedef struct {
    unsigned long long calls;
    unsigned int max_depth;
} Stats;

unsigned long long fib(unsigned int n, unsigned int depth, Stats *stats)
{
    ++stats->calls;
    if (depth > stats->max_depth) {
        stats->max_depth = depth;
    }
    if (n < 2) {
        return n;
    }
    unsigned long long left = fib(n - 1, depth + 1, stats);
    unsigned long long right = fib(n - 2, depth + 1, stats);
    return left + right;
}

unsigned long long fib_loop(unsigned int n)
{
    unsigned long long a = 0;
    unsigned long long b = 1;
    for (unsigned int i = 0; i < n; ++i) {
        unsigned long long next = a + b;
        a = b;
        b = next;
    }
    return a;
}

int main(void)
{
    int input = 4;
    if (input < 0 || input > 20) {
        fputs("n must be 0..20\n", stderr);
        return 1;
    }
    unsigned int n = (unsigned int)input;
    Stats stats = {0, 0};
    unsigned long long result = fib(n, 1, &stats);
    printf("fib=%llu calls=%llu depth=%u loop=%llu\n",
           result, stats.calls, stats.max_depth, fib_loop(n));
    return 0;
}
~~~

このプログラムの`fib`と`fib_loop`は，検査済みの0〜20の`n`を前提とします．`fib`の`stats`は有効な`Stats`を指し，`depth`は1から始めます．入力検査を外した大きな`n`には適用しません．

4. `depth`は対象関数の論理的な深さであり，実際に何バイトのスタックを使ったかを測っているわけではない．

## 発展3　帰りがけ順と解放の順序

第13回と結び付けて，「各ノードを個別に`malloc`した木」を考えます．子を解放する前に親を`free`すると，その後に親の`left`や`right`を読むことができません．子を処理してから自分を処理する帰りがけ順が，後始末にも使えます．

次のコードは**個別に動的確保したノードだけ**に使う説明用の断片です．講義の`nodes`配列には使いません．

~~~c
/* 前提：共有・循環がなく，各ノードが個別にmallocされている */
void destroy_tree(Node *p)
{
    if (p == NULL) {
        return;
    }
    destroy_tree(p->left);
    destroy_tree(p->right);
    free(p);
}
~~~

`Node`の宣言と`stdlib.h`が必要です．実際に動的な木を作る場合には，構築途中の確保失敗でも作成済みの部分を解放する経路が必要です．この課題ではまず順序の説明に集中し，完成した動的な木の構築プログラムは要求しません．

### 読解の問い

1. `free(p)`を最初へ移すと，どの式が解放後の使用になるか．
2. 2つの親が同じ子を指していた場合，何が起こるか．
3. 呼び出し元の`root`は自動で`NULL`になるか．
4. 木が一直線に長い場合，解放処理にも深さの問題があるか．

## 確認問題

1. 基底条件を書けば，入力の範囲を確認しなくても必ず止まるか．
2. `sum_to(3)`で`sum_to(0)`が`return`した直後，`main`へ戻るか．
3. `fib`の呼び出しが9回なら，最大深さも9か．

5. 木の走査で`NULL`を判定する前に`p->value`を読んでよいか．
