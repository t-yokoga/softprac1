## 課題1　階乗を再帰と反復で求める

`Factorial`プロジェクトに`factorial.c`を作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

1. 課題1-1：階乗を再帰と反復の両方で求め，結果を比べる．
2. 課題1-2：再帰の各段が返す値を，復帰するときに表示する．

### 課題1-1　再帰版と反復版を比べる

階乗を再帰と反復の両方で求めるプログラムを作成し，0!，1!，5!，20!で2つの結果が一致することを確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 講義の`unsigned long long factorial(unsigned int n)`（再帰版）と`unsigned long long factorial_loop(unsigned int n)`（反復版）を`main`の前に定義する．どちらも`n`は0〜20とする．
- 関数`void show_factorial(unsigned int n)`を作る．`show_factorial`は2つの関数で`n`の階乗を求め，`printf("%u! = %llu loop=%llu equal=%d\n", n, 再帰版の結果, 反復版の結果, 2つが等しいかの比較);`で表示する．比較は，等しければ1，そうでなければ0になる式とする．
- `main`では，0，1，5，20の順に`show_factorial`を呼ぶ．

表示は次のようになります．

~~~text
0! = 1 loop=1 equal=1
1! = 1 loop=1 equal=1
5! = 120 loop=120 equal=1
20! = 2432902008176640000 loop=2432902008176640000 equal=1
~~~

0!では，再帰版は基底条件ですぐに1を返し，反復版はループ本体を1回も実行せずに1を返します．再帰版は子から戻った後に積を作り，反復版はループの各回で積を更新します．

20!は64ビットの`unsigned long long`に収まりますが，21!は収まりません．そのため，21以上はこの関数へ渡しません．範囲外の値を拒否する入口は課題4で作ります．

### 課題1-2　各段の戻り値を表示する

再帰の各段が子から受け取った値と自分が返す値を，復帰するときに表示するプログラムを作成し，3!の計算で戻り値が基底条件の側から順に決まることを確認してください．

- 関数`unsigned long long factorial_trace(unsigned int n)`を作る．計算は`factorial`と同じで，`n`は0〜20とする．
- `n`が0なら，`printf("n=0 return=1\n");`で表示して1を返す．
- `n`が正なら，`factorial_trace(n - 1)`の戻り値を変数に受け取り，それに`n`を掛けた値を求めてから，`printf("n=%u child=%llu return=%llu\n", n, 子の戻り値, 自分の戻り値);`で表示して返す．
- `main`では，課題1-1の表示の後に`printf("3! = %llu\n", factorial_trace(3));`を実行する．

課題1-1の表示に続けて，次の5行が出ます．

~~~text
n=0 return=1
n=1 child=1 return=1
n=2 child=1 return=2
n=3 child=2 return=6
3! = 6
~~~

課題1全体の表示は次のようになります．

~~~text
0! = 1 loop=1 equal=1
1! = 1 loop=1 equal=1
5! = 120 loop=120 equal=1
20! = 2432902008176640000 loop=2432902008176640000 equal=1
n=0 return=1
n=1 child=1 return=1
n=2 child=1 return=2
n=3 child=2 return=6
3! = 6
~~~

呼び出しは`n`が3，2，1，0の順に進みますが，表示は0から始まります．各段の表示は子から戻った後に実行されるからです．`n=3`の段が待っている間も，その段の`n`は3のままです．深い呼び出しで`n`が0になっても，待っている段の`n`まで0になるわけではありません．

## 課題2　再帰の復帰順

`Trace`プロジェクトに`trace.c`を作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

1. 課題2-1：講義の`sum_to`を，入力を検査する関数から呼ぶ．
2. 課題2-2：`enter`の表示位置を変えた版を加える．

### 課題2-1　呼び出しと復帰の順を表示する

講義の`sum_to`を入力の検査付きで呼び出すプログラムを作成し，呼び出しと復帰の表示順と，範囲外の`n`では`sum_to`に入らないことを確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 講義の`trace.c`にある`int sum_to(int n)`を，`enter`と`leave`の表示を含めてそのまま`main`の前に定義する．`n`は0〜100とする．
- 関数`void show_sum(int n)`を作る．`show_sum`は，まず`printf("n=%d\n", n);`で表示する．`n`が0〜100でなければ，`sum_to`を呼ばずに`printf("rejected\n");`で表示して戻る．範囲内なら`printf("sum=%d\n", sum_to(n));`で表示する．
- `main`では，3，0，−1，101の順に`show_sum`を呼ぶ．

表示は次のようになります．

~~~text
n=3
enter 3
enter 2
enter 1
enter 0
leave 0: 0
leave 1: 1
leave 2: 3
leave 3: 6
sum=6
n=0
enter 0
leave 0: 0
sum=0
n=-1
rejected
n=101
rejected
~~~

`enter`は再帰呼び出しより前にあるので3，2，1，0の順に，`leave`は子から戻った後にあるので0，1，2，3の順に表示されます．`sum_to(0)`が`return`した直後に戻る先は`main`ではなく，待っている`sum_to(1)`です．

−1と101では`enter`が1行も表示されません．範囲外の値を`sum_to`へ渡す前に拒否しているからです．負数を渡すと`n`は0から遠ざかり，基底条件へ到達しません．

### 課題2-2　表示位置を変える

`enter`の表示位置だけを基底条件の判定の後へ移した関数で合計を求めるプログラムを作成し，`n=0`の段では`enter`が表示されないことを確認してください．

- 関数`int sum_to_late(int n)`を作る．計算と`leave`の表示は`sum_to`と同じで，再帰呼び出しは`sum_to_late`自身を呼ぶ．
- `printf("enter %d\n", n);`は，`if (n == 0)`のブロックの後，再帰呼び出しの前に置く．
- `main`では，課題2-1の表示の後に`printf("late\n");`と`printf("sum=%d\n", sum_to_late(2));`を実行する．

課題2-1の表示に続けて，次の7行が出ます．

~~~text
late
enter 2
enter 1
leave 0: 0
leave 1: 1
leave 2: 3
sum=3
~~~

課題2全体の表示は次のようになります．

~~~text
n=3
enter 3
enter 2
enter 1
enter 0
leave 0: 0
leave 1: 1
leave 2: 3
leave 3: 6
sum=6
n=0
enter 0
leave 0: 0
sum=0
n=-1
rejected
n=101
rejected
late
enter 2
enter 1
leave 0: 0
leave 1: 1
leave 2: 3
sum=3
~~~

`sum_to_late(0)`も呼ばれていることは，`leave 0: 0`の表示から分かります．`n=0`の段は表示位置へ到達する前に`return`するので，`enter 0`だけが出ません．表示がないことと，関数が呼ばれていないことは違います．どの文が実行されるかを基準に流れを追いましょう．

## 課題3　互除法を反復へ書き換える

`GcdLoop`プロジェクトに`gcd_loop.c`を作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

1. 課題3-1：最大公約数を再帰版と反復版で求め，結果を比べる．
2. 課題3-2：反復版のループの各回の値を表示する．

### 課題3-1　再帰版と反復版を比べる

最大公約数を再帰と`while`による反復の両方で求めるプログラムを作成し，7組の入力で2つの結果が一致することと，(0, 0)を呼び出し側で拒否することを確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 講義の`unsigned int gcd(unsigned int a, unsigned int b)`（再帰版）を`main`の前に定義する．
- 同じ計算を`while`で行う`unsigned int gcd_loop(unsigned int a, unsigned int b)`（反復版）を定義する．`gcd_loop`は再帰を使わない．
- どちらの関数も，`a`と`b`がともに0である入力は受け付けないものとする．
- 関数`void show_gcd(unsigned int a, unsigned int b)`を作る．`show_gcd`は，`a`と`b`がともに0なら，どちらの関数も呼ばずに`printf("gcd(0, 0): rejected\n");`で表示して戻る．それ以外なら`printf("gcd(%u, %u) = %u loop=%u\n", a, b, 再帰版の結果, 反復版の結果);`で表示する．
- `main`では，次の8組について，表の順に`show_gcd`を呼ぶ．

| `a` | `b` | 確かめる性質 |
| ---: | ---: | --- |
| 48 | 18 | 通常の値 |
| 18 | 48 | 引数の大小が逆 |
| 7 | 0 | 最初から基底条件 |
| 0 | 7 | 最初の余りが0 |
| 7 | 7 | 同じ数 |
| 13 | 8 | 互いに素 |
| 100 | 25 | 一方が他方の倍数 |
| 0 | 0 | 呼び出し側で拒否する |

表示は次のようになります．

~~~text
gcd(48, 18) = 6 loop=6
gcd(18, 48) = 6 loop=6
gcd(7, 0) = 7 loop=7
gcd(0, 7) = 7 loop=7
gcd(7, 7) = 7 loop=7
gcd(13, 8) = 1 loop=1
gcd(100, 25) = 25 loop=25
gcd(0, 0): rejected
~~~

??? tip "ヒント"

    ループは`b`が0でない間だけ続けます．余りを一時変数へ保存してから`a`と`b`を更新します．

どちらの関数も，`b`が0かを調べてから剰余を求めるので，0による剰余を計算しません．(0, 0)では関数の本体が0を返せますが，この授業では最大公約数の入力として扱いません．関数が受け付ける入力の条件と，呼び出し側で検査する条件をそろえています．

### 課題3-2　ループの各回を表示する

反復版のループの各回で`a`，`b`，余りを表示する関数で最大公約数を求めるプログラムを作成し，(48, 18)ではループが3回，(7, 0)では0回実行されることを確認してください．

- 関数`unsigned int gcd_loop_trace(unsigned int a, unsigned int b)`を作る．計算は`gcd_loop`と同じとする．
- ループ本体では，余りを求めた直後，`a`と`b`を更新する前に`printf("a=%u b=%u remainder=%u\n", a, b, 余り);`で表示する．
- `main`では，課題3-1の表示の後に`printf("result=%u\n", gcd_loop_trace(48, 18));`と`printf("result=%u\n", gcd_loop_trace(7, 0));`を実行する．

課題3-1の表示に続けて，次の5行が出ます．

~~~text
a=48 b=18 remainder=12
a=18 b=12 remainder=6
a=12 b=6 remainder=0
result=6
result=7
~~~

課題3全体の表示は次のようになります．

~~~text
gcd(48, 18) = 6 loop=6
gcd(18, 48) = 6 loop=6
gcd(7, 0) = 7 loop=7
gcd(0, 7) = 7 loop=7
gcd(7, 7) = 7 loop=7
gcd(13, 8) = 1 loop=1
gcd(100, 25) = 25 loop=25
gcd(0, 0): rejected
a=48 b=18 remainder=12
a=18 b=12 remainder=6
a=12 b=6 remainder=0
result=6
result=7
~~~

余りを保存する前に`a`を`b`で上書きすると，元の`a`を失って正しい余りを求められません．再帰版では最後の`gcd(6, 0)`も1回の呼び出しなので，(48, 18)の呼び出しは4回です．反復版は`b`が0の状態ではループ本体を実行しないので，3回です．

## 課題4　再帰の入口を安全にする

範囲を検査する入口の関数と，再帰を行う内部の関数に分けて階乗を求めるプログラムを作成し，範囲内の`n`では結果が保存され，範囲外の`n`や`NULL`では保存先が変わらないことを確認してください．

`CheckedFactorial`プロジェクトに`checked_factorial.c`を作ります．第8回の出力用の引数と，第12回の`static`関数を組み合わせます．プログラムが満たすこと（仕様）は次のとおりです．

- `NULL`を使うので`stddef.h`をインクルードする．
- 再帰を行う内部の関数を`static unsigned long long factorial_impl(unsigned int n)`とする．`n`は0〜20とし，計算は講義の`factorial`と同じにする．
- 入口の関数を`int factorial_checked(int n, unsigned long long *out)`とする．`n`が0〜20で`out`が`NULL`でなければ，`n`の階乗を`*out`へ保存して1を返す．`n`が範囲外か`out`が`NULL`なら，`*out`を変更せずに0を返す．
- 再帰は`factorial_impl`だけで行う．`factorial_checked`は，`int`のまま範囲を検査してから`unsigned int`へ変換し，範囲外の値で`factorial_impl`を呼ばない．
- 関数`void show_checked(int n)`を作る．`show_checked`は`unsigned long long result = 99;`を宣言して`ok = factorial_checked(n, &result)`を求め，`printf("n=%d ok=%d result=%llu\n", n, ok, result);`で表示する．
- `main`では，0，1，5，20，−1，21の順に`show_checked`を呼び，最後に`printf("null ok=%d\n", factorial_checked(5, NULL));`を実行する．

表示は次のようになります．

~~~text
n=0 ok=1 result=1
n=1 ok=1 result=1
n=5 ok=1 result=120
n=20 ok=1 result=2432902008176640000
n=-1 ok=0 result=99
n=21 ok=0 result=99
null ok=0
~~~

??? tip "ヒント"

    負数を先に`unsigned int`へ変換すると大きな正の値になります．`n < 0`の検査は，`int`のままで行います．

失敗したときの99は計算結果ではありません．この関数を使う側は，`ok`を確かめてから結果を使います．検査を通った後は，`n`が0〜20で，1ずつ減らせば0に到達することが分かっています．内部の関数はその前提を使えるので，再帰の中で検査を繰り返す必要はありません．

`NULL`を検査しても，無効なアドレスまで見分けられるわけではありません．`NULL`以外の`out`が有効な`unsigned long long`を指すことは，呼び出し側が保証します．

## 発展1　再帰の呼び出し回数と深さ

`Fibonacci`プロジェクトに`fibonacci.c`を作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

1. 発展1-1：フィボナッチ数を素朴な再帰で求め，呼び出し回数と最大深さを数える．
2. 発展1-2：`fib(4)`の呼び出しを，字下げした木の形で表示する．

フィボナッチ数は，`fib(0) = 0`，`fib(1) = 1`，`fib(n) = fib(n - 1) + fib(n - 2)`とします．

### 発展1-1　回数と深さを数える

フィボナッチ数を再帰で求めながら呼び出し回数と最大深さを数えるプログラムを作成し，8つの`n`で反復版と同じ値になることと，呼び出し回数と最大深さの違いを確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 回数と深さを記録する構造体を，次のように宣言する．

    ~~~c
    typedef struct {
        unsigned long long calls;
        unsigned int max_depth;
    } Stats;
    ~~~

- 関数`unsigned long long fib(unsigned int n, unsigned int depth, Stats *stats)`を作る．入口で`stats->calls`を1増やし，`depth`が`stats->max_depth`より大きければ`stats->max_depth`を`depth`にする．`n`が2未満なら`n`を返す．それ以外は，`fib(n - 1, depth + 1, stats)`と`fib(n - 2, depth + 1, stats)`を別々の文でこの順に呼び，2つの和を返す．
- 前の2項を保持して反復で求める`unsigned long long fib_loop(unsigned int n)`を作る．
- `fib`と`fib_loop`の`n`は0〜20とする．
- 関数`void show_fib(int input)`を作る．`input`が0〜20でなければ，`fib`を呼ばずに`printf("n=%d rejected\n", input);`で表示して戻る．範囲内なら，`Stats stats = {0, 0};`を宣言して`fib(n, 1, &stats)`を呼び，`printf("n=%u fib=%llu calls=%llu depth=%u loop=%llu\n", n, 結果, stats.calls, stats.max_depth, fib_loop(n));`で表示する．`n`は`input`を`unsigned int`へ変換した値とする．
- `main`では，0，1，2，3，4，5，10，20，−1，21の順に`show_fib`を呼ぶ．

表示は次のようになります．


??? tip "改善の方向"

    `fib(2)`を一度計算して保存できれば，再計算を省けます．これがメモ化の考え方です．`fib_loop`は前の2項だけを保持し，`n`に比例する回数の反復で求めます．メモ化と反復への書き換えは，異なる方法です．

## 発展2　二分木の3つの走査

`TreeTraversal`プロジェクトに`tree_traversal.c`を作ります．この課題では，次の3つの小問を順に行い，同じファイルへ書き足します．

1. 発展2-1：講義の木と部分木を，3つの順序で走査する．
2. 発展2-2：部分木のノード数と高さを求める．
3. 発展2-3：右へ一直線につないだ木を作り，同じ処理を行う．

### 発展2-1　3つの順序で走査する

講義の木と4つの部分木を行きがけ順，通りがけ順，帰りがけ順で走査するプログラムを作成し，走査順による表示の違いと，`NULL`や葉から始めた場合の動作を確認してください．

### 発展2-2　ノード数と高さを求める

部分木のノード数と高さを再帰で求めるプログラムを作成し，木全体，`NULL`，葉，2つの部分木で値を確認してください．

- 関数`size_t node_count(const Node *p)`を作る．空の木（`NULL`）は0，それ以外は1＋左の部分木のノード数＋右の部分木のノード数を返す．
- 関数`size_t tree_height(const Node *p)`を作る．高さは「根から葉までの最長の経路に含まれるノードの個数」とし，空の木は0，葉は1とする．
- 関数`void show_size(const char *name, const Node *root)`を作り，`printf("%s count=%zu height=%zu\n", name, ノード数, 高さ);`で表示する．
- `main`では，発展2-1の表示の後に，次の表の順に`show_size`を呼ぶ．

| `"nodes[1]"` | `&nodes[1]` |
| `"nodes[6]"` | `&nodes[6]` |

### 発展2-3　一直線の木と比べる

## 発展3　帰りがけ順で木を解放する

各ノードを個別に`malloc`して講義と同じ形の木を作り，帰りがけ順ですべて解放するプログラムを作成し，子を先に解放する順序と，解放後に残るノードが0個になることを確認してください．

`FreeTree`プロジェクトに`free_tree.c`を作ります．プログラムが満たすこと（仕様）は次のとおりです．

- `Node`の宣言は講義の`tree.c`と同じにする．`malloc`と`free`を使うので`stdlib.h`をインクルードする．
- 確保中のノードの個数を数えるファイルスコープの変数`static int live_count = 0;`を置く．
- 関数`Node *make_node(int value)`を作る．`malloc`でノードを1つ確保し，失敗したら`NULL`を返す．成功したら値を`value`，左右の子を`NULL`にし，`live_count`を1増やしてから返す．
- 関数`void destroy_tree(Node *p)`を作る．`p`が`NULL`なら何もしない．それ以外は，左の部分木，右の部分木の順に`destroy_tree`で解放した後，`printf(" %d", p->value);`で値を表示し，`p`を`free`して`live_count`を1減らす．
- `main`では，`Node *nodes[10]`の各要素へ`make_node(i + 1)`の結果を入れる．途中で`NULL`が返ったら，それまでに確保したノードをすべて`free`し，`fputs("out of memory\n", stderr);`で表示して1を返す．
- すべて確保できたら，講義の`tree.c`と同じ親子関係にノードをつなぎ，`Node *root = nodes[0];`とする．
- 次の順に実行する．
    1. `printf("live=%d\n", live_count);`
    2. `printf("freed:");`の後，`destroy_tree(root);`を呼び，`root = NULL;`とする．
    3. `printf("\nlive=%d\n", live_count);`
    4. もう一度`printf("freed:");`の後に`destroy_tree(root);`を呼び，`printf("\nlive=%d\n", live_count);`で表示する．

表示は次のようになります．

~~~text
live=10
freed: 4 5 3 6 2 9 8 10 7 1
live=0
freed:
live=0
~~~

解放の順序は，発展2の帰りがけ順と同じです．子を解放する前に親を`free`すると，その後に親の`left`や`right`を読めません．`free(p)`を関数の最初へ移すと，`p->left`と`p->right`が解放後の使用になります．

`destroy_tree`は`root`のコピーを受け取るので，呼び出し元の`root`は自動では`NULL`になりません．所有者が`root = NULL;`としておけば，2回目の`destroy_tree(root)`は何もせずに戻ります．2つの親が同じ子を指す木では同じノードを2回解放してしまうので，この関数は共有も循環もない木だけに使います．木が一直線に長いと，解放する関数の再帰も深くなります．

## 確認問題

この節は自習用で，成績には含めません．

1. 基底条件を書けば，入力の範囲を確認しなくても必ず止まるか．
2. `sum_to(3)`で`sum_to(0)`が`return`した直後，`main`へ戻るか．
3. `fib`の呼び出しが9回なら，最大深さも9か．
4. `gcd`は末尾再帰なので，C17では必ずスタックを使わないか．
5. 木の走査で`NULL`を判定する前に`p->value`を読んでよいか．

## チェックリスト

- 各課題のソースが1つのファイルにまとまり，警告なしでビルドできる．
- 1回の実行で，課題に示したすべての場合の結果が表示される．
- 表示が，課題に示した出力と一致する．
- 関数の名前，引数，戻り値の型が課題の指定どおりである．
- 小問のある課題で，前の小問の関数や表示を残している．
- 再帰関数に基底条件があり，再帰呼び出しの引数が基底条件へ近づく．
- 不正な入力を呼び出し側で拒否し，範囲外の値で再帰を始めていない．
- 木の走査で，`NULL`を判定してからノードのメンバを読んでいる．
- `malloc`したノードをすべて解放し，局所配列のノードは`free`していない．
