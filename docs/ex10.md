### ソースの書き方

- 課題に示した場合は，すべて`main`から呼び出して表示します．値やファイルを書き換えて実行し直すのではなく，1回の実行ですべての結果が表示されるようにします．
- 小問のある課題は，同じファイルへ小問の順に書き足します．前の小問で作った関数や表示は消さずに残します．
- 関数の名前，引数，戻り値の型は，課題の指定どおりにします．
- 表示は，課題に示した出力と同じにします．
- `fopen`を使うソースは，講義と同じく先頭のインクルードより前に`#define _CRT_SECURE_NO_WARNINGS`を置きます．
- `fopen`の戻り値が`NULL`かどうか，読み書き関数の戻り値，`fclose`の戻り値を調べます．開くのに失敗したときは，読み書きも`fclose`もしません．

今回のプログラムはどれも入力を待ちません．実行するとすぐに結果を表示して終了します．起動時の引数（コマンド引数）を設定するのは課題2だけです．

## 課題1　ファイルを読む

`ReadText`プロジェクトに`read_text.c`を作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

1. 課題1-1：ファイルを作り，1文字ずつ読んで表示する．
2. 課題1-2：1行ずつ読んで，各行の長さを表示する．

### 課題1-1　1文字ずつ読んで表示する

練習用のテキストファイルを作り，その内容を1文字ずつ読んで表示するプログラムを作成し，空ファイル，最後に改行のないファイル，空白を含む名前，存在しない名前，空の名前で結果を確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 関数`int write_text_file(const char *filename, const char *text)`を作る．`filename`をモード`w`で開き，`fputs`で`text`を書いて閉じる．開けない，書けない，閉じるのに失敗した，のどれかなら0，成功なら1を返す．
- 講義の`read_text.c`の読み取り部分を，関数`int print_file(const char *filename)`にする．
    - `filename`が空文字列なら，`fopen`を呼ばずに0を返す．
    - モード`r`で開けなければ0を返す．
    - `fgetc`の戻り値を`int`で受け取り，`EOF`以外を`putchar`で表示する．
    - ループの後で`ferror`を調べ，`fclose`の戻り値も調べる．読み取り・表示・閉じる処理のどれかが失敗したら0，すべて成功したら1を返す．
    - 診断メッセージは表示しない．失敗は戻り値だけで知らせる．
- 関数`void show_file(const char *filename)`を作る．`show_file`は`printf("\"%s\": [", filename);`を実行し，`print_file(filename)`の戻り値を`ok`に受け取り，`printf("] ok=%d\n", ok);`で表示する．
- `main`では，最初に`write_text_file`で次の4つのファイルを作る．1つでも失敗したら，`stderr`へ`write error`と表示して1を返す．

| ファイル名 | 書く内容（Cの文字列） |
| --- | --- |
| `input.txt` | `"Hello\nFile\n"` |
| `empty.txt` | `""` |
| `no_newline.txt` | `"Hello\nFile"` |
| `my input.txt` | `"Hello\nFile\n"` |

- 続けて，`input.txt`，`empty.txt`，`no_newline.txt`，`my input.txt`，`missing.txt`，`""`（空文字列）の順に`show_file`を呼ぶ．`missing.txt`は作らない．プロジェクトのフォルダに`missing.txt`という名前のファイルを置かないこと．

表示は次のようになります．

~~~text
"input.txt": [Hello
File
] ok=1
"empty.txt": [] ok=1
"no_newline.txt": [Hello
File] ok=1
"my input.txt": [Hello
File
] ok=1
"missing.txt": [] ok=0
"": [] ok=0
~~~

??? tip "ヒント"

    `print_file`は，講義の`read_text.c`の`main`から，引数の検査と診断の表示を除いた形です．`return 1;`で終わっていた失敗の処理は，`return 0;`に変わります．

角かっこの間が，ファイルから読んだ内容です．空ファイルでは最初の`fgetc`が`EOF`を返し，`ferror`も0なので，読むデータがなかっただけで失敗ではありません．最後に改行がないファイルでも，`File`の4文字は読まれ，`]`がその直後に続きます．

モード`r`は存在しないファイルを作らないので，`missing.txt`は開けずに0になります．空の名前は講義と同じく，開く前に拒否します．Windowsのテキストモードでは，書くときに`\n`がCRLFになり，読むときにLFへ戻るので，表示は書いた文字列と同じです．

Cの文字列の中では，空白を含む`"my input.txt"`もそのまま1つのファイル名です．これに対して，Visual Studioの「コマンド引数」欄で同じ名前を渡すには，`"my input.txt"`と引用符で囲みます．引用符なしの`my input.txt`は2つの引数になります．

### 課題1-2　各行の長さを表示する

ファイルの各行の長さを表示する関数を加えたプログラムを作成し，改行のない最後の行，空行，31文字の行，32文字の行で，表示される長さを確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 講義の`line_lengths.c`の処理を，関数`int print_line_lengths(const char *filename)`にする．
    - 空文字列の名前と，開けない場合は0を返す．
    - `char line[32];`へ`fgets`で読み，改行を除いた長さを`printf("%zu\n", length);`で1行ずつ表示する．
    - 長さ31で改行が配列にないときは，もう1文字読む．それが改行でも`EOF`でもなければ，長すぎる行として読み取りをやめ，0を返す．
    - `ferror`と`fclose`の結果も調べ，すべて成功したら1を返す．診断メッセージは表示しない．
- 関数`void show_lengths(const char *filename)`を作る．`show_lengths`は`printf("%s:\n", filename);`を実行し，`print_line_lengths(filename)`の戻り値を`ok`に受け取り，`printf("ok=%d\n", ok);`で表示する．
- `main`の最初で作るファイルに，次の3つを加える．

| ファイル名 | 書く内容 |
| --- | --- |
| `abc.txt` | `"ABC\n\nABC"` |
| `a31.txt` | `A`を31個（改行なし） |
| `a32.txt` | `A`を32個と改行 |

- 課題1-1の表示の後に，`input.txt`，`empty.txt`，`abc.txt`，`a31.txt`，`a32.txt`の順に`show_lengths`を呼ぶ．

課題1-2で加わる表示は次のとおりです．

~~~text
input.txt:
5
4
ok=1
empty.txt:
ok=1
abc.txt:
3
0
3
ok=1
a31.txt:
31
ok=1
a32.txt:
ok=0
~~~

課題1全体の表示は次のようになります．

~~~text
"input.txt": [Hello
File
] ok=1
"empty.txt": [] ok=1
"no_newline.txt": [Hello
File] ok=1
"my input.txt": [Hello
File
] ok=1
"missing.txt": [] ok=0
"": [] ok=0
input.txt:
5
4
ok=1
empty.txt:
ok=1
abc.txt:
3
0
3
ok=1
a31.txt:
31
ok=1
a32.txt:
~~~

??? tip "ヒント"

    `a31.txt`と`a32.txt`の内容は，`A`の個数を数え間違えないように，10個ずつ区切って確かめてから書きます．

空ファイルは長さ0の行があるのではなく，行がないので長さを1つも表示しません．`abc.txt`の2行目の空行は長さ0です．最後の`ABC`には改行がないので，改行を除かずに長さ3になります．`strlen(line)`から常に1を引くと，この行の長さが2になってしまいます．改行を実際に読み取ったかどうかを調べてから除きます．

`a31.txt`は31文字で改行がないので，追加で読んだ1文字が`EOF`になり，31文字の行として扱えます．`a32.txt`では，`fgets`が31文字を読んだ後の1文字が`A`なので，長すぎる行として失敗します．32文字の行を，31文字と1文字の2行として数えることはありません．

## 課題2　数値と引数の検査

`Arguments`プロジェクトに`arguments.c`を作ります．この課題では，次の3つの小問を順に行い，同じファイルへ書き足します．

1. 課題2-1：文字列が0〜100の整数かどうかを調べる．
2. 課題2-2：文字列の配列に入った整数を合計する．
3. 課題2-3：起動時の引数を表示して，特定の文字列を探す．

課題2-1と2-2は，文字列の配列を`main`の中で用意して確かめます．課題2-3で，同じ形の配列として`argv`を使います．

### 課題2-1　数値文字列を検査する

文字列が0〜100の整数を表すかどうかを`strtol`で調べるプログラムを作成し，12通りの文字列で，受け付けるものと拒否するものを確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- `stdio.h`，`stdlib.h`，`string.h`，`errno.h`をインクルードする．
- 講義の`parse_number.c`の検査を，関数`int parse_score(const char *s, long *value)`にする．`errno = 0;`としてから`strtol(s, &end, 10)`で変換し，数字を1つも読めない，後ろに文字が残る，`errno`が`ERANGE`，0未満，100より大きい，のどれかなら0を返す．このとき`*value`は変更しない．それ以外なら，変換した値を`*value`へ書き込んで1を返す．
- 関数`void check(const char *s)`を作る．`check`は`long value;`を宣言して`parse_score(s, &value)`を呼び，成功なら`printf("\"%s\" -> %ld\n", s, value);`，失敗なら`printf("\"%s\" -> invalid\n", s);`で表示する．
- `main`では，次の12個の文字列について，表の順に`check`を呼ぶ．

| 番号 | 文字列 | 番号 | 文字列 |
| ---: | --- | ---: | --- |
| 1 | `"42"` | 7 | `" 42"` |
| 2 | `"0"` | 8 | `"42 "` |
| 3 | `"100"` | 9 | `"12x"` |
| 4 | `"101"` | 10 | `"abc"` |
| 5 | `"-1"` | 11 | `""` |
| 6 | `"+42"` | 12 | `"999999999999999999999999999999"`（9が30個） |

表示は次のようになります．

~~~text
"42" -> 42
"0" -> 0
"100" -> 100
"101" -> invalid
"-1" -> invalid
"+42" -> 42
" 42" -> 42
"42 " -> invalid
"12x" -> invalid
"abc" -> invalid
"" -> invalid
"999999999999999999999999999999" -> invalid
~~~

??? tip "ヒント"

    12個の文字列は`const char *`の配列にまとめ，`for`文で`check`へ渡すと簡潔に書けます．

0と100は範囲に含まれます．`strtol`は先頭の空白と符号を読み飛ばすので，`+42`と` 42`は42になります．末尾の空白や`12x`の`x`は`*end != '\0'`で拒否するので，途中までの12だけで成功にはなりません．`abc`と空文字列では数字を1つも読めず，`end`が先頭のままです．

9が30個の文字列は`long`の範囲を超え，`errno`が`ERANGE`になります．Windowsと他の環境で`long`の大きさは同じとは限らないので，「10桁なら必ず範囲外」のようには判断しません．正常な0と変換できなかったときの0は戻り値だけでは区別できないので，`end`と`errno`を組み合わせて調べます．

### 課題2-2　複数の数値を合計する

文字列の配列に入った1〜10個の整数を，それぞれ検査しながら合計するプログラムを作成し，6通りの配列で，合計と拒否される場合を確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 関数`int sum_scores(int n, char *items[], long *total)`を作る．`n`が1〜10でなければ0を返す．`items[0]`〜`items[n - 1]`を順に`parse_score`で変換して合計し，1つでも失敗したら0を返す．すべて成功したら，合計を`*total`へ書き込んで1を返す．値を配列にためず，1つ変換するたびに`long`の合計へ加える．
- 関数`void show_sum(int n, char *items[])`を作る．`show_sum`は，`[`に続けて`items[0]`〜`items[n - 1]`を空白1つで区切って表示し，`sum_scores`が成功なら`printf("] -> %ld\n", total);`，失敗なら`printf("] -> invalid\n");`で表示する．
- `main`では，課題2-1の表示の後に，次の配列を宣言して表の順に`show_sum`を呼ぶ．

~~~c
char *three[] = {"12", "23", "34"};
char *two[] = {"0", "100"};
char *bad[] = {"12", "x", "34"};
char *hundreds[] = {"100", "100", "100", "100", "100", "100",
                    "100", "100", "100", "100", "100"};
~~~

| 呼び出し | 意味 |
| --- | --- |
| `show_sum(3, three)` | 3個の正しい値 |
| `show_sum(2, two)` | 下限と上限 |
| `show_sum(3, bad)` | 途中に数値でない文字列 |
| `show_sum(0, three)` | 個数が0 |
| `show_sum(10, hundreds)` | 10個の100 |
| `show_sum(11, hundreds)` | 個数が11 |

課題2-2で加わる表示は次のとおりです．

~~~text
[12 23 34] -> 69
[0 100] -> 100
[12 x 34] -> invalid
[] -> invalid
[100 100 100 100 100 100 100 100 100 100] -> 1000
[100 100 100 100 100 100 100 100 100 100 100] -> invalid
~~~

各値が0〜100で個数が10個までなので，合計は最大1000で，`long`の範囲に収まります．途中に`x`があると，その前の12を加えていても合計は表示しません．

`items`の型`char *items[]`は，`main`の`argv`と同じ形です．課題2-3では，この形の関数へ`argv`を渡します．

### 課題2-3　起動時の引数を調べる

受け取った文字列を1つずつ表示し，`toyama`，`ishikawa`，`fukui`のどれかがあれば`hokuriku!`を表示するプログラムを作成し，4通りの文字列の配列と，コマンド引数`nagano "red blue" ishikawa`で結果を確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 関数`int has_hokuriku(int n, char *items[])`を作る．`items[0]`〜`items[n - 1]`のどれかが`toyama`，`ishikawa`，`fukui`のどれかと`strcmp`で一致すれば1，そうでなければ0を返す．
- 関数`void show_args(int n, char *items[])`を作る．`show_args`は`printf("count=%d\n", n);`を実行し，各文字列を`printf("arg%d=%s\n", i + 1, items[i]);`で表示する．最後に，`has_hokuriku`が1なら`puts("hokuriku!");`を1回だけ実行する．
- `main`の形を`int main(int argc, char *argv[])`にする．
- `main`では，課題2-2の表示の後に，次の配列を宣言して表の順に`show_args`を呼ぶ．

~~~c
char *nagano[] = {"nagano", "ishikawa"};
char *twice[] = {"fukui", "ishikawa"};
char *upper[] = {"Toyama"};
~~~

| 呼び出し | 意味 |
| --- | --- |
| `show_args(2, nagano)` | 2番目が一致 |
| `show_args(2, twice)` | 2つとも一致 |
| `show_args(1, upper)` | 大文字を含む |
| `show_args(0, upper)` | 文字列が0個 |
| `show_args(argc - 1, argv + 1)` | 起動時の引数（プログラム名を除く） |

[講義の設定](lec10.md#arguments)で，`Arguments`プロジェクトの「コマンド引数」に次のとおり入力してから実行します．実行ファイル名は書きません．

コマンド引数を空にして実行すると，最後の5行の代わりに`count=0`の1行だけが表示されます．

## 課題3　バイト列を保存する

`Binary`プロジェクトに`binary.c`を作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

1. 課題3-1：バイト列をバイナリモードで書いて読み戻す．
2. 課題3-2：変数のバイト並びと1バイトのビットを表示する．

### 課題3-1　書いたバイト列を読み戻す

バイト列をモード`wb`でファイルへ書き，モード`rb`で読み戻して16進数で表示するプログラムを作成し，途中に00を含む4バイト，末尾にFFを加えた5バイト，UTF-8の「あ」と改行の4バイトで，書いたバイトと読み戻したバイトが一致することを確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 関数`int write_bytes(const char *filename, const unsigned char data[], size_t n)`を作る．モード`wb`で開き，`fwrite(data, 1, n, fp)`で書いて閉じる．書けた個数が`n`で，`fclose`も成功したら1，それ以外は0を返す．
- 関数`int print_bytes(const char *filename)`を作る．
    - モード`rb`で開き，`unsigned char buffer[16];`へ`fread(buffer, 1, sizeof buffer, fp)`で読む．戻り値を`size_t n`に受け取る．
    - `ferror`と`fclose`を調べ，開けない場合も含めて失敗なら何も表示せず0を返す．
    - 成功なら`printf("%s n=%zu:", filename, n);`に続けて，読んだ`n`バイトだけを`printf(" %02X", (unsigned int)buffer[i]);`で表示し，改行して1を返す．
- 関数`void show_bytes(const char *filename, const unsigned char data[], size_t n)`を作る．`write_bytes`で書いてから`print_bytes`で表示する．どちらかが失敗したら`printf("%s: error\n", filename);`で表示する．
- `main`では，次の3つの配列を宣言し，`show_bytes("bytes.bin", data, sizeof data);`，`show_bytes("more.bin", more, sizeof more);`，`show_bytes("utf8.bin", utf8, sizeof utf8);`の順に呼ぶ．

~~~c
const unsigned char data[] = {0x41, 0x00, 0x42, 0x0A};
const unsigned char more[] = {0x41, 0x00, 0x42, 0x0A, 0xFF};
const unsigned char utf8[] = {0xE3, 0x81, 0x82, 0x0A};
~~~

表示は次のようになります．

~~~text
bytes.bin n=4: 41 00 42 0A
more.bin n=5: 41 00 42 0A FF
utf8.bin n=4: E3 81 82 0A
~~~

`n`は`fread`が実際に読んだ要素数で，ここでは`size=1`なのでバイト数と一致し，ファイルの大きさにもなります．`buffer`は16要素ありますが，使えるのは最初の`n`個だけです．残りの要素は読んでいないので表示しません．16バイトより大きいファイルは1回の`fread`では読み切れないので，ここでは5バイト以下に限っています．

途中に00があっても，終端文字ではなく個数で読み書きしているので，その後ろの`42 0A`も扱えます．`fread`は後ろに`\0`を書かないので，`buffer`を`%s`で表示しません．

`utf8.bin`は，ソースに日本語を直接書かずに，UTF-8の「あ」（`E3 81 82`）とLFを表したものです．画面で「あ」と表示できるかどうかではなく，書いたバイトと読んだバイトが一致することを確かめます．UTF-8のBOMを付けるなら先頭に`EF BB BF`が増えますが，この形式には付けません．

### 課題3-2　バイト順とビットを表示する

`unsigned short`の値がメモリ上でどの順にバイトを並べているかと，1バイトのビット列を表示する関数を加えたプログラムを作成し，値1と`0x1234`のバイト順と，3つのバイトのビット列を確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 関数`void print_representation(unsigned short value)`を作る．`printf("value=0x%04X size=%zu bytes=", (unsigned int)value, sizeof value);`を実行し，続けて講義の「バイトオーダを具体的に見る」の断片と同じく，`value`を`const unsigned char *`で1バイトずつ`%02X`で表示する．バイトの間は空白1つで区切り，最後に改行する．
- 関数`void print_bits(unsigned char byte)`を作る．`printf("byte=0x%02X bits=", (unsigned int)byte);`を実行し，続けてビット7からビット0まで`1`または`0`を`putchar`で表示して改行する．
- `main`では，課題3-1の表示の後に，`print_representation(1);`，`print_representation(0x1234);`，`print_bits(0x01);`，`print_bits(0x34);`，`print_bits(0x12);`の順に呼ぶ．

課題3-2で加わる表示は次のとおりです．`size`とバイトの順序は環境によって異なります．次は通常のVisual Studio（x64）での表示です．

~~~text
value=0x0001 size=2 bytes=01 00
value=0x1234 size=2 bytes=34 12
byte=0x01 bits=00000001
byte=0x34 bits=00110100
byte=0x12 bits=00010010
~~~

課題3全体の表示は次のようになります．

~~~text
bytes.bin n=4: 41 00 42 0A
more.bin n=5: 41 00 42 0A FF
utf8.bin n=4: E3 81 82 0A
value=0x0001 size=2 bytes=01 00
value=0x1234 size=2 bytes=34 12
byte=0x01 bits=00000001
byte=0x34 bits=00110100
byte=0x12 bits=00010010
~~~

??? tip "ヒント"

    ビット`bit`が1かどうかは，`(byte & (1u << bit)) != 0`で調べられます．`bit`を7から0へ減らしながら調べると，上位ビットから表示できます．

x64のWindowsはリトルエンディアンなので，`0x1234`の下位バイト`34`が先に並びます．ビッグエンディアンの環境なら`12 34`です．先のバイトが`34`だからといって，値が`0x3412`に変わったわけではありません．メモリへ保存する順序の違いです．

バイト順は複数バイトの並び順で，1バイトの中のビットを反転する話ではありません．各バイトの中は，どちらの環境でも上位ビットから`00110100`のように表示します．`sizeof value`を使っているので，`unsigned short`が2バイトでない環境でもループは正しい回数で終わります．

## 課題4　テキストを書き出す

`WriteText`プロジェクトに`write_text.c`を作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

1. 課題4-1：モード`w`と`a`で書き，行数を比べる．
2. 課題4-2：モード`wx`で書く．

### 課題4-1　上書きと追記を比べる

72，85，60を1行ずつファイルへ書く処理を，`fopen`のモードを変えて繰り返すプログラムを作成し，`w`と`a`で書いたときのファイルの行数を確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 関数`int write_scores(const char *filename, const char *mode)`を作る．`filename`を`mode`で開き，`fprintf(fp, "%d\n", 値)`で72，85，60を1行ずつ書く．開けない場合，`fprintf`が負の値を返した場合，`fclose`が失敗した場合は0，成功なら1を返す．
- 関数`int count_lines(const char *filename)`を作る．モード`r`で開き，`fgetc`で最後まで読んで改行`'\n'`の個数を返す．開けない場合や読み取りエラーの場合は−1を返す．
- 関数`void try_write(const char *filename, const char *mode)`を作る．`try_write`は`write_scores(filename, mode)`の戻り値を`ok`に受け取り，`printf("%s mode=%s: ok=%d lines=%d\n", filename, mode, ok, count_lines(filename));`で表示する．
- `main`では，`scores.txt`に対して，モード`w`，`w`，`a`，`a`，`w`の順に`try_write`を呼ぶ．

表示は次のようになります．

~~~text
scores.txt mode=w: ok=1 lines=3
scores.txt mode=w: ok=1 lines=3
scores.txt mode=a: ok=1 lines=6
scores.txt mode=a: ok=1 lines=9
scores.txt mode=w: ok=1 lines=3
~~~

`w`は開く時点で以前の内容を消すので，2回続けても6行にはなりません．`a`は末尾へ追記するので，3行ずつ増えます．ファイルがない場合は，`a`も新しく作ります．最後に`w`で書くので，実行後の`scores.txt`は72，85，60の3行で，何回実行し直しても同じ表示になります．

Windowsのテキストモードでは`\n`がCRLFとして保存されるので，`scores.txt`は9バイトではなく12バイトになります．読むときにはLFへ戻るので，`count_lines`の結果は変わりません．

### 課題4-2　新しいファイルだけを作る

新しいファイルだけを作るモード`wx`で書く処理を加えたプログラムを作成し，ファイルがない場合とある場合の結果を確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- `main`では，課題4-1の表示の後に，`remove("new_scores.txt");`を実行する．前回の実行で作られた`new_scores.txt`を消して，毎回同じ結果にするためである．ファイルがなければ失敗するので，戻り値は調べない．
- 続けて，`try_write("new_scores.txt", "wx");`を2回呼び，最後に`try_write("scores.txt", "wx");`を呼ぶ．

!!! warning "removeはファイルを消す"

    `remove`はごみ箱を経由せずにファイルを削除します．引数は`"new_scores.txt"`だけにし，他の名前を書かないでください．

課題4-2で加わる表示は次のとおりです．

~~~text
new_scores.txt mode=wx: ok=1 lines=3
new_scores.txt mode=wx: ok=0 lines=3
scores.txt mode=wx: ok=0 lines=3
~~~

課題4全体の表示は次のようになります．

~~~text
scores.txt mode=w: ok=1 lines=3
scores.txt mode=w: ok=1 lines=3
scores.txt mode=a: ok=1 lines=6
scores.txt mode=a: ok=1 lines=9
scores.txt mode=w: ok=1 lines=3
new_scores.txt mode=wx: ok=1 lines=3
new_scores.txt mode=wx: ok=0 lines=3
scores.txt mode=wx: ok=0 lines=3
~~~

`wx`は，ファイルが既にあれば開くのに失敗します．そのため，2回目の`new_scores.txt`と`scores.txt`は`ok=0`になり，内容は3行のまま残ります．既存のファイルを誤って上書きしないために使うモードです．失敗したときに自動で`w`へ切り替えると保護の意味がなくなるので，別の未使用の名前を使います．

| モード | 実行前に3行ある場合 | ファイルがない場合 |
| --- | --- | --- |
| `w` | 今回の3行だけになる | 新しく作る |
| `a` | 以前の3行と今回の3行で6行 | 新しく作る |
| `wx` | 開くのに失敗し，元の3行が残る | 新しく作る |

`fprintf`がすべて成功していても，`fclose`の戻り値は調べます．出力はメモリ上にためられていることがあり，閉じるときに実際に書き込まれて失敗する場合があるからです．

## 発展1　数値をテキスト・バイナリで往復する

3つの`double`をテキスト形式とバイナリ形式の両方で保存して読み戻すプログラムを作成し，2組の値で，読み戻した値と，保存時の桁数による違いを確認してください．

`NumberFormats`プロジェクトに`number_formats.c`を作ります．保存形式は次のとおりです．

- テキスト形式：最初の行に個数を`%d`で書き，続けて各値を`%.2f`で1行ずつ書く．
- バイナリ形式：個数を`unsigned char`の1バイトで書き，続けて`double`の値をそのまま`fwrite`で書く．同じ処理系で読み戻す専用とする．

プログラムが満たすこと（仕様）は次のとおりです．

- 読み込める個数の上限を`enum { CAPACITY = 10 };`で定める．
- 次の4つの関数を作る．どれも，開けない場合や読み書き・閉じる処理のどれかが失敗した場合は0，成功なら1を返す．
    - `int save_text(const char *filename, const double data[], int n)`：モード`w`でテキスト形式を書く．
    - `int save_binary(const char *filename, const double data[], int n)`：モード`wb`でバイナリ形式を書く．`fwrite`の戻り値が書こうとした要素数と一致するかを調べる．
    - `int load_text(const char *filename, double data[], int capacity, int *n)`：モード`r`で開き，`fscanf`の`%d`で個数，`%lf`で各値を読む．個数が0未満または`capacity`より大きければ失敗とする．成功したときだけ，個数を`*n`へ書き込む．
    - `int load_binary(const char *filename, double data[], int capacity, int *n)`：モード`rb`で開き，`fread`で1バイトの個数を読み，`capacity`以下なら，その個数の`double`を`fread`で読む．読めた要素数が個数と一致しなければ失敗とする．成功したときだけ，個数を`*n`へ書き込む．
- 関数`void print_values(const char *label, const double data[], int n)`を作る．`printf("%s:", label);`に続けて，各値を`printf(" %.3f", data[i]);`で表示し，改行する．
- 関数`void round_trip(const char *text_name, const char *binary_name, const double data[], int n)`を作る．`round_trip`は`double`の配列を2つ（要素数`CAPACITY`）用意し，次の処理を行う．
    1. `save_text`で`text_name`へ書き，`load_text`で読み戻す．どちらかが失敗したら`printf("%s: error\n", text_name);`，成功なら`print_values(text_name, 読んだ配列, 読んだ個数)`で表示する．
    2. 同じことを`save_binary`，`load_binary`，`binary_name`で行う．
- `main`では，`const double numbers[] = {0.5, 1.25, -2.0};`と`const double precise[] = {0.123, 0.456, -7.891};`を宣言し，`round_trip("numbers.txt", "numbers.bin", numbers, 3);`，`round_trip("precision.txt", "precision.bin", precise, 3);`の順に呼ぶ．

表示は次のようになります．

~~~text
numbers.txt: 0.500 1.250 -2.000
numbers.bin: 0.500 1.250 -2.000
precision.txt: 0.120 0.460 -7.890
precision.bin: 0.123 0.456 -7.891
~~~

??? tip "ヒント"

    `fwrite`の第3引数は`size_t`です．`int`の`n`と比べるときは，`(size_t)n`のように型をそろえると，符号の異なる比較の警告を避けられます．

`numbers`の値は小数点以下2桁で表せるので，テキストで保存しても読み戻した値は元と同じです．`precise`は保存時に`%.2f`で丸められるので，テキスト側は0.120のように3桁目が失われます．バイナリ側はメモリ上の`double`をそのまま保存しているので，文字列への変換による丸めが入りません．テキストでも十分な桁数で書けば精度を保てるので，「テキストだから必ず精度が失われる」わけではありません．

`numbers.bin`の大きさは`1 + 3 * sizeof(double)`バイトで，`double`が8バイトなら25バイトです．`numbers.txt`の大きさは文字数と改行方式で変わり，WindowsのCRLFでは22バイト，LFでは18バイトです．この小さな例ではテキストの方が小さくなります．どちらの形式が常に小さい・速いというわけではなく，人が読めること，交換しやすいこと，値を正確に戻せることなど，目的で選びます．

ここでの`fscanf`は，この実行で自分が作ったファイルを読むためのものです．任意の外部ファイルに対する厳密な検査ではありません．外部のテキストを検査する例は，発展2で扱います．

## 発展2　二乗の一覧を書き出して検索する

`Squares`プロジェクトに`squares.c`を作ります．この課題では，次の2つの小問を順に行い，同じファイルへ書き足します．

1. 発展2-1：二乗の一覧をファイルへ書き，そのファイルから値を探す．
2. 発展2-2：形式の正しくないファイルも作って検索する．

保存形式は講義の「保存形式を先に決める」のとおりです．最初の行が個数`N`，続く`N`行が0から`N`−1までの整数の二乗です．`N`は0〜100，検索する値と保存する値は0〜9801に限ります．99の二乗が9801なので，この条件では計算のオーバーフローが起きません．

ファイルの各行は，ASCII・`NUL`なし・1行1整数・30バイト以内とします．値の前後の空白は許しますが，空行，個数不足，余分な行，範囲外の値は拒否します．最後の行に改行がなくても受け付けます．

### 発展2-1　書き出して検索する

個数`N`と，0から`N`−1までの整数の二乗を1行ずつファイルへ書き，そのファイルから整数を探すプログラムを作成し，3つのファイルと範囲外の`N`で，書き込みと検索の結果を確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- `stdio.h`，`stdlib.h`，`string.h`，`errno.h`，`ctype.h`をインクルードする．
- 関数`int write_squares(const char *filename, long n)`を作る．`n`が0〜100でなければ，ファイルを開かずに0を返す．範囲内なら，モード`w`で開き，`fprintf`の`%ld`で`n`と，`0 * 0`〜`(n - 1) * (n - 1)`を1行ずつ書く．書き込みと`fclose`がすべて成功したら1，それ以外は0を返す．
- 関数`int parse_value(const char *s, long limit, long *out)`を作る．`strtol`で変換し，数字を読めない，`ERANGE`，0未満，`limit`より大きい，のどれかなら0を返す．変換の終わりの後は`isspace`で空白を読み飛ばし，そこが文字列の終わりでなければ0を返す．成功したときだけ`*out`へ値を書き込んで1を返す．
- 関数`int read_value(FILE *fp, long limit, long *out)`を作る．`char line[64];`へ`fgets`で1行読み，読めなければ0を返す．行末の`'\n'`，続けてその前の`'\r'`があれば取り除き，残りが30バイトより長ければ0を返す．それ以外は`parse_value(line, limit, out)`の結果を返す．
- 関数`int check_value(const char *filename, long target, int *found)`を作る．
    - モード`r`で開き，`read_value`で個数`n`（上限100）を読む．
    - 続けて`n`個の値（上限9801）を`read_value`で読み，`target`と等しい値があったかを記録する．見つけても途中で`return`せず，`n`個すべてを読む．
    - その後に`fgetc`が`EOF`以外を返したら，余分なデータとして失敗にする．
    - `ferror`と`fclose`も調べる．形式の誤りや読み取りの失敗があれば0を返し，`*found`は変更しない．成功なら，見つかったかどうか（1または0）を`*found`へ書き込んで1を返す．
- 関数`void show_write(const char *filename, long n)`を作る．`printf("write %s n=%ld: ok=%d\n", filename, n, write_squares(filename, n));`で表示する．
- 関数`void search(const char *filename, long target)`を作る．`check_value`が失敗なら`printf("%s %ld: invalid\n", filename, target);`，成功なら`printf("%s %ld: %s\n", filename, target, found ? "found" : "not found");`で表示する．
- `main`では，次の順に呼ぶ．`missing.txt`は作らない．

| 順 | 呼び出し |
| ---: | --- |
| 1 | `show_write("squares.txt", 4)` |
| 2 | `show_write("squares0.txt", 0)` |
| 3 | `show_write("squares100.txt", 100)` |
| 4 | `show_write("bad.txt", 101)` |
| 5 | `search("squares.txt", 9)` |
| 6 | `search("squares.txt", 12)` |
| 7 | `search("squares0.txt", 0)` |
| 8 | `search("squares100.txt", 0)` |
| 9 | `search("squares100.txt", 9801)` |
| 10 | `search("missing.txt", 9)` |

表示は次のようになります．

~~~text
write squares.txt n=4: ok=1
write squares0.txt n=0: ok=1
write squares100.txt n=100: ok=1
write bad.txt n=101: ok=0
squares.txt 9: found
squares.txt 12: not found
squares0.txt 0: not found
squares100.txt 0: found
squares100.txt 9801: found
missing.txt 9: invalid
~~~

`squares.txt`は4，0，1，4，9の5行です．`squares0.txt`は個数0の1行だけなので，0も見つかりません．`squares100.txt`はヘッダを含めて101行で，最後の行は9801です．`n=101`はファイルを開く前に拒否するので，`bad.txt`は作られません．

### 発展2-2　形式の正しくないファイルを検索する

いろいろな内容のファイルを作って9を検索する処理を加えたプログラムを作成し，8通りの内容で，受け付けるファイルと拒否するファイルを確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 課題1-1と同じ`int write_text_file(const char *filename, const char *text)`を作る．
- 関数`void try_content(const char *filename, const char *text)`を作る．`write_text_file`で`text`を書き，失敗なら`printf("%s: write error\n", filename);`で表示して戻る．成功なら`search(filename, 9)`を呼ぶ．
- `main`では，発展2-1の表示の後に，次の表の順に`try_content`を呼ぶ．

| ファイル名 | 書く内容 | 内容の意味 |
| --- | --- | --- |
| `no_newline.txt` | `"4\n0\n1\n4\n9"` | 最後の行に改行がない |
| `spaces.txt` | `"1\n 9 \n"` | 値の前後に空白 |
| `short.txt` | `"4\n0\n1\n4\n"` | 個数が4なのに値が3個 |
| `letters.txt` | `"1\nabc\n"` | 数値でない行 |
| `large.txt` | `"1\n99999\n"` | 値が範囲外 |
| `extra.txt` | `"1\n9\n\n"` | 最後に余分な空行 |
| `header.txt` | `"101\n"` | 個数が範囲外 |
| `empty.txt` | `""` | 空のファイル |

発展2-2で加わる表示は次のとおりです．

~~~text
no_newline.txt 9: found
spaces.txt 9: found
short.txt 9: invalid
letters.txt 9: invalid
large.txt 9: invalid
extra.txt 9: invalid
header.txt 9: invalid
empty.txt 9: invalid
~~~

発展2全体の表示は次のようになります．

~~~text
write squares.txt n=4: ok=1
write squares0.txt n=0: ok=1
write squares100.txt n=100: ok=1
write bad.txt n=101: ok=0
squares.txt 9: found
squares.txt 12: not found
squares0.txt 0: not found
squares100.txt 0: found
squares100.txt 9801: found
missing.txt 9: invalid
no_newline.txt 9: found
spaces.txt 9: found
short.txt 9: invalid
letters.txt 9: invalid
large.txt 9: invalid
extra.txt 9: invalid
header.txt 9: invalid
empty.txt 9: invalid
~~~

ヘッダに個数が書かれていても，その個数の行が本当にあるかは別に確かめます．`short.txt`は9の行がないので個数不足，`extra.txt`は値を読み終えた後に空行が残るので失敗です．`read_value`が失敗したときは，その呼び出しで得られなかった値を使いません．

このプログラムが検査するのはファイルの形式で，各値が本当に0，1，4，9という順の二乗になっているかまでは調べません．例えば，個数2で5と6を持つファイルも受け付けます．「ファイル形式の検査」と「値が特定の計算結果かの検査」は別のものです．値を集めるだけなら固定長の配列に保存する方法もありますが，検索だけなら1個ずつ比べられるので，全体を配列に保存していません．

## 確認問題

この節は自習用で，成績には含めません．

1. ファイルを開くことに失敗した後，`fclose(NULL)`で後始末してよいか．
2. 最後に改行がない行の長さを，`strlen`から必ず1を引いて求めてよいか．
3. `argc`が正しくても引数の内容を調べる理由は何か．
4. `fread`の戻り値3は，必ず3バイト読んだという意味か．
5. ファイルの拡張子を変えるとテキストとバイナリが変換されるか．
6. UTF-8の「あ」のバイト数と見た目の文字数は同じか．
7. 読んだ個数をそのまま配列の長さとして信用してよいか．
8. 値を見つけても，`check_value`が最後まで読むのはなぜか．

## チェックリスト

- 各課題のソースが1つのファイルにまとまり，警告なしでビルドできる．
- 1回の実行で，課題に示したすべての場合の結果が表示される．
- 表示が，課題に示した出力と一致する．
- 関数の名前，引数，戻り値の型が課題の指定どおりである．
- 小問のある課題で，前の小問の関数や表示を残している．
- `fopen`の戻り値，読み書き関数の戻り値，`fclose`の戻り値を調べている．
- 課題に示した名前以外のファイルへ書き込んだり，削除したりしていない．
