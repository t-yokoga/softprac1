# 第11回　演習：構造体

解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

[講義](lec11.md)を読んでから取り組んでください．出力と処理の流れを予測しましょう．

## 準備と進め方

作業場所は `PL1\week11` です．[第1回](lec01.md#hello)と同じ設定（Cとしてコンパイル，C17，警告レベル4）で，課題ごとに別の空のプロジェクトを作ります．特に指定がなければ，`main`を持つソースは1プロジェクトに1つです．保存後にCtrl+Shift+Bでビルドし，Ctrl+F5で実行します．

各課題で，ソース，試した値，予測，実行結果，結果の説明を残してください．提出先や締切は，授業時に案内します．

### 今回の進め方

| 課題 | 作る・確認するもの | 学ぶこと |
| --- | --- | --- |

構造体の定義は`main`より前に置きます．同じプロジェクトに複数の`main`を置かず，別課題の型定義を重複して貼り付けないでください．指定初期化子の書き方で診断が出た場合は，`.cpp`ではなく`.c`で，C17としてコンパイルしているかも確認します．


## 課題1　値とポインタの違い

`PointMove` プロジェクトで`structs.c`を実行し，`moved`を呼んだ直後と`move_in_place`を呼んだ直後の`a`を比較します．移動量を0，0にした場合も確認してください．

### 変更される対象を追跡する

ダウンロードした`structs.c`の最初の出力は，`a`が(1.0, 2.0)，`b`が(4.0, 1.0)です．`moved`の中にも`p`という`Point`がありますが，それは`main`の`a`とは別のコピーです．呼び出し前後で次の表を埋めてください．

| 時点 | `a.x` | `a.y` | `b.x` | `b.y` |
| --- | ---: | ---: | ---: | ---: |
| `a`の初期化直後 | 1 | 2 | まだない | まだない |
| `moved`の戻り値で`b`を初期化した後 | 1 | 2 | 4 | 1 |
| `move_in_place`で`a`を変更した後 | 4 | 1 | 4 | 1 |

最後に`a`と`b`が同じ座標になっても，同じ保存場所になったわけではありません．その後に`b.x = 100.0;`を追加すれば，変わるのは`b`だけです．`a`も変わると予想した場合は，構造体のコピーをポインタのコピーと混同していないか，図で確かめましょう．

### 3つの呼び出し方を比較する

次の例は，`a`を(1, 2)で初期化した状態から，それぞれ独立に試します．`b`の宣言や表示も，試す形に合わせて整理してください．

| 呼び出し方 | 実行後の`a` | 理由 |
| --- | --- | --- |
| `moved(a, 3.0, -1.0);` | (1, 2) | 結果を受け取っていない |
| `a = moved(a, 3.0, -1.0);` | (4, 1) | 計算結果を`a`へ代入した |
| `move_in_place(&a, 3.0, -1.0);` | (4, 1) | `a`のアドレスを渡して変更した |

値渡しの関数でも，戻り値を元の変数へ代入すれば，結果としてその変数を更新できます．「値渡しなら呼び出した後も絶対に元の変数が変わらない」と覚えるのではなく，関数内での変更と呼び出し側の代入を分けて考えます．

### 移動量を変える

| `dx`，`dy` | 初期値(1, 2)からの移動結果 |
| --- | --- |
| 0，0 | (1, 2) |
| −1，−2 | (0, 0) |
| 2，3 | (3, 5) |

元のサンプルでは`moved`と`move_in_place`の2か所に移動量があります．両方を同じ条件へ変更して比較してください．片方だけ変えた場合，`a`と`b`の結果が違うのは自然です．

**説明すること**：`move_in_place`の`p`はポインタのコピーです．なぜそのコピーから`a`を書き換えられるのでしょうか．`p`自体と`p`が指す`Point`を別の箱として描いてください．`NULL`や初期化していないポインタは渡しません．

## 課題2　点数の平均

`Students` プロジェクトで名前と点数を持つ`Student`を定義し，`Aki=80`，`Ren=70`，`Mio=90`の平均を表示してください．点数は0〜100，人数は1〜3とします．

??? tip "ヒント"

    配列の各要素から`.score`を取り出します．計算の関数は読み取り専用です．

実行前に結果を予測し，実行後に結果とその理由を記録してください．

### 配列要素とメンバを順に読む

`a[1]`は2人目の`Student`，`a[1].score`はその点数70，`a[1].name`は名前を保存した配列です．`a[1].name[0]`は`'R'`になります．添字とドットのどちらを使っているかを順に確認してください．

関数の仮引数`a`は`Student`配列の先頭へのポインタです．`Student`を1個渡すのとは違い，3人分の構造体が自動でコピーされているわけではありません．平均関数では変更しないことを示すために`const`を付けています．

| 変更条件 | 期待する出力 |
| --- | --- |
| 元の点数，`n=1` | 記入してください |
| 元の点数，`n=2` | 記入してください |
| 全員0，`n=3` | 記入してください |
| 全員100，`n=3` | 記入してください |
| 80，70，91，`n=3` | 記入してください |

平均関数には`1<=n<=3`で，実際に`n`人分のデータがあることを約束して渡します．`n=4`なら存在しない要素へ進み，`n=0`なら0で割るので，どちらも実行する実験にはしません．

### 名前と点数を一緒に交換する

`main`で`a[0]`と`a[2]`を交換する場合は，次のように構造体全体をコピーできます．

~~~c
Student temp = a[0];
a[0] = a[2];
a[2] = temp;
for (int i = 0; i < 3; ++i) {
    printf("%s %d\n", a[i].name, a[i].score);
}
~~~

表示順は`Mio 90`，`Ren 70`，`Aki 80`です．平均は80.0のままです．`score`だけを交換すると，名前と点数の対応が壊れます．構造体へまとめたことで「1人分」という単位で操作できる点を確認してください．

### 名前を比較する

同じ学生のデータかを「名前と点数が一致すること」と定義する場合，`string.h`を追加して次の条件を使えます．ここで`left`と`right`は`Student`型の変数です．

~~~c
int same = strcmp(left.name, right.name) == 0 &&
           left.score == right.score;
~~~

`left == right`という比較はCの構造体には使えません．また，`name`のアドレスの一致を調べるのではなく，文字列の内容を比較します．同名の学生を区別する必要があるなら，学生番号など別のメンバを設計する必要があります．

## 課題3　長方形を表す

`Point`を2つ持つ`Rect`を定義してください．左下(1, 2)，右上(5, 5)から面積12.0を求めます．右上の`x`・`y`はそれぞれ左下以上とします．

幅0，高さ0でも面積0になることを確認します．

### メンバ参照を分解する

`main`の`r.lower.x`と，`area`の引数`r`に対する`r->lower.x`は同じ書き方ではありません．前者の`r`は`Rect`本体，後者の`r`は`Rect`へのポインタです．関数をまたいで同じ変数名を使っているため，宣言を確認してください．

`main`で`Rect *q = &r;`とすると，次の4つは同じ値1.0を表します．

~~~c
printf("%.1f %.1f %.1f %.1f\n",
       r.lower.x, (r.lower).x, q->lower.x, (q->lower).x);
~~~

`lower`は`Point`本体であって`Point`へのポインタではありません．そのため`q->lower->x`とは書けません．また，`*q.lower.x`という書き方では必要な間接参照の順序になりません．

### 面積の境界を確認する

| `lower` | `upper` | 幅 | 高さ | 面積 |
| --- | --- | ---: | ---: | ---: |
| (1, 2) | (5, 5) | 4 | 3 | 12 |
| (1, 2) | (1, 5) | 0 | 3 | 0 |
| (1, 2) | (5, 2) | 4 | 0 | 0 |
| (−2, −1) | (1, 3) | 3 | 4 | 12 |

この課題の`area`は，`upper`の各座標が`lower`以上であることを前提にしています．逆向きの座標を渡したら必ず適切な面積になる，という仕様ではありません．両方の差が負なら積が正になってしまうので，面積が正だっただけでは前提を守った証拠にもなりません．座標の順序をそろえる処理は発展2で扱います．

### 名前もメンバにする

`Rect`の型に`char name[21];`を追加すると，座標と名前をまとめられます．その場合は初期化も，例えば次の形へ変更します．

~~~c
Rect r = {
    .lower = {1.0, 2.0},
    .upper = {5.0, 5.0},
    .name = "sample"
};
~~~

この断片は`name`を追加した型でのみ使えます．21要素なので，ASCIIなら20文字と終端を保存できます．`r.name`を別の文字列で更新する場合，宣言後に`r.name = "other";`とは書けません．配列の容量を確かめて文字をコピーする必要があります．構造体全体の代入ができることと，配列メンバ単独への代入ができることは別です．

## 課題4　配列メンバとポインタメンバを比較する

`Student`の`name`が`char`配列ではなく`char *`なら，構造体をコピーした後の2つの`name`は何を指すでしょうか．図で説明してください．

### `CopyMembers`プロジェクト

配列を内部に持つ場合と，別の配列を指す場合を同じプログラムで比較します．どの出力が同じになり，どの出力が違うか，先に矢印の図を描いてください．

~~~text
array=Hoge hoge
pointer=Hoge Hoge same=1
redirect=fuga Hoge same=0
~~~

### 変更を分類する

| 処理 | 直接変更するもの | 他方にも見えるか |
| --- | --- | --- |
| `a1.text[0] = 'H';` | `a1`の内部配列 | `a2`には見えない |
| `p1.text[0] = 'H';` | 共有している`buffer` | `p2`からも見える |
| `p1.text = other;` | `p1`に入っているアドレス | `p2`のアドレスは変わらない |

ポインタをコピーした直後は同じ場所を指すため，`==`で1になります．最後は別々の配列を指すので0です．これはアドレスの比較を意図したものです．文字列の内容を比較したい場面の`strcmp`とは目的が違います．

実際のアドレスを表示するなら`printf("%p", (void *)p1.text);`とします．具体的な数値より，同じか違うかを確認してください．構造体自体のアドレス`&p1`と，メンバに保存された`p1.text`も別物です．

### 全体を別の文字列へ変える場合

長さ4の`hoge`を長さ4の`fuga`へ置き換えるなら，終端を含む5個をコピーします．次の断片を，先頭1文字だけを書き換えていた行の代わりに使えます．`a1.text`には7要素があり，この固定の文字列は収まります．

~~~c
const char replacement[] = "fuga";
for (size_t i = 0; i < sizeof replacement; ++i) {
    a1.text[i] = replacement[i];
}
~~~

配列版では`a1`が`fuga`，`a2`が`hoge`です．同様のコピーを`buffer`へ行えば，`p1`と`p2`の両方から`fuga`が見えます．任意の長さの文字列を受け付けるなら，第8回の容量検査を行う関数が必要です．この固定入力に十分な容量があることを，一般の文字列にもそのまま当てはめないでください．

### 危険な例は実行せず説明する

次の状況について，何が問題かを説明してください．

1. ポインタメンバへ文字列リテラル`"hoge"`を入れ，その先へ書き込む．
2. 関数内の`char buffer[8]`を指す構造体を返し，関数終了後に表示する．
3. 未初期化の`TextPointer`へ，いきなり`text[0]`を書き込む．

## 発展1　初期化と構造体を返す関数

`PointInit`プロジェクトで，メンバ名を指定した初期化，省略したメンバ，複合リテラル，構造体の戻り値を確認します．

~~~text
a=10.0 2.0 result=13.0 7.0
partial=3.0 0.0 zero=0.0 0.0
assigned=-1.0 4.0
~~~

### 宣言順と指定順を比較する

`a`は`.y`を先に書いていますが，`y`へ2.0，`x`へ10.0が入ります．`Point a = {2.0, 10.0};`へ変えると`x=2.0`，`y=10.0`となり，同じ意味にはなりません．名前を指定しない初期化は宣言順に対応します．

`partial.y`と`zero`の両メンバは0.0です．これを「初期化しなくても構造体は0になる」と説明してはいけません．`Point partial;`とだけ宣言したローカル変数のメンバを表示する実験はしません．

最後の代入で`(Point)`を省略した形は正しい代入式ではありません．複合リテラルは`Point`型の値として扱えるため，構造体全体の代入に利用できます．個別に`a.x`，`a.y`へ代入する方法と使い分けます．

### `typedef`の意味を説明する

`typedef int JPY;`と`JPY price = 100;`は別の役割です．前者は別名を付け，後者は変数を作ります．`Point`も同じで，`typedef`の定義だけで座標データが1個作られるわけではありません．

発展として，`Point`をタグ付きの`typedef`へ書き換え，変数宣言の1つだけをstruct pointに変えても，同じ型として扱えることを確認してください．型の定義を追加するのではなく，既存の定義を書き換えます．

## 発展2　長方形を正規化して点を判定する

`RectContains`プロジェクトを作ります．2点が逆順でも，`x`と`y`それぞれの下限・上限へそろえた長方形を作る関数`normalized`と，点が範囲内かを判定する`contains`を使います．この課題の範囲は下限を含み，上限を含みません．

~~~text
sample lower=1.0 1.0 upper=3.0 4.0
inside=1 original=1.0 4.0
~~~

### 座標の順序を独立にそろえる

| 入力の2点 | 正規化後の`lower` | 正規化後の`upper` |
| --- | --- | --- |
| (1, 1)，(3, 4) | (1, 1) | (3, 4) |
| (3, 4)，(1, 1) | (1, 1) | (3, 4) |
| (1, 4)，(3, 1) | (1, 1) | (3, 4) |
| (3, 1)，(1, 4) | (1, 1) | (3, 4) |

それぞれを別々に試します．2点を一括で交換するだけでは，3行目や4行目を正規化できません．また，`x`を交換した後の値を使って`y`を判定する必要はなく，各軸を独立に処理できます．

関数の最初の`Rect result = r;`は，座標だけでなく名前もコピーします．座標だけを新しい未初期化の`Rect`へ書き込むと，`name`が未設定のままになってしまいます．戻す構造体のすべてのメンバが，どこで値を得たのかを説明してください．

### 内側・外側・境界を調べる

`lower=(1, 1)`，`upper=(3, 4)`へ正規化した長方形について確認します．

| 点 | 結果 | 理由 |
| --- | ---: | --- |
| (2, 2) | 記入してください | 内側 |
| (1, 1) | 記入してください | 下限を含む |
| (1, 3) | 記入してください | `x`が下限でも`y`が範囲内 |
| (3, 2) | 記入してください | `x`の上限を含まない |
| (2, 4) | 記入してください | `y`の上限を含まない |
| (0, 2) | 記入してください | `x`が下限より小さい |
| (2, 5) | 記入してください | `y`が上限より大きい |

幅0や高さ0の長方形では，この条件を満たす点はありません．例えば`lower=(1, 1)`，`upper=(1, 4)`で`p=(1, 2)`でも0です．閉じた図形なら境界も含めるという直感だけで，`<`を`<=`へ変えないでください．まず仕様を決めます．

### 元のデータと計算結果

`normalized`は`r`の値を変更して返すのではなく，`r`のコピーから結果を作ります．呼び出し元の`r`は入力の順序のままです．元も正規化したい場合は`r = normalized(r);`と代入します．

名前の保持を確かめるには，`.name`を`"test_rect"`などへ変えて実行します．名前が長すぎて21要素に収まらない例は使いません．名前を保存することと座標を並べ替えることは別の処理ですが，1つの構造体の戻り値にまとめられます．

## 発展3　構造体のサイズを観察する

`StructLayout`プロジェクトでは`stdio.h`と`stddef.h`を読み込み，講義の`Record`を定義します．次の断片を`main`へ置きます．

~~~c
printf("size=%zu tag=%zu count=%zu flag=%zu\n",
       sizeof(Record), offsetof(Record, tag),
       offsetof(Record, count), offsetof(Record, flag));
~~~

通常のVisual Studio x64の既定設定では`size=12 tag=0 count=4 flag=8`となります．ただし環境や配置設定によって結果が違っても，直ちに誤りとは限りません．`sizeof`が3個のメンバのサイズの単純な合計と違う場合，どこに隙間があるかを図にしてください．

この実験は隙間の中身を表示するものではありません．パディングの値が一定だと仮定せず，メンバの位置と全体サイズだけを調べます．`memcmp`で構造体全体を比較して，同じデータか判定する課題にも使いません．

第10回と結び付けて考えましょう．構造体全体を`fwrite`した場合，どのような情報まで保存されるでしょうか．メンバの表現だけでなく，処理系依存の配置も含まれます．ポインタメンバのアドレスを保存しても，次の実行で同じ文字列を指せるとは限りません．保存形式はメンバごとに意味を決めて設計する必要があります．

## 確認問題

1. struct pointの定義と`Point p;`は何が違うか．
2. 指定初期化子で`.y`を先に書くと，値の対応は変わるか．
3. 構造体内の配列もコピーされるのに，通常の配列代入ができないのは矛盾か．
4. `Point`を値で渡す場合と`Point`配列を渡す場合は同じか．
5. `q->lower.x`では，なぜ->とドットが両方必要か．

7. 長方形を正規化するとき，2点を交換するだけで十分か．
8. `contains`で上限の点が0になるのはバグか．
