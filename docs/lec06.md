# 第6回　文字列


## 到達目標

- 文字と文字列，終端文字と数字の0を区別できる．
- 容量を考えて文字列をコピー・比較できる．
- 型変換が行われるタイミングと情報の損失を説明できる．


## 1　文字と文字列

### 前回とのつながりと作業の準備 { #environment }

第5回では，同じ型の値を配列にまとめ，関数へ渡す方法を学びました．今回は`char`配列を使って文字列を扱います．数値配列との違いは，**値0の終端文字を文字列の終わりの目印にする**ことです．後半では，文字コードや整数・小数の計算にも関係する型変換を整理します．

作業場所は`PL1`の下の`week06`です．Visual Studioで課題ごとに空のプロジェクトを作り，`.c`ファイルを追加します．[第1回の設定](lec01.md#hello)と同じくC17・Cとしてコンパイル・警告レベル4を使います．文字列はソース内の固定値で用意し，キーボード入力は次回扱います．

短いコード片は`main`内に置き，関数定義は`main`の外へ置きます．`printf`には`stdio.h`，文字列ライブラリには`string.h`をインクルードしてください．今回の例はASCIIの英数字と記号を対象とし，日本語の文字コードは第10回で扱います．

### 1文字は整数としても読める

~~~c
char ch = 'a';
printf("character=%c code=%d\n", ch, ch);
~~~

ASCIIでは`character=a code=97`と表示されます．`%c`は対応する文字，`%d`は整数として表示します．`'A'`は65，`'B'`は66で，大文字と小文字は別の値です．文字コードをそのまま数値で書くより，`'a'`のように文字で書く方が意図を読み取りやすくなります．

ASCIIは0〜127の符号位置を使います．その中には改行などの制御文字もあり，すべてが画面上の記号になるわけではありません．`char`は授業の環境では8ビットですが，ASCII自体が8ビットすべてを使うわけではありません．

### 終端を持つ`char`配列

`'A'` は文字定数，`"A"` は文字列リテラルです．Cの文字列は，`char`の並びを**終端文字 `'\0'`** で終えたものです．

~~~c
char word[] = "cat";
~~~

| 添字 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| 要素 | `'c'` | `'a'` | `'t'` | `'\0'` |

文字列の長さは3，配列の要素数は4です．`char word[16] = "cat";` とすれば，容量16のうち文字列には4要素を使います．終端までの部分が文字列なので，配列の容量と文字列の長さは違います．

| 表記 | 意味 |
| --- | --- |
| 0 | 整数のゼロ |
| `'0'` | 数字として見える文字．ASCIIでは値48 |
| `'\0'` | 値0の文字．文字列の終わり |
| `"0"` | `'0'`と`'\0'`からなる文字列 |
| `"\0"` | `'\0'`が2個の配列．明示した0と自動的に付く終端を含む |
| `""` | `'\0'`だけの配列．長さ0の空文字列 |

`"\0"`は`sizeof`で2バイト，`strlen`では0です．最初の要素が終端だからです．`'\0'`は**ヌル文字**とも呼びます．後で学ぶポインタの`NULL`とは区別してください．Windowsではバックスラッシュが円記号に見える場合がありますが，ソースのエスケープはバックスラッシュと0で書きます．

### 初期化とメモリ上の並び

`char word[] = "cat";`は，`char word[] = {'c', 'a', 't', '\0'};`と同じ並びを用意します．要素数を省略すると終端を含めた4になります．`char word[6] = "cat";`では初期化で残った要素も0になります．

~~~text
添字         0       1       2       3       4       5
           ┌───────┬───────┬───────┬───────┬───────┬───────┐
要素       │ 'c'   │ 'a'   │ 't'   │ '\0'  │ '\0'  │ '\0'  │
ASCII値    │ 99    │ 97    │ 116   │ 0     │ 0     │ 0     │
           └───────┴───────┴───────┴───────┴───────┴───────┘
文字列       └─── 表示する3文字 ───┘  ↑ 最初の終端
配列容量     └──────────────── 6バイト ──────────────────┘
~~~

各要素は1バイトで連続します．数値とアドレスを同時に見れば，第5回の配列と同じ仕組みだと確認できます．

~~~c
char s[] = "cat";
for (size_t i = 0; i < sizeof s; ++i) {
    printf("index=%zu code=%d address=%p\n",
           i, s[i], (void *)&s[i]);
}
~~~

`code`は99，97，116，0の順です．`%c`で終端を表示しても目に見える文字にはなりません．アドレスの具体値は環境によりますが，隣接要素は1バイトずつ進みます．

!!! warning "終端を含めて領域を用意する"

    `cat`には最低4要素必要です．`char s[3] = "cat";`はCでは終端なしの配列になり，`%s`や`strlen`で文字列として扱えません．範囲外を読ませて結果を観察するのではなく，配列の要素を紙に書いて不足を確認します．

`char s[3] = "hello";`のように文字そのものも収まらない初期化は，Cの制約に違反し診断の対象になります．「余分な文字が都合よく切り捨てられる」と考えてはいけません．終端がない配列を`%s`へ渡した場合も，隣の変数が表示されるなど特定の結果は保証されません．

## 2　表示・変更・コピー

`printf("%s\n", word);` は終端まで表示します．`word[0] = 'C';` は書き換え可能な配列の要素を変更します．`word = "dog";` のような配列への代入はできません．

文字列をコピーするには，終端を含めて1文字ずつ移すか，ライブラリ関数を使います．どちらもコピー先の容量が必要です．読み込んだ文字列を`printf`の書式そのものにせず，`printf("%s", word);` のようにデータとして渡します．

### 最初の終端で文字列が終わる

~~~c
char s[] = {'a', 'b', 'c', '\0', 'd', 'e'};
printf("%s\n", s);
~~~

表示は`abc`です．配列は6要素ですが，最初の終端より後の`d`と`e`は，この文字列の一部としては読まれません．`word[1] = '\0';`とすれば`word`の表示は先頭1文字だけになります．配列そのものの容量が小さくなったわけではありません．

文字列リテラルも添字で読むことができ，"abcd"[3]は`'d'`です．ただし文字列リテラル自体を書き換えてはいけません．`char word[] = "cat";`では，リテラルから別の書き換え可能な配列を初期化しています．ポインタでリテラルを指す場合との違いは第8回で扱います．

### 文字列を関数へ渡して走査する

~~~c
size_t count_spaces(const char s[])
{
    size_t count = 0;
    for (size_t i = 0; s[i] != '\0'; ++i) {
        if (s[i] == ' ') {
            ++count;
        }
    }
    return count;
}
~~~

この関数へ`"abc def gh"`を渡すと2，`"ijk lmn opq rst"`なら3を返します．`' '`は半角スペースであり，タブや改行は数えません．`const`は要素をこの引数から変更しないことを表します．`size_t`を使う宣言には`stddef.h`などが必要です．

数値配列では長さを別に渡しましたが，ここでは終端から終わりが分かります．ただし，**読み取り可能な領域内に終端が存在すること**が前提です．終端があるから配列の容量も分かる，という意味ではありません．関数の配列引数へ`sizeof`を使っても元の容量は得られません．

### 書式も文字列だが，データとは分ける

~~~c
char format[] = "%d\n";
int n = 2;
printf(format, n);
~~~

自分で内容を固定した書式文字列を変数から渡すこともでき，この例は2を表示します．ただし，任意のデータを`printf(text);`と渡すと，含まれる`%`が書式として解釈されます．通常は`printf("%s", text);`と書き，書式と表示したいデータを分離します．

## 3　文字列ライブラリ

`<string.h>` をインクルードして使います．

| 関数 | 役割 | 注意点 |
| --- | --- | --- |
| `strlen(s)` | 終端を除く長さ | `size_t`を返す．終端のある文字列が必要 |
| `strcmp(a, b)` | 内容を辞書式に比較 | 等しければ0，前なら負，後なら正 |
| `strcpy(dst, src)` | 終端を含めてコピー | 容量を自動確認しない．重なる領域には使わない |
| `strcat(dst, src)` | 末尾に連結 | 元の長さ＋追加の長さ＋1の容量が必要 |

`strcmp`の結果が-1や1になるとは限りません．**符号だけ**を調べます．文字列の内容の比較には `==` を使いません．

この回の実行例では，容量を確認した要素ごとのコピーを用います．Visual Studio固有の警告を一括で無効にする必要はありません．

### `strlen`と`sizeof`を比較する

| 宣言 | `sizeof`で求める容量 | `strlen`で求める長さ | 終端込みで必要な量 |
| --- | ---: | ---: | ---: |
| `char s[] = "abc";` | 4 | 3 | 4 |
| `char s[10] = "abc";` | 10 | 3 | 4 |
| `char s[10] = "";` | 10 | 0 | 1 |

`strlen`は最初の終端までを調べます．`sizeof`はその配列全体の大きさです．途中の要素を終端へ書き換えると`strlen`の結果は変わりますが，`sizeof`の結果は変わりません．どちらの結果も`size_t`型なので`%zu`で表示します．

### `strcpy`と`strcat`の役割を読む

次は標準関数の読み方を知るためのコードです．Visual Studioでは`strcpy`・`strcat`に安全性に関する`C4996`の診断が出ることがあるため，今回の実行課題では後述の容量確認付きループを使います．

~~~c
char destination[10];
strcpy(destination, "hello");
char joined[10] = "hoge";
strcat(joined, "fuga");
~~~

`destination`には`hello`と終端の6バイト，`joined`には`hogefuga`と終端の9バイトが入ります．どちらの容量も10のままです．`strcpy`は先頭から上書きし，`strcat`は元の文字列の終端位置から追加して，新しい末尾にも終端を書きます．`strcat`のコピー先は，呼び出す前から終端を持つ文字列でなければなりません．

これらの関数はコピー先の容量を引数で受け取らず，自動的に配列を大きくもしません．容量不足や領域の重なりを起こしてはいけません．容量を渡せる別の関数を使う場合も，正しい容量と有効な引数を渡す責任は残ります．

### 容量を確かめて連結する

~~~c
char joined[10] = "hoge";
char suffix[] = "fuga";
size_t used = strlen(joined);
size_t added = strlen(suffix);
if (added < sizeof joined - used) {
    for (size_t i = 0; i <= added; ++i) {
        joined[used + i] = suffix[i];
    }
}
printf("%s\n", joined);
~~~

`used`は4，`added`も4です．残り6バイトに，追加する4文字と終端が収まるので`hogefuga`になります．`<= added`は終端もコピーするためです．このコードは`joined`が容量内で終端を持ち，`suffix`とは別の配列であることを前提にしています．収まらない場合は追加せず，元の文字列を保ちます．

### `strcmp`は最初に違う文字で決まる

`strcmp("abc", "abc")`は0，`strcmp("abc", "abcd")`は負，`strcmp("b", "a")`は正です．同じ位置の文字を先頭から比較し，最初に異なる位置で順序が決まります．`abc`と`abcd`なら，3文字の後の終端と`'d'`が違うため，短い方が先になります．

概念的には「同じ文字なら次へ進む，両方が終端なら等しい，異なるならその位置の大小を返す」という処理です．標準の`strcmp`は比較する文字を`unsigned char`として解釈します．実装によって差の値を返す場合もありますが，結果がちょうど−1や1，あるいは−100になることには依存しないでください．

~~~c
int comparison = strcmp("abc", "abcd");
if (comparison < 0) {
    printf("before\n");
} else if (comparison == 0) {
    printf("equal\n");
} else {
    printf("after\n");
}
~~~

文字列の長さを比較しているわけではなく，`"z"`は`"aaa"`より後です．また，大小文字を区別し，言語ごとの辞書の並び順を自動で理解するわけではありません．

## 4　文字コードと長さ

この回の演習ではASCIIの英数字を使います．ASCIIでは英大文字・英小文字・数字に数値が割り当てられています．`'7' - '0'` は7です．`"123"` は3文字なので，数値123にするには各桁を解釈する処理が必要です．キャストだけでは数値へ変換できません．

日本語は1文字を複数バイトで表す場合があります．`strlen`は見た目の文字数ではなく，終端までの**バイト数**を返します．文字コードは第10回で詳しく扱います．

数字の文字を数値へ変えるときは，先に`'0'`〜`'9'`の範囲かを調べます．範囲外の`'A'`などから`'0'`を引いても，数字を解釈した結果にはなりません．ASCIIの英大文字を小文字へ変える場合も，`'A'`〜`'Z'`だけを選び，`'a' - 'A'`を加えます．空白，数字，記号をそのまま残すことが重要です．

ASCII表を調べるなら，印字可能な32〜126を`%c`と整数値で表示します．0〜31と127は制御用なので，文字として出力する代わりに値や名称で確認しましょう．タブや改行を不用意に出力すると，表の配置自体が変わります．

## 5　数値の型変換

~~~c
int total = 7;
int count = 2;
double mean = (double)total / count;
~~~

`(double)total` は明示的な型変換（キャスト）です．除算の前に変換するため3.5になります．`(double)(total / count)` は整数除算の後なので3.0です．

代入や計算でも暗黙の変換が行われます．`int n = (int)3.9;` は3，`(int)-3.9` は-3です．変換先の整数型の範囲に収まる場合だけ行います．浮動小数点数から整数への変換は小数部分を失い，大きな整数を`float`へ変換する場合も精度を失うことがあります．

小さい整数型は計算前に通常`int`へ整数拡張されます．ただし`int`同士の演算が，桁あふれを避けるため自動で`long long`になることはありません．符号付きと符号なしを混ぜた比較にも注意します．

### 暗黙の変換が起きる4つの場面

| 場面 | 例 | 何が変わるか |
| --- | --- | --- |
| 異なる型の演算 | `2 + 0.5` | `int`の2を`double`へ変換して加算 |
| 代入・初期化 | `double x = 3;` | `int`の3を`double`へ変換 |
| 宣言された引数へ渡す | `int`を受ける関数へ3.9を渡す | 仮引数の型`int`へ変換 |
| `return`で返す | `int`の関数で`return 3.9;` | 戻り値型`int`へ変換 |

最後の2つは3となり，処理系が情報損失について警告することがあります．警告を消すためだけにキャストせず，そもそも整数を受け取る・返す仕様でよいかを考えます．

### 通常の算術型変換と整数拡張

この回の型の組み合わせでは，`int`と`float`なら`float`，`float`と`double`なら`double`へ型をそろえて計算します．ただし「自動変換なら情報を失わない」とは限りません．大きな整数を`float`へ移すと，下位の桁を区別できなくなる場合があります．

~~~c
char c1 = 10, c2 = 100, c3 = 20;
int result = c1 * c2 / c3;
printf("%d\n", result);
~~~

MSVCではこれらの`char`の全値を`int`で表せるため，計算前に`int`へ拡張します．途中の1000も`int`で計算され，結果は50です．一般には，小さい整数型の全値を`int`で表せるなら`int`，表せなければ`unsigned int`へ拡張する規則です．

### 代入先の型が大きくても，計算は先に終わる

~~~c
int i = 50000;
long long square = (long long)i * i;
printf("%lld\n", square);
~~~

この例では先に`long long`へ変換してから掛けるので2500000000になります．`long long square = i * i;`では右辺が`int`同士の演算のままで，32ビット`int`の範囲を超えます．その危険な形を実行する実験は行いません．MSVCの`long`は4バイトなので，この例では`long`ではなく`long long`を使います．

10進整数リテラルは接尾辞がなければ`int`，`long`，`long long`の順に表現できる型が選ばれます．MSVCでは5000000000は`long`にも収まりません．`long long n = 5000000000LL;`のように意図する型を明示し，`%lld`で表示します．小さい型に入れて失った値を，`printf`の書式だけで復元することはできません．書式と実際の引数の型の不一致も避けてください．

`float x = 3.223;`では`double`のリテラルから`float`へ変換します．`float`を意図するなら`3.223f`と書けますが，どちらも小数が必ず厳密に保存されるという意味ではありません．

### 狭い型への変換と往復

| 変換 | この回での注意 |
| --- | --- |
| 小数→整数 | 範囲内で小数部を0方向へ切り捨てる．四捨五入ではない |
| 整数→狭い符号付き整数 | 範囲外ならC17では結果またはシグナルが処理系定義．特定の値を期待しない |
| 整数→符号なし整数 | 変換先の範囲に入るよう，最大値＋1を法とする値になる |
| 整数→`float` | 値によって精度が失われる．バイト数だけで安全と判断しない |

例えば8ビット`unsigned char`へ整数300を変換すると，256を法として44になります．符号付き整数の**計算のオーバーフロー**は未定義動作であり，ここでの整数型への変換規則とは別です．浮動小数点数を整数へ変換するときも，整数部分が変換先で表せない場合は安全ではありません．

MSVCで`char c = 'A';`を`int i`へ移し，その`i`を`char`へ戻す場合，もとの値は保たれます．一方，`int`から`char`などへ縮めて情報を失った後に`int`へ戻しても，失った情報は復元されません．キャストは警告を抑えるおまじないでも，値の範囲を保証する検査でもありません．

### 符号付きと符号なしを混ぜない

`int i = -10;`，`unsigned int u = 10u;`として`i < u`を比較すると，`i`が`unsigned int`へ変換されます．32ビット`unsigned int`では−10が4294967286として扱われ，結果は偽です．この比較は読解例であり，実際のコードでは型と値の範囲を整理してから比較します．

`u`が`INT_MAX`以下と確認できる場合に限り，`i < (int)u`とすれば`int`同士で比較できます．無条件にキャストすると別の情報損失を生むため，先に範囲を確かめることが必要です．`strlen`や`sizeof`の`size_t`も符号なしなので，負数との比較や，0から1を引く操作には注意してください．

## 6　例：コピー元とコピー先

~~~c title="strings.c" linenums="1"
--8<-- "sample/06/strings.c"
~~~

[`strings.c`](sample/06/strings.c){ download }

~~~text
Cat cat
length=3 capacity=16
equal=0
mean=3.5
~~~

コピーのループが `i <= length` なのは，終端も移すためです．コピー後に`word`を変更しても，別の配列`copy`の要素は変わりません．

### 実行順を追う

| 時点 | `word` | `copy` | 注目点 |
| --- | --- | --- | --- |
| 初期化後 | `cat` | 空文字列 | `copy`の先頭は0 |
| コピー後 | `cat` | `cat` | 添字0〜3の4要素を移す |
| `word[0]`の変更後 | `Cat` | `cat` | 別々の配列なので片方だけ変化 |

`length`は最初に求めた3です．容量16に対する`length < sizeof copy`は，終端用の1要素を残せるかを調べています．容量が3なら条件は偽になり，コピーせず初期化済みの空文字列を保ちます．このときも`%s`へ渡せる終端があります．

| 文字列の後ろに余分な表示が出る | 終端が容量内にあるか．結果観察より原因修正を優先 |
| 空文字列の`sizeof`が0でない | 終端用の1要素が必要 |
| 同じ文字列なのに`==`が真にならない | 内容比較に`strcmp`を使ったか |
| コピー後の容量が変わらない | 内容の長さと配列容量は別 |
| 平均の小数部が失われる | 割り算の前に型を変えたか |
| 大きな値を別の書式で表示しても直らない | 計算・代入の時点で情報を失っていないか |

「文字数＋1の容量」「終端の位置」「変換が起きるタイミング」を順に確認してから演習へ進みましょう．
