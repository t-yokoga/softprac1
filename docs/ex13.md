## 課題1　動的配列

`DynamicArray`プロジェクトに`dynamic_array.c`を作ります．この課題では，次の3つの小問を順に行い，同じファイルへ書き足します．

1. 課題1-1：実行時に決めた個数の配列を確保し，合計と平均を表示する．
2. 課題1-2：確保した配列を逆順に並べ替える．
3. 課題1-3：配列の独立したコピーを作る．

### 課題1-1　1から`n`までの配列を作る

1から`n`までの整数を入れた配列を`malloc`で確保して返す関数を使うプログラムを作成し，5通りの個数で，合計と平均，範囲外の個数を確保前に拒否することを確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 必要な標準ヘッダ（`stdio.h`，`stdlib.h`，`stdint.h`）をインクルードする．
- 関数`int *make_sequence(size_t n)`を作る．`n`は1以上とする．`n`要素の`int`配列を`malloc`で確保し，`a[i]`に`i + 1`を入れて返す．成功時の所有者は呼び出し元で，呼び出し元が`free`する．
- `make_sequence`は，`malloc`の前に，要素数と要素の大きさの積`n * sizeof *a`が`SIZE_MAX`を超えないことを調べる．超える場合と確保に失敗した場合は`NULL`を返す．この約束を関数の前にコメントで書く．
- 関数`void show_sequence(size_t n)`を作る．`show_sequence`は次の処理を行う．
    - `n`が1〜1000の範囲外なら，`printf("n=%zu rejected\n", n);`で表示し，確保せずに戻る．
    - `make_sequence(n)`を呼ぶ．戻り値が`NULL`なら`printf("allocation failed\n");`で表示して戻る．
    - 要素の合計を`long long`で求め，`printf("n=%zu sum=%lld mean=%.1f\n", n, sum, (double)sum / (double)n);`で表示してから，配列を`free`する．
- `main`では，`n`が1，5，1000，0，1001の順に`show_sequence`を呼ぶ．

表示は次のようになります．

~~~text
n=1 sum=1 mean=1.0
n=5 sum=15 mean=3.0
n=1000 sum=500500 mean=500.5
n=0 rejected
n=1001 rejected
~~~

??? tip "ヒント"

    要素の大きさは`sizeof *a`で求めます．`sizeof a`はポインタ自身の大きさで，要素の大きさではありません．`n > SIZE_MAX / sizeof *a`なら，積`n * sizeof *a`は`size_t`で表せません．

`values`のようなポインタの`sizeof`から，`malloc`へ渡した個数を復元することはできません．個数`n`を別に持ち続けることが，動的配列を安全に使うための情報管理です．`n`要素の最後の添字は`n - 1`なので，ループの条件は`i <= n`ではなく`i < n`です．

### 課題1-2　配列を逆順にする

確保した配列を同じ領域の中で逆順に並べ替える関数を加えたプログラムを作成し，要素数が1，2，5の配列で並べ替えの結果を確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 関数`void print_array(const char *label, const int *a, size_t n)`を作る．`printf("%s:", label);`の後，各要素を`printf(" %d", a[i]);`で表示し，最後に改行する．
- 関数`void reverse(int *a, size_t n)`を作る．先頭と末尾から組にして，半分まで交換する．新しい領域は確保しない．
- 関数`void show_reverse(size_t n)`を作る．`make_sequence(n)`で配列を作り，`NULL`なら`printf("allocation failed\n");`で表示して戻る．成功したら`reverse`で逆順にし，`print_array("reversed", 配列, n)`で表示してから`free`する．
- `main`で，課題1-1の表示の後に，`n`が1，2，5の順に`show_reverse`を呼ぶ．

表示は，課題1-1の5行に続けて次の3行が出ます．

~~~text
reversed: 1
reversed: 2 1
reversed: 5 4 3 2 1
~~~

交換する組は`n / 2`組です．整数の除算なので，奇数個のときの中央の要素は交換しません．中央の要素は自分自身と組になるので，交換しなくても結果は同じです．すべての添字について交換すると，各組を2回交換することになり元の順序に戻ります．

作業用の変数`temp`は通常の局所変数なので，`free`は不要です．`reverse`はポインタを進めずに添字で操作するので，呼び出し元の`values`は確保した領域の先頭を指したままで，そのまま`free`へ渡せます．

### 課題1-3　独立したコピーを作る

配列の要素を新しく確保した別の領域へコピーする関数を加えたプログラムを作成し，コピーだけを逆順にしても元の配列が変わらないことを確認してください．

プログラムが満たすこと（仕様）は次のとおりです．

- 関数`int *copy_array(const int *a, size_t n)`を作る．`n`要素の新しい配列を`malloc`で確保し，`a`の要素をコピーして返す．成功時は呼び出し元が`free`し，確保に失敗したら`NULL`を返す．この約束を関数の前にコメントで書く．`n`は課題1-1で範囲を調べた個数とする．
- 関数`void show_copy(size_t n)`を作る．`show_copy`は次の処理を行う．
    - `make_sequence(n)`で元の配列`values`を作る．`NULL`なら`printf("allocation failed\n");`で表示して戻る．
    - `copy_array(values, n)`でコピー`copy`を作る．`NULL`なら`printf("allocation failed\n");`で表示し，先に確保した`values`を`free`してから戻る．
    - `copy`だけを`reverse`で逆順にし，`print_array("values", values, n)`と`print_array("copy", copy, n)`の順に表示する．
    - `copy`と`values`をそれぞれ1回ずつ`free`する．
- `main`で，課題1-2の表示の後に，`n`が2，5の順に`show_copy`を呼ぶ．

表示は，課題1-2までの8行に続けて次の4行が出ます．

~~~text
values: 1 2
copy: 2 1
values: 1 2 3 4 5
copy: 5 4 3 2 1
~~~

`int *copy = values;`ではポインタの値をコピーするだけで，領域は1つのままです．その`copy`を通して逆順にすると，`values`から見ても逆順になります．元の配列を残すには，別の領域を確保して要素をコピーします．このとき領域は2つになるので，それぞれを解放します．

課題1全体の表示は次のようになります．

~~~text
n=1 sum=1 mean=1.0
n=5 sum=15 mean=3.0
n=1000 sum=500500 mean=500.5
n=0 rejected
n=1001 rejected
reversed: 1
reversed: 2 1
reversed: 5 4 3 2 1
values: 1 2
copy: 2 1
values: 1 2 3 4 5
copy: 5 4 3 2 1
~~~

## 課題2　構造体を確保する関数

`Point`を動的に確保して返す関数を使うプログラムを作成し，3通りの座標で生成したメンバの値と，失敗を模擬した場合に確保した領域を使わず`allocation failed`を表示することを確認してください．

`NewPoint`プロジェクトに`new_point.c`を作ります．プログラムが満たすこと（仕様）は次のとおりです．

- `stdio.h`と`stdlib.h`をインクルードする．
- `double`型のメンバ`x`と`y`を持つ構造体を，`typedef`で`Point`という名前にする．
- 関数`Point *new_point(double x, double y, int fail)`を作る．
    - `fail`が0以外なら，確保せずに`NULL`を返す．これは確保の失敗を試験するための引数である．
    - `fail`が0なら`malloc(sizeof *p)`で`Point`を1個確保する．失敗したら`NULL`を返す．
    - 成功したら，複合リテラル`*p = (Point){.x = x, .y = y};`で両メンバを初期化して返す．
    - 「成功なら初期化済みの`Point`を返し，呼び出し元が`free`する．失敗なら`NULL`を返す」という約束を関数の前にコメントで書く．
- 関数`void show_point(double x, double y, int fail)`を作る．`new_point(x, y, fail)`を呼び，`NULL`なら`printf("allocation failed\n");`で表示して戻る．成功したら`printf("point=(%.1f, %.1f)\n", p->x, p->y);`で表示してから`free`する．
- `main`では，次の4通りを表の順に`show_point`へ渡す．

| `x` | `y` | `fail` |
| ---: | ---: | ---: |
| 3.0 | 4.0 | 0 |
| 0.0 | 0.0 | 0 |
| −2.0 | 5.0 | 0 |
| 3.0 | 4.0 | 1 |

表示は次のようになります．

~~~text
point=(3.0, 4.0)
point=(0.0, 0.0)
point=(-2.0, 5.0)
allocation failed
~~~

??? tip "ヒント"

    複合リテラルの代入の左辺は`p`ではなく`*p`です．`p`はアドレス，`*p`は確保した構造体本体を表します．`NULL`を確かめる前に`*p`へ代入してはいけません．

`new_point`の局所変数`p`の寿命は`return`で終わりますが，`malloc`した本体は`free`されるまで生きています．そのため，呼び出し元の`p`から本体を使えます．関数内の通常の局所変数`Point`のアドレスを返すと，戻った時点でその変数の寿命が終わっているので，そのようには書きません．

`fail`を使うと，本当にメモリを使い切らなくても，`NULL`が返った後の経路を毎回確実に通せます．失敗の経路で`p->x`を読まないことが大切です．この関数は`errno`を設定しないので，失敗は`NULL`かどうかで判定します．

1個の小さな`Point`を作るだけなら，値として返す方法や，呼び出し元の`Point *`へ書き込む方法でも足ります．動的確保を選ぶと，寿命を呼び出し元が決められる代わりに，失敗の可能性と解放責任が増えます．

## 発展1　`calloc`と`realloc`で配列を拡張する

`calloc`で確保した配列を`realloc`で拡張・縮小する関数を使うプログラムを作成し，7通りの個数と失敗の指定で，0で初期化されること，保持される要素と追加される要素，失敗したときに元の領域が残ることを確認してください．

`GrowArray`プロジェクトに`grow_array.c`を作ります．プログラムが満たすこと（仕様）は次のとおりです．

- 必要な標準ヘッダ（`stdio.h`，`stdlib.h`，`stdint.h`）をインクルードする．
- 課題1-2と同じ`void print_array(const char *label, const int *a, size_t n)`を作る．
- 関数`int *resize_array(int *p, size_t old_n, size_t new_n, int fail)`を作る．`p`は`old_n`要素の確保済みの配列とする．
    - `new_n`が1〜1000の範囲外，または積`new_n * sizeof *p`が`SIZE_MAX`を超える場合は，`realloc`を呼ばずに`NULL`を返す．
    - `fail`が0以外なら，`realloc`を呼ばずに`NULL`を返す．これは再確保の失敗を試験するための引数である．
    - `realloc`の戻り値を別の変数`next`で受け，`NULL`なら`NULL`を返す．
    - 成功したら，増えた要素（添字`old_n`〜`new_n - 1`）に添字+1を代入し，`next`を返す．
    - `NULL`を返したときは，`p`の領域は解放されずに残り，その解放は呼び出し元が行う．
- 関数`void try_grow(size_t old_n, size_t new_n, int fail)`を作る．`try_grow`は次の処理を行う．
    - `printf("%zu -> %zu\n", old_n, new_n);`で表示する．
    - `old_n`が1〜1000の範囲外なら，`printf("invalid size\n");`で表示し，確保せずに戻る．
    - `calloc(old_n, sizeof *p)`で配列`p`を確保する．`NULL`なら`printf("allocation failed\n");`で表示して戻る．
    - `print_array("zero", p, old_n)`で確保直後の値を表示し，その後に`p[i]`へ`i + 1`を代入する．
    - `resize_array(p, old_n, new_n, fail)`を呼ぶ．`NULL`なら`printf("resize failed\n");`と`print_array("kept", p, old_n)`で表示し，`p`を`free`して戻る．
    - 成功したら，以後は返されたポインタだけを使い，`print_array("values", 配列, new_n)`で表示してから`free`する．
- `main`では，次の7通りを表の順に`try_grow`へ渡す．

| `old_n` | `new_n` | `fail` | 確認すること |
| ---: | ---: | ---: | --- |
| 3 | 5 | 0 | 先頭3要素を保持し，2要素を追加 |
| 3 | 1 | 0 | 縮小すると先頭の1要素だけが残る |
| 1 | 4 | 0 | 1を保持し，2，3，4を追加 |
| 3 | 0 | 0 | 新しい個数が0なら失敗し，元の領域が残る |
| 3 | 1001 | 0 | 上限を超えると失敗し，元の領域が残る |
| 3 | 5 | 1 | 再確保の失敗でも，元の領域が残る |
| 0 | 5 | 0 | 最初の確保の前に拒否する |

表示は次のようになります．

~~~text
3 -> 5
zero: 0 0 0
values: 1 2 3 4 5
3 -> 1
zero: 0 0 0
values: 1
1 -> 4
zero: 0
values: 1 2 3 4
3 -> 0
zero: 0 0 0
resize failed
kept: 1 2 3
3 -> 1001
zero: 0 0 0
resize failed
kept: 1 2 3
3 -> 5
zero: 0 0 0
resize failed
kept: 1 2 3
0 -> 5
invalid size
~~~

??? tip "ヒント"

    `realloc`の戻り値を`p = realloc(p, ...)`と直接`p`へ代入すると，失敗したときに元の領域への唯一の手がかりを失います．`next`で受け，成功してから持ち替えます．初期化が必要なのは添字`old_n`から`new_n - 1`までです．縮小した場合は増分がないので，そのループは1回も実行されません．

`calloc`は全ビットを0にして確保するので，`int`配列なら代入前に読んでも0です．`malloc`や`realloc`で増えた部分は初期化されないので，値を代入してから読みます．

縮小した後に有効なのは先頭の`new_n`要素だけです．`new_n`が1のとき`p[3]`を読んで確かめることはできません．拡張した後の`p[3]`は，代入してから読める要素です．`realloc`が成功したら，古いポインタや古い要素へのポインタは使わず，返されたポインタから参照を作り直します．サイズ0の`realloc`は扱いが複雑なので，この課題では呼ばずに失敗として扱います．

## 発展2　`static`変数の寿命を確かめる

局所変数の書き方だけを変えた，呼ばれた回数を返す3つの関数を使うプログラムを作成し，それぞれを3回呼んだ結果で，静的記憶期間と自動記憶期間，初期化と代入の違いを確認してください．

`StorageCount`プロジェクトに`storage_count.c`を作ります．プログラムが満たすこと（仕様）は次のとおりです．

- 3つの関数は，どれも`static int 関数名(void)`の形とし，局所変数`count`を1増やしてその値を返す．
- 3つの関数の`count`の書き方は次のとおりとする．

| 関数 | `count`の書き方 |
| --- | --- |
| `next_static` | `static int count = 0;` |
| `next_auto` | `int count = 0;` |
| `next_reset` | `static int count;`の後に，文として`count = 0;` |

- `main`では，`next_static`，`next_auto`，`next_reset`の順に，それぞれを3回呼ぶ．関数ごとに，`printf("static:");`のように関数名から`next_`を除いた名前とコロンを表示し，各戻り値を`printf(" %d", 値);`で続けて表示して改行する．

表示は次のようになります．

~~~text
static: 1 2 3
auto: 1 1 1
reset: 1 1 1
~~~

`static int count = 0;`の`count`は静的記憶期間を持ち，初期化はプログラムの開始前に一度だけ行われます．そのため，呼ぶたびに値が増えます．`int count = 0;`は呼ぶたびに新しい`count`が作られて0で初期化されます．`next_reset`の`count`は静的記憶期間を持ちますが，文として書いた`count = 0;`は呼ぶたびに実行されるので，値は保たれません．

関数の前の`static`は，その関数名を同じファイルの中だけで使えるようにする内部リンケージを表します．関数内の`count`に付けた`static`は，名前の見える範囲を関数内に保ったまま，静的記憶期間を与えます．`count`は`malloc`で確保した領域ではないので，`free`しません．

## 発展3　不透明な`Vector`の生成と解放

講義の`Vector`を使って`2x+y`を計算する関数を使うプログラムを作成し，途中の生成を失敗させない場合と1〜3番目の生成を失敗させた場合で，結果と後始末の後の状態を確認してください．

`DynamicVector`プロジェクトに，講義の`vector.h`と`vector.c`を変更せずに追加し，`vector_check.c`を作ります．`vector.h`には構造体のメンバがないので，`vector_check.c`からはメンバを直接使わず，`vector.h`の関数だけを使います．プログラムが満たすこと（仕様）は次のとおりです．

- `"vector.h"`と`stdio.h`をインクルードする．
- 関数`int run_axpy(int fail_on)`を作る．講義の`vector_main.c`と同じく，所有する3つのポインタ`x`，`y`，`result`を最初に`NULL`で初期化し，`int status = 1;`とする．`goto`で初期化を飛び越えないように，`double first, second;`，`double out = 99.0;`，`int ok = 0;`も最初に宣言する．
- `printf("fail_on=%d\n", fail_on);`で表示した後，次の3つの生成を順に行う．`fail_on`が1，2，3のときは，それぞれ1番目，2番目，3番目の生成の関数を呼ばず，ポインタを`NULL`のままにして確保の失敗を模擬する．`fail_on`が0なら失敗させない．
    1. `x = vector_create(1.0, 2.0);`
    2. `y = vector_create(3.0, 4.0);`
    3. `result = vector_axpy(2.0, x, y);`
- 各生成の後でポインタが`NULL`なら，`printf("allocation failed\n");`で表示して`goto cleanup;`で後始末へ進む．
- 3つとも成功したら，`vector_get`で`result`の添字0と1の値を取り出し，`printf("result=%.1f %.1f\n", first, second);`で表示する．続けて，範囲外の添字2で`ok = vector_get(result, 2, &out);`とし，`printf("ok=%d out=%.1f\n", ok, out);`で戻り値と`out`を表示する．最後に`status`を0にする．
- `cleanup:`では，`vector_destroy(&result);`，`vector_destroy(&y);`，`vector_destroy(&x);`の順に解放する．その後，`printf("cleared=%d\n", x == NULL && y == NULL && result == NULL);`で表示し，さらに`vector_destroy(&x);`をもう一度呼んでから，`status`を返す．
- `main`では，`fail_on`を0から3まで変えながら`run_axpy`を呼び，戻り値を`printf("status=%d\n", run_axpy(fail_on));`の形で表示する．

表示は次のようになります．

~~~text
fail_on=0
result=5.0 8.0
ok=0 out=99.0
cleared=1
status=0
fail_on=1
allocation failed
cleared=1
status=1
fail_on=2
allocation failed
cleared=1
status=1
fail_on=3
allocation failed
cleared=1
status=1
~~~

??? tip "ヒント"

    `fail_on`による模擬は，`if (fail_on != 1) { x = vector_create(1.0, 2.0); }`のように，生成の呼び出しを`if`で囲むと書けます．その直後の`NULL`の検査は，本当に確保に失敗した場合と共通にします．

確保できる領域は，`fail_on`が0なら`x`，`y`，`result`の3つ，1ならなし，2なら`x`だけ，3なら`x`と`y`です．どの場合も同じ`cleanup:`へ進み，生成に成功した領域だけが解放されます．まだ生成していないポインタは`NULL`なので，`vector_destroy`へ渡しても何もしません．

`vector_destroy`へ渡すのは`x`ではなく`&x`です．関数が`x`そのものを書き換えられるので，解放後に`x`が`NULL`になり，`cleared=1`と表示されます．そのため，2回目の`vector_destroy(&x);`も何もしません．ただし，解放前に`x`を別のポインタへコピーしていた場合，そのコピーは自動では`NULL`になりません．このAPIで，すべての二重解放を防げるわけではありません．

範囲外の添字2では，`vector_get`が添字を検査して0を返し，`out`を変更しません．そのため`out`は99.0のままです．

`Vector`の配列メンバは本体に含まれるので，この例は本体への`free`で後始末が終わります．メンバを`double *v;`に変えて配列を別に確保するなら，配列の確保に失敗したときに本体を解放する処理と，配列，本体の順に解放する処理が必要になります．

## 確認問題

この節は自習用で，成績には含めません．

1. ポインタ変数が局所変数なら，指す領域も必ずスタックにあるか．
2. `calloc`した整数配列と`malloc`した整数配列を，代入前に同じように表示してよいか．
3. `free`の後に`p=NULL`としたら，`q=p`で以前に作った別名も`NULL`になるか．
4. `realloc`失敗後の元の配列と，成功後の古い要素ポインタは同じ扱いか．
5. 動的な配列を含む構造体の本体だけを`free`すれば，配列も自動で解放されるか．
6. エラー処理があることを確認するのに，実際にメモリを使い切る必要があるか．

## チェックリスト

- 各課題のソースが1つのファイルにまとまり，警告なしでビルドできる．
- 1回の実行で，課題に示したすべての場合の結果が表示される．
- 表示が，課題に示した出力と一致する．
- 関数の名前，引数，戻り値の型が課題の指定どおりである．
- 小問のある課題で，前の小問の関数や表示を残している．
- `malloc`，`calloc`，`realloc`の戻り値を`NULL`と比べてから使っている．
- 確保に成功した領域を，失敗の経路も含めてすべて1回ずつ解放している．
- 解放後の使用，二重解放，確保していない領域の`free`，未初期化の要素の読み取りを書いていない．
- `realloc`の戻り値を別の変数で受け，成功してから持ち替えている．
