# 第9回　ポインタ2


## 到達目標

- 二重ポインタで呼び出し元のポインタを変更できる．
- ポインタ配列と配列へのポインタの宣言を読める．
- 二次元配列をint \*\*へ渡せない理由を説明できる．


## 1　ポインタ変数の場所を渡す

### 前回からのつながり { #environment }

第8回では，変数の値と，変数の場所を表すアドレスを区別しました．今回は「ポインタも，値を保存する変数である」という点から始めます．ポインタ変数の中身を変更するには，その変数の場所が必要です．星の数を暗記するよりも，**何を書き換えるのか**を先に決めましょう．

演習は引き続きWindowsのVisual Studioで行います．空のC++プロジェクトへ.cファイルを追加し，C17・警告レベル4を使います．この回では動的メモリ確保を使いません．配列本体を宣言してから，それを指すポインタを用意します．ファイルとコマンドライン引数は第10回，mallocは第13回で扱います．

前回はint変数を書き換えるためにint \*を渡しました．では，呼び出し元の`int *`変数そのものを書き換えるにはどうするでしょうか．その変数のアドレスを渡すので，引数の型は `int **` です．

~~~c
int value = 10;
int *p = &value;
int **pp = &p;
~~~

~~~text
pp → p → value
     *pp   **pp
~~~

ppはpを指し，\*ppはp，\*\*ppはvalueを表します．`**pp = 20;` はvalueを変更します．`*pp = &other;` はpの指す先を変更します（otherは有効なint変数とします）．

### 式の型と，読み書きする対象

| 式 | 型 | 表しているもの |
| --- | --- | --- |
| value | int | 整数の保存場所にある値 |
| &value | int \* | valueのアドレス |
| p | int \* | valueのアドレスを保存したポインタ |
| &p | int \*\* | p自身のアドレス |
| pp | int \*\* | pのアドレスを保存したポインタ |
| \*pp | int \* | ppが指すポインタ変数p |
| \*\*pp | int | pが指す整数value |

初期状態ではpと\*ppは同じアドレスを表し，value，\*p，\*\*ppは同じ整数10を表します．一方，ppとpは別の場所を指します．アドレスを表示するならprintf("%p", (void \*)p);のようにvoid \*へ変換します．表示されるアドレスの具体的な数値は実行環境によって変わり，暗記する必要はありません．

~~~c
int other = 30;
**pp = 20;
*pp = &other;
**pp = 40;
~~~

| 実行直後 | value | other | pの指す対象 |
| --- | ---: | ---: | --- |
| otherの初期化 | 10 | 30 | value |
| \*\*pp = 20; | 20 | 30 | value |
| \*pp = &other; | 20 | 30 | other |
| \*\*pp = 40; | 20 | 40 | other |

2番目の代入は整数をコピーしていません．pの中に保存されているアドレスを変えています．ppは最初から最後までpを指したままです．矢印の終点を一段ずつ確認すると，変更される対象を追えます．

### 関数に渡す星の数を決める

| 呼び出し元で変更したい変数 | その型 | 関数に渡す式 | 仮引数の型 |
| --- | --- | --- | --- |
| int x | int | &x | int \* |
| int \*p | int \* | &p | int \*\* |
| int \*\*pp | int \*\* | &pp | int \*\*\* |

「対象の型へのポインタ」を使うという規則は同じです．三重ポインタが存在することは知っておけば十分で，今回の演習では使いません．星が増えても，自動的に配列を確保したり，値を初期化したりするわけではありません．

~~~c
void redirect(int **destination, int *target)
{
    *destination = target;
}
~~~

redirect(&p, &other);なら呼び出し元のpを変更できます．destination自身も値渡しで作られるローカルなポインタですが，そのコピーが同じpを指すためです．destinationに別のアドレスを代入することと，\*destinationへ代入することは異なります．

仮にvoid redirect_wrong(int \*destination, int \*target)の中でdestination = target;としても，変更されるのは関数側のコピーだけです．呼び出し元でpを渡してもpの中身は変わりません．「ポインタ引数なら何でも呼び出し元が変わる」のではなく，何を間接参照して代入したかが重要です．


find_maxのoutは呼び出し元のanswerを指します．`*out = best;` によってanswerが最大要素を指します．戻り値は成功・失敗を表し，nが0以下なら0を返します．out自体には有効なポインタ変数のアドレスを渡す必要があります．最大値が同じ要素は最初のものを選びます．

返したポインタの対象は呼び出し元の配列です．配列の寿命が終わったあとには使えません．

### find_maxの契約と動作

outには，書き込み可能なint \*変数のアドレスを必ず渡します．outへNULLを渡す使い方はこの関数の対象外です．nが正なら，aには少なくともn個の読み取り可能な要素が必要です．nが0以下なら要素を読まず，\*outをNULLにして失敗を返します．戻り値を確認する前に\*\*outや\*answerを読んではいけません．

~~~text
呼び出し元                         関数内
answer [NULL] <-------------------- out [&answer]
a      [7][12][4] <--------------- a   [先頭のアドレス]
            ^
            +--------------------- best [最大候補のアドレス]

*out = best; の後：answerがa[1]を指す
~~~

配列全体が関数へコピーされるわけではありません．配列の先頭アドレス，整数n，answerのアドレスという3つの値が渡されます．関数の仮引数aと，mainの配列aは，同じ名前でも別のものです．

| 調べたところ | bestの対象 | \*best |
| --- | --- | ---: |
| 初期化 | a[0] | 7 |
| i=1を調べた後 | a[1] | 12 |
| i=2を調べた後 | a[1] | 12 |

条件がa[i] > \*bestなので，同じ値なら候補を変更しません．最大値が複数あるときは最初の要素が選ばれます．>=にすると最後の要素になります．仕様と比較演算子の関係を説明できるようにしましょう．

### 値を返すか，場所を返すか

結果を渡す方法には，戻り値と出力引数があります．また，渡すものには整数値とアドレスがあります．この2つを区別すると，4通りを整理できます．

| 得たい結果 | 戻り値を使う | 出力引数を使う |
| --- | --- | --- |
| 最大の整数値 | intをreturnする | int \*outへ\*out = 値; |
| 最大要素の場所 | int \*をreturnする | int \*\*outへ\*out = アドレス; |

次は「値を直接返す」版です．n>=1，aがn要素以上という条件に限定します．空入力に対して意味のある最大値はないので，0を最大値の代わりに返すという仕様にはしません．

~~~c
int max_value(const int a[], int n)
{
    int best = a[0];
    for (int i = 1; i < n; ++i) {
        if (a[i] > best) { best = a[i]; }
    }
    return best;
}
~~~

次は「場所を直接返す」版です．空入力はNULLで表せます．

~~~c
int *max_pointer(int a[], int n)
{
    if (n <= 0) { return NULL; }
    int *best = &a[0];
    for (int i = 1; i < n; ++i) {
        if (a[i] > *best) { best = &a[i]; }
    }
    return best;
}
~~~

mainでint saved = max_value(a, 3);とすればsavedは独立した整数です．int \*found = max_pointer(a, 3);なら，foundは元の配列を指します．成功後に\*found = 99;とすると配列が変わりますが，savedは変わりません．必要なのが値だけなら値を返す形が簡潔です．成功・失敗を戻り値にし，結果の場所を別に渡したいならfind_maxの形が使えます．

いずれの場合も，関数内のローカルな整数変数のアドレスを返す設計にはしません．max_pointerのbest自体は関数終了時になくなりますが，その値をコピーして返すことはできます．返された値が指しているのは，まだ生きている呼び出し元の配列だからです．

## 3　ポインタ配列

`const char *names[3]` は，「const charへのポインタ」が3つ並んだ配列です．それぞれ別の長さの文字列を指せます．names[0]とnames[2]の交換は**ポインタ値の交換**であり，文字列の内容を書き換えていません．文字列リテラルは読み取り専用として扱います．

ポインタ配列そのものは連続していますが，指す文字列が連続しているとは限りません．要素ごとの対象の寿命と長さを別に考えます．

### 文字列本体と，入り口の配列

~~~text
namesという配列                 文字列リテラル
+---------+                     +----------------+
| names[0]| ------------------> | r e d \0       |
| names[1]| --------+            +----------------+
| names[2]| ----+   |            +----------------+
+---------+    |   +----------> | g r e e n \0   |
               |                +----------------+
               |                +----------------+
               +--------------> | b l u e \0     |
                                +----------------+
~~~

names[i]は文字列の先頭を指すポインタです．names[i][j]は，その文字列のj番目の文字です．例えばnames[1][0]は'g'です．有効なiは0〜2で，jの上限は選んだ文字列の長さと容量によって変わります．ポインタ配列だから各文字列が同じ長さになるわけではありません．

names[0] = names[2];は可能ですが，names[0][0] = 'B';はこのconst char \*の型では認められません．constを外して文字列リテラルを書き換えようとしても，安全な操作にはなりません．同一内容の文字列リテラルが同じ場所に置かれるかどうかも保証されないので，文字列の一致はアドレスではなくstrcmpで判定します．

文字を書き換えたい場合は，自分で変更可能な文字配列を用意します．

~~~c
char s1[] = "toyama";
char s2[] = "ishikawa";
char s3[] = "fukui";
char *prefectures[] = {s1, s2, s3};
for (int i = 0; i < 3; ++i) {
    prefectures[i][0] = 'A';
    printf("%s\n", prefectures[i]);
}
~~~

結果はAoyama，Ashikawa，Aukuiです．これはprefecturesのポインタ値を変える操作ではなく，各ポインタの先にある文字を変えています．s1などを直接表示しても先頭が変わっています．

### ポインタ配列を関数に渡す

~~~c
void print_each(const char *prefectures[], int n)
{
    for (int i = 0; i < n; ++i) {
        printf("%s-ken\n", prefectures[i]);
    }
}

void swap_names(const char *names[], int i, int j)
{
    const char *temp = names[i];
    names[i] = names[j];
    names[j] = temp;
}
~~~

print_eachは表示に-kenを付けるだけで，文字列の末尾へ書き足していません．nは配列の要素数以下，各要素は終端のある有効な文字列を指すものとします．swap_namesのi，jは有効な添字で，同じ添字でも構いません．関数には添字の範囲を検査する情報がないため，呼び出し側がこの条件を守ります．

仮引数のconst char \*names[]はconst char \*\*namesへ調整されます．配列の要素型をTとすると，T names[]がT \*namesになる規則に，T = const char \*を当てはめただけです．先頭のconstは文字への書き込みを禁止し，配列に保存したポインタの交換は禁止しません．

この関数に渡す配列はconst char \*names[]として宣言します．char \*\*をconst char \*\*へ安易に変換できるとは考えないでください．多段のポインタでは，単なるchar \*からconst char \*への変換と同じ扱いにはなりません．キャストで合わせず，関数と配列の要素型をそろえます．

### intの配列も，長さを変えて集められる

~~~c
int row0[] = {1, 2, 3};
int row1[] = {4, 5};
int *rows[] = {row0, row1};
int lengths[] = {3, 2};
int **p = rows;
~~~

p[0][1]は2，p[1][0]は4です．pはポインタ配列の先頭を指し，p+1は次のポインタ要素へ進みます．p[1]はrow1の先頭を指し，p[1]+1は次のintへ進みます．どの段階を進めるのかで単位が変わります．p[1][2]は2要素しかない行の範囲外です．長さは自動で記録されないので，lengthsのような別配列で管理します．

int \*rows[] = {{1, 2, 3}, {4, 5}};という書き方でint配列本体が作られるわけではありません．ポインタ配列の要素に必要なのはアドレスです．今回は上のように配列本体を明示的に用意します．文字列リテラルは文字の保存領域を持つため，数値を並べた初期化リストとは事情が違います．

### 二重ポインタは「二次元」を意味しない

| 二重ポインタの直接の対象 | その先の対象 | 例 |
| --- | --- | --- |
| 1個のポインタ変数 | 1個の整数 | pp → p → value |
| 1個のポインタ変数 | 文字列の先頭 | const char \*animal = "dog"; と &animal |
| ポインタ配列の要素 | 1個ずつの文字 | char c1='a', c2='b'; と char \*letters[]={&c1,&c2}; |
| ポインタ配列の要素 | 配列・文字列の先頭 | rows，names |

どれも二段階の間接参照ですが，繰り返しで扱える要素数は違います．単独のcharを指すletters[i]は終端のある文字列ではありません．printf("%c", \*letters[i]);とし，%sへ渡してはいけません．型だけから対象の個数や終端の存在を判断しないことが大切です．

## 4　二次元配列と比較する

| 宣言 | 保持するもの | 1つ進んだとき |
| --- | --- | --- |
| int \*p[3] | 3個のポインタ | 次のポインタ要素へ |
| int a[2][3] | 3個のintからなる行が2つ | a + 1は次の行へ |
| int (\*q)[3] | 3個のintの配列へのポインタ | q + 1は次の行へ |
| int \*\*r | intへのポインタへのポインタ | r + 1は，同じポインタ配列内なら次のポインタへ |

宣言は名前に近い部分から読みます．`int *p[3]` はpがまず配列で，`int (*q)[3]` は括弧によりqがまずポインタです．

~~~text
二次元配列 a:       [1 2 3][4 5 6]    intが行ごとに並ぶ
ポインタ配列 rows:  [  *  ][  *  ]    各要素は場所を持つ
                       ↓      ↓
                    [1 2 3] [4 5 6]  対象は別領域でもよい
~~~

`a` が変換される型は `int (*)[3]` です．int \*\*ではありません．int \*\*でアクセスすると「そこにはポインタ値がある」と解釈してしまいます．キャストで警告を消して渡してはいけません．

### 同じ添字でも，途中に何があるかが違う

a[1][2]を読む場合は，2行目を選び，その行の3個目のintを読みます．rows[1][2]なら，まずポインタ配列の2個目のポインタ値を読み，そのアドレスを起点として3個目のintを読みます．二次元配列の行頭にポインタが埋め込まれているわけではありません．

| 比較項目 | int a[2][3] | int \*rows[2] |
| --- | --- | --- |
| 宣言で確保するもの | int本体が6個 | ポインタが2個 |
| 行の幅 | どの行も3個 | 指す先によって変えられる |
| 行ごとの長さの情報 | 型に3が含まれる | 別に管理する必要がある |
| 行同士の配置 | 連続した配列要素 | 指す先の連続性は保証しない |
| 行の入れ替え | 行の要素を交換する | ポインタを交換できる |
| sizeof | 6 \* sizeof(int) | 2 \* sizeof(int \*) |

rowsはポインタの分だけ保存領域を使い，別に配列本体も必要です．長さのばらつきが大きいと未使用部分を減らせる一方，どのサイズでも必ず二次元配列より小さいわけではありません．用途と必要な操作に応じて選びます．

### 文字列を二次元配列へ入れる

~~~c
char prefectures[][9] = {"toyama", "ishikawa", "fukui"};
~~~

これは3行9列，合計27個のcharです．最長のishikawaは8文字なので終端を含めて9個必要です．短い行も9個分が確保され，初期化で余った要素は0になります．fukuiの行はf，u，k，u，i，終端，0，0，0です．この配列の文字は書き換え可能です．

const char \*prefectures[]の場合は各要素へ別のアドレスを代入できますが，この二次元配列ではprefectures[0] = prefectures[2];とは書けません．配列の行を代入演算子で丸ごとコピーすることはできないためです．行交換は，幅9の全要素を1個ずつ交換します．終端も含めて交換すると，短い文字列と長い文字列を安全に入れ替えられます．

### 配列へのポインタを読む

int (\*q)[3]の宣言では，括弧内の\*qを先に読みます．「qはポインタ」で，指す対象は「intが3個の配列」です．int \*q[3]ならq[3]が先なので「qは3要素の配列」で，各要素がint \*です．括弧は見た目の飾りではなく，宣言の意味を変えます．

intが4バイトの環境なら，q+1は格納場所として12バイト分先の行へ進みます．しかしCの式(q+1)-qの結果は12ではなく1です．ポインタの差はバイト数ではなく，そのポインタが指す型の要素数で表されます．差は同じ配列内で求め，表示には%tdを使います．sizeof \*qなら1行のバイト数を得られます．

結果は `3 6`，`sum=21` です．仮引数 `int a[][COLS]` は `int (*a)[COLS]` と同じ型になります．列数は，次の行までの大きさを決めるために必要です．今回はMSVCに合わせてCOLSを固定の定数にします．rowsは実際の行数以下とし，合計がintの範囲に収まる値を渡します．

### なぜ列数が必要なのか

a[r][c]の行を選ぶには，先頭から何行分進むかを計算します．1行がCOLS個のintであることが分からないと，次の行の場所を決められません．第1の添字の長さは，配列引数がポインタになると型には残りません．そのため行数rowsを別に渡します．

関数内のsizeof aはポインタのサイズであり，呼び出し元の配列全体のサイズではありません．sizeof a[0]は行のサイズを表します．一方，mainで実際の二次元配列にsizeof aを使えば，全体のサイズです．同じ式でも，変数がどこで何として宣言されたかを確認します．

今回はenum { COLS = 3 };を使います．#define COLS 3という定数の与え方もあります．C17では単なるconst int cols = 3;を配列の幅に使うと，固定長配列と同じ扱いになるとは限りません．実行時の引数widthを幅に使う可変長配列はMSVCでは利用しないため，本回ではすべて固定幅にそろえます．

行ごとの平均は，各行の合計を(double)total / COLSで割ります．全体の平均は，全行の合計を要素の総数で割ります．rows=0では全体の平均が定義できないので，計算前に失敗として扱います．整数の合計が範囲内でも，整数同士の割り算を先にすると小数部分は失われます．

### 一次元の保存形式との比較

二次元配列は連続していますが，&a[0][0]をint \*として受け取り，最初の行の範囲を越えて添字を増やし続ける書き方は使いません．各行が独立した配列要素であることを保ち，a[r][c]で走査します．隣の行も物理的に続いていることと，そのポインタで境界を越えてアクセスできることは別です．

一次元として計算したいなら，最初から一次元配列を用意できます．

~~~c
int flat[] = {1, 2, 3, 4, 5, 6};
~~~

幅3として扱うとき，行r・列cの添字はr \* 3 + cです．r=1，c=2なら5番目なのでflat[5]は6になります．この形式では6個すべてが同じ一次元配列の要素なので，添字0〜5で走査できます．ポインタの型をキャストして保存形式を変えるのではなく，データの作り方から決めます．

## 6　型とサイズの早見表

### 一次元の場合

int v[3]; int \*p = v;と宣言した場合を考えます．「配列の型」と「通常の式で先頭へのポインタに変換された型」を区別してください．sizeofのオペランドや単項&の対象では，その配列からポインタへの変換は起きません．

| 式 | 型・意味 | 注意 |
| --- | --- | --- |
| v | int [3]という配列 | 通常の式ではint \*へ変換 |
| v + 0，p | int \* | 最初のintを指す |
| v[1]，\*(p + 1) | int | 2個目の整数 |
| &v | int (\*)[3] | 3個のintをまとめた配列を指す |
| &p | int \*\* | ポインタ変数p自身を指す |
| sizeof v | 3 \* sizeof(int) | 配列全体 |
| sizeof p，sizeof(v + 0) | sizeof(int \*) | ポインタ1個 |

&vと&pは指す対象も型も違います．v+1は次のintへ進み，&v+1は配列全体の直後を指します．後者は終端の1つ先なので，間接参照してはいけません．

### 二次元の場合

int a[2][3]; int (\*q)[3] = a;の場合です．

| 式 | 型・意味 | +1で進む単位 |
| --- | --- | --- |
| a | int [2][3]という配列 | 通常は先頭行へのポインタに変換 |
| a + 0，q，&a[0] | int (\*)[3] | intが3個の1行 |
| a[0]，q[0] | int [3]という行の配列 | 通常はint \*に変換 |
| a[0] + 0，&a[0][0] | int \* | intが1個 |
| &a | int (\*)[2][3] | 2行3列の配列全体 |
| &q | int (\*\*)[3] | 1個の「行へのポインタ」 |

&a，aが変換されたポインタ，&a[0]，a[0]が変換されたポインタ，&a[0][0]は，いずれも格納領域の先頭に対応します．しかし型は同じではありません．%pで同じように表示されても，関数の引数として自由に交換できるわけではありません．特に&aはint \*\*ではないことを確認してください．

sizeof aは6 \* sizeof(int)，sizeof a[0]とsizeof \*qは3 \* sizeof(int)，sizeof qはポインタ自体のサイズです．sizeof qだけから何行を指しているかを知ることはできません．

発展として，int cube[2][3][4];の先頭要素は「3行4列の配列」です．その先頭要素を指す宣言はint (\*plane)[3][4] = cube;です．外側の配列だけがポインタへ変換され，内側の幅は残る，という規則は二次元の場合と同じです．C++の型表示機能を使わなくても，宣言とsizeofを使って段階的に整理できます．

### 安全に読むための順番

1. 配列本体とポインタ変数を別々に描く．
2. その式の型と，1回の\*で得られるものを確認する．
3. どの配列の何要素目を扱っているかを確認する．
4. 要素数・文字列の終端・対象の寿命を確認する．
5. 型の警告が出たら，キャストではなく宣言と渡す対象を見直す．

NULLでないだけでは安全と判断できません．ポインタ配列を交換しても対象の寿命は延びず，配列へのポインタに行数が自動で保存されることもありません．型とデータの範囲の両方を説明できることが，今回の目標です．
