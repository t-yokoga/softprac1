# 第10回　ファイル


## 到達目標

- ファイルを開き，戻り値を検査し，閉じることができる．
- テキスト・バイナリ・文字コードを区別できる．
- Visual Studioで起動引数と作業ディレクトリを設定できる．


## 1　ファイルの入口と出口

### 前回までとのつながり { #environment }

第7回では標準入力・標準出力，第8・9回ではポインタと配列を学びました．今回はプログラムが終了しても残るデータを，ファイルへ保存したり読み戻したりします．入力データを毎回ソースへ書き直すのではなく，同じプログラムに違うファイルを渡せるようにします．

今回の例はWindowsのVisual Studio，C17，.cファイルで実行します．ソースを書くエディタ，実行するプログラム，データを保存するフォルダを区別してください．ファイルを「プロジェクトへ追加すること」と「実行時に正しい場所へ保存すること」は別です．

~~~text
起動時の引数：input.txt
        |
        v
プログラム -- fopen --> ファイルのストリーム
        |                 |
        |             fgetc / fgets / fread
        |                 v
        |             変数・配列で処理
        |                 |
        +-- printf --> 画面     fprintf / fwrite --> 出力ファイル
~~~

短い設定値やファイル名は起動引数，多数の数値や長い文章はファイル，という使い分けができます．リダイレクトも有効な方法ですが，今回はプログラムの中で明示的にファイルを開きます．

ファイル操作は **開く → 読む／書く → 閉じる** の順です．`FILE *` は開いたストリームを扱うためのポインタで，ファイル全体の内容をメモリに読み込んだ配列ではありません．

| 操作 | 関数 | 確認すること |
| --- | --- | --- |
| 開く | fopen(名前, モード) | 失敗ならNULL |
| 1文字読む | fgetc(fp) | intで受け，EOFを調べる |
| 行を読む | fgets(buf, 容量, fp) | 成功ならbuf，失敗・入力終了ならNULL |
| 書式付きで書く | fprintf(fp, ...) | 負の戻り値はエラー |
| 閉じる | fclose(fp) | 成功は0，失敗はEOF |

fgetcがEOFを返した後，ferrorでエラーか確認します．`while (!feof(fp))` で先に終了を予測するのではなく，読み取り関数の戻り値でループを制御します．最後に改行がないファイルもあり得ます．

| モード | 意味 |
| --- | --- |
| r | 既存ファイルを読む |
| w | 新規作成または既存内容を消して書く |
| a | 末尾へ追記する |
| rb，wb | 変換をしないバイナリの読み・書き |

!!! warning "wとwbは既存ファイルを上書きする"

    練習用の新しいフォルダで，指定した出力名だけを使います．大切なデータを出力先に指定しないでください．閉じる際に書き込みが失敗する場合もあるため，fcloseも検査します．

### FILEとファイル名は別のもの

ファイル名は`"input.txt"`のような文字列，`FILE *fp`は開いたストリームを扱うものです．fpへファイル名のアドレスを代入しても，ファイルは開けません．FILEの内部構造を自分で操作せず，stdio.hの関数へ渡します．

`FILE *`の宣言だけではファイルは開かれません．fopenが成功して初めて使えます．閉じた後は，同じfpをfgetcやfprintfへ渡したり，もう一度fcloseしたりしてはいけません．必要なら再びfopenし，新しい結果を使います．

| 場面 | すべき処理 | 避けること |
| --- | --- | --- |
| 開くのに失敗 | 診断して終了する | NULLを読み書き関数へ渡す |
| 読み取り途中に失敗 | エラーを記録して閉じる | 成功したことにする |
| 書き込み途中に失敗 | 閉じる処理も行い，失敗を返す | 部分的な出力を完成品と扱う |
| 正常に処理できた | fcloseの結果も確認する | 終了時の自動処理だけに頼る |

プログラムの配列はメモリ上のデータ，ファイルは保存先です．どちらかを変更しても，他方が自動的に同期されるわけではありません．また，出力はバッファに一時的に蓄えられることがあり，fprintfが成功してもfcloseで失敗が分かる場合があります．

### 標準入出力・ファイル・文字列の対応

| 処理 | 標準入出力 | FILEを指定する | 文字列を対象にする |
| --- | --- | --- | --- |
| 1文字読む | getchar | fgetc，getc | 配列の添字で読む |
| 1文字書く | putchar | fputc，putc | 配列の添字へ代入 |
| 1行読む | fgetsでstdinを指定 | fgets | 文字列中の改行などを調べる |
| 文字列を書く | puts | fputs | 容量を確かめてコピー |
| 書式を指定して読む | scanf | fscanf | sscanf |
| 書式を指定して書く | printf | fprintf | snprintf |

putsは末尾に改行を付けますが，fputsは自動では付けません．fgetsは読み取った改行を配列に残します．fgetcは文字をunsigned char相当の値としてintで返し，EOFと区別できるようにします．freadは後述のとおり，文字列の終端を自動で追加しません．

getsは容量を指定できずC17にはないため使用しません．sprintfも出力先の容量を指定できないので，本講義ではsnprintfを選びます．strtokやstrcpyは行入力関数の代用品ではありません．関数名が似ていても，引数と戻り値を確認します．

### 書式付き入力を読むときの注意

例えば，入力が`ID:13`で，整数がintの範囲内だと分かっている場合は，次のように読めます．ここではfpは開くことに成功した読み取り用ストリームです．

~~~c
int id;
if (fscanf(fp, "ID:%d", &id) == 1) {
    printf("id=%d\n", id);
} else {
    fprintf(stderr, "invalid ID\n");
}
~~~

戻り値1は整数を1個代入できたという意味です．`ID:`などの文字は入力と一致する必要があります．0は書式不一致，最初の代入より前に入力終了や読み取り失敗があればEOFです．失敗したidを表示してはいけません．また，1が返っても行末まで正しいとは限りません．`ID:13x`なら整数13を読み，xが残る場合があります．

任意の巨大な整数を%dで読むと，戻り値の確認だけでは範囲外変換を安全に処理できません．外部から来る数値は，容量を決めて文字列として読み，strtolで範囲まで確認する形を演習で使います．sscanfも文字列を対象とするだけで，すべての入力検証を自動で行うわけではありません．

## 2　起動時に情報を渡す

`int main(int argc, char *argv[])` とすると，起動時に指定した引数を受け取れます．通常，argcにはプログラム名も含む個数，argv[0]にはプログラム名，argv[1]以降には追加の引数が入ります．`argv[argc]` はNULLです．要素へアクセスする前にargcを確認します．

### Visual Studioでの設定 {#arguments}

1. 対象の**プロジェクト**を右クリックし，「プロパティ」を開く．
2. 実行に使う構成・プラットフォームを選び，「構成プロパティ → デバッグ」を開く．
3. 「コマンド引数」に `input.txt` と入力する．実行ファイル名は書かない．
4. 「作業ディレクトリ」を `$(ProjectDir)` にする．
5. .vcxprojがあるフォルダにinput.txtを保存し，ビルドして実行する．

空白を含むファイル名は `"my input.txt"` のように引用符で囲みます．相対パスはソースの位置ではなく**作業ディレクトリ**を基準に解決されます．設定項目の意味は[Microsoftのデバッグ設定](https://learn.microsoft.com/en-us/cpp/build/reference/debugging-prop-pages?view=msvc-170)でも確認できます．

### argcとargvの対応を描く

コマンド引数欄へ`input.txt 42`と書くと，通常は次の関係になります．argv[0]の具体的な表示は環境によって異なります．

~~~text
argc = 3
argv[0] --> 実行プログラムを表す文字列
argv[1] --> "input.txt"
argv[2] --> "42"
argv[3] = NULL
~~~

argvは，第9回で扱ったポインタ配列の引数です．仮引数`char *argv[]`は`char **argv`とも書けます．argcとargvという名前自体は任意ですが，この慣用的な名前を使います．argv[2]は整数42ではなく，'4'，'2'，終端からなる文字列を指します．

追加の引数がない通常の実行ではargcは1です．argv[1]はNULLなので，%sやstrtolへ渡してはいけません．空文字列を引数として渡す場合は違います．引数欄の`""`は，終端だけを持つ文字列を1個渡すので，argcは通常2になります．引数の個数が正しくても内容が正しいとは限りません．

`const char *filename = argv[1];`は文字列を複製する処理ではありません．同じ文字列の先頭アドレスを保存するだけです．引数を使う前に個数と内容を確認し，プログラムの使い方に合わなければstderrへ説明して終了します．

### 複数の引数を順に扱う

次は，argv[1]以降を空白で区切って表示する処理です．mainの中で使います．プログラム名を表示対象から外すため，i=1から始めています．

~~~c
for (int i = 1; i < argc; ++i) {
    if (i > 1) { putchar(' '); }
    printf("%s", argv[i]);
}
putchar('\n');
~~~

引数欄が`red blue`ならred blue，引数なしなら改行だけです．`"red blue" green`は2つの引数です．引用符は空白を含む1つの引数を作るためのもので，通常その引用符自体はargvの文字列に含まれません．

数値を合計する場合は各argv[i]を検査してから加えます．atoiやatofは簡潔ですが，変換失敗を十分に識別できないため，整数にはstrtol，実数にはstrtodを検討します．実数も変換の終点・範囲と，必要なら非有限値を検査します．atoiは「安全なstrtolの省略形」ではありません．

### パスが見つからない場合

| 症状 | 確認すること |
| --- | --- |
| input.txtがあるのに開けない | 作業ディレクトリと実際の保存場所 |
| 名前が一致しているように見える | input.txt.txtのような二重拡張子 |
| 空白を含む名前だけ失敗する | 引数欄で全体を二重引用符で囲んだか |
| プロパティを変えても結果が変わらない | 実行するプロジェクト・構成・プラットフォーム |
| 出力ファイルが見つからない | ソースの場所ではなく作業ディレクトリを確認 |

最初はファイル名も内容もASCIIだけにして，文字コードに関する問題と切り分けます．Cのソース文字列内でWindowsの区切り文字を書くなら`"data\\input.txt"`のようにエスケープします．Visual Studioの引数欄はCの文字列リテラルではないので，バックスラッシュを二重にする必要はありません．

`_CRT_SECURE_NO_WARNINGS` は，ここで使用する標準Cのfopenに対するMSVCの非推奨診断を抑える指定です．**ファイル先頭のインクルードより前**に置きます．一般の警告を無効にする指定ではなく，処理を安全にする機能でもありません．この例では戻り値とエラーを明示的に検査します．

診断の意味は[MicrosoftのCRTの説明](https://learn.microsoft.com/en-us/cpp/c-runtime-library/security-features-in-the-crt?view=msvc-170)を参照してください．

### read_text.cの処理を追う

1. 引数を1個受け取ったか，名前が空でないかを確認する．
2. 読み取りモードrで開き，NULLならperrorで理由を表示する．
3. fgetcの戻り値をintへ受け取り，EOF以外をputcharへ渡す．
4. ループを抜けたらferrorで読み取りエラーを調べる．
5. fcloseで入力を閉じ，fflushで標準出力の書き込み結果も確認する．

空のファイルは失敗とは限りません．最初のfgetcがEOFを返し，ferrorが0なら，読み取るデータがなかっただけです．最後の文字が改行でなくても，文字を読むループはその文字を処理します．

feofは「次に読めるかの予報」ではなく，既に行った読み取りで終端に達したかを調べるものです．`while (!feof(fp))`の中で読み取り結果を確認せず処理すると，最後に失敗した値を処理してしまうことがあります．終了を決めるのは読み取り関数の戻り値です．

perrorはライブラリ等が設定したerrnoに対応する診断を表示します．通常のファイル終端はエラーではないため，短く読めたという理由だけでperrorを呼ぶと不適切なメッセージになる場合があります．内容が仕様に合わない場合は，自分で`invalid data`などと説明します．

### 行単位で長さを調べる

次の例は，ASCII・NULバイトなし・各行31文字以内の入力を対象に，改行を除いた長さを表示します．Windowsでは通常のテキストモードがCRLFをLFへ変換します．

~~~c title="line_lengths.c" linenums="1"
--8<-- "sample/10/line_lengths.c"
~~~

[line_lengths.c](sample/10/line_lengths.c){ download }

fgetsは容量32なら最大31バイトと終端を格納します．行末の改行が入っていたら，その1バイトだけを除きます．常にstrlen(line)−1とすると，最後に改行のない行の文字まで除いてしまいます．

長さ31で改行が配列にない場合は，もう1文字だけ読みます．それが改行かEOFなら31文字の行として扱えます．それ以外なら32文字以上なので失敗にします．長い1行を複数行と数えないための検査です．空行は長さ0，空ファイルは出力なしです．途中にNULを含むデータはこの例の対象外で，バイナリとして扱います．

## 4　テキストとバイナリ

文字列の123をテキストで保存すると，ASCIIでは `31 32 33`（十六進数）の3バイトです．数値123をバイナリでどう表すかは，定めた形式によります．両者とも物理的にはバイト列ですが，解釈の規則が違います．

WindowsのCランタイムでは，テキストモードに改行変換などがあります．そのままのバイト列を扱うならbを指定します．fread・fwriteの戻り値は**処理した要素数**です．第2引数を1にした場合だけ，その数がバイト数と一致します．

~~~c title="binary.c" linenums="1"
--8<-- "sample/10/binary.c"
~~~

[binary.c](sample/10/binary.c){ download }

新しい練習フォルダで実行すると，bytes.binを作成し，読み返して `41 00 42 0A` と表示します．途中に0があっても読み取れます．これは文字列ではないため，%sでは表示しません．

整数や構造体のメモリをそのまま保存すると，型のサイズ，**エンディアン**（複数バイトの並び順），構造体の隙間などに依存します．異なる環境で交換するデータでは，各フィールドのサイズ・順序・符号化を定めます．バイナリなら常に小さい・速い，という保証もありません．

### テキストモードとバイナリモード

| ファイルにあるバイト | Windowsの通常のテキスト読み取り | バイナリ読み取り |
| --- | --- | --- |
| 41 0D 0A 42 | A，改行，Bとして読む | 4バイトをそのまま読む |
| 41 1A 42 | 1Aを入力終了として扱う | 1Aも通常のデータ |
| 41 00 42 | 00が文字列処理の障害になり得る | 個数を指定して扱う |

CRは0D，LFは0Aです．Windowsでテキストモードへ`\n`を書けば通常CRLFとして保存されますが，バイナリモードではLFの1バイトのままです．0x1AはWindowsのテキスト入力で特別扱いされるバイトで，CのEOFという整数定数そのものではありません．

ファイル名を.txtから.binへ変えても内容は変換されません．fopenのbは，文字列を自動で数値へ変換する指定でもありません．表示される文字ではなく，保存形式と入出力モードを分けて考えます．詳細は[Microsoftのfopen仕様](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/fopen-wfopen?view=msvc-170)を参照してください．

### freadとfwriteの4つの引数

`fread(buffer, size, count, fp)`は，fpから，1要素sizeバイトを最大count個読み，bufferから始まる領域へ格納します．`fwrite(data, size, count, fp)`は逆向きです．必要な保存領域は事前に確保しておきます．関数が配列を拡張してくれるわけではありません．

| 呼び出しの考え方 | 要求する量 | 戻り値の単位 |
| --- | --- | --- |
| size=1，count=16 | 最大16バイト | 1バイトの要素数 |
| size=4，count=4 | 最大16バイト | 完全な4バイト要素の個数 |
| size=sizeof(double)，count=3 | doubleが3個分 | 完全なdouble要素の個数 |

例えば4バイトの要素を4個要求して，残りが10バイトなら，完全な要素は2個分です．一部だけ読めた3個目を完成した値として使いません．バイト単位で不足を正確に数えたいならsize=1を使います．読み取れた個数が要求より小さいときは，ferrorと終端を確認します．

binary.cのbufferは16バイトなので，読み取ったnバイトだけを表示します．freadはその後ろに`\0`を書きません．文字列として扱う必要があるなら終端用に1バイト残し，内容がテキストであることも確認します．00を途中に含むデータでは，終端を追加しても%sは途中までしか表示できません．

このサンプルは自分で作る4バイトを読む専用例で，任意の大きなファイル全体を読むプログラムではありません．大きな入力では，一定サイズずつfreadを繰り返して処理する方法や，第13回の動的メモリ確保があります．読み込み先の容量と，ファイルの大きさを混同しないようにします．

### バイナリ形式の約束とヘッダ

複数の数値を保存するなら，「先頭に個数，その後に数値を順番に置く」などの約束を作ります．個数や形式の情報をヘッダ，実際の値をデータ部分と呼びます．読み取った個数が配列容量以内か，その個数分のデータが本当にあるかを確認してから使います．

~~~text
この回の小さな実験形式
[個数1バイト: 03][double 1個目][double 2個目][double 3個目]
  ヘッダ           データ部分（同じ処理系でのみ読み戻す）
~~~

実際のファイル形式でも，先頭情報を読んで後続データを解釈します．ただし，すべての形式が固定長の同じヘッダを持つわけではありません．構造体をそのままfreadで読む方法にも，隙間・型サイズ・バイト順への依存があります．構造体は第11回で学びます．

### 数値の保存と精度

テキストの`fprintf(fp, "%f", value)`は通常，小数点以下6桁で丸めて出力します．元のdoubleのすべての情報が残るとは限りません．十分な桁数で保存する方法もあり，テキストだから必ず精度が失われるわけではありません．一方，メモリ上のdoubleをバイナリ保存して同じ形式で読み戻せば，文字列変換による丸めは入りません．

小さな整数0を保存するなら，テキストは数字1文字で済む一方，固定幅の整数では複数バイトを使うこともあります．容量や速度は値・書式・ヘッダ・入出力環境によります．どちらが常に優れるかではなく，人が読めること，交換しやすいこと，数値を正確に戻せることなど，目的で選びます．

### バイトオーダを具体的に見る

16ビットの数値0x1234を2バイトで保存する約束なら，並べ方は次のようになります．

| 方式 | 先のバイト | 後のバイト |
| --- | --- | --- |
| リトルエンディアン | 34 | 12 |
| ビッグエンディアン | 12 | 34 |

これは1バイトの中のビットを反転する話ではありません．複数バイトの順番です．実際の変数の表現はunsigned charのポインタで観察できます．stdio.hを読み込み，mainの中で次の断片を使います．

~~~c
unsigned short value = 1;
const unsigned char *bytes = (const unsigned char *)&value;
for (size_t i = 0; i < sizeof value; ++i) {
    printf("%02X%s", (unsigned int)bytes[i],
           i + 1 == sizeof value ? "\n" : " ");
}
~~~

Visual Studioの通常のx64環境ではunsigned shortが2バイトで，01 00になります．型のサイズを常に2と決めつけず，ループではsizeofを使っています．これはオブジェクトの表現をunsigned charとして観察する例で，任意のバイト配列を強引にdoubleのポインタへ変えてよいという意味ではありません．

第3回のビット演算で1バイトを表示するなら，unsigned char byte = 1;に対して，7から0へビット位置を調べます．Windowsでは1バイト8ビットなので00000001です．バイト順の比較でも，それぞれのバイト内の表示は上位ビットから行います．

## 5　文字コード

ASCIIは英数字などの文字と数値の対応です．Unicodeは幅広い文字にコードポイントを割り当てます．UTF-8はUnicodeをバイト列にする符号化方式の1つで，多くの日本語文字は3バイトです．UTF-16は別の方式で，すべての文字が必ず2バイトというわけではありません．

文字化けを避けるには，**保存側と読み取り側で文字コードを合わせる**必要があります．fopenやfgetsが自動でどんな文字コードでも変換するわけではありません．UTF-8の先頭にBOMが付く場合もあり，単純な数値読み取りでは問題になることがあります．演習の入力はまずASCIIだけ，BOMなしで保存します．日本語の表示はソース・ファイル・コンソールの設定が関係するため，strlenによるバイト数の観察とは分けます．

### 文字・コードポイント・バイトを分ける

| 対象 | Unicodeのコードポイント | UTF-8のバイト列 |
| --- | --- | --- |
| A | U+0041 | 41 |
| あ | U+3042 | E3 81 82 |
| 😀 | U+1F600 | F0 9F 98 80 |

同じ1つのコードポイントでも，UTF-8では1〜4バイトです．画面で1文字のように見えるものが複数のコードポイントからできることもあるため，コードポイント数と見た目の文字数も常に同じではありません．strlenは終端までのバイト数を数え，日本語の文字数を数える関数ではありません．

UTF-16は16ビットの単位を使い，補助的な範囲の文字は2単位で表します．UTF-8のBOMはEF BB BFという先頭の3バイトで，UTF-8にバイト順の区別を付けるためのものではなく，符号化を示す目印です．BOMを付けるかどうかも読み書き側で合意する必要があります．[UnicodeのFAQ](https://www.unicode.org/faq/utf_bom.html)に対応関係が整理されています．

### 文字コードと改行コードは別

UTF-8で保存したファイルでも，改行はCRLFにもLFにもできます．文字コードを合わせても改行処理が自動ですべて解決するわけではありません．また，ファイル名の文字をOSにどう渡すかと，ファイル内部の文字をどう解釈するかも別問題です．本回はASCIIのファイル名と入力から始めます．

| 観察したいこと | 使う入力・方法 |
| --- | --- |
| 読み書きの手順 | ASCIIのみの短い文章 |
| 改行変換 | CRLFの入力とテキスト・バイナリモード |
| UTF-8のバイト数 | 既知のUTF-8バイト列を16進数で観察 |
| 日本語の画面表示 | ソースの符号化とコンソールの表示設定も確認 |

文字化けしたときにデータそのものが壊れたとは限りません．元のファイルを上書きせず，保存時の文字コードと，表示側の解釈を確かめます．

## 6　数値文字列を検査する

~~~c title="parse_number.c" linenums="1"
--8<-- "sample/10/parse_number.c"
~~~

[parse_number.c](sample/10/parse_number.c){ download }

strtolはlongへ変換し，endへ「変換が終わった位置」を返します．`&end` は二重ポインタです．数字がなかった場合，後ろに文字が残った場合，longの範囲を超えた場合，課題の範囲0〜100を外れた場合を区別して検査します．この関数は先頭の空白と符号を許しますが，このコードは末尾の空白を含む余分な文字を拒否します．atoiのように失敗の識別が難しい関数より，検査の内容を明示できます．

### 検査の順番を理解する

| 検査 | 何を防ぐか | 例 |
| --- | --- | --- |
| argc != 2 | 引数の過不足 | 引数なし，42 50 |
| 入力の先頭 == end | 数字を1つも読めない | 空文字列，abc |
| \*end != '\0' | 末尾に余分な文字が残る | 12x，引用符で囲んだ42と空白 |
| errno == ERANGE | longで表せる範囲を超える | 極端に長い整数 |
| value < 0またはvalue > 100 | 課題が許す範囲を外れる | −1，101 |

strtolの前にerrno=0とするのは，前の処理のエラー状態と区別するためです．正常な値0と，変換できなかったときの0は，戻り値だけでは見分けられません．endとerrnoを組み合わせて判断します．

同じ考え方をファイルから読んだ1行にも使えます．ただしfgetsが改行を残すので，行末の改行を取り除くか，検査時に改行だけを許す必要があります．引数用の検査をそのまま流用して正常な行まで拒否しないようにしましょう．

## 7　保存形式を先に決める

演習では，二乗の一覧を次の形式で保存します．最初の行は個数N，続くN行が0からN−1までの整数を二乗した値です．N=4なら5行になります．

~~~text
4
0
1
4
9
~~~

読み取り側は，個数が許容範囲か，値がN個あるか，数値として正しいか，余分なデータがないかを確認します．ヘッダに書かれているからといって無条件に信用しません．対象値を見つけても，ファイル全体の形式を検査するなら最後まで読みます．

書くプログラムと読むプログラムは別プロジェクトにします．どちらも同じ保存形式の約束に従えば，ソースを共有しなくてもデータを交換できます．「とりあえず書いてから読む方法を考える」のではなく，値の範囲・順番・個数・改行・文字コードを決めてから実装するのが重要です．
