# 第7回　演習：入出力

解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

[講義](lec07.md)を読んでから取り組んでください．出力と処理の流れを予測しましょう．

## 準備と進め方

作業場所は PL1\week07 です．[第1回](lec01.md#hello)と同じ設定（Cとしてコンパイル，C17，警告レベル4）で，課題ごとに別の空のプロジェクトを作ります．特に指定がなければ，mainを持つソースは1プロジェクトに1つです．保存後にCtrl+Shift+Bでビルドし，Ctrl+F5で実行します．

各課題で，ソース，試した値，予測，実行結果，結果の説明を残してください．提出先や締切は，授業時に案内します．

### 今回の課題と入力方法

| 課題 | 内容 | 終了条件 |
| --- | --- | --- |
| 1 | 複写・小文字化フィルタ | 入力終了（EOF） |
| 2 | 1行の英字数と，全入力のバイト数 | 改行またはEOF／EOF |
| 3 | 1行を配列へ読み込む | 1行または入力終了 |
| 4 | ストリームの接続・書式 | 読解と固定値の表示 |
| 発展 | タイピングの採点 | 改行またはEOF |

起動したコンソールに英数字を入力してEnterを押します．EOFまで読むプログラムでは，Enterだけでは終了しません．通常のWindowsコンソールで新しい行の先頭からCtrl+Z，続けてEnterを押して入力終了を知らせてください．強制停止すると，最後の集計や表示まで実行されない場合があります．

記録には，キーボードから入力した文字とプログラムが表示した文字を分けて書きます．コンソールに入力文字が映ることは，printfやputcharで表示したこととは別です．ソースを変更するたびに保存・ビルドしてから再実行しましょう．

この回の対話入力はASCIIの英数字・空白・記号と改行を対象にします．NULバイトや日本語を含む入力は扱いません．大量の入力を試す必要はなく，各課題の上限を守ります．


## 課題1　入力をそのまま出力する

`Echo` プロジェクトで講義のecho.cを実行します．abcと入力してEnter，次にXYZと入力してEnterを押し，入力終了を知らせてください．空の入力（最初に終了）でも確認します．

??? tip "ヒント"

    入力待ちの間はプログラムは終わっていません．通常のWindowsコンソールでは，新しい行でCtrl+Z，Enterです．

### 読み取り順を紙上で追う

| getcharで読む値 | EOFとの比較 | プログラムの処理 |
| --- | --- | --- |
| 'a' | 等しくない | aを出力 |
| 'b' | 等しくない | bを出力 |
| 'c' | 等しくない | cを出力 |
| '\n' | 等しくない | 改行を出力 |
| 次の入力 | 到着するまで待つ | 終了ではない |
| EOF | 等しい | 本体へ入らず終了 |

次の3つを独立に試します．①最初に入力終了，②Enterだけを押してから入力終了，③abcとXYZの2行を入力してから入力終了．それぞれ出力なし，改行1個，2行の複写になります．「空の入力」と「空行1個の入力」は同じではありません．

### 改行を見える形で確認する

echo.cのputcharとその失敗処理の部分を，次の表示へ一時的に置き換えます．

~~~c
if (ch == '\n') {
    printf("new line\n");
} else {
    printf("character=%c\n", ch);
}
~~~

abとEnterならcharacter=a，character=b，new lineの3行です．getcharを3回呼んでいることと，Enterでまとめて文字が届くことを区別します．確認後は元へ戻してください．

次に，元のputchar(ch)の前に，putchar('/')とその戻り値の確認を加えます．入力abとEnterに対して出力が/a/b/と改行になることを予測してください．スラッシュは入力の各文字の前へ入るため，改行の前にも付く点に注意します．

### 小文字化フィルタを作る

別の`LowerInput`プロジェクトで，ASCIIの英大文字だけを小文字へ変えます．第6回の文字列配列とは異なり，今回は入力を1文字ずつ処理します．

Hello C17!ならhello c17!，AZaz09ならazaz09です．空白・記号・改行をそのまま残し，EOFは変換対象にしません．2行以上でも働くことを確かめます．

**説明すること**：変換処理をEOFの判定より後に行う理由と，配列へ全入力を保存しなくても処理できる理由を説明してください．

## 課題2　英字の数を数える

`LetterCount` プロジェクトで，Enterまでの1行に含まれるASCII英字の個数を数えてください．abc 12!なら3，空行なら0，AZazなら4です．この課題の入力は1000バイト以内とします．

??? tip "ヒント"

    EOFだけでなく改行でもループを止めます．大文字と小文字の2つの範囲を論理演算でつなぎます．

### 英字の範囲と停止条件を確かめる

| 1行の入力 | 期待する数 | 注目点 |
| --- | ---: | --- |
| abc 12! | 記入してください | 数字・空白・記号は除く |
| 空行 | 記入してください | 本体を実行せず改行で終了 |
| AZaz | 記入してください | 大文字・小文字の両方を数える |
| @AZ[ | 記入してください | Aの前，Zの後は英字ではない |
| 123!? | 記入してください | 英字なし |

EOFを知らせなくても，このプログラムはEnterで集計を表示します．課題1との違いは，継続条件にch != '\n'が加わっていることです．&&の左側が偽なら右側を評価しない，という短絡評価も確認しましょう．

### 改行も含めた全入力のバイト数

別の`ByteCount`プロジェクトで次を実行します．入力は改行を含め合計1000バイト以内とし，EOFまで読む方式に変えます．

~~~c
#include <stdio.h>
int main(void)
{
    int count = 0;
    while (getchar() != EOF) {
        ++count;
    }
    if (ferror(stdin)) {
        fprintf(stderr, "input error\n");
        return 1;
    }
    printf("%d\n", count);
    return 0;
}
~~~

| 入力してからEOF | 期待する数 |
| --- | ---: |
| 何も入力しない | 記入してください |
| Enterだけ | 記入してください |
| abcdとEnter | 記入してください |
| abとEnter，CとEnter | 記入してください |

ここで数えているのはプログラムが読み取ったバイトで，単語数ではありません．改行も数えます．日本語の見た目の文字数や，改行変換前のファイルサイズを求めるプログラムでもありません．

**説明すること**：英字数を数えるプログラムと，このプログラムの「何を数えるか」「いつ表示するか」をそれぞれ説明してください．

## 課題3　行の容量

`LineInput` プロジェクトで講義のline.cを実行します．空行，Hello，31個のA，32個のAを入力し，それぞれの結果を記録してください．

### 3つの長さを区別する

HelloとEnterでは，入力として読むのは本文5文字と改行の6文字です．fgetsはさらに終端を付けて保存するので7要素を使います．例題は改行を終端に置き換えてから，本文の長さ5を表示します．

| 本文 | 最初のfgetsの保存内容 | 例題の最終結果 |
| --- | --- | --- |
| 空行 | 改行＋終端 | length=0 text= |
| Hello | Hello＋改行＋終端 | length=5 text=Hello |
| Aが30個 | A30個＋改行＋終端 | 長さ30 |
| Aが31個 | A31個＋終端 | 後から改行を消費し，長さ31 |
| Aが32個 | A31個＋終端 | 残ったAを検出して超過の診断 |

31個と32個を用意するときは，エディタなどで個数を確認してからコンソールへ貼り付けてかまいません．個数があいまいなまま結果だけを比較しないでください．初期のText:は入力案内で，length=...はプログラムが読み取り後に出す結果です．

### 入力終了だけを知らせた場合

起動後，何も入力せず新しい行でCtrl+Z，Enterを押すと，No line read.と診断します．Enterだけの空行は正常に読めます．「長さ0の文字列を読み取れた」と「行を読み取れなかった」を区別しましょう．

### 容量を小さくして仕組みを見る

line[32]をline[8]へ変更し，他の容量検査はそのまま残します．本文は最大7文字になります．ABCDEF（6文字），ABCDEFG（7文字），ABCDEFGH（8文字）を入力して，それぞれ長さ6，長さ7，Line too long.になることを確認してください．

sizeof lineで容量を渡しているため，配列の宣言だけを変えても読み込み上限が追従します．ただし，関数の配列引数に同じ方法をそのまま使えないことは第5回の復習です．

**説明すること**：fgetsで改行が読めなかったとき，追加のgetcharで何を調べているか．extraは何を表し，超過がなければどの値のままか．終了条件まで読み捨てるループが必要な理由を説明してください．

## 課題4　接続関係を説明する

プログラムAは小文字化したテキストをstdoutへ出し，処理状況をstderrへ出します．Aのstdoutを，入力バイト数を数えるプログラムBへ接続すると，Bは処理状況も数えるでしょうか．また，Aのstdoutへ入力案内を出すと何が起きますか．実行操作は不要です．

### リダイレクトの結果を予測する

以下はすべて接続図・文章で答える問題で，シェル操作やファイルの上書きは行いません．入力ファイルの内容はABと改行，Aは小文字化フィルタ，Bは改行を含めて数えるプログラムとします．

1. 入力ファイルをAのstdinへ接続し，Aのstdoutを画面へつなぐと何が表示されるか．
2. 同じ出力をファイルへつなぐと，ファイルには何が記録されるか．
3. その接続を上書きで2回実行した場合と，最初は上書き，次は追記とした場合で，結果はどう違うか．
4. AのstdoutをBのstdinへ接続すると，Bは何と表示するか．
5. AがstdoutへReadyと改行を追加してから処理結果を出すと，Bの集計はどう変わるか．

### printfの幅と書式を確かめる

`Formats`プロジェクトで次を実行します．このプログラムは入力を待ちません．縦棒で囲むことで，追加された空白を見やすくしています．

~~~c
#include <stdio.h>
int main(void)
{
    int n = 3;
    double value = 154.423;
    unsigned int base = 500u;
    long long big = 5000000000LL;
    printf("|%d|%5d|\n", n, n);
    printf("|%f|%.2f|%8.2f|\n", value, value, value);
    printf("|%e|%g|\n", 1.3e10, 1.3e10);
    printf("%u %o %x\n", base, base, base);
    printf("%lld\n", big);
    return 0;
}
~~~

~~~text
|3|    3|
|154.423000|154.42|  154.42|
|1.300000e+10|1.3e+10|
500 764 1f4
5000000000
~~~

nを123456へ変更すると%5dでも6桁すべてを表示します．表示幅は上限ではないからです．baseの初期値を0764uまたは0x1f4uに変えても同じ500なので，出力は変わりません．bigの書式を%dへ変更する実験は行わず，型に合う%lldを保ちます．

**説明すること**：%.2fと%8.2fの違い，%fと%gの精度指定の意味の違い，長い整数の表示に正しい長さ修飾子が必要な理由を説明してください．

## 発展　タイピングの採点

`Typing`プロジェクトで，お手本のThis is a penと入力の**同じ位置の文字**を比較し，一致した数を得点にします．空白も1文字です．入力は1行1000バイト以内とし，改行またはEOFで採点を終えます．お手本は13文字で，14文字目以降の入力は加点しません．

次の段階を順に考えてください．作成する最終版は，大文字・小文字を区別せず，同じ位置の一致を数える仕様です．

| 段階 | 確認すること | 入力例と得点 |
| --- | --- | --- |
| A | 空行と完全一致 | 空行→0，This is a pen→13 |
| B | 途中まで入力 | This→4 |
| C | 同じ位置だけを採点 | Txxxxxxxxxp→2 |
| D | 大文字・小文字を区別しない | thiS is a Pen→13 |

文字を挿入・削除した後に位置を自動で合わせ直す処理ではありません．例えばThi is a penはsが1文字抜けて後ろがずれるため，最初のThiだけの3点です．配列の範囲内かを先に調べてから，お手本を読みます．

??? tip "ヒント"

    入力位置positionと得点scoreを別に管理します．入力するたびにpositionは進みますが，scoreは一致した場合だけ増えます．小文字化関数はgetcharの値をintで受け取り，EOFを除いた後に呼びます．

まずA〜Dのすべての入力で確認します．さらにThis is a pen!でも13点，xxxxxxxxxxxxxなら0点を確認してください．大文字・小文字を区別する版に戻す場合は，比較をch == target[position]へ変えます．

このプログラムは対話用なので入力案内をstdoutへ表示しています．得点だけを別プログラムへ渡したいなら，案内の出力先を分けるなどの変更が必要です．課題4のストリーム接続と関連付けて考えてください．

## 確認問題

1. getcharの戻り値をcharへ先に保存しないのはなぜか．
2. '0'，'\0'，'\n'，EOFの役割はそれぞれ何か．
3. abcdとEnterは，getcharで何回の読み取りに対応するか．
4. getcharを1回呼ぶと，入力した112は整数112になるか．
5. fgetsの戻り値を確認する前にstrlenを使ってはいけないのはなぜか．
6. char line[32]に保存できる本文の最大長は，この例題では何バイトか．
7. printfでdoubleを表示するときと，scanfでdoubleへ読み込むときの書式は何か．
8. パイプへ接続されるのは通常どの出力か．stderrはどう扱われるか．
