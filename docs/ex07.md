### 今回の課題と入力方法

| 課題 | 内容 | 終了条件 |
| --- | --- | --- |
| 1 | 複写・小文字化フィルタ | 入力終了（`EOF`） |
| 2 | 1行の英字数と，全入力のバイト数 | 改行または`EOF`／`EOF` |
| 3 | 1行を配列へ読み込む | 1行または入力終了 |

起動したコンソールに英数字を入力してEnterを押します．`EOF`まで読むプログラムでは，Enterだけでは終了しません．通常のWindowsコンソールで新しい行の先頭からCtrl+Z，続けてEnterを押して入力終了を知らせてください．強制停止すると，最後の集計や表示まで実行されない場合があります．

記録には，キーボードから入力した文字とプログラムが表示した文字を分けて書きます．コンソールに入力文字が映ることは，`printf`や`putchar`で表示したこととは別です．ソースを変更するたびに保存・ビルドしてから再実行しましょう．

この回の対話入力はASCIIの英数字・空白・記号と改行を対象にします．`NUL`バイトや日本語を含む入力は扱いません．大量の入力を試す必要はなく，各課題の上限を守ります．


## 課題1　入力をそのまま出力する

`Echo`プロジェクトを作り，講義のサンプル`echo.c`を追加して実行します．この課題では，次の3つの小問を順に行います．

1. 課題1-1：複写プログラムをそのまま実行し，入力と出力の関係を確かめる．
2. 課題1-2：複写プログラムを一時的に書き換え，改行やスラッシュを見える形で表示する．
3. 課題1-3：複写プログラムをもとに，小文字化フィルタを作る．

??? tip "ヒント"

    入力待ちの間はプログラムは終わっていません．通常のWindowsコンソールでは，新しい行でCtrl+Z，Enterです．

### 課題1-1　複写と読み取り順を確かめる

| `getchar`で読む値 | `EOF`との比較 | プログラムの処理 |
| --- | --- | --- |
| `'a'` | 等しくない | `a`を出力 |
| `'b'` | 等しくない | `b`を出力 |
| `'c'` | 等しくない | `c`を出力 |
| `'\n'` | 等しくない | 改行を出力 |
| 次の入力 | 到着するまで待つ | 終了ではない |
| `EOF` | 等しい | 本体へ入らず終了 |

次の3通りを，それぞれプログラムを起動し直して試します．

| 試すこと | 操作 | 予想される出力 |
| --- | --- | --- |
| ① 空の入力 | 起動直後に，何も入力せずCtrl+Z，Enter | 何も出力されない |
| ② 空行1個 | Enterだけを押し，次の行でCtrl+Z，Enter | 改行が1個出力される |
| ③ 2行の入力 | `abc`とEnter，`XYZ`とEnterを押し，次の行でCtrl+Z，Enter | 2行がそのまま出力される |

「空の入力」と「空行1個の入力」は同じではありません．①と②の違いを記録に書いてください．

### 課題1-2　改行表示とスラッシュ追加を試す

`echo.c`にある複写プログラムのうち，`while`の中にある次の部分（`putchar`とその失敗処理）を，一時的に置き換えます．

~~~c
if (putchar(ch) == EOF) {
    fprintf(stderr, "output error\n");
    return 1;
}
~~~

置き換えた後の`while`の中身は，次のようになります．

~~~c
if (ch == '\n') {
    printf("new line\n");
} else {
    printf("character=%c\n", ch);
}
~~~

`ab`とEnterを入力すると，`character=a`，`character=b`，`new line`の3行が表示されます．Enterを1回押しただけで3つの文字がまとめて届き，`getchar`がそれを3回に分けて読んでいることを確かめてください．確かめたら，元の`putchar`の部分に戻します．

次に，元の`if (putchar(ch) == EOF) { ... }`の直前に，`putchar('/')`を呼ぶ処理を加えます．`putchar('/')`の戻り値も，`putchar(ch)`と同じ形で`EOF`かどうかを確かめてください．実行する前に，`ab`とEnterを入力したときの出力を予測して記録し，その後で実行して比べます．スラッシュは入力の各文字の前に入るので，改行の前にも付く点に注意します．確かめたら，加えた処理を消して元に戻します．

### 課題1-3　小文字化フィルタを作る

`LowerInput`プロジェクトを作り，複写プログラムを`lower_input.c`へコピーして書き換え，入力をすべて出力し，そのうち英大文字（`'A'`〜`'Z'`）だけを小文字に変えて出力するプログラムを作ります．第6回では文字列を配列に入れてから変換しましたが，今回は配列を使わず，`getchar`で読んだ1文字ずつを変換して`putchar`で出力します．入力は`EOF`まで読みます．

| 入力 | 出力 |
| --- | --- |
| `Hello C17!` | `hello c17!` |
| `AZaz09` | `azaz09` |

英大文字以外（小文字・数字・空白・記号・改行）は変えずにそのまま出力します．`EOF`は文字ではないので，変換も出力もしません．2行以上入力しても正しく動くことを確かめてください．

**説明すること**：次の2点を記録に書いてください．

- 変換の処理を，`EOF`かどうかを調べた後に行う理由．
- 入力全体を配列に保存しなくても変換できる理由．

## 課題2　英字の数を数える

この課題は2つの小問からなります．課題2-1は英字の数を数えるプログラムを自分で作り，課題2-2は全入力のバイト数を数えるプログラム（下に掲載）を実行して比べます．

### 課題2-1　1行の英字数を数える

課題2-1では，`LetterCount`プロジェクトに`letter_count.c`を作り，1行（Enterを押すまで）に含まれる英字（`'A'`〜`'Z'`と`'a'`〜`'z'`）の個数を数えるプログラムを作ります．改行を読むか`EOF`になったら読むのをやめ，数えた個数を`printf("%d\n", count);`のように1行で表示します．例えば`abc 12!`なら3，空行なら0，`AZaz`なら4です．この課題の入力は1000バイト以内とします．

??? tip "ヒント"

    `EOF`だけでなく改行でもループを止めます．大文字と小文字の2つの範囲を論理演算でつなぎます．

#### 英字の範囲と停止条件を確かめる

次の表の「期待する数」は，実行する前に自分で予測して記録に書き，その後で実行結果と比べてください．入力ごとにプログラムを起動し直します．

| 1行の入力 | 期待する数 | 注目点 |
| --- | ---: | --- |
| `abc 12!` | 記入してください | 数字・空白・記号は除く |
| 空行 | 記入してください | 本体を実行せず改行で終了 |
| `AZaz` | 記入してください | 大文字・小文字の両方を数える |
| `@AZ[` | 記入してください | `A`の前，`Z`の後は英字ではない |
| `123!?` | 記入してください | 英字なし |

このプログラムは，`EOF`を知らせなくてもEnterを押した時点で個数を表示します．課題1との違いは，ループを続ける条件に`ch != '\n'`が加わることです．条件を`&&`でつなぐときは，左側が偽なら右側は評価されない（短絡評価）ことを踏まえて，`getchar`で読む部分と`ch != '\n'`のどちらを左に書くべきかを考えましょう．

### 課題2-2　改行も含めた全入力のバイト数

課題2-2では，`ByteCount`プロジェクトを作り，次のプログラム全体を`byte_count.c`へ保存して実行します．このプログラムは改行では止まらず，`EOF`まで読んで，読み取ったバイト数（改行を含む）を表示します．入力は改行を含めて合計1000バイト以内とします．

~~~c linenums="1"
#include <stdio.h>
int main(void)
{
    int count = 0;
    while (getchar() != EOF) {
        ++count;
    }
    if (ferror(stdin)) {
        fprintf(stderr, "input error\n");
        return 1;
    }
    printf("%d\n", count);
    return 0;
}
~~~

課題2-1と同じように，「期待する数」を予測して記録に書いてから実行します．どの入力でも，最後に新しい行の先頭でCtrl+Z，Enterを押して入力を終わりにします．

| 入力してから`EOF` | 期待する数 |
| --- | ---: |
| 何も入力しない | 記入してください |
| Enterだけ | 記入してください |
| `abcd`とEnter | 記入してください |
| `ab`とEnter，`C`とEnter | 記入してください |

ここで数えているのはプログラムが読み取ったバイトで，単語数ではありません．改行も数えます．日本語の見た目の文字数や，改行変換前のファイルサイズを求めるプログラムでもありません．

**説明すること**：課題2-1の英字数を数えるプログラムと，課題2-2のバイト数を数えるプログラムのそれぞれについて，「何を数えるか」と「いつ結果を表示するか」を記録に書いてください．

## 課題3　行の容量

`LineInput`プロジェクトを作り，講義のサンプル`line.c`を追加して実行します．このプログラムは1回の実行で1行だけ読むので，入力ごとに起動し直します．次の5つを入力し，それぞれの結果を記録してください．

- 空行（Enterだけ）
- `Hello`
- 30個の`A`
- 31個の`A`
- 32個の`A`

### 課題3-1　3つの長さを区別する

`Hello`とEnterでは，入力として読むのは本文5文字と改行の6文字です．`fgets`はさらに終端を付けて保存するので7要素を使います．例題は改行を終端に置き換えてから，本文の長さ5を表示します．

| 本文 | 最初の`fgets`の保存内容 | 例題の最終結果 |
| --- | --- | --- |
| 空行 | 改行＋終端 | `length=0 text=` |
| `Hello` | `Hello`＋改行＋終端 | `length=5 text=Hello` |
| `A`が30個 | `A`30個＋改行＋終端 | `length=30 text=`の後に`A`が30個 |
| `A`が31個 | `A`31個＋終端 | 残った改行を`getchar`で読み，`length=31 text=`の後に`A`が31個 |
| `A`が32個 | `A`31個＋終端 | 残った`A`を`getchar`で見つけ，`Line too long.` |

31個と32個を用意するときは，エディタなどで個数を確認してからコンソールへ貼り付けてかまいません．個数があいまいなまま結果だけを比較しないでください．初期の`Text:`は入力案内で，`length=...`はプログラムが読み取り後に出す結果です．

### 課題3-2　入力終了だけを知らせた場合

起動後，何も入力せず新しい行でCtrl+Z，Enterを押してください．`No line read.`と表示されることを確かめ，記録します．Enterだけの空行は正常に読めます．「長さ0の文字列を読み取れた」と「行を読み取れなかった」を区別しましょう．

### 課題3-3　容量を小さくして仕組みを見る

`LineInput`の`line.c`で，`char line[32];`を`char line[8];`に変えます．それ以外の部分は変更しません．このとき保存できる本文は最大7文字です．`ABCDEF`（6文字），`ABCDEFG`（7文字），`ABCDEFGH`（8文字）をそれぞれ起動し直して入力し，`length=6`，`length=7`，`Line too long.`と表示されることを確かめてください．

`fgets`には`sizeof line`で容量を渡しているので，配列の宣言を変えるだけで，読み込む上限も自動的に変わります．ただし，関数の引数として受け取った配列に`sizeof`を使っても，元の配列の大きさは得られません（第5回の復習）．

**説明すること**：次の3点を記録に書いてください．

- `fgets`で改行まで読めなかったとき，続く`getchar`で何を調べているか．
- 変数`extra`は何を表すか．行が長すぎなかった場合，`extra`はどの値のままか．
- 改行か`EOF`になるまで，残りを読み捨てるループが必要な理由．

## 課題4　接続関係を説明する

この課題は，課題4-1・4-2が接続関係を考える問題，課題4-3が`printf`の書式を確かめる実行課題です．課題4-1・4-2はプログラムを実行せず，文章か接続図で答えて記録に書きます．コマンドの操作やファイルの上書きは行いません．

### 課題4-1　ストリームの分け方を考える

次の2つのプログラムを考えます．

- プログラム`A`：課題1-3で作った小文字化フィルタに，処理の状況を知らせるメッセージを`stderr`へ出す処理を加えたもの．小文字にしたテキストは`stdout`へ出す．
- プログラム`B`：課題2-2のように，`stdin`から読んだバイト数を改行も含めて数え，表示するプログラム．

1. `A`の`stdout`を`B`の`stdin`につなぐと，`B`は`A`が`stderr`へ出したメッセージも数えるか．理由も答えよ．
2. `A`が`stdout`へ入力案内を出すと，`B`の結果にどのような影響があるか．

### 課題4-2　リダイレクトの結果を予測する

入力ファイルの内容は`AB`と改行で，プログラムが読み取るのは3バイトとします．`A`と`B`は上と同じプログラムです．

1. 入力ファイルを`A`の`stdin`につなぎ，`A`の`stdout`を画面につなぐと，何が表示されるか．
2. 1と同じ`A`の`stdout`を，画面ではなく出力ファイルにつなぐと，ファイルには何が書かれるか．
3. 2の実行を2回行うとき，「2回とも上書き（`>`）」の場合と，「1回目は上書き（`>`），2回目は書き足し（`>>`）」の場合とで，出力ファイルの中身はどう違うか．
4. `A`の`stdout`を`B`の`stdin`につなぐと，`B`は何と表示するか．
5. `A`が処理結果の前に，`stdout`へ`Ready`と改行を出すように変えると，4の`B`の表示はどう変わるか．

### 課題4-3　`printf`の幅と書式を確かめる

`Formats`プロジェクトを作り，次のプログラム全体を`formats.c`へ保存して実行します．このプログラムは入力を待ちません．縦棒で囲むことで，追加された空白を見やすくしています．

~~~c linenums="1"
#include <stdio.h>
int main(void)
{
    int n = 3;
    double value = 154.423;
    unsigned int base = 500u;
    long long big = 5000000000LL;
    printf("|%d|%5d|\n", n, n);
    printf("|%f|%.2f|%8.2f|\n", value, value, value);
    printf("|%e|%g|\n", 1.3e10, 1.3e10);
    printf("%u %o %x\n", base, base, base);
    printf("%lld\n", big);
    return 0;
}
~~~

~~~text
|3|    3|
|154.423000|154.42|  154.42|
|1.300000e+10|1.3e+10|
500 764 1f4
5000000000
~~~

実行して上の出力と同じになることを確かめたら，次の2つを1つずつ試します．それぞれ，実行する前に出力を予測して記録し，実行結果と比べてください．

1. `n`の初期値を`123456`に変える．
2. `base`の初期値を`0764u`に変え，次に`0x1f4u`に変える．

1では，`%5d`でも6桁すべてが表示されます．表示幅は最小の幅で，上限ではないからです．2では，`0764u`も`0x1f4u`も十進数の500と同じ値なので，出力は変わりません．なお，`big`の書式を`%d`に変える実験は行わず，型に合った`%lld`のままにします．

**説明すること**：次の3点を記録に書いてください．

- `%.2f`と`%8.2f`の違い．
- `%f`の精度（`.2`など）と`%g`の精度の意味の違い．
- `long long`の値を表示するとき，`%lld`の`ll`（長さ修飾子）が必要な理由．

## 発展　タイピングの採点

`Typing`プロジェクトを作り，タイピングの採点プログラムを`typing.c`に作ります．お手本の文字列`This is a pen`と，キーボードから入力した1行とを，**同じ位置の文字どうし**で比べ，一致した文字の数を得点として表示します．

プログラムが満たすこと（仕様）は次のとおりです．

- お手本`This is a pen`は，プログラムの中に文字列の配列として用意する．お手本は空白も含めて13文字である．
- 入力の前に，お手本を示す入力案内を`stdout`へ表示する（文言は自由）．
- 入力を`getchar`で1文字ずつ読み，改行を読むか`EOF`になったら採点を終えて得点を表示する．
- 入力の1文字目とお手本の1文字目，2文字目と2文字目，…のように同じ位置どうしを比べる．空白も1文字として比べる．
- 大文字と小文字は区別しない（`t`と`T`は一致とみなす）．
- 14文字目以降の入力は比べず，得点にも加えない．お手本の配列の範囲外を読まないように，位置が13未満かどうかを先に調べてから，お手本の文字を読む．
- 入力は1行1000バイト以内とする．

完成したら，次の入力で確かめます．入力ごとにプログラムを起動し直してください．

| 確認すること | 入力 | 得点 |
| --- | --- | --- |
| 空行 | Enterだけ | 0 |
| 完全に一致 | `This is a pen` | 13 |
| 途中まで入力 | `This` | 4 |
| 同じ位置だけを比べる | `Txxxxxxxxxp` | 2 |
| 大文字・小文字を区別しない | `thiS is a Pen` | 13 |
| 14文字目以降は加点しない | `This is a pen!` | 13 |
| 一致なし | `xxxxxxxxxxxxx` | 0 |

文字が抜けたり余分に入ったりしても，位置を合わせ直す処理はしません．例えば`Thi is a pen`は`s`が1文字抜けているので，4文字目以降が1つずつずれ，最初の`Thi`だけが一致して3点になります．

??? tip "ヒント"

    入力の位置`position`と得点`score`を別々の変数で管理します．1文字読むたびに`position`は1進みますが，`score`は一致したときだけ1増えます．大文字・小文字を区別せずに比べるには，入力の文字とお手本の文字の両方を，課題1-3と同じ方法で小文字に変えてから比べます．入力の文字は`getchar`の値を`int`で受け取り，`EOF`でないことを確かめてから小文字に変えます．

大文字・小文字を区別する版を試したいときは，比較を`ch == target[position]`に変えます（`ch`は入力の文字，`target`はお手本の配列）．

**考えること**：このプログラムは，人が画面を見ながら使うことを想定しているので，入力案内を`stdout`に表示しています．得点だけを別のプログラムにパイプで渡したい場合，どこを変える必要があるかを，課題4と関連付けて考え，記録に書いてください．

## 確認問題

1. `getchar`の戻り値を`char`へ先に保存しないのはなぜか．
2. `'0'`，`'\0'`，`'\n'`，`EOF`の役割はそれぞれ何か．
3. `abcd`とEnterは，`getchar`で何回の読み取りに対応するか．
4. `getchar`を1回呼ぶと，入力した112は整数112になるか．
5. `fgets`の戻り値を確認する前に`strlen`を使ってはいけないのはなぜか．
6. `char line[32]`に保存できる本文の最大長は，この例題では何バイトか．
7. `printf`で`double`を表示するときと，`scanf`で`double`へ読み込むときの書式は何か．
8. パイプへ接続されるのは通常どの出力か．`stderr`はどう扱われるか．

## チェックリスト
