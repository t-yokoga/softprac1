# 第12回　演習：コンパイル

解答・解説は授業で別途提示します．このページには問題とヒントを掲載しています．

[講義](lec12.md)を読んでから取り組んでください．出力と処理の流れを予測しましょう．

## 準備と進め方

作業場所は `PL1\week12` です．[第1回](lec01.md#hello)と同じ設定（Cとしてコンパイル，C17，警告レベル4）で，課題ごとに別の空のプロジェクトを作ります．特に指定がなければ，`main`を持つソースは1プロジェクトに1つです．保存後にCtrl+Shift+Bでビルドし，Ctrl+F5で実行します．

各課題で，ソース，試した値，予測，実行結果，結果の説明を残してください．提出先や締切は，授業時に案内します．

基本課題1〜4で，分割・変更・エラーの切り分け・ヘッダの依存関係を確認します．発展課題は，独立したライブラリ化，並べ替えモジュール，標準ライブラリの使い分けです．基本課題が終わったら取り組んでください．

## 課題1　分割ビルド

講義の[分割手順](lec12.md#split)に従って`SplitCalc`を作ります．`main.c`と`calc.c`を同じプロジェクトに入れます．`calc.h`も保存してください．この回では課題4と発展2も複数の`.c`を使います．

### 手順

1. 3ファイルを読み，`main.c`だけを見て出力を予測する．
2. `calc.h`の宣言と`calc.c`の定義を線で対応させる．
3. Visual Studioにファイルを追加してビルドし，警告とエラーを確認する．
4. 実行結果を予測と比べる．
5. `calc.c`だけを保存し直してビルドした場合と，何も変えずに再ビルドした場合の出力ウィンドウを比べる．タイムスタンプや設定によって表示される処理は異なるので，観察した内容を記録する．

### 考察

- なぜ`main.c`に`add`の本体がなくてもコンパイルできるか．
- `calc.h`を取り込んだだけで`calc.c`もビルド対象になるか．
- `.obj`と`.exe`は同じものか．
- `main.c`と`calc.c`を別々の実行アプリ用プロジェクトにしてよいか．

??? tip "ファイルが見つからないとき"

    エクスプローラーで実際の拡張子を確認します．`calc.h.txt`や`main.c.cpp`になっていないか，同名の別ファイルを編集していないかを調べます．ソリューションエクスプローラーの表示だけで保存場所を判断せず，ファイルのプロパティで実際のパスを確認してください．

## 課題2　関数を追加する

`subtract` という`double`引数2つ・`double`戻り値の関数を追加し，5.0から2.0を引いた3.0を表示してください．さらに0−0，2−5で確認します．

??? tip "ヒント"

    宣言・定義・呼び出しの3か所を対応させます．

### 追加課題：失敗を返す割り算

次の仕様の関数を追加します．関数名は標準ライブラリの`div`と衝突しないように`calc_divide`とします．

- 引数は`double`の`a`，`b`と，結果を保存する`double`へのポインタ`out`．
- `out`は有効な`double`オブジェクトを指すことを呼び出し側の条件とする．
- `b`が0.0なら失敗として0を返し，保存先の値を変更しない．
- それ以外は`a/b`を保存し，成功として1を返す．
- この課題では小さな有限値を使い，浮動小数点の範囲を超える計算は対象にしない．

第8回の「戻り値で成功・失敗を返し，ポインタで結果を返す」を，別ファイルの関数にします．仕様が公開側の契約に当たることも意識してください．

??? tip "ヒント"

    0で割ってから調べるのではなく，計算前に`b`を検査します．失敗時に`out`へ書き込まなければ，呼び出し前の値を保てます．宣言・定義・呼び出しの3か所を同時に整えましょう．

### 検証表

| 操作 | 入力 | 期待する結果 |
| --- | --- | --- |
| `subtract` | 5，2 | 記入してください |
| `subtract` | 0，0 | 記入してください |
| `subtract` | 2，5 | 記入してください |
| `calc_divide` | 6，2 | 記入してください |
| `calc_divide` | −6，2 | 記入してください |
| `calc_divide` | 0，2 | 記入してください |
| `calc_divide` | 6，0 | 記入してください |

宣言だけを追加しても計算はできません．逆に本体だけを追加しても，呼び出し側へ正しい宣言が伝わりません．表を埋めるだけでなく，変更した3か所を示してください．

## 課題3　リンクエラーを調べる

ソースを残したまま，`calc.c`のプロパティで実行中の構成の「ビルドから除外」を「はい」にしてリビルドします．エラーを記録し，必ず「いいえ」に戻して再ビルドします．ビルド失敗時に以前の実行ファイルを実行する案内が出ても実行しません．

### エラーの比較

課題1の正常版をコピーして，次を1つずつ試します．エラーメッセージの全文を暗記する必要はありません．最初の原因に近い診断を探し，前処理・コンパイル・リンクを区別しましょう．

| 変更 | 予想する段階 | 元に戻す操作 |
| --- | --- | --- |
| `main.c`の`include`を存在しない`calc_missing.h`にする | 自分で予想 | `calc.h`へ戻す |
| `calc.c`の`add`の戻り値型だけを`int`にする | 自分で予想 | `double`へ戻す |
| `calc.c`をビルドから除外する | 自分で予想 | 除外を「いいえ」へ戻す |
| `add`の本体を`main.c`にもコピーする | 自分で予想 | コピーした本体だけを除く |

### ビルド記録に残すこと

変更箇所，予想，実際の段階，診断の要点，復旧後の成功を1行ずつ記録します．「エラーが消えた」だけでなく，元の出力に戻ったことも確認してください．診断の違いから，ヘッダ検索先を直すべき場面と，リンクする実装を確認すべき場面を区別できるようにします．

## 課題4　ベクトルと行列を分割する

講義7の5ファイルを使い，`VectorCalc`を作ります．`vector_main.c`，`vector.c`，`matrix.c`をソースとして登録し，`vector.h`と`matrix.h`を同じ実フォルダに保存します．他の課題の`main.c`は追加しません．

### 手計算して実行する

1. `x=(1,2)`，`y=(3,4)`，`A`の第1行=(1,−1)，第2行=(−1,1)について，`2x+y`と2Ax+yを計算する．
2. 実行し，講義の出力と手計算を比較する．
3. `A`を単位行列に変更し，2Ax+yが`2x+y`と一致することを確認する．
4. `gemv`の`alpha`を0，`beta`を1に変更し，結果が`y`になることを確認する．
5. 入力`x`と`y`が関数呼び出し後も変わっていないことを，`print_vector`で確認する．

### インクルードガードを調べる

`vector_main.c`では，`matrix.h`経由と直接の2回，`vector.h`が取り込まれます．正常版を保存し，`vector.h`のガードの3行（`#ifndef`，`#define`，対応する最後の`#endif`）だけを一時的に外してビルドしてください．本文は変更しません．結果を記録したら，必ず3行を戻します．

### ヘッダの独立性を確認する

`vector_main.c`から直接の`#include "vector.h"`だけを一時的に外し，ビルドしてください．結果を予測し，`matrix.h`の内容と関連付けて説明します．確認後は元の表記に戻します．「同じ内容を二度読まない工夫」と「必要な型をヘッダ自身で用意する工夫」を区別して説明してください．

??? tip "前処理を詳しく見たい場合"

    講義4.2に従って`vector_main.c`の前処理済みファイルを生成し，`Vector`の構造体定義を検索します．標準ヘッダの展開などで行数は元の`.c`より多くなる場合があります．ガードの効果を確認したら`/P`の設定を戻し，リビルドしてください．`.i`を生成しただけでは実行ファイルは更新されません．

## 発展1　静的ライブラリとして使う

元の`SplitCalc`は残し，別の`LibraryDemo`ソリューションに`CalcLib`と`CalcApp`を作って試します．

1. `CalcLib`を空のC++プロジェクトで作り，「プロパティ → 構成プロパティ → 全般 → 構成の種類」を「スタティック ライブラリ（`.lib`）」にする．C17・`/TC`も設定する．
2. `CalcLib`へ`calc.c`と`calc.h`を保存・追加する．`main.c`は入れない．
3. 同じソリューションへ空のC++プロジェクト`CalcApp`を追加し，C17・`/TC`を設定して`main.c`だけを入れる．
4. `CalcApp`の「参照 → 参照の追加」（またはプロジェクト右クリックの同項目）で`CalcLib`を選ぶ．
5. `CalcApp`の「C/C++ → 全般 → 追加のインクルード ディレクトリ」に，`calc.h`のある`CalcLib`の実フォルダを指定する．既存の設定値は残す．
6. 両プロジェクトの構成とプラットフォームをそろえ，`CalcApp`をスタートアッププロジェクトに指定してビルド・実行する．

### 更新の伝わり方

まず講義の加算・乗算だけの3ファイルで確認します．その後，課題2の`subtract`を`CalcLib`へ追加し，`CalcApp`から呼び出します．次の4つを別の作業として説明してください．

1. `calc.h`に宣言を追加して利用側へ見せる．
2. `calc.c`に実装を追加し，`CalcLib`をビルドして`.lib`を更新する．
3. `CalcApp`の呼び出しをコンパイルする．
4. `CalcApp`を更新後の`.lib`とリンクする．

Visual Studioのプロジェクト参照が適切なら，必要な順序でこれらが行われます．`.lib`を作り直しただけでは，すでに別の場所へ配布した`.exe`の内容まで変わりません．

### 配布済み`.lib`を使う場合との違い

同じソリューション内にソースのないライブラリは，配布された`.h`と`.lib`を使います．講義9の表に従い，「追加のインクルード ディレクトリ」「追加のライブラリ ディレクトリ」「追加の依存ファイル」の役割を説明してください．検索先とファイル名は違う設定です．既存の継承設定を消さずに追加します．

この課題で作る`CalcLib`は静的ライブラリです．`CalcLib.dll`を探す必要はありません．ただし，アプリ全体が他のDLLやVisual C++ランタイムに依存しないという意味ではありません．ライブラリを利用するときは，x64等のプラットフォーム，Debug/Release，実行時ライブラリの設定を整えます．

## 発展2　並べ替えをモジュールにする

整数配列を昇順にする処理を`intlib`へ分けます．利用者は比較方法の実装を意識せず，`sort_ints`を呼び出せるようにします．また，第10回のコマンドライン引数を使い，並べ替える個数を指定します．

### 仕様

- データは`{7, -2, 7, 0, 3, 9, -8, 1}`の8要素で固定する．
- 引数は1つ，先頭から処理する個数`N`（0〜8）とする．
- 引数の不足・過剰，数字がない文字列，末尾の余計な文字，範囲外の数値を拒否する．
- `N=0`では要素を表示せず，改行だけを表示する．
- `intlib.h`に公開する宣言，`intlib.c`に変換と並べ替え，`sort_main.c`に実行の流れを書く．
- 比較関数は`intlib.c`の中だけで使い，`static`にする．

課題を再現しやすくするため，最初は乱数ではなく同じ配列を使います．可変長配列は使わず，8要素の固定長配列と個数を分けて扱います．

`intlib.h`には容量8を表す`INTLIB_CAPACITY`と，`int parse_count(const char *text, int *out)`，`void sort_ints(int a[], size_t n)`を宣言します．`size_t`のため`stddef.h`も取り込みます．`parse_count`は成功時1を返して個数を保存し，失敗時0を返して保存先を変更しない仕様です．`intlib.c`で実装し，`sort_main.c`で引数の検査・呼び出し・表示を行ってください．

??? tip "qsortの比較関数"

    比較関数に渡される`const void *`は要素へのポインタです．今回の要素型は`int`なので，`const int *`として読み出します．`qsort`には`compare_int`と関数名を渡します．`compare_int(...)`と書いてその場で呼び出した結果を渡すのではありません．関数を必要なときに呼んでもらう仕組みをコールバックと呼びます．

### 引数を設定して検証する

Visual Studioの`SortModule`の「プロパティ → 構成プロパティ → デバッグ → コマンド引数」に`5`を設定します．1つの引数として空文字列を試すときは`""`を設定します．設定対象が実行する構成と一致していることを確かめてください．

| コマンド引数 | 期待する結果 |
| --- | --- |
| 5 | 記入してください |
| 0 | 記入してください |
| 1 | 記入してください |
| 8 | 記入してください |
| 指定なし，`""`，`abc`，`3x` | 記入してください |
| −1（半角では`-1`），9 | 記入してください |
| 999999999999999999999999 | 記入してください |
| 3 4 | 記入してください |

さらに，`data`の先頭2つを`INT_MAX`，`INT_MIN`に変え，`limits.h`を追加して`N=2`で試してください．小さい方が先になります．単に元の値の差を返す比較関数では危険な理由を説明しましょう．

### 設計を説明する

- `intlib.h`に`compare_int`の宣言を置かないのはなぜか．
- `sort_main.c`が`qsort`の使い方を知らなくてもよいのはなぜか．
- 型の宣言・数値の検査・エラー表示は，それぞれどこにあるか．
- 固定配列の容量と有効な個数`N`は同じものか．

## 発展3　標準ライブラリの契約を確かめる

次のプログラムを`LibraryCheck`で動かします．関数名だけでなく，ヘッダ，入力条件，戻り値の意味を表にまとめてから実行してください．コピー先の容量が十分であることも確認します．

~~~c title="library_check.c" linenums="1"
#define _CRT_SECURE_NO_WARNINGS
#include <assert.h>
#include <ctype.h>
#include <float.h>
#include <math.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void)
{
    char src[5] = {'a', 'b', '\0', 'c', 'd'};
    char text[10] = {0};
    char bytes[10] = {0};
    strcpy(text, src);
    memcpy(bytes, src, sizeof src);
    printf("math=%.1f %.1f %.1f\n",
           sqrt(9.0), pow(3.0, 2.0), fabs(-2.5));
    printf("alpha=%d digit=%d min_positive=%d\n",
           isalpha((unsigned char)'A') != 0,
           isdigit((unsigned char)'7') != 0, FLT_MIN > 0.0f);
    printf("text=%s bytes=%c%c %c%c\n",
           text, bytes[0], bytes[1], bytes[3], bytes[4]);
    assert(text[2] == '\0');
    assert(bytes[3] == 'c');

    srand(123U);
    int first = rand();
    srand(123U);
    int again = rand();
    printf("same_seed=%d\n", first == again);
    double u = (double)rand() / RAND_MAX;
    printf("in_range=%d\n", 0.0 <= u && u <= 1.0);
    return 0;
}
~~~

ここでの`_CRT_SECURE_NO_WARNINGS`は，容量が確認できる固定例で標準関数`strcpy`を学ぶための指定です．危険なコピーを安全にする機能ではありません．一般の入力では終端までの長さとコピー先の容量を必ず調べます．

### 追加の観察

1. 先頭で`NDEBUG`を定義して，`assert`が無効でもコピーや乱数の処理が同じように実行されることを確認する．定義は`assert.h`を読むより前に置く．
2. `assert`の式にコピーや`rand`の呼び出しを入れない理由を説明する．式自体が評価されなくなる設定があることに注意する．
3. `rand() % 10`の値が0〜9になる理由と，完全に均等とは限らない理由を説明する．何回かの実行だけで一様性を証明できるかも考える．
4. 発展2の配列の初期値を，ループ内の`rand() % 1024`で用意する形へ変更してよい．`srand`はループの前に1回だけ呼び，実行前後の配列を表示する．出力そのものではなく，要素数と昇順になったことを確かめる．

!!! note "今回は行わない操作"

    `assert`が入力検査の代わりになるか確かめるために，配列の範囲外アクセスを実行してはいけません．また，`system`による外部コマンドの実行は行いません．標準ライブラリに含まれる機能でも，入力条件と作用を理解してから使います．

## 確認問題

1. 「`calc.h`を追加したので`calc.c`を追加しなくてもよい」は正しいか．
2. インクルードガードで，同じ外部関数を2つの`.c`に定義した問題は解決するか．
3. `.lib`の検索先が正しくても，ヘッダが見つからないことはあるか．
4. 静的ライブラリを更新すれば，配布済みの`.exe`も自動的に新しくなるか．
5. 不完全型の`Vector *`を宣言できることと，`Vector`の実体を作れることは同じか．

## チェックリスト

- 正常な値だけでなく，課題に示された境界の値でも確認した．
- 警告を確認し，原因を説明・修正した．
- 自分の言葉で，処理の流れと使った型を説明できる．
- 1つの実行アプリに`main`が1つだけあり，必要な`.c`がすべてビルド対象になっている．
- 意図的に作ったエラーと前処理用の設定を元に戻し，最後のビルドが成功した．
- 宣言・定義・呼び出しと，コンパイル・リンクの関係を説明できる．
- ヘッダのガード名を使い回さず，必要な型をヘッダ自身で取り込んでいる．
