# 第7回　入出力


## 到達目標

- 標準入力・標準出力・標準エラー出力を区別できる．
- `EOF`を正しく見分けながら文字を読み，容量を指定して行を読める．
- リダイレクトとパイプによる接続を説明できる．


## 1　プログラムと外部をつなぐストリーム

### 前回とのつながりと準備 { #environment }

第6回では，プログラムの中に配列として用意した文字列を扱いました．今回は，プログラムを実行している間に外から受け取るデータ（キーボードから打ち込んだ文字など）を扱います．外から来るデータは，どれくらいの量があるのか，どこで終わるのかが，プログラムに前もって分かるとは限りません．そこで，**データを読み取る，入力が終わったかを判断する，読んだ結果を保存する**という3つの仕事に分けて考えましょう．

作業場所は`PL1\week07`です．[第1回の手順](lec01.md#hello)でプロジェクトを作り，「C17」「Cとしてコンパイル」「警告レベル4」を設定します．講義例の確認には空のプロジェクト`Week07`を1つ作り，ソースファイル`main.c`を1つだけ追加します．講義に出てくるプログラムは，この`main.c`に書いて実行します．演習課題では，演習ページの一覧に従ってプログラムごとに別のプロジェクトとファイルを作成します．完全なプログラムを試すときは内容全体を置き換え，短い断片を試すときは`main`関数内の対応する処理を置き換えます．置き換える前のソースは，`PL1\week07\records`などプロジェクト外のフォルダへ保存してください．

一部のプログラムはファイルとしてダウンロードできますが，ダウンロードしたファイルはプロジェクトに追加しないでください．1つのプロジェクトに`main`関数が2つ以上あると，ビルドでエラーになるからです．ほかの`.c`ファイルをすでに追加してしまった場合は，ソリューションエクスプローラーでそのファイルを右クリックし，「削除 → プロジェクトから除外」を選んで，`main.c`だけを残してください．

保存したらCtrl+Shift+Bでビルドし，成功したことを確かめてからCtrl+F5で実行します．

キーボードからの入力は，Visual Studioのエディタではなく，実行すると開くウィンドウ（コンソール）に打ち込みます．

入出力を使うプログラムには`#include <stdio.h>`が必要です（`strlen`を使う例では`#include <string.h>`も必要です）．この回は，コマンドを打ち込む実習は行いません．後半で学ぶリダイレクトとパイプは，つながり方を表す図で理解します．

**ストリーム**は，データを先頭から順番に読んだり書いたりするための仕組みです．データが1列に並んで流れてくる「流れ」だと考えてください．`<stdio.h>`には，最初から使える3つのストリームが用意されています．

| 名前 | 役割 | ふだん実行したときのつながる先 |
| --- | --- | --- |
| `stdin` | 標準入力 | キーボード |
| `stdout` | 標準出力 | 画面 |
| `stderr` | 標準エラー出力 | 画面 |

`printf`は標準出力に書きます．エラーのメッセージは，`fprintf(stderr, "input error\n");`のように書くと，標準エラー出力という別の出力先に書けます．どちらも同じ画面に表示されますが，別々のストリームです．

ストリームを流れてくるデータは，「改行で区切られた行がいくつか並んだもの」になっているとは限りません．最後の行に改行が付いていない入力や，何も入っていない空の入力もあります．また，第6回で学んだ文字列の終わりの印`'\0'`が，入力の最後に自動で付いてくるわけでもありません．読んだデータを配列に保存して文字列として使うときは，プログラムで`'\0'`を付ける必要があります．

データがキーボードから来ても，ファイルから来ても，プログラムから見れば「順番に読めるストリーム」として同じように扱えます．このため，同じプログラムのまま，入力元を別のものに付け替えることができます．後の回でファイルを直接開くときも，同じストリームの考え方を使います．

## 2　1文字ずつ読む

### `getchar`と`putchar`の役割

`getchar()`は，読み取った1バイトの値，または **`EOF`** を`int`型で返します．`EOF`（End Of File の略）は，「入力が終わった」または「読み取りに失敗した」ことを知らせる特別な値で，文字ではありません．

`getchar`が返す値は，文字なら0〜255のどれか，入力の終わりや失敗なら`EOF`です．つまり全部で257通りの値があります．`int`の変数なら257通りをすべて区別して保存できますが，`char`の変数は1バイトなので256通りしか入りません．1つ足りないので，どこかで2つの値が同じになってしまいます．

例えばMSVCでは，値255の文字を`char`の変数に入れると，`EOF`と同じ負の値になります．すると，その文字を読んだところで「入力が終わった」と誤って判断し，ループが途中で止まります．別の環境では逆に，`EOF`を`char`の変数に入れると255に変わり，`EOF`と比べても等しくならないので，ループがいつまでも終わりません．

どちらも`char`の変数に入れた時点で起きる問題です．`getchar`の戻り値は必ず`int`の変数で受け取りましょう．

| 関数 | 読む・書く先 | 単位 | 戻り値 |
| --- | --- | --- | --- |
| `getchar()` | `stdin` | 1バイト | 読んだ文字の値（0〜255），または`EOF` |
| `putchar(ch)` | `stdout` | 1バイト | 書いた文字の値，失敗したときは`EOF` |

`getchar`の`char`は，英語のcharacter（文字）の略です．「単語」を読む関数ではなく，1回呼ぶたびに1文字（正確には1バイト）だけを読みます．

例えば`112`と入力してEnterを押した場合，最初の`getchar`が返すのは整数の112ではなく，文字`'1'`を表す値です．もう一度呼ぶと次の`'1'`，その次は`'2'`，最後に改行`'\n'`を読みます．つまり`112`は，「1」「1」「2」「改行」の4文字としてプログラムに届きます．

なお，日本語の「あ」のような文字は，コンピュータの中では複数のバイトで表されることがあります．その場合，画面で見える1文字を読み終えるまでに，`getchar`を何回か呼ぶことになります．

`putchar`も1回呼ぶたびに1文字だけを書きます．`putchar('a');`は`a`を書くだけで，改行は自動では付きません．行を変えたいときは，`putchar('\n');`も呼びます．

`EOF`は`stdio.h`の中で決められている負の整数です．プログラムでは−1のような数を直接書かず，必ず`EOF`という名前を使って比べます．`printf("EOF=%d\n", EOF);`を実行すれば値を確かめられますが，表示された数をキーボードから打ち込んでも，入力の終わりにはなりません．打ち込んだものは，`112`のときと同じように，`'-'`や数字の文字として`getchar`に届くだけです．

### 実行例：`112`を1文字ずつ読む

次のプログラムで`main.c`の中身をすべて置き換えて実行し，`112`と打ってEnterを押します．出力に出てくる数値は，それぞれの文字に割り当てられた番号（ASCIIコード）です．

~~~c linenums="1"
#include <stdio.h>
int main(void)
{
    int ch;
    while ((ch = getchar()) != EOF) {
        if (ch == '\n') {
            printf("new line: %d\n", ch);
            break;
        }
        printf("character=%c value=%d\n", ch, ch);
    }
    if (ferror(stdin)) {
        fprintf(stderr, "input error\n");
        return 1;
    }
    return 0;
}
~~~

入力は次の1行です．

~~~text
112
~~~

プログラムの出力は次のとおりです．

~~~text
character=1 value=49
character=1 value=49
character=2 value=50
new line: 10
~~~

`'1'`は49，`'2'`は50，改行は10という番号で表されています．プログラムは`112`を整数の112に直しているわけではありません．改行を含めて4回読み取り，改行を読んだところで`break`によってループを抜けて終わります．

入力された文字を，そのまま出力するプログラムです．

~~~

`while ((ch = getchar()) != EOF)`は，次の順に動きます．①`getchar`で1文字読む，②読んだ値を`ch`に代入する，③`ch`が`EOF`でないかを調べる．`EOF`でなければループの中に入り，その文字を`putchar`で出力します．`EOF`のときはループを抜けるので，`EOF`そのものを`putchar`に渡すことはありません．

条件の中で`(ch = getchar())`を括弧で囲んでいる点に注意してください．括弧を外して`ch = getchar() != EOF`と書くと，`!=`の方が`=`より先に計算されます．そのため`ch`には読んだ文字ではなく，比較の結果である0か1が入ってしまいます．第3回で学んだ演算子の優先順位と代入式の値に関わる部分なので，括弧は省かないでください．

ループが終わる理由には，入力の終わりと読み取りエラーの2つがあり，どちらも同じ`EOF`で知らされます．そこで，ループを抜けた後に`ferror(stdin)`で，エラーだったかどうかを確かめています．また，`putchar`も書き込みに失敗すると`EOF`を返すので，その場合はエラーメッセージを出して終わります．

読み込みと条件を分けて，次のように書くこともできます．流れは上と同じです．ここでは流れだけを示すため，出力エラーの処理は省いています．実行するときは，上の複写プログラム全体を`main.c`へコピーして使ってください．

~~~c
int ch = getchar();
while (ch != EOF) {
    putchar(ch);
    ch = getchar();
}
~~~

この書き方では，ループの前とループの最後の2か所に`getchar`を書く必要があります．最後の`getchar`を書き忘れると，`ch`が変わらないので，同じ文字をいつまでも出力し続けます．条件の中で読み込む書き方なら，`getchar`は1か所で済みます．

複写プログラムを`main.c`にコピーして実行し，`ab`と打ってEnterを押します．ふつうのコンソールでは，次のように2行表示されます．

1行目は自分が打ち込んだ文字をコンソールが表示したもの，2行目は`putchar`が出力したものです．Enterの後も，プログラムは次の入力を待ち続けています．続けて新しい行の先頭でCtrl+Zを押し，Enterを押すと，ループが終わります．上の表示例には，`^Z`のようなキー操作の表示や，終了後にVisual Studioが出す案内文は含めていません．

### Enterと`EOF`を区別する

ふつうのコンソールでは，打ち込んだ文字はEnterを押すまでいったんためておかれ，Enterを押した時点で改行も含めてまとめてプログラムに渡されます．ただし，これはコンソールの仕組みによるもので，「`getchar`は必ずEnterを待つ」というC言語の決まりではありません．まだ読んでいない文字が残っていれば，`getchar`は待たずにその文字を読みます．

~~~text
コンソールで ab と入力してEnter
              ↓
読む順序：    'a' → 'b' → '\n' → 次の入力を待つ
              ↓      ↓       ↓
複写の出力：   a      b      改行
~~~

| 状況 | 意味 | `EOF`まで読むループ |
| --- | --- | --- |
| Enterだけ押す | 改行1文字が届く（空行） | まだ続く |
| `ab`の後にEnter | `a`，`b`，改行が届く | まだ続く |
| 新しい行の先頭でCtrl+Z，Enterを押す | これ以上の入力がない | 終わる |
| 強制停止する | 実行そのものを途中で止める | ループの後の処理（集計の表示など）が行われるとは限らない |

`EOF`は「入力が終わった」という状態を表す値，`'\n'`は改行という文字，`'\0'`は配列の中で文字列の終わりを示す文字です．この3つを混同しないでください．また，入力の終わり（`EOF`）で集計結果を出すプログラムを強制停止で終わらせても，正しく終わったときと同じ動きにはなりません．デバッグ中は「デバッグの停止」で実行を止められますが，これも入力の終わりとは別のものです．

### 実行例：読み取りの前後を表示する

次のプログラムで`main.c`の中身を置き換えて実行します．`before read 1`と表示されたら，`ab`と打ってEnterを押します．

~~~c linenums="1"
#include <stdio.h>
int main(void)
{
    for (int i = 0; i < 3; ++i) {
        printf("before read %d\n", i + 1);
        fflush(stdout);
        int ch = getchar();
        if (ch == EOF) {
            if (ferror(stdin)) {
                fprintf(stderr, "input error\n");
                return 1;
            }
            printf("end of input\n");
            return 0;
        }
        if (ch == '\n') {
            printf("after read: new line\n");
        } else {
            printf("after read: %c\n", ch);
        }
    }
    return 0;
}
~~~

自分が打ち込んだ文字も含めた表示例です．`ab`の行だけが入力で，ほかはプログラムの出力です．

~~~text
before read 1
ab
after read: a
before read 2
after read: b
before read 3
after read: new line
~~~

1回目の`getchar`は，Enterが押されるまで待ちます．Enterを押すと`a`，`b`，改行の3文字がまとめて渡されるので，2回目と3回目の`getchar`は，残っている`b`と改行をすぐに読みます．入力し直す必要はありません．このプログラムは3回読んだところで終わります．

### 読んだ文字を数える・変換する

`getchar`で1文字読めるたびにカウンタ（数を数える変数）を1増やせば，読み取ったバイト数を数えられます．`abcd`と打ってEnterを押し，入力を終わりにした場合は，`a`，`b`，`c`，`d`，改行で5になります．単語の数ではないことに注意してください．なお，Windowsでは読み書きのときに改行が変換されるため，この数がディスク上のファイルのバイト数と同じになるとは限りません．

また，`putchar(ch)`の直前に`putchar('/');`を加えると，入力された各文字の前にスラッシュを付けられます．`ab`と改行を入力すると，出力は`/a/b/`と改行になります．改行も1文字として扱われるので，改行の前にもスラッシュが付きます．

第6回の小文字への変換も，配列を使わずに書けます．読み取った`ch`が`'A'`〜`'Z'`のどれかなら小文字に変えてから，`putchar`で出力すればよいのです．このように，入力を少しずつ読んで処理し，結果を次へ渡していくプログラムを**フィルタ**と呼びます．

## 3　行を読む

### `fgets`での容量の指定

`fgets(配列, 容量, stdin)`は，標準入力から1行を読んで配列に保存する関数です．読むのは最大で「容量−1」個の文字までで，読み取りに成功すると，最後に文字列の終わりの印`'\0'`を付けます．改行まで読めた場合は，改行も配列に入ります．以前のCには容量を指定できない`gets`という関数がありましたが，配列からあふれる危険があるため削除されており，この授業のC17では使いません．

この回では，容量が2以上の配列を使います．`fgets`の戻り値は，読み取りに成功すれば配列の先頭を指す値，1文字も読めないまま入力が終わったときや読み取りエラーのときは`NULL`です．戻り値が`NULL`でないことを確かめる前に，配列を`strlen`や`%s`に渡してはいけません．`NULL`が何なのかはポインタの回で詳しく学びます．今は「読み込みに失敗した印」として使ってください．

例えば`Hello`と打ってEnterを押すと，配列には`'H'`，`'e'`，`'l'`，`'l'`，`'o'`，`'\n'`，`'\0'`が入ります．このとき`strlen`の結果は，改行も数えて6です．最後の改行を`'\0'`に置き換えると，`Hello`の長さである5になります．Enterだけを押した空行でも，`'\n'`と`'\0'`が入るので，読み込みは成功です．

### 実行例：改行を除く前後の長さ

次のプログラムで`main.c`の中身を置き換えて実行します．この例では，入力する文字は英数字（ASCII）で6文字以内とし，空行も試します．

~~~c linenums="1"
#include <stdio.h>
#include <string.h>
int main(void)
{
    char line[8];
    if (fgets(line, sizeof line, stdin) == NULL) {
        fprintf(stderr, "No line read.\n");
        return 1;
    }
    size_t n = strlen(line);
    printf("before=%zu\n", n);
    if (n > 0 && line[n - 1] == '\n') {
        line[--n] = '\0';
    }
    printf("after=%zu text=|%s|\n", n, line);
    return 0;
}
~~~

`Hello`と打ってEnterを押した場合の出力です．

~~~text
before=6
after=5 text=|Hello|
~~~

起動し直してEnterだけを押すと，次の出力になります．

~~~text
before=1
after=0 text=||
~~~

`strlen`は改行を数えますが，終わりの印`'\0'`は数えません．`Hello`と改行を保存すると，`'\0'`も含めて配列の要素を7個使います．

### 改行を除去して本文の長さを調べる

~~~c linenums="1"
--8<-- "sample/07/line.c"
~~~

[`line.c`](sample/07/line.c){ download }

`Hello`と入力すると，`length=5 text=Hello`と表示します．配列の大きさは32なので，保存できる文字は`'\0'`の分を除いた31バイトまでです．`fgets`で読んだ文字列の最後に改行がなかった場合は，その行の残りを`getchar`で読み，ちょうど31バイトだったのか，それより長かったのかを区別します．この例題は，1行のテキストを入力することを想定しています．入力の途中に値0の文字（`NUL`バイト）が含まれる場合は考えません．

`fflush(stdout)`は，改行の付いていない入力案内`Text: `をすぐに画面に出すために使っています．なお，`fflush(stdin)`で残った入力を捨てる方法は使いません．

### 容量の直前・ちょうど・超過を区別する

| 入力する文字 | 最初の`fgets`で保存されるもの | 追加の読み取り | 結果 |
| --- | --- | --- | --- |
| 30文字＋Enter | 30文字＋改行＋`'\0'` | 必要ない | 長さ30 |
| 31文字＋Enter | 31文字＋`'\0'` | 改行を1個読む | 長さ31 |
| 32文字＋Enter | 最初の31文字＋`'\0'` | 残りの1文字と改行を読む | 長すぎると判断 |

配列の最後に改行がないというだけでは，行が長すぎたとは決められません．ちょうど31文字で，改行だけがまだ読まれずに残っている場合や，改行を付けずに入力が終わった場合もあるからです．そこで例題では残りを読み，改行と`EOF`以外の文字が出てきたら`extra`を1にして，長すぎることを知らせます．長すぎた行の残りを読んでおくことは，次の入力に読み残しを持ち越さないためにも大切です．

`line[--n] = '\0';`は，まず`n`を1減らし，その位置にある改行を`'\0'`に置き換えます．その前に`n > 0`を確かめているのは，`n`が0のときに`line[n - 1]`を調べないようにするためです．`size_t`は負の数を表せないので，0から1を引くと非常に大きな数になり，配列の外を読んでしまいます．また，入力の途中に`NUL`バイトがないという今回の入力の条件も守ってください．

### 実行例：容量8で境界を比較する

`main.c`にコピーした行入力プログラム（`line.c`）で，`char line[32];`だけを`char line[8];`に変えてビルドします．ほかの部分はそのまま使い，入力を試すたびにプログラムを起動し直します．次の表示例には，入力案内の後に打ち込んだ文字も含めています．

6文字とEnterを入力した場合です．

~~~text
Text: ABCDEF
length=6 text=ABCDEF
~~~

7文字とEnterを入力した場合です．

~~~text
Text: ABCDEFG
length=7 text=ABCDEFG
~~~

8文字とEnterを入力した場合です．

~~~text
Text: ABCDEFGH
Line too long.
~~~

容量8の配列には，7文字と`'\0'`までしか入りません．6文字なら改行も配列に入ります．7文字なら改行は入りきらないので，続く`getchar`で残った改行を読みます．8文字では，続く`getchar`で改行ではない文字（8文字目）が見つかるため，長すぎると判断します．

### 読めなかった場合とエラー

何も入力せずに入力を終わりにすると，このプログラムは`No line read.`を`stderr`に表示し，`return 1;`で終わります．一方，Enterだけを押した場合は，長さ0の正しい行として読めます．「空の行がある」ことと「行が1つもない」ことは別のものです．

`getchar`が`EOF`を返す理由には，入力が終わった場合と読み取りエラーの場合の2つがあります．どちらだったかは，`ferror(stdin)`（エラーが起きたか）や`feof(stdin)`（入力が終わったか）で調べられます．ただし，読む前に`feof`を調べても，次の読み込みが成功するかどうかは分かりません．**まず読み取り関数の戻り値を確かめ，その後で状態を調べる**という順番にしてください．

### 実行例：空行と入力終了を比較する

`main.c`を元の行入力プログラム（容量32）に戻し，起動してEnterだけを押した場合です．

~~~text
Text:
length=0 text=
~~~

中身が空の行を読み取れています．次に，起動し直して何も打ち込まずに，新しい行の先頭でCtrl+Zを押してEnterを押すと，次のようになります．キー操作の表示は省いています．

~~~text
Text: No line read.
~~~

こちらは`fgets`が`NULL`を返すので，長さを表示する処理には進みません．入力案内`Text: `は`stdout`に，`No line read.`は`stderr`に出ています．

## 4　書式付き入出力

### 出力する型と書式を対応させる

`printf`では，`%d`，`%f`，`%s`などの書式を，渡す値の型に合わせて選びます．一方，`scanf`は書式に従って入力を読み，値に変換する関数です．例えば`scanf("%d", &n)`は，変換に成功した項目の数を返すので，その数を確かめる必要があります．変数の前に`&`を付けて渡す理由は第8回で学びます．

`scanf`には，`int`に入りきらない数が入力された場合や，読み残した改行の扱いなど，注意する点があります．そのため，この回の必須演習は`getchar`と`fgets`で行います．数字の並びを確かめてから数値に変換する方法は第10回で扱います．

| `printf`に渡す値 | 書式 | 例 |
| --- | --- | --- |
| `int` | `%d` | 123 |
| `unsigned int` | `%u`，`%o`，`%x` | 十進，八進，十六進 |
| `long / unsigned long` | `%ld` / `%lu` | 値が小さくても型に合わせる |
| `long long / unsigned long long` | `%lld` / `%llu` | 大きな整数 |
| `double`（`float`は渡すときに`double`に変換される） | `%f`，`%e`，`%g` | 小数・指数の形 |
| `size_t` | `%zu` | `sizeof`や`strlen`の結果 |
| `int`として渡される文字 | `%c` | `'A'`など |
| `'\0'`で終わる文字列 | `%s` | `"abc"`など |
| `void *` | `%p` | `(void *)&n`など |

`long`型の値は，値が小さくても`%d`で表示してよいわけではありません．書式は実際の型に合わせてください．書式の型・順番・個数を間違えると，未定義動作（何が起きるか決まっていない状態）になることがあり，おかしな表示が出るだけで済むとは限りません．コンパイラが警告を出したら型を確かめてください．間違った書式でどうなるかを試す実験はしないでください．

MSVCでは，`char`・`short`・`unsigned char`・`unsigned short`の値は，`printf`に渡すときに自動的に`int`に変換されます（整数拡張）．例えば`unsigned char c = 200;`は，`printf("%d\n", c);`で200と表示できます．`unsigned int`として表示したいときは，`printf("%u\n", (unsigned int)c);`のように型をそろえます．`float`が`double`に変換されることと合わせて，**宣言した型だけでなく，実際に渡される型**を確かめましょう．

### 幅と小数点以下の桁数

この節の短いコードは，`main.c`の`main`関数の中に入れ，ファイルの先頭に`#include <stdio.h>`を書いて実行します．ビルドするのは`main.c`だけです．別のコードを試すときは，前のコードと置き換えてください．

~~~c
int i = 3;
double f = 154.423;
printf("|%d|%5d|\n", i, i);
printf("|%f|%.2f|%8.2f|\n", f, f, f);
~~~

~~~text
|3|    3|
|154.423000|154.42|  154.42|
~~~

`%5d`の5は**最小の表示幅**です．表示する文字数が5より少なければ左側に空白を足しますが，123456のように6桁ある値は切り捨てずに6桁すべてを表示します．符号（`-`）や小数点も幅に数えます．`%.2f`の2は，小数点以下を何桁表示するかを表します．表示するときに丸めても，変数`f`に入っている値は変わりません．

### 実行例：表示幅を超える整数

次のプログラムで`main.c`の中身を置き換えて実行します．縦棒の間にある空白も出力の一部です．

~~~c linenums="1"
#include <stdio.h>
int main(void)
{
    printf("|%5d|\n", 3);
    printf("|%5d|\n", 12345);
    printf("|%5d|\n", 123456);
    printf("|%5d|\n", -3);
    printf("|%5d|\n", -12345);
    return 0;
}
~~~

~~~text
|    3|
|12345|
|123456|
|   -3|
|-12345|
~~~

符号も表示幅に数えます．5文字より少なければ空白で補い，5文字を超える値は切り捨てずにすべて表示します．

### 指数形式と基数の違い

次のコードも`main.c`の`main`関数の中に入れて実行します．

~~~c
double value = 1.3e10;
printf("%e\n", value);
printf("%g %g\n", 154.423, value);
unsigned int n = 500u;
printf("%u %o %x\n", n, n, n);
~~~

`%e`は`1.300000e+10`のように，指数を使った形で表示します．`1.3e10`という書き方は，1.3×10の10乗を表します．`%g`は，値と精度に応じて，ふつうの形と指数の形のどちらかを選んで表示します．この例の2行目は`154.423 1.3e+10`になります．`%g`の精度は有効数字の桁数を表し，`%f`の精度（小数点以下の桁数）とは意味が違います．

最後の行は`500 764 1f4`です．同じ500という値を十進数・八進数・十六進数で表示しているだけで，値そのものは変わりません．プログラムの中で`0764`（八進数）や`0x1f4`（十六進数）と書いても，十進数の500と同じ値です．整数の先頭にうっかり0を付けると八進数として扱われるので注意してください．

### 実行例：小数点以下の桁数と有効桁数

次のプログラムで`main.c`の中身を置き換えて実行します．

~~~c linenums="1"
#include <stdio.h>
int main(void)
{
    double a = 154.423;
    double b = 0.001234;
    printf("f: %f / %f\n", a, b);
    printf("e: %e / %e\n", a, b);
    printf("g: %g / %g\n", a, b);
    printf(".2f: %.2f / %.2f\n", a, b);
    printf(".2g: %.2g / %.2g\n", a, b);
    return 0;
}
~~~

~~~text
f: 154.423000 / 0.001234
e: 1.544230e+02 / 1.234000e-03
g: 154.423 / 0.001234
.2f: 154.42 / 0.00
.2g: 1.5e+02 / 0.0012
~~~

`%.2f`は小数点以下を2桁，`%.2g`は有効数字を2桁表示します．小さな値を`%.2f`で表示すると`0.00`になることがありますが，変数の値が0になったわけではありません．なお，指数部の桁数は環境によって違う場合があります．

### `scanf`の書式は`printf`と同じではない

`scanf("ID:%d", &n)`は，「`ID:`という文字の後に続く整数を読み取り，`n`に保存する」という意味です．`ID:13`なら成功しますが，`ID :13`のように決まった部分（`ID:`）と違う入力では失敗します．戻り値が1であることを確かめてから`n`を使います．`&n`のように変数の場所（アドレス）を渡すのは，`scanf`が呼び出し元の変数に値を書き込めるようにするためです．

| 対象 | `printf`で表示 | `scanf`で読み込む |
| --- | --- | --- |
| `int n` | `%d`に`n` | `%d`に`&n` |
| `float f` | `%f`に`f`（`double`に変換される） | `%f`に`&f` |
| `double d` | `%f`に`d` | `%lf`に`&d` |

`scanf`の戻り値は，変換して変数に代入できた項目の数です．入力が書式と合わなければ0，1つ目を代入する前に入力が終わった場合などは`EOF`になることがあります．失敗した入力はそのまま残ることがあるので，同じ`scanf`をただ繰り返すだけでは先に進めない場合もあります．また，`%d`で数値を読んだ後には改行が残り，次の`getchar`や`fgets`がその改行を読む点にも注意してください．

Visual Studioでは，`scanf`を使うと安全性についての警告が出る場合もあります．この節はコードを読むことと教員による実演で扱い，必須演習は`getchar`と`fgets`で行います．`scanf`の書式や型を変えるだけで，どんな範囲外の数値も安全に見つけられるとは考えないでください．

### 実演例：`scanf`の成功と失敗

以下の2つの例は，教員が実演するためのものです．必須演習ではこれまでどおり`getchar`と`fgets`を使います．実演でも，同じ`main.c`の中身を置き換えて実行します．プログラムの先頭にある`#define _CRT_SECURE_NO_WARNINGS`は，MSVCが`scanf`に対して出す警告を止めるためのもので，入力を確かめる機能ではありません．

次のプログラムで`main.c`の中身を置き換えて実行します．入力する数値は，`int`に収まる小さな値にします．

~~~c linenums="1"
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>
int main(void)
{
    int n = 0;
    int result = scanf("ID:%d", &n);
    printf("result=%d\n", result);
    if (result == 1) {
        printf("n=%d\n", n);
    } else {
        printf("No integer read.\n");
    }
    return 0;
}
~~~

入力を試すたびに起動し直します．表には，プログラムが表示する2行を示しています．

| 入力してEnter | 出力の1行目 | 出力の2行目 |
| --- | --- | --- |
| `ID:13` | `result=1` | `n=13` |
| `ID :13` | `result=0` | `No integer read.` |
| `ID:abc` | `result=0` | `No integer read.` |

`ID :13`は決まった部分の`ID:`と一致せず，`ID:abc`は`abc`を整数に変換できません．どちらも`n`には何も代入されていないので，`n`の値を読み取った値として表示しません．

### 実演例：数値の後に残った改行

次のプログラムで`main.c`の中身を置き換えて実行し，`13`と打ってEnterを押します．この例でも，入力する数値は`int`に収まる小さな値にします．

~~~c linenums="1"
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>
int main(void)
{
    int n;
    if (scanf("%d", &n) != 1) {
        fprintf(stderr, "No integer read.\n");
        return 1;
    }
    int ch = getchar();
    printf("n=%d\n", n);
    if (ch == '\n') {
        printf("next=new line\n");
    } else if (ch == EOF) {
        if (ferror(stdin)) {
            fprintf(stderr, "input error\n");
            return 1;
        }
        printf("next=EOF\n");
    } else {
        printf("next=%c\n", ch);
    }
    return 0;
}
~~~

プログラムの出力です．

~~~text
n=13
next=new line
~~~

`scanf("%d", &n)`は整数の部分（`13`）だけを読み，Enterで入った改行は読まずに残します．そのため続く`getchar`は，新しい入力を待たずに，残っていた改行を読みます．この後で`fgets`を使って行を読もうとした場合も，残った改行のせいで空行を読んだように見えることがあります．

## 5　リダイレクトとパイプ

標準入力はいつもキーボード，標準出力はいつも画面，と決まっているわけではありません．**リダイレクト**は，入力や出力のつながる先をファイルなどに変えることです．**パイプ**は，あるプログラムの標準出力を，別のプログラムの標準入力につなぐことです．

~~~text
通常の入力：    キーボード → プログラム → 画面
リダイレクト：  入力ファイル → プログラム → 出力ファイル
パイプ：        プログラムAのstdout → プログラムBのstdin
~~~

パイプを使うために，Cのプログラムに特別な文を書く必要はありません．ストリームのつなぎ替えは，プログラムを実行する側（実行環境）が行います．例えば「文字を小文字にする処理」と「文字数を数える処理」をパイプでつなげば，2つを部品のように組み合わせて使えます．

!!! note "この回の演習範囲"

    演習ではVisual Studioのコンソールから入力します．リダイレクトとパイプは，つながり方を考える課題で確かめ，コマンドを打ち込む操作は行いません．ファイルを直接開くプログラムは第10回で作ります．

結果は`stdout`に，エラーなどのメッセージは`stderr`に分けて出しておくと，次のプログラムに渡すデータにエラーメッセージが混ざりにくくなります．データを処理するためのプログラムでは，`Text: `のような入力案内を`stdout`に出してよいかどうかも考える必要があります．

### 入力・出力・追記を区別する

コマンドの説明でよく出てくる記号を，操作の手順ではなく意味として整理します．これらはC言語の文法ではなく，プログラムを実行する側で使う，つなぎ方の指定です．

| 記号 | 意味 | 注意 |
| --- | --- | --- |
| `<` | ファイルを標準入力につなぐ | `getchar`を使うプログラムを書き直す必要はない |
| `>` | 標準出力をファイルにつなぐ | ファイルの元の中身が上書きされることがある |
| >> | 標準出力をファイルの最後に書き足す | 実行するたびに結果が増えていく |
| \| | 左側の標準出力を右側の標準入力につなぐ | `stderr`まで自動で一緒に流れるわけではない |

入力と出力のつなぎ替えを同時に行えば，「入力ファイル → フィルタ → 結果ファイル」という流れを作れます．上書き（`>`）と書き足し（`>>`）を間違えると，前の記録を消してしまったり，同じ結果を二重に保存してしまったりします．授業では実際にファイルを上書きする操作は行わず，つなぐ先と結果の違いを考えます．

### 小さい処理を組み合わせる

固定の文字列を出力する`echo`，ファイルの中身を出力する`cat`，ファイルの一覧を出力する`ls`のような機能も，文字データを送り出す側として考えることができます．これらの名前は，つなぎ方の例を読むために紹介しているだけで，コマンドを実行する課題ではありません．なお，一覧の表示の形などは，画面に出すときとパイプに渡すときで変わることもあります．

~~~text
文字列を出力する処理
  stdout → 小文字化フィルタ → バイト数を数える処理 → 結果ファイル
                 ↓ stderr              ↓ stderr
               診断を画面へ           診断を画面へ
~~~

例えば，上流（送り出す側）が`ABC`と改行を出すなら，小文字にした後は`abc`と改行です．下流（受け取る側）で改行も数えるなら，結果は4になります．送り出す側を，ファイルの中身を出す処理やファイルの一覧を出す処理に変えても，フィルタの仕組みは変わりません．ただし，上流が改行を付けるかどうかも含めて，実際に流れてくるデータを考える必要があります．

パイプでつながれた下流のプログラムは，上流がデータを送り終えるまで入力を待つことがあります．プログラムは「画面に見えた順に何でも受け取る」わけではなく，つながっているストリームからデータを読むだけです．また，標準出力と標準エラー出力は，それぞれ別の場所（バッファ）にデータをためてから表示することがあるため，画面に表示された順番が処理した順番と同じとは限りません．画面の並びだけを見て処理の順番を判断しないようにしましょう．

## 6　確認の進め方とよくある間違い

| 症状 | 確かめること |
| --- | --- |
| Enterを押しても集計が出ない | ループの終わる条件が改行なのか`EOF`なのか |
| 入力が2回表示される | コンソールが表示した入力と，複写の出力を見間違えていないか |
| 0や1の値しか処理されない | `getchar`への代入を括弧で囲んだか |
| `EOF`で止まらない | 戻り値を`char`ではなく`int`の変数に入れているか |
| 次の行を読むとすぐ空行になる | 前の処理が改行を読み残していないか |
| 長い行の後の入力がずれる | 読み残しをどこまで読んだか |
| 表示が崩れる | 書式と引数の型・個数・順番が合っているか |
| パイプの下流で数が合わない | 入力案内や改行までデータに混ざっていないか |

確かめるときは，まず空の入力，空行，短い1行，複数行の順に試します．次に，配列に入る文字数より少ない場合，ちょうどの場合，超える場合を試します．読み取った1文字，配列に保存した文字列，標準出力に書いたデータを分けて記録しておくと，どこで予想と違う動きになったのかを見つけやすくなります．
